# 새 학원(고객) 이식 체크리스트

> 이 문서는 하다 학원관리 시스템을 **다른 학원(고객)에게 새로 세팅**할 때 쓰는 체크리스트입니다.
> 목표는 (1) 이 저장소를 그 학원 소유 GitHub 저장소로 복제, (2) 그 학원 전용 Supabase 프로젝트 생성,
> (3) 그 학원의 Notion 워크스페이스 연결까지 빠짐없이 끝내는 것입니다.
>
> 코드 자체에는 특정 학원의 값이 하드코딩되어 있지 않지만(아래 0번 항목 예외),
> 아래 값들은 **학원마다 반드시 새로 채워야** 합니다. 하나라도 빠뜨리면 그 학원의 데이터가
> 기존 학원(원본) 것과 뒤섞이거나 조회/발송이 조용히 실패할 수 있습니다.

## 0) 저장소 복제 직후 — 하드코딩 값 자동 치환 (필수, 가장 먼저)

정적 파일 3개(`attendance_kiosk.html`, `legal_documents.html`, `student_report_part1.js`)와
pg_cron 마이그레이션 6개는 GitHub Pages가 서버 환경변수를 못 쓰는 구조상 값이 파일 안에
직접 들어갑니다. **저장소를 새로 복제한 뒤, 첫 커밋/배포 전에** 아래 스크립트를 한 번 실행해
이전 학원 값을 이번 학원 값으로 한 번에 바꿉니다.

```bash
python3 scripts/setup-new-academy.py \
  --new-url https://<새 Supabase 프로젝트 ref>.supabase.co \
  --new-anon-key <새 프로젝트 anon key> \
  --new-pages-path <이 저장소의 GitHub 저장소 이름>
```

실행 후 `git diff`로 변경 내역을 확인하고 커밋하세요. (이 스크립트는 GitHub/Supabase Secrets는
다루지 않습니다 — 아래 1)·2)는 별도로 진행합니다.)

## 1) 새 Supabase 프로젝트 준비 — GitHub 저장소 Secrets

새 Supabase 프로젝트를 만들고, GitHub 저장소를 그 학원 소유로 복제한 뒤 GitHub Actions 배포가
그 프로젝트를 향하도록 아래 GitHub 저장소 Secrets(Settings → Secrets and variables → Actions)를
설정합니다.

| GitHub Secret 이름 | 용도 |
| --- | --- |
| `SUPABASE_PROJECT_ID` | 새 프로젝트의 ref (배포 대상 지정, cron 워크플로 호출 URL 조립에도 사용) |
| `SUPABASE_ACCESS_TOKEN` | Supabase CLI 배포용 개인 액세스 토큰 (최대 1년 만료, 만료 전 재발급 필요) |
| `SUPABASE_DB_PASSWORD` | 새 프로젝트 DB 비밀번호 (마이그레이션 적용용) |
| `SUPABASE_ANON_KEY` | 새 프로젝트의 anon key (cron 워크플로가 Edge Function 호출 시 사용) |

## 2) Supabase Edge Function Secrets (대시보드 → Edge Functions → Secrets)

먼저 Notion 쪽에서 이 학원의 각 DB를 준비하고(템플릿 복제 권장) ID를 확인한 뒤 아래 이름
그대로 등록합니다.

> ⚠️ **데이터베이스 ID와 데이터소스 ID는 다른 값입니다.** Notion의 멀티 데이터소스 구조상
> 하나의 DB에 "데이터베이스(페이지) ID"와 "데이터소스 ID" 두 가지 별개 ID가 있고, 서로 유도할
> 수 없습니다. 아래 표에서 `DATA_SOURCE_*_ID` 계열(18개)은 **데이터소스 ID**(`collection://...`
> 형태, DB를 열고 속성 패널이나 API로 확인)를, `NOTION_REGISTRATION_DB_ID`·`NOTION_SEND_LOG_DB_ID`·
> `NOTION_ALIMTALK_CONFIG_DB_ID` 3개는 **데이터베이스(페이지) ID**(그 DB가 인라인으로 들어있는
> 메뉴 페이지를 열었을 때 DB 블록 자체의 URL)를 씁니다. 반대로 넣으면 404로 조용히 실패합니다.

| 분류 | Secret 이름 | 비고 |
| --- | --- | --- |
| Notion 연결 | `NOTION_TOKEN` | 이 학원 Notion 워크스페이스에 연결된 인테그레이션 토큰 |
| Notion 연결 (DB 페이지 ID) | `NOTION_REGISTRATION_DB_ID` | 등록(학원) DB |
| Notion 연결 (DB 페이지 ID) | `NOTION_SEND_LOG_DB_ID` | 자동화 로그(학원) DB (구 "전송로그") |
| Notion 연결 (DB 페이지 ID) | `NOTION_ALIMTALK_CONFIG_DB_ID` | 알림톡 설정(학원) DB — 비워두면 발송이 조용히 fallback 처리되니 필수 |
| 데이터소스 ID (18개) | `DATA_SOURCE_STUDENT_ID` | 학생(학원) DB |
| | `DATA_SOURCE_REGISTRATION_ID` | 등록(학원) DB |
| | `DATA_SOURCE_CLASS_ID` | 클래스(학원) DB |
| | `DATA_SOURCE_TIMETABLE_ID` | 시간표(학원) DB |
| | `DATA_SOURCE_CLASS_SESSION_ID` | 수업(학원) DB |
| | `DATA_SOURCE_ATTENDANCE_ID` | 출석(학원) DB |
| | `DATA_SOURCE_SCHEDULE_EVENT_ID` | 일정(학원) DB |
| | `DATA_SOURCE_DASHBOARD_ID` | 대시보드(학원) DB |
| | `DATA_SOURCE_LEARNING_RECORD_ID` | 학습기록(학원) DB |
| | `DATA_SOURCE_PROGRESS_BOOK_ID` | 진도교재(학원) DB |
| | `DATA_SOURCE_STUDY_ACTIVITY_ID` | 학습활동(학원) DB |
| | `DATA_SOURCE_REPORT_ID` | 보고서(학원) DB |
| | `DATA_SOURCE_TEXTBOOK_CART_ID` | 교재비(학원) DB |
| | `DATA_SOURCE_TEXTBOOK_DISTRIBUTION_ID` | 교재배부(학원) DB |
| | `DATA_SOURCE_TEXTBOOK_PAYMENT_ID` | 교재결제(학원) DB |
| | `DATA_SOURCE_TUITION_ID` | 수강료(학원) DB |
| | `DATA_SOURCE_EXAM_SCOPE_ID` | 시험범위(학원) DB |
| | `DATA_SOURCE_GRADE_ID` | 성적(학원) DB |
| 인프라 | `SB_URL` | 새 Supabase 프로젝트 URL |
| 인프라 | `SB_SERVICE_ROLE_KEY` | 새 프로젝트의 service role key |
| 인프라 | `ADMIN_SECRET` | 이 학원의 관리자 키 (Notion 자동화 헤더·웹앱 로그인용, 학원마다 다르게 설정) |
| 웹앱 | `SITE_BASE_URL` | 예: `https://<계정>.github.io` |
| 웹앱 | `REPORT_PATH` | 예: `/<이 저장소 이름>/student_report.html` |

| 알림톡(Solapi) | `SOLAPI_PF_ID` | 카카오 채널 프로필 키 |
| 알림톡(Solapi) | `SOLAPI_SENDER_NUMBER` | 발신번호 |
| 알림톡(Solapi) | `SOLAPI_TEMPLATE_ID_DAILY`/`_MONTHLY`/`_TEXTBOOK`/`_TUITION`/`_WEEKLY` | 심사 완료된 알림톡 템플릿 ID 5종 |

## 3) Supabase Vault 시크릿

Database → Vault → Add new secret 에서 이름 `sync_queue_admin_key`, 값은 위 `ADMIN_SECRET`과
동일하게 등록합니다(`process-sync-queue`의 pg_cron 인증용). 없으면 1분마다 도는 pg_cron
안전망 호출만 401로 실패하고, 다른 경로는 정상 동작합니다.

## 4) Notion 쪽에서 직접 고쳐야 하는 부분 (코드/스크립트로 자동화 불가)

- **등록(학원) DB의 "안내 링크" 수식**: `link(..., "https://<계정>.github.io/<저장소>/student_report.html?token=" + prop("토큰"))`
  형태로 되어 있습니다. 이 학원의 실제 GitHub Pages 주소로 직접 고쳐야 합니다(Notion 수식이라
  코드 배포로는 안 바뀝니다).
- 6-1·6-2의 각 Edge Function을 호출하는 Notion 자동화("웹훅 보내기" 액션)를 전부 새 프로젝트의
  URL로 다시 연결하고, 관리자 키가 필요한 함수는 `x-admin-key` 헤더도 이 학원의 `ADMIN_SECRET`
  값으로 다시 넣어야 합니다.
  - 어떤 DB의 어떤 버튼/자동화가 어떤 Edge Function을 호출해야 하는지는 추측하지 말고
    [`docs/버튼-웹훅-매핑.md`](버튼-웹훅-매핑.md) 표를 참고하세요.

## 6) 최종 확인

- GitHub Actions 배포 워크플로우가 성공하는지 확인 (마이그레이션 적용 + 함수 전체 배포).
- 학부모 리포트 웹앱(`student_report.html?token=...`)이 실제로 열리는지 확인.
- 알림톡 테스트 발송 1건으로 Solapi 연동 확인.
