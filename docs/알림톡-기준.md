# 알림톡 기준

새 알림톡을 만들거나 기존 알림톡을 고칠 때 이 문서를 따른다. 원본·운영 학원의 AI와 사람이 같은 기준으로 만들기 위한 문서이며, 항상 최신 기준만 담는다(바뀐 경과는 CHANGELOG·`docs/updates`). Notion 속성 이름의 일반 규칙은 [이름 규칙](이름-규칙.md) 5-1에도 요약되어 있다.

## 1. 본문 틀

모든 알림톡은 카카오 **강조표기형**으로 만든다. 본문은 **네 단계 표시**로 짠다(10/30 사용자 확정). 같은 표시는 언제나 같은 단계이고, 한 단계에는 한 가지 표시만 쓴다. 이모지와 대괄호가 같은 단계에 오는 일은 없다.

| 단계 | 표시 | 역할 | 모양 |
|---|---|---|---|
| 1 | `[ ]` | 큰 구역 | `[기본 정보]` — 이모지를 붙이지 않는다 |
| 2 | 이모지 | 작은 구역 머리, 또는 한 줄 항목 | `📋 과제 체크` / `👤 학생  이도윤` |
| 3 | `#` | 교재·주제 묶음 | `#개념원리 공통수학1 (p.40-52)` — 범위는 괄호로 붙인다 |
| 4 | `  •` | 세부 항목 | `  • 1-2. 다항식의 연산` / `  • 점수  85점 (17/20)` |

예시(일일 보고서, 10/30 사용자 시안):

```
[기본 정보]
👤 학생  이도윤
🏛 클래스  중1 A 수학

[등원정보]
📅 수업일  10.30(목)
✅ 출결  출석

[과제, 루틴 체크]
📋 과제 체크
#개념원리 공통수학1
  • 1-2. 다항식의 연산
  • 유제 문제풀이
  • 제출  제출

🔄 루틴 체크
  • 단어 시험  O
  • 오답 노트  X

[학습 내용]
📗 공통수학1
#개념원리 공통수학1 (p.40-52)
  • 1-2. 나머지정리
  • 개념학습
#쎈 공통수학1 (p.40-52)
  • 1-2. 나머지정리
  • B스텝 문제풀이

📄 평가 결과
#개념원리 공통수학1
  • 1-2. 다항식의 연산
  • 점수  85점 (17/20)
  • 반 평균  80점 (6명 응시)

[전달 사항]
📋 과제 안내
#개념원리 공통수학1
  • 단원  다항식의 연산
  • 평가 오답 정리
  • 제출 11.03(화)

💬 선생님 한마디
오늘 집중력이 정말 좋았어요.
```

- **1단계 `[ ]` 큰 구역**: 본문을 나누는 칸. 구분선(`──`)은 쓰지 않는다(지저분함). 구역 사이는 빈 줄 하나.
- **2단계 이모지**: 두 가지로만 쓴다.
  - 작은 구역 머리 `이모지 이름` — 그 줄에 이름만. 아래에 3·4단계나 자유 문장이 온다. 같은 큰 구역 안의 작은 구역 사이는 빈 줄 하나.
  - 한 줄 항목 `이모지 라벨  값` — 라벨 뒤 공백 두 칸. 콜론(`:`)을 쓰지 않는다. 라벨은 짧게(학생·클래스·수업일·출결·기간·합계).
  - 이모지만 있고 이름이 없는 줄은 만들지 않는다.
- **3단계 `#` 묶음**: 같은 작은 구역에 교재(주제)가 여럿 나올 수 있는 곳(과제·학습·평가)에서 교재마다 한 줄. 묶음 사이는 빈 줄 없이 바로 잇는다. 묶을 대상이 없는 구역(루틴·수강 내역)은 바로 4단계로 간다.
- **4단계 `  •` 세부 항목**: 공백 두 칸 + `•` + 공백. 값이 붙으면 `  • 라벨  값`(두 칸). `·`·`-`·`▪`·들여쓰기 없는 `•`는 쓰지 않는다. Notion 텍스트 속성의 글머리 목록과 같은 모양이다(`_shared/noticeBlocks.ts` `BULLET`).
- **목록 안 날짜는 `11.07(토)`**(점·두 자리·요일). 같은 달 기간은 `11.09(월)~11(수)`, 달이 넘으면 `11.30(월)~12.02(수)`.
- **인사말을 넣지 않는다.** 학원 이름은 알림톡 맨 위 채널명에 보인다. 예외는 처음 연락하는 학부모에게 가는 상담 신청 접수 안내뿐이다(10/29 사용자).
- **제목은 목적이 드러나는 고정 글자를 둔다.** 변수만으로 된 제목·넓은 말머리('안내'·'일정 안내'·'가정통신문'·'공지사항')는 반려된다(10/28·29 반려 8건). 변수로 시작하는 제목은 승인된 적도 있어(주간/월간 9월판·수강료) 신청은 해 보되, 반려되면 고정 글자를 앞에 둔다.

|---|---|
| 👤 | 학생 |
| 🏛 | 클래스 |

| 🕒 | 시간(날짜와 따로 쓸 때) |
| 📌 | 일정(상담 일정 안내의 일정 이름) |
| 🔁 | 기존(보강의 원래 결석한 날) |
| ✅ | 출결·출석 |
| 🔄 | 루틴 체크(작은 구역) |
| 📋 | 과제 체크·과제 안내(작은 구역) |

| 📝 | 전달사항 구역(학원이 수업·일정 전체에 알리는 공지: 준비물·진행 여부·시간 변경) |

| 📞 | 연락처(본문), 학습문의(부가정보) |

## 2. 변수 설계

- **상황 블록 변수**: 상황에 따라 줄이 생기거나 빠지는 부분은 변수 하나에 여러 줄로 담는다(예: `#{수업정보}` = 보강이면 `🔁 기존` + `📅 일시`, 아니면 `📅 일시`만, 메모가 있으면 `📝 전달사항` 구역까지).
  - 블록에는 **늘 한 줄 이상 들어가는 내용**을 바탕에 둔다. 변수가 통째로 비면 안 된다(빈 값 발송·심사 문제). 아무것도 없을 수 있으면 기본 문구를 넣는다(예: 일일 보고서 `결석으로 이날 학습 기록이 없습니다.`).
  - 블록 안의 줄도 1장 표기(두 칸·이모지 표)를 따른다.
  - **변수 값은 공백이나 줄바꿈으로 시작하지 않는다.** 솔라피가 변수 값 맨 앞의 공백을 지운다(폭 없는 공백 U+200B까지, 10/29 실발송 확인). 그래서 목록이 든 구역은 머리줄까지 변수에 넣는다(`#{클래스정보}` = `🏛 클래스` + `  • 반`, `#{수강정보}` = `📚 수강 내역` + `  • 반  금액`). 본문에 `📚 수강 내역` 줄을 두고 다음 줄에 목록 변수를 놓으면 첫 줄 들여쓰기만 빠진다. 값이 옆에 붙는 자리(`🏛 클래스#{…}`)도 같은 이유로 쓰지 않는다.
- **고정 글자는 고정으로**: 늘 같은 라벨은 템플릿 글자로 둔다. 본문이 대부분 변수면 카카오가 반려할 수 있다.
- **자유 문장 변수**(전달사항·선생님 한마디)는 그 알림톡 내용에 관한 말만, 50자 안팎. 홍보·모집·이벤트 문구는 넣지 않는다(광고성은 문자로).
- 변수 이름은 뜻이 드러나는 한국어 명사(`학생이름`, `수업정보`). 옛 템플릿에 같은 이름이 있는데 값 모양이 다르면 **새 이름**을 쓴다(예: 옛 `보고서요약` → 새 `학습현황`). 서버가 두 템플릿을 함께 쓰는 동안 섞이지 않게 하기 위해서다.

## 3. Notion 속성

- 템플릿 변수 하나마다 그 알림톡을 보내는 페이지의 DB에 수식 속성 **`변수이름(알림톡)`**을 만든다(예: `#{학생이름}` → `학생이름(알림톡)`). 계산은 이 속성 안에서 한다.
  - 한 DB가 여러 알림톡을 보내면(출석: 일일 보고서·수업 안내) 값이 같은 변수는 한 속성을 함께 쓴다.
  - 속성 설명에 `(버전 알림톡) ○○ 안내 #{변수}. 서버가 이 값을 먼저 쓴다.`처럼 쓰임새를 적는다.
  - 오른쪽 패널 '시스템' 구역에 **숨김**으로 둔다.
- **예외**
  - 보낼 때 정해지는 값(리포트 주소 `#{페이지ID}`, 키오스크 구분·일자·시간)은 속성이 없다.
  - 날짜·시각이 든 변수는 속성을 만들되 **미리보기용**이다. Notion API는 수식 안의 날짜를 UTC로 계산해 시각이 9시간 어긋나므로, 서버가 서울 시각으로 직접 만든다. 이 사실을 속성 설명에 적는다.
- **미리보기 수식**(`○○ 미리보기`): 실제 템플릿 제목·본문을 그대로 옮기고 `#{변수}` 자리에 `(알림톡)` 속성만 넣는다. 미리보기 안에서 lets·map·filter 같은 계산을 하지 않는다. 학생마다 바뀌는 자리는 `(학생이름)`처럼 적는다.
- 수식에서 `and`로 이은 조건은 앞이 거짓이어도 뒤까지 계산된다. 비어 있을 수 있는 날짜에 `dateBetween` 같은 계산을 하려면 `if`를 겹쳐 쓴다.

## 4. 서버

- 변수 값은 `alimtalkVar(page, 이름, 계산값, 옛 이름)`으로 읽는다: `이름(알림톡)` → 옛 이름 → 서버 계산(`_shared/noticeBlocks.ts`). 상황 블록 조립 함수도 이 파일에 둔다.
- 템플릿을 바꾸는 동안에는 옛 템플릿 변수와 새 템플릿 변수를 **함께** 만든다. 보내기 직전 `fitVariablesToTemplate`(`_shared/templateFit.ts`)가 그 템플릿의 본문·제목·버튼에 실제로 적힌 `#{…}`만 남긴다. 솔라피의 변수 칸은 사본에 옛 값이 남아 있어 보지 않는다. 그래서 알림톡 설정 행의 템플릿 ID만 바꾸면 전환된다.
- 설정 행이 꺼졌거나 템플릿 ID·채널이 비면 보내지 않고 사유를 남긴다(다른 템플릿으로 잘못 나가지 않게).
- 새 블록 함수에는 `noticeBlocks_test.ts`처럼 상황별 테스트를 붙인다(줄이 생기는 경우·빠지는 경우·비는 경우).

## 5. 솔라피 신청

1. 같은 종류의 **이미 승인된 템플릿을 사본**으로 만든다. 유형·보조문구·부가정보·버튼·카테고리(리포팅 > 피드백)·대체발송(안 함) 설정을 그대로 가져오기 위해서다. 이름·제목·본문·검수 참고 의견만 바꾼다. 이름은 `○○ v버전 (설명)`.
2. 본문은 알림톡 설정 행의 템플릿 콜아웃을 줄바꿈·빈 줄·두 칸까지 그대로 옮긴다.
3. **검수자 참고 의견**(500자 안)에 다음을 쓴다.
   - 누구에게 무엇을 알리는 정보성 메시지인지(예: "수강 중인 학생의 학부모에게 … 수강 계약 이행 관련 정보성 메시지")
   - 누가 어떻게 보내는지(담당자가 버튼을 눌러 그 학생·반에게만, 공지·홍보에 쓰지 않음)
   - 제목 변수에 들어가는 값 목록
   - 블록 변수가 상황별로 어떤 줄을 담는지
   - 예시 값 1~2개(블록 변수는 줄 단위로)
4. 반려되면 블록을 덜 쓰는 쪽(예: 제목 변수를 고정 글자로)으로 바꿔 다시 낸다. 대안을 설정 행에 미리 적어 둔다.
5. 템플릿 ID가 나오면 설정 행 '심사할 새 본문' 구역에 적는다. 행의 '템플릿 ID'는 승인 뒤에 바꾼다.

## 6. 알림톡 설정 행 페이지

알림톡 설정(학원) DB의 행 페이지는 이렇게 둔다.

- 2단 콜아웃: 왼쪽 **템플릿**(보조문구·제목·본문·부가정보·버튼), 오른쪽 **예시 값을 넣은 모습**.
- 아래 파란 콜아웃 **추가 설명**: 언제 나가나 / 누구에게 / 변수(블록이면 상황별 내용) / 버튼 / 고칠 때.
- 새 본문을 심사 중이면 그 아래 '심사할 새 본문' 구역(템플릿·예시, 신청 값, 참고 의견, 반려 대안, 승인 뒤 바꿀 것).
- `알림 수신 대상`(다중 선택): 우선 연락 대상·어머니·아버지·기타 보호자·학생 중 받을 사람. 비어 있으면 우선 연락 대상. 같은 번호는 한 번만, 여럿을 고르면 번호 없는 사람은 건너뛴다(하나만 고르면 없을 때 오류). 학생은 학생정보 `학생 연락처`. 원본은 수업 일정·보강·휴강 안내만 우선 연락 대상 + 학생.
- 원본 행의 학원 이름("하다 수학학원")과 학습문의 번호는 원본 값이다. 운영 학원은 자기 학원 이름·번호로 바꿔 신청하고 행에도 그렇게 적는다.

## 7. 전환과 시험

1. 승인되면 설정 행 '템플릿 ID'를 새 ID로 바꾸고, 템플릿·예시 콜아웃을 새 본문으로 바꾼다.
2. 본인 번호 학생(원본은 테스트학생)으로 한 통 보낸다. 상황 블록이 있으면 상황마다 한 통씩(예: 보강/정규, 메모 있음/없음).
3. 받은 카톡을 템플릿 원문과 `○○ 미리보기`에 대조하고, 서버 로그(대상 수·설정 조회)를 확인한다.
4. 결과를 "원문 비교 완료 / 목록만 확인 / 미검증 / 보류"로 나눠 패치 기록에 남긴다.

## 8. 새 알림톡 체크리스트

- [ ] 본문 틀·인사말 없음·두 칸·이모지 표를 지켰다
- [ ] 상황 블록 변수는 늘 한 줄 이상이 들어간다(빈 경우 기본 문구)
- [ ] 옛 템플릿과 이름이 같은데 값 모양이 다른 변수가 없다
- [ ] 변수마다 `변수이름(알림톡)` 속성(날짜는 미리보기용 표시)과 미리보기 수식이 있다
- [ ] 서버는 `alimtalkVar`로 읽고, 블록 함수에 테스트가 있다
- [ ] 승인 템플릿 사본으로 신청했고 참고 의견에 제목 값 목록·블록 설명·예시가 있다
- [ ] 설정 행 페이지(2단 콜아웃·추가 설명)를 맞췄다
- [ ] 본인 번호 시험 발송을 상황별로 하고 원문 대조했다

- **비었을 때**: 구역 변수가 비면 기본 문구를 넣는다(일일 `확인한 과제·루틴이 없습니다.` / `이날 학습 기록이 없습니다.`(결석이면 `결석으로 …`) / `오늘은 평가와 새 과제가 없습니다.`, 주간·월간 `이 기간 학습 기록이 없습니다.`, 수료 `이 과정을 모두 마쳤습니다.`, 전달사항·월간 목록 `없음`).
- **날짜가 든 변수**(등원정보·수업일정·일정내역·월간 목록·시간표정보)는 서버가 서울 시각으로 만든다. 나머지는 각 DB의 `변수(알림톡)` 수식을 서버가 그대로 읽는다.
- **목록 첫 줄 들여쓰기**: 솔라피가 변수 맨 앞 공백을 지운다. 그래서 목록 변수 앞의 `  • `는 템플릿 글자로 두고, 변수 첫 줄은 점 없이 쓴다(월간 목록). 변수를 이모지·`#`·글자로 시작하게 만드는 것도 같은 이유다.
- **일일 1,000자**: 넘으면 서버가 세부(`  •`) 줄을 학습기록 → 학습준비 → 학습결과 순으로 빼고 "자세한 내용은 아래 버튼에서 확인해 주세요."를 붙인다(이모지는 2자로 센다).
- **템플릿 고르기**: 서버가 설정 행을 고르고, 그 행이 없거나 꺼져 있으면 옛 행으로 넘어간다(예체능 → 교과, 보강·휴강·정규 → `수업 안내`, 상담 → `일정 안내`, 주간·월간 → `보고서`). 수료 보고서는 넘어갈 옛 행이 없어 행이 없으면 보내지 않는다.

**반려 경험(10/28~29, 8건)**: 변수로 시작하는 제목(`#{구분} 안내`, `#{안내월} 가정통신문`), 넓은 말머리(`안내`, `일정 안내`, `월간 학원 일정 안내`, `학원 일정 변경 안내`), 본문 대부분이 변수 하나(고정값 부족). 검수자는 "목적별로 템플릿을 분리"하라고 했다. 그래서 위 템플릿은 제목에 목적을 고정 글자로 두고, 구역 머리(`[ ]`)와 라벨을 고정 글자로 늘렸다. 새 템플릿은 하다 알림톡 미리보기 도구의 심사 진단으로 먼저 확인한다.
