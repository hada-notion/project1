# Notion 버튼·자동화·상태 속성 이름 규칙

원본과 운영이 같은 이름으로 말하기 위한 규칙이다. "수업 DB `[웹훅] 출석 조정` 자동화를 고쳐 주세요"라고 하면 어느 워크스페이스에서든 같은 것을 가리킨다. 새로 만들거나 고칠 때는 이 규칙을 따르고, 이 문서에 없는 이름이 필요하면 먼저 이 문서에 더한다.

## 1. 규칙

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 버튼 | `대상 + 동작`, 띄어 쓴다. 동작 낱말: 생성·추가·전송·조정·담기·등록·입력·설정·동기화·처리·가져오기·재발급·삭제. 알림톡을 보내는 버튼은 모두 **전송** | [안내문 전송], [수업 추가] |
| 상태 속성 | `버튼 이름 + " 상태"`. 시작 시각은 `버튼 이름 + " 시작 시각"`. 버튼이 다른 DB에 있으면 그 버튼 이름을 쓴다 | [출석 조정] → `출석 조정 상태` |
| 상태 선택지 | ⚪ 대기 / ⏳ 대기열 / 🔄 작업중 / ✅ 완료 / ⚠️ 오류 / ⏱️ 타임아웃 복구 중 필요한 것만, 이 글자 그대로 | |
| 자동화 | `[방식] 기능`. 방식 = **웹훅**(서버 함수를 부름) · **생성**(다른 DB에 페이지를 추가) · **편집**(속성 값만 바꿈). 같은 기능의 자동화가 둘 이상이면 뒤에 ` · 트리거`를 붙인다 | `[웹훅] 출석 조정`, `[웹훅] 대시보드 연결 · 페이지 추가` |
| 계획 수식 | `기능 + " 계획"` 또는 `기능 + " 정보"`(서버가 본문에서 읽는 JSON 수식) | `학습기록 계획`, `수업 추가 정보` |
| 웹훅 주소 | 함수 이름과 경로(`/queue` 등)는 바꾸지 않는다(운영 버튼이 지금 주소를 쓴다). 새로 만들 때만 `함수/queue` 형식 | |

- 자동화 이름에 DB 이름은 넣지 않는다(자동화 목록이 DB마다 따로 있다). 말할 때는 "수업 DB `[웹훅] 출석 조정`"처럼 DB를 앞에 붙인다.
- 상태 속성 이름은 서버가 읽고 쓴다. 서버 코드는 표준 이름을 쓰고, 예전 이름만 있는 운영도 자동으로 알아본다(`_shared/notionClient.ts`의 `PROP_ALIASES`). 그래도 운영은 v2.7.3에서 표준 이름으로 맞춘다.

- 이 표에 없는 이름 붙이기 자동화도 `[편집] ○○ 이름`으로 맞춘다(예: 보고서 `[편집] 보고서 이름`).
- `[웹훅] 삭제`의 본문(콘텐츠)은 `삭제 상태` 하나, `[웹훅] 리포트 반영`은 제목 하나만 체크한다. 본문을 모두 비우면 Notion이 "유효하지 않음"으로 표시한다. 출석·보고서·수강료·교재비 전송 자동화의 본문은 `실행자`.
- `[웹훅]` 자동화에는 헤더 `x-admin-key`(웹훅 키)가 있어야 한다. 없으면 서버가 401로 거절해 버튼이 실패한다(원본 교재배부 `[웹훅] 삭제`에서 빠져 있던 적이 있다). 예외는 라이브러리·일정 `[웹훅] 리포트 반영`으로, 키 없이도 받는 경로라 있어도 없어도 된다.
- 라이브러리 `[웹훅] 리포트 반영 · 속성 편집`은 트리거를 전체 "속성 편집"으로 둔다(파일 속성 `북커버`는 트리거 조건으로 고를 수 없다).
- 자동화 목록은 Notion API로 읽을 수 없다. 운영 AI는 운영자에게 DB별 자동화 화면 캡처를 받아 이 표와 대조한다.

## 5. 실시간 처리 상태 수식

각 DB의 `실시간 처리 상태`는 같은 순서로 보여 준다: 타임아웃 복구 → `마지막 오류` → 상태 ⚠️ 오류 → "🔄 ○○ 중" → "⏳ ○○ 대기". ○○에는 2장의 버튼 이름을 쓴다. 수식 원문은 `docs/updates/v2.7-노션-작업.md` N-34.

| 예전 방식 정리 때 지움 | 클래스 | `교재 생성 상태`, `교재비 생성 상태`, `보고서 생성 상태`, `수강료 생성 상태`와 각 처리 시작 시각 | 예전 웹훅만 씀(새 방식은 등록 DB의 같은 이름 상태를 씀) |
| 예전 방식 정리 때 지움 | 수업 | `보고서 일괄전송 상태`와 시작 시각 | 예전 일괄 전송 함수만 씀 |
| 예전 방식 정리 때 지움 | 시간표 | `상태`, `처리 시작 시각` | 예전 [수업추가] 웹훅만 씀 |
| 예전 방식 정리 때 지움 | 시험정보 | `상태`, `처리 시작 시각`, `마지막 동기화` | 예전 응시학생 등록 웹훅만 씀 |
| 예전 방식 정리 때 지움 | 보고서·수강료 / 교재비 / 출석 | `발송중` / `안내문 발송중` / `보고서 전송중` | 예전 발송 웹훅만 씀 |

"예전 방식 정리"는 모든 운영이 v2.7.3을 마친 뒤 예전 함수 경로, 관리자 체크리스트의 "(예전 방식)" 항목, 상태 감시(워치독) 목록과 함께 한 번에 한다. 그 전에 지우면 예전 버튼을 눌렀을 때 서버가 없는 속성에 쓰다 오류가 난다.

## 7. 페이지 탭 (탭 구조 레이아웃)

- 첫 탭(그 페이지 자신의 내용)은 `○○ 정보`(띄어 씀), 아이콘은 그 DB의 아이콘과 같다. "콘텐츠"·ⓘ는 쓰지 않는다.
- 나머지 탭의 아이콘은 그 탭이 보여 주는 DB의 아이콘을 쓴다. 같은 DB를 나눠 보여 주는 탭은 내용으로 구분한다: 학습활동 전체 💼, 이번과제(과제) 📋, 과제검사 ☑, 평가결과(평가) 📄.
- 같은 내용은 DB가 달라도 같은 이름·아이콘·순서를 쓴다. 수업과 출석의 공통 탭은 진도교재 → 학습기록 → 과제검사 → 이번과제 → 평가결과.
- 레이아웃은 DB 단위다. 레이아웃 편집에서 "모든 페이지에 적용"으로 저장하면 기존 페이지에도 바로 반영된다. Notion API로는 바꿀 수 없어 화면에서 고친다.

| DB | 첫 탭 · 아이콘 | 나머지 탭 |
| --- | --- | --- |
| 수업 | 수업 정보 · `drafts` | 출석, 진도교재, 학습기록 ✏, 과제검사, 학습활동 💼, 이번과제, 평가결과 |
| 출석 | 출석 정보 · `following` | 진도교재, 학습기록, 과제검사, 이번과제, 평가결과 (학습기록·이번과제·평가결과는 갤러리) |
| 등록 | 수강 정보 · `push-pin` | 대시보드, 시간표, 진도교재, 캘린더, 수업, 과제, 평가, 보고서, 수강료, 교재비 |
| 학생 | 학생 정보 · 사람 | 일정, 등록, 자료, 성적 |
| 클래스 | 클래스 정보 · `bank` | 등록 학생, 시간표, 진도교재, 수업, 일정 |
| 학습기록 | 학습기록 정보 · ✏ | 학습 💼, 과제, 평가 |
| 진도교재 | 교재 정보 · `book` | 학습기록 ✏, 개별교재 |
| 보고서 | 보고서 정보 · 막대 차트 | 대시보드, 학습기록, 과제, 평가 |
| 라이브러리 | 교재 정보 · `book-closed` | 단원목록 |
| 학교 | 학교 정보 · `school` | 학생, 학사일정, 시험범위 |
| 시험정보 | 시험 정보 · `bookmark` | 시험범위, 학생성적 |
| 교재비 | 교재비 정보 · `cash` | 교재배부, 교재결제 |
| 교재배부 | 교재배부 정보 · `package` | 교재결제 |
| 알림톡 발송함 | 발송함 정보 · 봉투 | 수강료, 보고서 |
| 대시보드 | 대시보드 정보 · `window` | 수업, 출석, 일정 |

- 학습활동·수강료·시간표·성적·일정은 탭 구조를 쓰지 않는다.
- 아직 맞추지 않은 것: 등록·학습기록·보고서의 "과제·평가"와 수업·출석의 "이번과제·평가결과" 이름 통일, 학교·시험정보 "시험범위" 탭 이름(관계 이름은 `시험정보`), 교재비·교재배부의 교재배부·교재결제 탭 아이콘(표 아이콘).
