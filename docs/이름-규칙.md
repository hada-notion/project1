# Notion 버튼·자동화·상태 속성 이름 규칙

원본과 운영이 같은 이름으로 말하기 위한 규칙이다. "수업 DB `[웹훅] 출석 조정` 자동화를 고쳐 주세요"라고 하면 어느 워크스페이스에서든 같은 것을 가리킨다. 새로 만들거나 고칠 때는 이 규칙을 따르고, 이 문서에 없는 이름이 필요하면 먼저 이 문서에 더한다.

## 1. 규칙

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 버튼 | `대상 + 동작`, 띄어 쓴다. 동작 낱말: 생성·추가·전송·조정·담기·등록·입력·설정·동기화·처리·가져오기·재발급·삭제. 알림톡을 보내는 버튼은 모두 **전송** | [안내문 전송], [수업 추가] |
| 상태 속성 | `버튼 이름 + " 상태"`. 시작 시각은 `버튼 이름 + " 시작 시각"`. 버튼이 다른 DB에 있으면 그 버튼 이름을 쓴다 | [출석 조정] → `출석 조정 상태` |
| 상태 선택지 | ⚪ 대기 / ⏳ 대기열 / 🔄 작업중 / ✅ 완료 / ⚠️ 오류 / ⏱️ 타임아웃 복구 중 필요한 것만, 이 글자 그대로 | |
| 자동화 | `[방식] 기능`. 방식 = **웹훅**(서버 함수를 부름) · **생성**(다른 DB에 페이지를 추가) · **편집**(속성 값만 바꿈). 같은 기능의 자동화가 둘 이상이면 뒤에 ` · 트리거`를 붙인다 | `[웹훅] 출석 조정`, `[웹훅] 대시보드 연결 · 페이지 추가` |
| 계획 수식 | `기능 + " 계획"` 또는 `기능 + " 정보"`(서버가 본문에서 읽는 JSON 수식) | `학습기록 계획`, `수업 추가 정보` |
| 웹훅 주소 | 함수 이름과 경로(`/queue` 등)는 바꾸지 않는다(운영 버튼이 지금 주소를 쓴다). 새로 만들 때만 `함수/queue` 형식 | |

- 자동화 이름에 DB 이름은 넣지 않는다(자동화 목록이 DB마다 따로 있다). 말할 때는 "수업 DB `[웹훅] 출석 조정`"처럼 DB를 앞에 붙인다.
- 상태 속성 이름은 서버가 읽고 쓴다. 서버 코드는 표준 이름을 쓰고, 예전 이름만 있는 운영도 자동으로 알아본다(`_shared/notionClient.ts`의 `PROP_ALIASES`). 그래도 운영은 v2.7.3에서 표준 이름으로 맞춘다.

- `[웹훅] 삭제`의 본문(콘텐츠)은 `삭제 상태` 하나, `[웹훅] 리포트 반영`은 제목 하나만 체크한다. 본문을 모두 비우면 Notion이 "유효하지 않음"으로 표시한다. 출석·보고서·수강료·교재비 전송 자동화의 본문은 `실행자`.
- `[웹훅]` 자동화에는 헤더 `x-admin-key`(웹훅 키)가 있어야 한다. 없으면 서버가 401로 거절해 버튼이 실패한다(원본 교재배부 `[웹훅] 삭제`에서 빠져 있던 적이 있다). 예외는 라이브러리·일정 `[웹훅] 리포트 반영`으로, 키 없이도 받는 경로라 있어도 없어도 된다.
- 라이브러리 `[웹훅] 리포트 반영 · 속성 편집`은 트리거를 전체 "속성 편집"으로 둔다(파일 속성 `북커버`는 트리거 조건으로 고를 수 없다).
- 자동화 목록은 커넥터로 읽을 수 없다. [스캔 도구](기준/적용-절차.md#4-스캔과-비교)로 읽어 비교한다.

## 5. 실시간 처리 상태 수식

각 DB의 `실시간 처리 상태`는 같은 순서로 보여 준다: 타임아웃 복구 → `마지막 오류` → 상태 ⚠️ 오류 → "🔄 ○○ 중" → "⏳ ○○ 대기". ○○에는 2장의 버튼 이름을 쓴다. 수식 원문은 `docs/updates/v2.7-노션-작업.md` N-34.

## 5-1. 알림톡 변수 수식과 미리보기

알림톡을 보내는 DB(보고서·수강료·가정통신문 등)는 이 모양을 지킨다.

- 템플릿 변수 하나마다 수식 속성을 하나씩 만든다. 이름은 `변수이름(용도)` 형식으로 쓴다. 예: `학생이름(수강료안내)`, `학원일정(일정안내)`. 계산은 모두 이 변수 속성 안에서 한다.
- 미리보기 수식은 실제 템플릿 본문을 그대로 옮기고, `#{변수}` 자리에 변수 속성만 넣는다. 예: `"👤 학생 " + prop("학생이름(수강료안내)") + "\n..."`. 미리보기 안에서 lets·map·filter 같은 계산을 하지 않는다.
- 서버는 변수 속성 값을 먼저 쓰고, 비어 있으면 같은 규칙으로 계산한다. 템플릿 본문이 바뀌면 미리보기의 고정 글자만 고친다.

## 6. 더 쓰지 않는 상태 속성

| 시점 | DB | 속성 | 이유 |
| --- | --- | --- | --- |
| v2.7.3에서 지움 | 등록 | `시간표 상태`, `시간표 처리 시작 시각` | 시간표 설정이 Notion만으로 바뀐 뒤 어디서도 쓰지 않음(N-34로 등록 수식을 먼저 바꾼 뒤) |
| 예전 방식 정리 때 지움 | 등록 | `등록 상태`, `종료 상태`, `수업 상태`와 각 처리 시작 시각 | 예전 웹훅(등록·종료 처리·수업 생성)만 씀 |
| 예전 방식 정리 때 지움 | 클래스 | `교재 생성 상태`, `교재비 생성 상태`, `보고서 생성 상태`, `수강료 생성 상태`와 각 처리 시작 시각 | 예전 웹훅만 씀(새 방식은 등록 DB의 같은 이름 상태를 씀) |
| 예전 방식 정리 때 지움 | 수업 | `보고서 일괄전송 상태`와 시작 시각 | 예전 일괄 전송 함수만 씀 |
| 예전 방식 정리 때 지움 | 시간표 | `상태`, `처리 시작 시각` | 예전 [수업추가] 웹훅만 씀 |
| 예전 방식 정리 때 지움 | 시험정보 | `상태`, `처리 시작 시각`, `마지막 동기화` | 예전 응시학생 등록 웹훅만 씀 |
| 예전 방식 정리 때 지움 | 보고서·수강료 / 교재비 / 출석 | `발송중` / `안내문 발송중` / `보고서 전송중` | 예전 발송 웹훅만 씀 |

"예전 방식 정리"는 모든 운영이 v2.7.3을 마친 뒤 예전 함수 경로, 관리자 체크리스트의 "(예전 방식)" 항목, 상태 감시(워치독) 목록과 함께 한 번에 한다. 그 전에 지우면 예전 버튼을 눌렀을 때 서버가 없는 속성에 쓰다 오류가 난다.

## 7. 페이지 레이아웃 (헤더·탭·세부 정보 패널)

레이아웃은 DB 단위다. 헤더 고정 속성·패널 섹션과 표시 방식·첫 탭 내용은 커넥터(`page_layout`)로 바꿀 수 있고, 페이지 탭(연결 보기)은 화면의 레이아웃 편집에서 고친다. 화면에서 "모든 페이지에 적용"으로 저장하면 기존 페이지에도 바로 반영된다. 페이지가 열리지 않는 DB는 DB 보기 설정 → 추가 설정 → "페이지 레이아웃 사용자 지정"으로 편집기를 연다.

### 원칙

1. **헤더(제목 아래 고정 속성)** = 핵심 정보 → 그 페이지에서 누를 버튼(업무 순서, [삭제]는 버튼 맨 끝) → `발송 횟수` → `실시간 처리 상태`(맨 끝). 그 페이지에서 할 일은 헤더에서 다 누른다.
2. **첫 탭 `○○ 정보`** = 사람이 읽고 쓰는 내용(미리보기·메모·선생님 한마디·현황 수식, 버튼 누르기 전에 고르고 확인하는 값). 그다음 댓글, 본문.
3. **세부 정보 패널** = 속성 묶음을 섹션으로 나눈다. 보통 `[참조 섹션]` → `처리 기록` → `시스템` 순서.
   - 입력·설정값(연락처, 청구 설정 등): **항상 표시**, 자주 비는 것은 **비어 있으면 숨김**
   - `처리 기록`: [오류 지우기]는 항상 표시, `마지막 오류`·`마지막 동기화`·`실행자`·`전송 내역`·`종료 상태`는 비어 있으면 숨김
   - `시스템`: 상태 속성·시작 시각·계획 수식·롤업 표시용·관계·토큰·`발송중`·`일괄전송 선택`·`삭제 체크` 등은 **항상 숨김**. 값이 늘 차 있는 내부 속성(`동기화 필요`, `생성 일시`, `담기 계획` 같은 JSON 수식)을 "비어 있으면 숨김"으로 두면 늘 보이므로 항상 숨김으로 한다.
   - 버튼은 늘 "비어 있음"으로 취급돼 "비어 있으면 숨김"이면 보이지 않는다. 패널에 두는 버튼은 **항상 표시**로 하고, 가능하면 헤더에 고정한다.
   - 사람이 적는 값(`청구금액 조정 사유`, `접수안내 마지막 오류`, `문의 경로` 등)을 "항상 숨김"으로 두지 않는다. 값이 있어도 안 보인다.
4. **학습활동 탭은 하나로**: 한 페이지에서 학습활동 DB를 여러 탭(과제·평가·이번과제·평가결과·학습활동)으로 나누지 않는다. `학습활동` 탭 하나를 **대시보드**로 두고 표 세 칸 `과제` / `평가` / `학습`을 위에서부터 한 줄씩 놓는다. "이 페이지" 조건(`수업`·`출석`·`등록`·`보고서`에 이 페이지 포함)은 **대시보드 공통 필터**에 한 번만 두고, 칸마다 빠른 필터 `구분` = 과제 / 평가 / 학습 하나씩만 건다. 칸마다 필요한 열만 보인다(과제: 과제 마감일·과제상태, 수업·출석은 `과제 마감`도 / 평가: 전체 문항·정답 문항·오답 문항·점수 / 학습: 내용까지). 날짜로 모아 보는 등록·보고서는 `수업일`을 `교재` 앞에 둔다. 그래서 `점수`는 문항 수가 없으면 비우는 조건 없이 `정답 문항 / 전체 문항 * 100`이다. 대상은 수업·출석·등록·보고서. 칸별 열·정렬은 [노션-레이아웃.md](기준/노션-레이아웃.md). 예외: 수업·출석의 `과제검사`(오늘 마감인 과제를 체크하는 표)는 목적이 달라 따로 둔다.
5. **진도교재 탭은 수업·등록에만**: `오늘 학습` 체크와 [학습기록 생성]은 수업 페이지에서 한다(수업 `진도교재`에 명단 학생의 진도교재가 그룹·개별 모두 들어온다). 출석 페이지에는 진도교재 탭을 두지 않는다. 그룹 진도교재는 반 전체가 한 권을 쓰므로 학생 한 명의 출석에서 `오늘 학습`을 체크하면 반 전체 교재가 체크된다. 그날 한 내용은 출석의 `학습기록` 탭에서 본다.
6. 탭 아이콘은 그 탭이 보여 주는 DB의 아이콘을 쓴다. 첫 탭 아이콘은 그 DB의 아이콘. "콘텐츠"·ⓘ는 쓰지 않는다.

### DB별 최종 형태

DB마다의 최종 모양(상단 고정 속성, 콘텐츠 탭에 놓는 속성과 나머지 탭의 조건, 세부 정보 패널의 섹션별 속성과 표시 방식)은 [노션-레이아웃.md](기준/노션-레이아웃.md)에 있다. 원본 스캔에서 자동으로 만든 문서라 손으로 고치지 않는다. 학원은 [적용 절차](기준/적용-절차.md)대로 스캔·비교해 맞춘다. 탭 필터는 보기 위 '빠른 필터'(칩)까지 조건이다. 같은 조건을 두 번 넣지 않는다.

### DB 보기

- 기본 보기(첫 보기)에는 DB 이름을 붙인다(`수업`, `수강 정보`, `출석`, `학습기록`, `학습활동`, `보고서`, `교재배부`, `교재결제`, `시간표`, `시험정보`, `학교`, `일정`). 이름 없는 보기·`표`를 두지 않는다.
- 기본 보기 열은 사람이 보는 값과 `실시간 처리 상태`만 둔다. 상태·시작 시각·계획 수식·토큰·`삭제 체크`·`일괄전송 선택`·`(내부)` 롤업은 뺀다.
- 버튼 웹훅을 거는 보기 이름은 `웹훅 등록`(띄어 씀). 열은 그 DB의 버튼과 `실시간 처리 상태`. 관리자 설정 웹훅 체크리스트는 띄어쓰기를 무시하고 이 이름을 찾는다.
- 보기 이름·열·정렬은 커넥터(`update-view`)로 바꿀 수 있어 운영 AI가 직접 한다. 보기 삭제와 페이지 탭(연결 보기)은 화면에서 한다.

### 화면 메모

- 탭 필터에 같은 "관계 포함 이 페이지" 규칙이 두 번 들어간 경우가 있었다. 고칠 때 중복 규칙을 지운다.
- 시험정보 페이지의 "시험범위" 탭은 그 시험의 출제 범위라 이름이 맞다. 학교 페이지에서 시험정보 DB를 보여 주는 탭은 "시험정보".
- 버튼에 보이는 글자는 버튼 속성 이름과 따로 저장된다. 버튼 이름을 바꾸면 속성 메뉴 → 자동화 편집 → 맨 위 이름도 같이 바꾼다(원본에서 수강료 [안내문 전송], 학생 [접수안내 전송]이 예전 글자로 남아 있었다).
