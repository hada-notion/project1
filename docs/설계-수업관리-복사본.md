# 수업 관리 Supabase 복사본 — 현재 구조

- 목적: 수업 관리 화면이 Notion을 직접 읽어 생기는 대기(동작마다 1~4초)를 Supabase 복사본 읽기로 줄인다.
- 상태: 원본 구현 완료. 학원 적용은 [v2.6.5](updates/v2.6.5.md). 읽는 곳은 함수 설정값 `CLASS_ROOM_SOURCE`가 정한다(5장).
- 대상: 수업·출석·학습기록·학습활동 4개 DB. 교재·등록·원생과 학부모 리포트 경로는 그대로 Notion·기존 캐시를 쓴다.
- 화면이 부르는 동작 목록: [화면-데이터-목록](화면-데이터-목록.md). 기록 카드 본문은 펼칠 때만 `record-body`로 읽는다.

## 1. 복사본 테이블 — 학부모 리포트와 분리

이미 `attendance_records`(출석 원자료)가 있지만 **새 테이블을 따로 만든다.**

- 이유: `attendance_records`는 학부모 리포트용이고, v2.5.13부터 "정리되지 않은 중간 상태를 학부모에게 자동으로 내보내지 않는다"는 원칙으로 정기 동기화를 끈 상태다. 수업 관리는 선생님용이라 자주(수 분 단위) 맞춰야 한다. 같은 테이블을 쓰면 두 원칙이 부딪힌다.
- 비용: 출석 데이터가 두 군데 저장된다(학원 규모에서 수천~수만 행, 용량 문제 없음).

| 테이블 | 열(화면에 쓰는 것만) |
| --- | --- |
| `cr_sessions` | `id`, `class_id`, `teacher_ids[]`, `starts_at`, `ends_at`, `is_makeup`, `name`, `attendance_ids[]`, `record_ids[]`, `notion_edited_at`, `synced_at` |
| `cr_attendance` | `id`, `session_id`, `registration_id`, `student_name`, `status`, `arrived_at`, `left_at`, `memo`, `comment`, `class_at`, `notion_edited_at`, `synced_at` |
| `cr_records` | `id`, `session_ids[]`, `kind`(학습·과제·평가), `title`, `topic`, `range`, `content`, `unit`, `book_id`, `progress_book_id`, `is_makeup`, `registration_ids[]`, `activity_status`, `has_body`, `notion_edited_at`, `synced_at` |
| `cr_activities` | `id`, `record_id`, `attendance_id`, `registration_id`, `homework_status`, `due_on`, `correct`, `total`, `notion_edited_at`, `synced_at` |

- 색인: `cr_sessions(class_id, starts_at)`, `cr_attendance(session_id)`, `cr_records using gin(session_ids)`, `cr_activities(record_id)`, `cr_activities(due_on)`.
- 보안: RLS 켜고 정책 없음, `anon`·`authenticated` 권한 회수 — 기존 원자료 테이블과 같다. 함수(서비스 역할)만 읽고 쓴다.
- 커서: 기존 `sync_cursors`에 `cr_sessions`·`cr_attendance`·`cr_records`·`cr_activities` 네 줄.

## 2. 맞추는 방법 (세 겹)

| 겹 | 언제 | 무엇을 |
| --- | --- | --- |
| ① 함께 쓰기(write-through) | 우리 함수가 Notion에 쓸 때 | Notion 응답(바뀐 페이지)을 그대로 복사본에 upsert. 수업 관리 저장·만들기(`class-room`), 키오스크 등원·하원(`kiosk-checkin`), 단원 입력(`fill-record-units`). 이 밖의 쓰기(수업 생성·기록 버튼·삭제 등)는 ②가 잡는다 |
| ② 증분 동기화 | 5분마다(pg_cron) + 수업 관리 ⟳ 새로고침 | DB 네 개를 `last_edited_time ≥ 커서 − 2분`으로 질의해 바뀐 것만 반영. Notion 화면에서 선생님이 직접 고친 것을 잡는다. 바뀐 것이 없으면 DB마다 질의 1회 |
| ③ 대조 | 매일 밤 1회 | 기간(앞뒤 몇 달) 전체를 Notion과 비교해 빠진 것·삭제된 것을 바로잡는다 |

- Notion에서 직접 고친 내용은 최대 5분 늦게 보일 수 있다. 수업 관리 화면에 "n분 전 동기화"를 작게 보이고, ⟳를 누르면 그 반만 바로 증분 동기화한 뒤 다시 읽는다.
- 수식·롤업 값(예: 출석의 학생 이름, 학습활동의 과제 마감일)은 Notion 응답에 계산된 값이 들어 있어 그대로 저장한다. 연결된 페이지가 바뀌어 수식만 바뀌는 경우는 ③ 대조가 잡는다.

## 3. 읽기 전환 — 스위치와 그림자 비교

- 함수 설정값 `CLASS_ROOM_SOURCE` = `notion`(기본) / `shadow`(둘 다 읽고 다르면 로그) / `copy`(복사본).
- 순서: 복사본 채우기 → `shadow`로 며칠 운영해 차이 로그 0 확인 → `copy`로 전환. 문제가 생기면 값을 `notion`으로 되돌리면 바로 원래대로.
- 쓰기는 항상 Notion이 먼저(원본). 복사본은 읽기 전용 거울이다.
- 복사본으로 읽는 동작: `day`·`days`·`classes`·`session`·`class-sessions`·`class-records`·`class-stats`(`_shared/classRoomRead.ts`). `teachers`·`roster`·`books`·`activities`·`record-body`·`student`와 모든 저장은 그대로 Notion.
- `copy`에서 복사본에 없는 수업·출석·기록이 있거나(방금 Notion에서 만든 것 등) 읽기에 실패하면 그 요청만 Notion으로 읽는다. 함수 로그 `[class-room] 복사본 없음 → Notion`.
- `copy`에서는 수업 관리 저장이 복사본을 맞춘 뒤 응답한다(화면이 저장 직후 다시 읽기 때문). 출석·학습활동 저장·기록 고치기는 Notion 수정 응답을 그대로 넣어 Notion을 다시 읽지 않는다.
- ⟳ 새로고침은 먼저 `sync-copy`(네 표의 바뀐 것만, `incremental`)를 부른다. `notion`일 때는 바로 끝난다.
- 그림자 비교 로그: `[class-room shadow] <동작> 같음` / `다름 n건: 경로 notion=… copy=…`(값 40자까지) / `순서만 다름` / `복사본 없음`. 같은 시각을 다른 형식으로 적은 값(`+09:00`↔UTC)은 같은 것으로 본다.
- Notion에서 지운 기록·학습활동은 복사본에 남으므로, 기록은 수업의 "학습기록" 관계(`record_ids`)에 있는 것만, 학습활동은 그 기록에 붙은 것만 쓴다. Notion 화면에서 지운 기록이 수업 관계에서 빠지는 것은 수업이 다시 동기화될 때(⟳·매일 밤 대조) 반영된다.

## 4. 예약 실행과 비상 실행

- 예약(pg_cron): 처음 채우기 `class-room-copy-first-fill`(3분마다, 커서가 없는 표부터 하나씩 reconcile, 다 끝나면 스스로 지움) → `class-room-copy-incremental`(5분마다, 네 표 모두 커서가 있을 때만) → `class-room-copy-reconcile-*`(한국 03:00·03:05·03:10·03:15, 표마다). 관리자 키는 Vault `sync_queue_admin_key`(관리자 보안 설정이 키를 바꿀 때 함께 바뀜)를 실행 시점에 읽는다. GitHub 시크릿은 쓰지 않는다(사용자 결정, 2026-10-14).
- 비상 실행(Supabase 대시보드 → SQL Editor, 비밀값을 다루지 않음):
  - 한 표 전체 대조: `select public.class_room_copy_call('{"mode":"reconcile","table":"cr_sessions"}'::jsonb);` (표 이름만 바꿔 하나씩)
  - 바뀐 것만: `select public.class_room_copy_call('{"mode":"incremental"}'::jsonb);`
  - 처음부터 다시 채우기: `delete from public.sync_cursors where source like 'cr\_%';` 뒤 `select cron.schedule('class-room-copy-first-fill', '*/3 * * * *', $c$ select public.class_room_copy_first_fill_step(); $c$);`
- 부담: 바뀐 것이 없으면 5분마다 Notion 질의 4회. Notion 호출 한도(연결당 초당 약 3회)를 다른 함수와 나눠 쓰므로, 느려지면 incremental 주기를 10분으로 늘린다.
