# 하다 학원관리 웹 화면 디자인 규칙

이 문서는 두 부분이다.

- **1부 웹앱 디자인 규칙**: 학부모 리포트(`student_report.html`)에서 나온 원래 기준이다. 모든 웹 화면의 기준이며, 2부와 다르면 1부를 따른다. 원문은 Notion에서 관리하던 문서를 그대로 옮겼다.
- **2부 관리 화면 공용 토큰·부품**: 관리자 설정·출결 키오스크·학교 검색·법정 서류가 1부 기준을 같은 값으로 쓰도록 만든 토큰(`assets/hada-tokens.css`), 공용 부품(`assets/hada-ui.css`), 검사(`tests/design-lint.cjs`)의 규칙이다.

카드뉴스·영상 같은 콘텐츠는 Notion "콘텐츠 디자인 기준"을 따른다. 색 팔레트는 같지만 웹앱의 페이지 바탕은 1부의 전체 캔버스(`#F7F8FA`)를 쓴다.

# 1부. 웹앱 디자인 규칙
> 🎯 학생 리포트와 출결 키오스크를 수정할 때 지켜야 하는 **현재 디자인 기준**입니다. 과거 수정 과정이나 날짜별 로그는 이 문서에 추가하지 않습니다.

## 1. 정보 노출 범위

### 학부모 화면에 표시

- 학생명과 등록 클래스
- 교재와 진도
- 출석 캘린더
- 학습기록·과제·평가
- 주간·월간 보고서와 선생님 코멘트
- 학생에게 공개 가능한 일정과 휴원 안내

### 항상 제외

- 학교 성적과 성적 이력
- 수강료·교재비·결제금액
- 다른 학생·학부모 정보
- 보호자 전체 연락처와 형제 정보
- 상담 메모와 내부 운영 메모
- Notion 페이지 ID·내부 DB URL
- 관리자 키·토큰·service role key

학교 성적은 학원 내부 운영에서만 확인합니다. 학원 수업 중 진행한 평가와 평가 차트는 계속 표시합니다.

## 2. 화면 구조

- 첫 화면은 학생명·학교/학년과 등록 클래스 선택을 간결하게 보여줍니다. 요약 정보를 첫 화면에 늘리지 않습니다.
- 등록 상세는 홈, 교재, 캘린더, 학습기록, 보고서의 다섯 영역으로 이동하고, 반을 열면 홈이 먼저 보입니다.
- 홈은 그 반의 오늘(출석·남은 과제·다음 수업), 곧 마감 과제, 교재 진도, 최근 선생님 한마디를 모아 보여줍니다. 각 항목은 해당 탭과 같은 카드 모양을 씁니다.
- 모바일에서는 하단 고정 탭바를 사용하고, 선택 탭은 배경과 글자색으로 분명하게 구분합니다.
- 데스크톱에서도 모바일과 같은 정보 순서와 정렬 기준을 유지합니다.
- 카드·달력·탭의 가로 중심선과 좌우 여백은 공통 콘텐츠 폭을 기준으로 맞춥니다.

## 4. 타이포그래피

```css
font-family: -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
```

- 제목·카드 제목·헤더 이동경로는 명확한 볼드를 사용합니다.
- 설명과 보조정보는 기본 글자보다 한 단계 옅게 표시합니다.
- 너무 작은 글자를 사용하지 않고 모바일에서 확대 없이 읽을 수 있어야 합니다.
- 숫자·날짜·상태 배지는 같은 계층에서 크기와 굵기를 통일합니다.

### 소제목 4단계 (학부모 리포트 등록 상세)

| 단계 | 쓰임 | 위치 | 아이콘 | 글자 |
| --- | --- | --- | --- | --- |
| 1 탭 제목 | 진도 교재·캘린더·학습기록·보고서 (홈은 상단 반 이름) | 맨 위, 카드 밖 | 18px | 17px 굵게, 기본색 + 12px 안내 |
| 2 섹션 제목 | 오늘·곧 마감·진도·선생님 한마디·교재 상세의 학습기록 | 카드 밖 바로 위 | 16px | 15px 굵게, 기본색 |
| 3 묶음 라벨 | 학습기록 날짜, 캘린더 선택일, 카드 안 하위 구분(지난 과제·이번 과제·이번 평가·최근 평가 추이) | 카드 밖 또는 카드 안 | 없음 | 13px 중간 굵기, 옅은색 |
| 4 카드 안 작은 라벨 | 요약 칸(남은 과제·다음 수업 등) | 카드 안 | 14px 또는 없음 | 12px 이하, 보조색 |

- 보고서 탭도 같은 규칙이다: 세션 제목(학습·과제·평가·선생님 코멘트, 주간·월간의 평가 기록·선생님 한마디)과 묶음 라벨(지난 과제·이번 과제·이번 평가·최근 평가 추이)은 박스 밖, 기록은 하나마다 개별 박스. 출석·이날 마감 과제·출석률·과제이행률 같은 요약 카드만 카드 제목(`.donut-title`)을 카드 안에 같은 크기로 가운데 정렬한다.
- 일간 보고서 세션 순서: 출석 / 이날 마감 과제 → 학습 → 과제(지난 과제 · 이번 과제) → 평가(이번 평가 · 최근 평가 추이) → 선생님 코멘트. 기록 박스 머리는 "교재 · 범위" 제목과 단원·날짜만(표지·분류 아이콘 없음). 이번 과제는 출제일 기준, 지난 과제·이날 마감 과제는 마감일 기준이다.
- 기록 박스(보고서·학습기록 탭·교재 상세 공통): 흰 머리 + 박스 아래 끝까지 차는 베이지 본문. 본문은 "라벨 → 내용"을 한 덩어리로 보고, 선은 기록 쪽(수업 자료·출제 내용·평가 문항)과 활동 쪽(학습 결과·제출 내용·풀이·답안) 사이에만 하나 둔다(첫 선 없음). 학습기록 탭·교재 상세는 본문을 접어 두고, 보고서는 늘 펼쳐 둔다.

## 5. 상세 헤더

- 접힌 헤더 높이는 `56px`을 기준으로 합니다.
- 헤더 내부는 높이의 정중앙에 수직 정렬합니다.
- 뒤로가기와 메뉴·새로고침 버튼은 `44×44px` 클릭 영역 안에 `20×20px` 선형 아이콘을 사용합니다.
- 아이콘 배경과 그림자는 사용하지 않고 투명하게 둡니다.
- 뒤로가기는 왼쪽, 메뉴·새로고침은 오른쪽에 대칭 배치합니다.
- 이동경로는 학생명·클래스명·페이지명을 **이모지 없이 텍스트로만** 표시합니다.
- 이동경로 전체를 동일한 볼드 굵기로 표시하며 마지막 항목만 일반 글자로 바꾸지 않습니다.
- 헤더 안 콘텐츠는 세로 중앙에 맞추고 화면 이동 시 위로 밀려 보이지 않도록 합니다.

## 6. 정렬과 간격

- 한 화면 안의 제목, 탭, 카드, 달력은 같은 좌우 기준선을 사용합니다.
- 등록 상세의 모든 탭(홈·교재·캘린더·학습기록·보고서)과 교재 상세는 본문 폭 `--feed-w`(640px) 하나를 씁니다. 제목·안내 문구·전환 탭·카드·캘린더가 모두 이 폭 안에서 같은 왼쪽 선에 맞춥니다. 캘린더는 폭을 줄이지 않고 화면 높이에 맞춰 칸 높이만 줄입니다.
- 폭을 맞춰야 하는 요소는 서로 다른 px 값을 쓰지 말고 같은 CSS 변수와 `max-width` 공식을 공유합니다.
- 섹션 제목과 첫 카드 사이, 카드와 카드 사이 간격을 화면별로 임의 변경하지 않습니다.
- 빈 상태 문구는 해당 카드나 목록의 중앙에 표시합니다.
- 하단 탭바와 겹치지 않도록 본문 마지막에 안전 여백을 둡니다.
- 새로고침은 떠 있는 버튼으로 두지 않습니다(카드를 가림). 모든 화면에서 오른쪽 위 44×44px 아이콘으로 둡니다: 첫 화면은 메뉴(≡) 왼쪽, 반·교재 상세는 접힌 헤더 오른쪽 끝.

## 7. 캘린더

- 일정과 출결 캘린더는 같은 폭·셀 크기·요일 헤더 구조를 공유합니다.
- 기간 제목은 좌우 버튼 폭이 같은 3열 구조로 화면 정중앙에 둡니다.
- 날짜 셀의 크기와 간격은 가로·세로 중 더 좁은 화면에 맞춰 줄어들어야 합니다.
- 출결 달력은 일정 달력과 같이 월요일부터 시작합니다.
- 날짜를 탭하면 달력을 그 주 한 줄로 접고, 아래에 그날의 학습·과제·평가 카드를 보여줍니다. 같은 날짜를 다시 누르거나 [월 전체 보기]로 돌아갑니다.
- 수업이 있었던 날만 상태 배경색을 칠하고, 나머지 날짜는 숫자만 둡니다. 지난 수업은 실제 출석 행만 기준으로 하고(시간표만으로 칠하지 않음), 출석 행은 있는데 출결 상태가 비어 있으면 연한 빗금(출결 미입력)으로 표시합니다. 앞으로 남은 수업일은 시간표 기준(휴원 제외)으로 베이지 테두리를 둡니다.
- 오늘은 빨간 테두리로 표시해 예정일(베이지 테두리)·선택일(갈색 테두리)과 구분합니다.
- 과제 현황은 과제 마감일 기준입니다. 마감일 칸을 제출(초록)·일부(노랑)·미제출(빨강)로 칠하고, 아직 마감 전인 과제의 마감일만 테두리로 표시합니다. 막대는 그달 마감 과제 수만큼 칸을 나눕니다.
- 출결 상태는 배경색으로 구분합니다.
    - 출석: 연한 초록 / 초록 글자
    - 결석: 연한 빨강 / 빨강 글자
    - 보강: 연한 파랑 / 파랑 글자
- 달력 위에는 그달 수업 횟수만큼 칸을 나눈 막대를 둡니다. 지난 수업 칸부터 상태 중간 톤(`--bar-*`)으로 채우고 남은 수업은 빈 칸으로 둡니다. 숫자는 퍼센트 대신 `지난 수업 / 전체 수업`(예: `3 / 8회`)으로 씁니다. 첫 수업 하나로 100%가 되는 표시는 쓰지 않습니다.
- 선택일·오늘·기록일의 테두리와 배경 역할이 서로 겹치지 않게 합니다.
- 주간은 최대 26주 전, 월간은 최대 6개월 전까지 이동하도록 제한하고, 한계에 도달한 버튼은 시각적으로 비활성화합니다.

## 8. 카드와 상태 표시

- 카드 모서리·그림자·테두리는 같은 깊이에서 통일합니다.
- 학생 목록은 카드 여러 개보다 한 줄 목록과 얇은 구분선을 우선합니다.
- 일간 보고서 위쪽의 출석·과제 상태는 한 카드 안 두 칸 요약으로 보여줍니다(칸마다 작은 제목 + 상태 배지 + 보조 글자).
- 교재 목록은 표지(없으면 교재 이름이 들어간 색 표지) + 제목 + 진도 막대 + 최근 학습 범위의 한 줄 카드로 보여줍니다.
- 출석률·과제이행률은 같은 크기의 도넛 카드 구조를 사용합니다.
- 도넛 내부에는 퍼센트, 아래에는 `(완료/전체)` 형식의 건수를 둡니다.
- 데이터가 있는 도넛 카드는 클릭 가능하게 하고, 클릭 시 해당 기간의 세부 목록을 평가·과제 상세 모달과 같은 카드 스타일로 보여줍니다.
- 상태 배지 색상은 항목의 의미 축을 기준으로 통일합니다: 과제 제출·완료는 정보색(파란), 출석은 성공색(초록), 미제출·결석은 오류색(빨강), 일부 제출은 경고색(주황).
- 평가 추이는 같은 브라운 계열의 선·점·그리드 구조를 사용합니다.
- 데이터가 없으면 빈 그래프를 억지로 그리지 않고 안내 문구를 보여줍니다.

### 용어 (학부모 리포트, 2026-10-13)

화면마다 같은 뜻은 같은 말로 씁니다. 새 제목·라벨을 만들 때 이 표를 먼저 봅니다.

| 쓰는 말 | 쓰지 않는 말 | 쓰는 곳 |
| --- | --- | --- |
| 탭 제목 = 하단 탭 이름(교재, 학습기록) | 진도 교재, 학습기록 타임라인 | 각 탭 맨 위 제목 |
| 출석 현황 / 과제 현황 | 출결 현황, 출석, 이날 마감 과제 | 캘린더 전환, 일간 보고서 요약 카드 |
| 제출 / 일부 제출 / 미제출 | 완료, 부분완료, 일부 | 과제 배지, 캘린더 범례·막대 |
| 선생님 한마디 | 선생님 코멘트 | 홈, 일간·주간·월간 보고서 (Notion 출석 DB 속성 이름과 같음) |
| 남은 과제 | 곧 마감 | 홈 |
| 교재 진도 | 진도(제목) | 홈 |
| 최근 평가 추이 | 평가 기록(제목) | 일간·주간·월간 보고서 |
| 지난 과제 / 이번 과제 / 이번 평가 | — | 일간 보고서 묶음 이름(유지) |
| 과제이행률 | — | 주간·월간 요약 도넛(유지) |

- 안내 문구는 "~어요"(해요체)로 씁니다. "~합니다", "~하세요"로 끝내지 않습니다.
- 화면 글자만 바꿉니다. 데이터 값과 CSS 클래스 이름(예: `부분완료`)은 그대로 둡니다.

## 9. 학습기록

- 학습·과제·평가 카드는 같은 기본 구조를 사용합니다.
- 날짜는 카드 안에 반복하지 않고 날짜 그룹 제목으로 카드 밖에 표시합니다.
- 과제 항목은 마감일이 아니라 수업일(출제일) 기준으로 날짜 그룹을 나누고 정렬합니다. 마감일은 카드 안에 `출제: YYYY-MM-DD (요일)` 다음 줄로 `마감: YYYY-MM-DD (요일)`을 별도 메타 줄로 표시합니다.
- 다음과제·과제이행률처럼 앞으로의 일정을 안내하는 영역에는, 이미 과제상태 배지로 보여준 오늘 마감 과제를 반복하지 않고 마감일이 아직 남은 과제만 포함합니다.
- 과제 상태와 평가 점수는 의미 색상의 배지로 표시합니다.
- 단원·범위·내용은 정보 계층을 분리하고, 값이 없는 줄은 표시하지 않습니다.
- 교재 상세에서도 학습기록 타임라인과 같은 날짜·카드 구조를 사용합니다.
- 교재 단원은 정규교재의 전체 단원 목록을 사용하고 숫자 단원 순서로 다시 정렬합니다.
- 진도가 나간 단원만 완료 표시하고 미진행 단원도 목록에서 숨기지 않습니다.

- 모바일 세로: `375×812`
- 데스크톱: `1280×900`

## 11. 변경 원칙

1. 요청받지 않은 화면과 스타일은 함께 바꾸지 않습니다.
2. 비슷한 컴포넌트는 기존 클래스와 색상 함수를 재사용합니다.
3. CSS 숫자를 화면별로 복제하지 말고 공용 변수로 관리합니다.
4. 백엔드 필드를 추가하면 프론트 매핑과 렌더링까지 실제로 소비하는지 확인합니다.

6. JavaScript 문법 검사와 회귀 검사 후 배포합니다.
7. 실제 모바일·데스크톱 화면에서 정렬을 확인한 뒤 완료로 판단합니다.
8. 날짜별 변경 기록은 이 문서가 아니라 GitHub `docs/archive`에 남깁니다.

## 12. 아이콘

- 모든 아이콘은 이모지가 아니라 Feather Icons 스타일의 선형 SVG를 사용합니다.
- SVG 기준: `viewBox="0 0 24 24"`, `fill: none`, `stroke: currentColor`, `stroke-width: 2`, `stroke-linecap/linejoin: round`.
- 아이콘은 항상 고정된 정사각 박스(width/height)에 넣고 font-size로 크기를 조절하지 않습니다. 이모지는 글자마다 폭이 달라 탭·제목 정렬이 틀어지는 원인이었습니다.
- 탭바, 헤더(뒤로가기·메뉴·닫기·새로고침), 사이드 메뉴, 아코디언 화살표, 페이지·섹션 제목(`.page-title-icon`), 카드 안 상태·타임라인 아이콘까지 전부 이 규칙을 따릅니다.
- 클래스(반) 구분색은 이모지 대신 `class_name` 문자열을 해시해 고정 팔레트에서 배경색·글자색 쌍을 고르는 방식(`pickClassColorPalette`)을 사용합니다. 같은 반은 항상 같은 색을 받습니다.

## 13. 텍스트 줄바꿈과 링크

- 반 이름처럼 짧은 한글 구(句)가 들어가는 배지·슬롯(예: 시간표 `.week-slot`)은 `word-break: keep-all`을 사용해 어절 단위로만 줄바꿈합니다. 기본 CJK 줄바꿈은 음절 사이 아무 데서나 끊어 읽기 어렵습니다.
- 다른 학생(형제자매) 정보처럼 페이지 내부로 이동하는 링크는 파란색 밑줄의 기본 `<a>` 스타일을 쓰지 않습니다. 본문 글자색을 유지하고, 밑줄 대신 옅은 점선 `border-bottom`과 작은 external-link 아이콘으로 클릭 가능함을 표시합니다(`.sibling-link`).

## 14. 스크롤바와 레이아웃 안정성

- `html`에 `overflow-y: scroll; scrollbar-gutter: stable;`을 적용해 스크롤바 유무에 따라 `margin: 0 auto` 중앙 정렬 콘텐츠가 좌우로 밀리지 않도록 고정합니다. 항목 수가 적어 스크롤이 생기지 않는 탭(예: 교재)만 다른 탭보다 오른쪽으로 치우쳐 보이는 문제의 원인이었습니다.

## 2-3. 레이아웃

- 모든 화면은 `.shell`(바깥 폭 `--page-max`) → `.top`(로고·상단 메뉴·상단 버튼) → `header`(h1·설명) → `.notice`(연결 상태 한 줄) → `.card`(본문) → `.foot` 순서다.
- 화면을 바꿔도 바깥 폭은 그대로 둔다. 입력이 하나뿐인 폼처럼 좁아야 하는 내용은 카드 안에서 `--form-max`로 **가운데** 놓고, 제목도 같이 가운데로 맞춘다.
- 나란히 놓는 구성(대시보드 두 칸, 안내+예시)은 860px 아래에서 위아래로 쌓는다. 카드 목록은 `repeat(auto-fill,minmax(320px,1fr))`, 700px 아래에서 한 줄.
- 확인 화면 크기는 1부 10장과 같다: 375×812(모바일 세로), 1280×900(데스크톱), 812×375·568×320(짧은 가로). 관리 화면은 768×1024(태블릿)도 함께 본다. 어느 크기에서도 가로 스크롤이 생기면 안 된다.
- 부가 정보(보안 설정 현황 등)는 본문을 좁히는 옆 칸 대신 상단 버튼으로 여는 대화상자에 둔다.

### 인쇄 문서 구역 (법정 서류)

- 출석부·수강생 대장·영수증 원부처럼 **인쇄해 보관하는 공식 서식**은 화면 토큰을 쓰지 않는다. 흰 바탕·검은 글자·회색 선, 인쇄 크기는 mm, 서식이 정한 칸 높이를 지킨다. 화면 디자인을 바꿔도 이 구역은 건드리지 않는다.
- CSS에서는 `/* design-lint: print-document */`와 `/* design-lint: end */` 사이에 둔다. 디자인 규칙 검사는 이 구역을 건너뛴다. 조회 화면(탭·필터·버튼·열 메뉴)은 구역 밖에 두고 토큰만 쓴다.
- 인쇄할 때(`@media print`)는 상단 바·제목·조회 카드·버튼 줄·꼬리말을 숨기고 출력 문서만 남긴다.
- 스크립트가 만드는 문서 표의 계산된 폭(`style="--day-count`, 열 너비 %)은 허용한다. 화면 HTML에 적힌 `style` 속성만 금지한다.

### 기기 화면 모드 (출결 키오스크)

- 학원 입구 태블릿처럼 한 화면을 꽉 채워 쓰는 화면은 `<html class="device">`로 둔다. 세로 카드(`--device-w` = `min(86vw, 52vh, 640px)`, 최소 높이 = 폭 ÷ 0.6)를 가운데 놓고, 기준 글자 크기(`--device-font` = `max(10px, min(3.82vw, 2.31vh, 28.4px))`, 카드 폭 ÷ 22.5)를 카드 폭에 비례시켜 모든 rem 토큰이 함께 커진다. 카드와 바깥 여백을 합쳐 화면 높이·폭 안에 들어오도록 정한 값이다(예전 `90vw`/`90vh × .68`은 카드가 화면보다 길어 태블릿에서 페이지가 스크롤됐다). 내용이 카드보다 크면(짧은 가로 화면) 카드가 늘어난다. CSS에서 길이를 길이로 나누는 식은 브라우저가 무시해 예전 키오스크는 항상 16px로 그려졌다. 최소 10px.
- 짧은 가로 화면(812×375, 568×320)에서는 카드가 화면 안에 다 들어오는 것을 우선한다. 이때는 버튼이 44px보다 작아질 수 있다(높이 375px 안에 숫자판 4줄과 등·하원 버튼을 모두 넣어야 하므로). 세로·데스크톱 화면(높이 600px 이상)에서는 44px 이상을 지킨다(`--hit-min`). 기기 모드에서는 스크롤바 자리를 비워 두지 않는다(모달 배경이 화면 끝까지 덮이게).
- 상단 바·제목 줄(`.shell`/`.top`) 대신 카드 안에 아이콘·제목·설명을 가운데 정렬한다. 로고는 넣지 않는다. 로그아웃 같은 부가 버튼은 카드 오른쪽 위 모서리에 둔다.
- 카드 위아래 여백은 같게 둔다(`--space-8`). 내용 높이가 바뀌는 요소(처리 결과 문구 등)를 카드 안에 두지 않고 **결과는 모달**(`dialog.result-dialog`: 아이콘·문구·확인)로 띄운다. 성공·이미 처리는 3초 뒤 자동으로 닫고, 오류는 확인을 눌러 닫는다.
- 카드 맨 아래 여백 안에 학원 이름(`.academy-name`, `--text-caption`, `--text-subtle`)을 한 줄로 작게 겹쳐 둔다(가운데 정렬에 영향 없음). 이름은 서버가 그 학원 Notion 연결이 걸린 루트 페이지(원본 "하다 학원관리 v2.0") 제목에서 가져오므로 화면에 적어 두지 않는다.
- 확인 화면 크기는 1부 10장 기준(375×812, 1280×900, 812×375, 568×320)과 768×1024(세로 태블릿)이다. 모든 경우 카드가 화면 안에 들어와야 한다.

- 아이콘은 1부 12장(Feather 스타일 선형 SVG, 고정 정사각 박스)을 따른다. 새 아이콘은 Feather Icons(feathericons.com, MIT)의 원본 SVG 경로를 그대로 가져와 쓴다(2026-10-12 사용자 지정). 다른 외부 서비스의 아이콘 파일은 가져와 쓰지 않는다.

- **구분 탭·내용 글머리(v2.5.81)**: 구분 탭 [학습 | 과제 | 평가]는 글자 앞에 분류 아이콘(14px, 학습 edit-2 `--info-ink`, 과제 clipboard `--warning-ink`, 평가 file-text `--success-ink` — 기록 박스 `.kind-icon`과 같은 그림·색). 내용 칸(기록 만들기·기록 카드)은 줄 맨 앞 "- "·"* "를 "  • "(스페이스 두 개 + 점 + 스페이스)로 바꾸고, 글머리 줄에서 Tab은 한 단계 들여쓰기("      ◦ " → "          ▪ ", 4칸씩·3단계까지), Shift+Tab은 내어쓰기. Enter는 다음 줄에 같은 단계 글머리, 빈 글머리 줄 Enter와 글머리 바로 뒤 Backspace는 한 단계 내어쓰고 첫 단계면 글머리를 지운다. 글머리가 아닌 줄의 Tab은 원래대로 다음 칸으로 이동한다. 한글 조합 중에는 건드리지 않는다. 저장은 글자 그대로라 리포트·Notion에서도 "•"로 보인다.
- **수업 한 줄(v2.5.70)**: `[클래스 이모지] [클래스명] [등원 n/전체] [수업 시간]`. 이모지는 리포트처럼 Notion 클래스 "이모지"(없으면 페이지 아이콘, 그것도 없으면 리포트와 같은 반 이름 색 이모지). 데이터의 이모지라 1부 12장의 이모지 아이콘 금지와 별개다. 등원은 키오스크 등원 기록 수로 0명 회색, 일부 노랑, 모두 초록. 보강 수업은 이모지 자리에 "보강" 표시와 수업 이름. 날짜·강사는 위(캘린더·상단 바)에 있으니 줄에 넣지 않는다.
- **상단 바(v2.5.79)**: 수업 화면은 위 "화면 구조"의 세 칸(가운데 제목은 `--text-lead` 굵게, 둘째 줄 날짜·시간 `--text-caption`, 길면 말줄임). 학생 공간·기록 카드는 `← 클래스명 › 학생/기록 구분` 경로와 오른쪽 ↗. 수업 페이지 ↗는 학생 목록·학습기록 제목 줄 오른쪽 끝에 둔다. 리포트 경로처럼 글자만 쓰고 테두리 버튼은 쓰지 않는다.
- **상단 바 간격(v2.5.83)**: 바 안쪽 여백 8px(`--space-2`)에 아이콘 버튼(44px)을 붙여, 아이콘 그림이 화면 끝에서 20px에 온다. 글자(제목·경로)가 바 끝에 오면 12px(`--space-3`) 더 들여 같은 20px 선에서 시작·끝난다(로그인·강사 선택처럼 아이콘 없이 글자만 있는 바 포함). 로그인 화면 상단 바 제목은 "수업 관리".
- **뒤로가기(v2.5.85)**: 브라우저·휴대폰 뒤로가기가 페이지를 벗어나지 않고 앱처럼 직전 동작으로 돌아간다(History API). ① 창·서랍(≡·📅·기록 만들기·메모·보강 수업 만들기·교재 고르기)이 열려 있으면 그것부터 닫는다(교재 고르기는 기록 만들기로). 창을 닫는 ✕·바깥 누르기·Esc·저장 뒤 닫기도 같은 길로 닫는다. ② 학생 공간·기록 카드·보강 대기실·강사 선택·다른 반/날짜 수업으로 옮긴 화면은 들어오기 전 화면으로. 상단 ←도 같은 동작. ③ 하단 탭은 쌓지 않는다: 학생 목록 → 학습기록만 한 칸, 학습기록에서 뒤로가기나 [학생 목록]은 그 학생 목록으로, 학생 목록에서 뒤로가기는 이전 화면. ④ 처음 연 화면에서는 원래대로 페이지를 나간다. 앞으로 가기는 무시한다. 저장하지 않은 편집이 있으면 먼저 묻는다. 주소는 바꾸지 않아 새로고침하면 지금처럼 오늘 수업이 열린다.
- **아래 막대와 알림**: 저장 막대는 카드와 같은 16px 안쪽. 알림은 하단 탭·저장 막대가 있으면 그 위에 뜨고, 글자 폭만큼 넓게(가운데 정렬 때문에 화면 반 폭으로 줄지 않게) 두 줄이면 `--radius-lg` 모서리.
- **폭(v2.5.70)**: 리포트처럼 모든 화면·모든 폭에서 `--feed-w`(640) 한 줄. v2.5.69의 PC 두 칸 배치는 없앴다. 1081px 이상에서는 대화상자만 아래 시트 대신 가운데(`--dialog-md`).

### 기타 화면 공통

- `html`에 `overflow-y: scroll; scrollbar-gutter: stable`(1부 14장)을 공용 스타일에서 건다.
- 로고와 학원 이름은 아래 "로고" 규칙을 따른다(Notion 에셋 "하다 워드마크" 기준).

## 2-5. 금지

- 토큰 밖의 색(16진수, rgb, white/black)을 화면 CSS에 직접 쓰기
- 간격·글자 크기·모서리·레이아웃 폭에 임의 px 쓰기
- HTML의 `style="..."` 속성
- 페이지 바탕을 `--canvas` 외의 색으로 하기, 그라데이션 배경
- 이모지 아이콘(1부 12장)
- 화면별 어두운 모드(브랜드는 밝은 테마 하나만 쓴다)
- `--brand-deep` 외의 포인트 색 추가

## 2-6. 작업 절차

1. 고치기 전 화면을 캡처한다(1280×900·375×812).
2. 토큰과 공용 부품으로 고친다. 새 값이 꼭 필요하면 먼저 `assets/hada-tokens.css`와 이 문서에 추가하고 이유를 적는다. 요청받지 않은 화면은 함께 바꾸지 않는다(1부 11장).
3. `node tests/design-lint.cjs`를 실행한다. 공용 파일(`hada-tokens.css`, `hada-ui.css`, `hada-shortcuts.js`, `admin_auth.js`, `admin_settings.js`, `class_room.js`)이나 학부모 리포트 스크립트(`student_report_part1.js`, `student_report_part2.js`, v2.5.77부터)를 고쳤으면 먼저 `node tests/design-lint.cjs --fix`로 화면의 `?v=` 버전 표시를 갱신한다. 버전 표시는 파일 내용의 해시라서 내용이 바뀌면 주소가 바뀌고, 브라우저가 예전 파일(GitHub Pages는 10분 보관)을 쓰지 않는다. 갱신을 빠뜨리면 이 검사가 실패한다. 학원별 설정 파일 `hada_config.js`는 일부러 버전 표시를 붙이지 않는다. 붙이면 학원마다 화면 파일 내용이 달라져 업데이트 때 화면 파일을 통째로 바꿀 수 없다.
4. 화면 검사(1부 10장 크기에서 가로 넘침, 버튼 높이 44px 이상, 글자 잘림)를 실행하고 전후 캡처를 비교해 보고한다.
