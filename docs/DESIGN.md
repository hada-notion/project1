# 하다 학원관리 웹 화면 디자인 규칙

이 문서는 두 부분이다.

- **1부 웹앱 디자인 규칙**: 학부모 리포트(`student_report.html`)에서 나온 원래 기준이다. 모든 웹 화면의 기준이며, 2부와 다르면 1부를 따른다. 원문은 Notion에서 관리하던 문서를 그대로 옮겼다.
- **2부 관리 화면 공용 토큰·부품**: 관리자 설정·출결 키오스크·학교 검색·법정 서류가 1부 기준을 같은 값으로 쓰도록 만든 토큰(`assets/hada-tokens.css`), 공용 부품(`assets/hada-ui.css`), 검사(`tests/design-lint.cjs`)의 규칙이다.

카드뉴스·영상 같은 콘텐츠는 Notion "콘텐츠 디자인 기준"을 따른다. 색 팔레트는 같지만 웹앱의 페이지 바탕은 1부의 전체 캔버스(`#F7F8FA`)를 쓴다.

# 1부. 웹앱 디자인 규칙
> 🎯 학생 리포트와 출결 키오스크를 수정할 때 지켜야 하는 **현재 디자인 기준**입니다. 과거 수정 과정이나 날짜별 로그는 이 문서에 추가하지 않습니다.

## 1. 정보 노출 범위

### 학부모 화면에 표시

- 학생명과 등록 클래스
- 교재와 진도
- 출석 캘린더
- 학습기록·과제·평가
- 주간·월간 보고서와 선생님 코멘트
- 학생에게 공개 가능한 일정과 휴원 안내

### 항상 제외

- 학교 성적과 성적 이력
- 수강료·교재비·결제금액
- 다른 학생·학부모 정보
- 보호자 전체 연락처와 형제 정보
- 상담 메모와 내부 운영 메모
- Notion 페이지 ID·내부 DB URL
- 관리자 키·토큰·service role key

학교 성적은 학원 내부 운영에서만 확인합니다. 학원 수업 중 진행한 평가와 평가 차트는 계속 표시합니다.

## 2. 화면 구조

- 첫 화면은 학생명·학교/학년과 등록 클래스 선택을 간결하게 보여줍니다. 요약 정보를 첫 화면에 늘리지 않습니다.
- 등록 상세는 홈, 교재, 캘린더, 학습기록, 보고서의 다섯 영역으로 이동하고, 반을 열면 홈이 먼저 보입니다.
- 홈은 그 반의 오늘(출석·남은 과제·다음 수업), 곧 마감 과제, 교재 진도, 최근 선생님 한마디를 모아 보여줍니다. 각 항목은 해당 탭과 같은 카드 모양을 씁니다.
- 모바일에서는 하단 고정 탭바를 사용하고, 선택 탭은 배경과 글자색으로 분명하게 구분합니다.
- 데스크톱에서도 모바일과 같은 정보 순서와 정렬 기준을 유지합니다.
- 카드·달력·탭의 가로 중심선과 좌우 여백은 공통 콘텐츠 폭을 기준으로 맞춥니다.

## 4. 타이포그래피

```css
font-family: -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
```

- 제목·카드 제목·헤더 이동경로는 명확한 볼드를 사용합니다.
- 설명과 보조정보는 기본 글자보다 한 단계 옅게 표시합니다.
- 너무 작은 글자를 사용하지 않고 모바일에서 확대 없이 읽을 수 있어야 합니다.
- 숫자·날짜·상태 배지는 같은 계층에서 크기와 굵기를 통일합니다.

## 5. 상세 헤더

- 접힌 헤더 높이는 `56px`을 기준으로 합니다.
- 헤더 내부는 높이의 정중앙에 수직 정렬합니다.
- 뒤로가기와 메뉴·새로고침 버튼은 `44×44px` 클릭 영역 안에 `20×20px` 선형 아이콘을 사용합니다.
- 아이콘 배경과 그림자는 사용하지 않고 투명하게 둡니다.
- 뒤로가기는 왼쪽, 메뉴·새로고침은 오른쪽에 대칭 배치합니다.
- 이동경로는 학생명·클래스명·페이지명을 **이모지 없이 텍스트로만** 표시합니다.
- 이동경로 전체를 동일한 볼드 굵기로 표시하며 마지막 항목만 일반 글자로 바꾸지 않습니다.
- 헤더 안 콘텐츠는 세로 중앙에 맞추고 화면 이동 시 위로 밀려 보이지 않도록 합니다.

## 6. 정렬과 간격

- 한 화면 안의 제목, 탭, 카드, 달력은 같은 좌우 기준선을 사용합니다.
- 폭을 맞춰야 하는 요소는 서로 다른 px 값을 쓰지 말고 같은 CSS 변수와 `max-width` 공식을 공유합니다.
- 섹션 제목과 첫 카드 사이, 카드와 카드 사이 간격을 화면별로 임의 변경하지 않습니다.
- 빈 상태 문구는 해당 카드나 목록의 중앙에 표시합니다.
- 하단 탭바와 겹치지 않도록 본문 마지막에 안전 여백을 둡니다.
- 새로고침은 떠 있는 버튼으로 두지 않습니다(카드를 가림). 모든 화면에서 오른쪽 위 44×44px 아이콘으로 둡니다: 첫 화면은 메뉴(≡) 왼쪽, 반·교재 상세는 접힌 헤더 오른쪽 끝.

## 7. 캘린더

- 일정과 출결 캘린더는 같은 폭·셀 크기·요일 헤더 구조를 공유합니다.
- 기간 제목은 좌우 버튼 폭이 같은 3열 구조로 화면 정중앙에 둡니다.
- 날짜 셀의 크기와 간격은 가로·세로 중 더 좁은 화면에 맞춰 줄어들어야 합니다.
- 출결 달력은 일정 달력과 같이 월요일부터 시작합니다.
- 날짜를 탭하면 달력을 그 주 한 줄로 접고, 아래에 그날의 학습·과제·평가 카드를 보여줍니다. 같은 날짜를 다시 누르거나 [월 전체 보기]로 돌아갑니다.
- 수업이 있었던 날만 상태 배경색을 칠하고, 나머지 날짜는 숫자만 둡니다. 앞으로 남은 수업일(시간표 기준, 휴원 제외)은 테두리만 표시합니다.
- 출결 상태는 배경색으로 구분합니다.
    - 출석: 연한 초록 / 초록 글자
    - 결석: 연한 빨강 / 빨강 글자
    - 보강: 연한 파랑 / 파랑 글자
- 달력 위에는 그달 수업 횟수만큼 칸을 나눈 막대를 둡니다. 지난 수업 칸부터 상태 중간 톤(`--bar-*`)으로 채우고 남은 수업은 빈 칸으로 둡니다. 숫자는 퍼센트 대신 `지난 수업 / 전체 수업`(예: `3 / 8회`)으로 씁니다. 첫 수업 하나로 100%가 되는 표시는 쓰지 않습니다.
- 선택일·오늘·기록일의 테두리와 배경 역할이 서로 겹치지 않게 합니다.
- 주간은 최대 26주 전, 월간은 최대 6개월 전까지 이동하도록 제한하고, 한계에 도달한 버튼은 시각적으로 비활성화합니다.

## 8. 카드와 상태 표시

- 카드 모서리·그림자·테두리는 같은 깊이에서 통일합니다.
- 학생 목록은 카드 여러 개보다 한 줄 목록과 얇은 구분선을 우선합니다.
- 일간 보고서 위쪽의 출석·과제 상태는 한 카드 안 두 칸 요약으로 보여줍니다(칸마다 작은 제목 + 상태 배지 + 보조 글자).
- 교재 목록은 표지(없으면 교재 이름이 들어간 색 표지) + 제목 + 진도 막대 + 최근 학습 범위의 한 줄 카드로 보여줍니다.
- 출석률·과제이행률은 같은 크기의 도넛 카드 구조를 사용합니다.
- 도넛 내부에는 퍼센트, 아래에는 `(완료/전체)` 형식의 건수를 둡니다.
- 데이터가 있는 도넛 카드는 클릭 가능하게 하고, 클릭 시 해당 기간의 세부 목록을 평가·과제 상세 모달과 같은 카드 스타일로 보여줍니다.
- 상태 배지 색상은 항목의 의미 축을 기준으로 통일합니다: 과제 제출·완료는 정보색(파란), 출석은 성공색(초록), 미제출·결석은 오류색(빨강), 부분완료는 경고색(주황).
- 평가 추이는 같은 브라운 계열의 선·점·그리드 구조를 사용합니다.
- 데이터가 없으면 빈 그래프를 억지로 그리지 않고 안내 문구를 보여줍니다.

## 9. 학습기록

- 학습·과제·평가 카드는 같은 기본 구조를 사용합니다.
- 날짜는 카드 안에 반복하지 않고 날짜 그룹 제목으로 카드 밖에 표시합니다.
- 과제 항목은 마감일이 아니라 수업일(출제일) 기준으로 날짜 그룹을 나누고 정렬합니다. 마감일은 카드 안에 `출제: YYYY-MM-DD (요일)` 다음 줄로 `마감: YYYY-MM-DD (요일)`을 별도 메타 줄로 표시합니다.
- 다음과제·과제이행률처럼 앞으로의 일정을 안내하는 영역에는, 이미 과제상태 배지로 보여준 오늘 마감 과제를 반복하지 않고 마감일이 아직 남은 과제만 포함합니다.
- 과제 상태와 평가 점수는 의미 색상의 배지로 표시합니다.
- 단원·범위·내용은 정보 계층을 분리하고, 값이 없는 줄은 표시하지 않습니다.
- 교재 상세에서도 학습기록 타임라인과 같은 날짜·카드 구조를 사용합니다.
- 교재 단원은 정규교재의 전체 단원 목록을 사용하고 숫자 단원 순서로 다시 정렬합니다.
- 진도가 나간 단원만 완료 표시하고 미진행 단원도 목록에서 숨기지 않습니다.

## 10. 반응형 검수

변경 후 최소 아래 화면에서 확인합니다.

- 모바일 세로: `375×812`
- 데스크톱: `1280×900`
- 짧은 가로: `812×375`, `568×320`

확인 항목:

- 헤더 아이콘과 이동경로가 수직 중앙에 있는가
- 제목·탭·카드·달력의 좌우 기준선이 맞는가
- 하단 탭바와 콘텐츠가 겹치지 않는가
- 캘린더 셀과 카드가 잘리거나 가로로 넘치지 않는가
- 뒤로 이동할 때 화면이 위로 튀어 보이지 않는가
- 빈 상태·로딩·오류 상태가 동시에 표시되지 않는가

## 11. 변경 원칙

1. 요청받지 않은 화면과 스타일은 함께 바꾸지 않습니다.
2. 비슷한 컴포넌트는 기존 클래스와 색상 함수를 재사용합니다.
3. CSS 숫자를 화면별로 복제하지 말고 공용 변수로 관리합니다.
4. 백엔드 필드를 추가하면 프론트 매핑과 렌더링까지 실제로 소비하는지 확인합니다.
5. `student_report.html`은 전체 재작성하지 않고 부분 수정합니다.
6. JavaScript 문법 검사와 회귀 검사 후 배포합니다.
7. 실제 모바일·데스크톱 화면에서 정렬을 확인한 뒤 완료로 판단합니다.
8. 날짜별 변경 기록은 이 문서가 아니라 GitHub `docs/archive`에 남깁니다.

## 12. 아이콘

- 모든 아이콘은 이모지가 아니라 Feather Icons 스타일의 선형 SVG를 사용합니다.
- SVG 기준: `viewBox="0 0 24 24"`, `fill: none`, `stroke: currentColor`, `stroke-width: 2`, `stroke-linecap/linejoin: round`.
- 아이콘은 항상 고정된 정사각 박스(width/height)에 넣고 font-size로 크기를 조절하지 않습니다. 이모지는 글자마다 폭이 달라 탭·제목 정렬이 틀어지는 원인이었습니다.
- 탭바, 헤더(뒤로가기·메뉴·닫기·새로고침), 사이드 메뉴, 아코디언 화살표, 페이지·섹션 제목(`.page-title-icon`), 카드 안 상태·타임라인 아이콘까지 전부 이 규칙을 따릅니다.
- 클래스(반) 구분색은 이모지 대신 `class_name` 문자열을 해시해 고정 팔레트에서 배경색·글자색 쌍을 고르는 방식(`pickClassColorPalette`)을 사용합니다. 같은 반은 항상 같은 색을 받습니다.

## 13. 텍스트 줄바꿈과 링크

- 반 이름처럼 짧은 한글 구(句)가 들어가는 배지·슬롯(예: 시간표 `.week-slot`)은 `word-break: keep-all`을 사용해 어절 단위로만 줄바꿈합니다. 기본 CJK 줄바꿈은 음절 사이 아무 데서나 끊어 읽기 어렵습니다.
- 다른 학생(형제자매) 정보처럼 페이지 내부로 이동하는 링크는 파란색 밑줄의 기본 `<a>` 스타일을 쓰지 않습니다. 본문 글자색을 유지하고, 밑줄 대신 옅은 점선 `border-bottom`과 작은 external-link 아이콘으로 클릭 가능함을 표시합니다(`.sibling-link`).

## 14. 스크롤바와 레이아웃 안정성

- `html`에 `overflow-y: scroll; scrollbar-gutter: stable;`을 적용해 스크롤바 유무에 따라 `margin: 0 auto` 중앙 정렬 콘텐츠가 좌우로 밀리지 않도록 고정합니다. 항목 수가 적어 스크롤이 생기지 않는 탭(예: 교재)만 다른 탭보다 오른쪽으로 치우쳐 보이는 문제의 원인이었습니다.

# 2부. 관리 화면 공용 토큰·부품

1부의 값과 규칙을 관리 화면에서 같은 이름으로 쓰기 위한 장치다. 규칙은 말이 아니라 검사로 지킨다: `node tests/design-lint.cjs`가 토큰 밖의 값을 막고, 화면 검사가 1부 10장 크기에서 깨짐을 찾는다.

## 2-1. 적용 현황

| 화면 | 상태 | 비고 |
| --- | --- | --- |
| `student_report.html` | **기준 화면(1부)** | 공용 토큰·부품 파일을 쓰지 않고 1부 규칙대로 부분 수정한다 |
| `attendance_kiosk.html` | 공용 토큰·부품 | 1부 적용 대상. 기기 화면 모드(`html.device`) |
| `admin_settings.html` | 공용 토큰·부품 | |
| `school_search.html` | 공용 토큰·부품 | |

새 화면을 공용 스타일로 옮기면 `tests/design-lint.cjs`의 `PAGES`에 추가하고 이 표를 고친다. 옮기는 작업은 화면 하나씩, 기능 변경 없이 한다.

## 2-2. 토큰

값은 `assets/hada-tokens.css`에만 있다(`hada-ui.css`가 불러온다). 화면 CSS는 `var(--이름)`만 쓴다. 화면이 자기 레이아웃용 변수를 만들 수는 있지만 색 변수는 만들지 않는다. 색 값은 1부 3장 색상표와 같다.

글자·간격·모서리·높이 토큰은 `rem`이다(기본 16px = 1rem이라 보이는 크기는 아래 px와 같다). 그래서 기기 화면 모드에서 기준 글자 크기만 바꾸면 화면 전체가 같은 비율로 커진다.

### 글자

- 글꼴: `--font-sans` = 1부 4장 글꼴(`-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`). 코드·키 값은 `--font-mono`. `word-break: keep-all` 필수.
- 크기는 7단계만 쓴다.

| 토큰 | 크기 | 쓰임 |
| --- | --- | --- |
| `--text-display` | 32px (모바일 28px) | 페이지 제목(h1) 하나 |
| `--text-title` | 22px | 카드 제목(h2), 로고 |
| `--text-lead` | 17px | 소제목, DB 카드 이름(리포트 섹션 제목 크기) |
| `--text-body` | 16px | 본문, 입력칸, 버튼 |
| `--text-small` | 14px | 도움말, 상태 상자, 표 |
| `--text-label` | 13px | 배지, 보조 정보 |
| `--text-caption` | 12px | 가장 작은 메타 정보 |

- 굵기: 400 본문, 600 강조·버튼·라벨, 700 배지·작은 제목, 800 로고.

### 간격

`--space-1` 4 · `--space-2` 8 · `--space-3` 12 · `--space-4` 16 · `--space-5` 20 · `--space-6` 24 · `--space-8` 32 · `--space-12` 48 (px)

- 같은 성격의 간격은 같은 단계를 쓴다: 카드 안쪽 32(휴대폰 20), 카드 사이 16~24, 폼 항목 사이 24, 제목과 설명 사이 12.
- 0~3px는 선·미세 정렬용으로만 직접 쓸 수 있다.

### 모서리·크기

- 모서리(리포트 기준): `--radius-sm` 6(배지·코드) · `--radius-md` 10(버튼·입력칸·상태 상자·칸) · `--radius-lg` 14(카드·대화상자) · `--radius-pill`(전환 탭·숫자 배지·둥근 버튼)
- 카드: 1부 8장대로 모서리·그림자·테두리를 통일한다. 바깥 카드는 **테두리 없이** 흰 표면 + `--shadow-card`. 카드 안의 칸(대시보드 두 칸, DB 카드)은 그림자 없이 `--brand-border` 1px 선으로 나눈다.
- 폭: `--page-max` 1180(모든 화면의 바깥 폭 동일) · `--form-max` 560(입력 폼은 이 폭으로 가운데) · `--dialog-sm` 440 · `--dialog-md` 600
- 높이: `--control-h` 48(버튼·입력칸), `--control-lg` 56(키오스크 숫자판·등하원 버튼), `--header-h` 56(1부 5장 상세 헤더). 누르는 요소는 최소 44px.
- 아이콘 버튼: `--hit-area` 44×44 클릭 영역 안에 `--icon-md` 20×20 선형 아이콘, 배경·그림자 없음(1부 5장).
- 아이콘: `--icon-sm` 14 · `--icon-md` 20 · `--icon-lg` 28. 선 아이콘은 `svg.line`(stroke 2, currentColor).

### 로고

- 파일: `assets/brand/hada-wordmark.png`. Notion 에셋 "하다 워드마크"의 brand-deep 버전(투명 배경)이다. 밝은 바탕에만 쓰고, 어두운 바탕이 생기면 같은 에셋의 화이트 버전을 추가한다. 블랙·라이트 원본은 쓰지 않는다.
- 위치: 상단 바 왼쪽, "하다 학원관리" 글자 앞(`.brand` → `.logo` + `.wordmark`), 간격 `--space-3`. **기기 화면 모드(키오스크)에는 로고를 넣지 않는다**(학원생과 보호자가 보는 화면이라 과하다). 대신 카드 아래에 학원 이름을 작게 표시한다.
- 높이: `--logo-h` 36px(모바일 28px), 가로는 비율대로. 늘리거나 색을 바꾸지 않는다.

## 2-3. 레이아웃

- 모든 화면은 `.shell`(바깥 폭 `--page-max`) → `.top`(로고·상단 메뉴·상단 버튼) → `header`(h1·설명) → `.notice`(연결 상태 한 줄) → `.card`(본문) → `.foot` 순서다.
- 화면을 바꿔도 바깥 폭은 그대로 둔다. 입력이 하나뿐인 폼처럼 좁아야 하는 내용은 카드 안에서 `--form-max`로 **가운데** 놓고, 제목도 같이 가운데로 맞춘다.
- 나란히 놓는 구성(대시보드 두 칸, 안내+예시)은 860px 아래에서 위아래로 쌓는다. 카드 목록은 `repeat(auto-fill,minmax(320px,1fr))`, 700px 아래에서 한 줄.
- 확인 화면 크기는 1부 10장과 같다: 375×812(모바일 세로), 1280×900(데스크톱), 812×375·568×320(짧은 가로). 관리 화면은 768×1024(태블릿)도 함께 본다. 어느 크기에서도 가로 스크롤이 생기면 안 된다.
- 부가 정보(보안 설정 현황 등)는 본문을 좁히는 옆 칸 대신 상단 버튼으로 여는 대화상자에 둔다.

### 정렬·간격·줄바꿈 (화면 폭 3단계, 2026-10-12)

화면 폭은 세 단계로 나눠 본다: **데스크탑**(1081px 이상), **태블릿**(701~1080px), **휴대폰**(700px 이하). 관리 화면 검사는 1280·768·375와 짧은 가로(812·568)를 모두 돈다.

| 대상 | 규칙 |
| --- | --- |
| 바깥 여백 | `.shell` 좌우 32(휴대폰 20). 카드 안쪽 32(휴대폰 20). 카드 안 칸(DB 카드·대시보드 칸)은 16 |
| 세로 간격 | 제목→설명 12, 라벨→입력 8, 입력→도움말 8, 폼 항목 사이 24, 카드 사이 16~24, 알림 줄→카드 24 |
| 입력·선택·날짜 칸 | 높이 48, 글자 시작 왼쪽 16(세 칸 모두 같음). 오른쪽 아이콘은 Feather 20×20, 오른쪽 16에서 세로 가운데(선택 상자 `chevron-down`, 날짜 칸 `calendar` — 기기·브라우저 기본 아이콘과 가운데 정렬은 끈다) |
| 버튼 | 높이 48, 글자는 **한 줄**. 같은 줄 버튼은 높이가 같다. 처리 중에도 크기 그대로(2-4 "처리 중"). 상태에 따라 글자가 바뀌면 가장 긴 글자에 맞춘 최소 폭 |
| 버튼 줄 | 데스크탑·태블릿은 오른쪽 정렬 또는 칸 끝. 휴대폰은 세로로 쌓고 가로 꽉(`.actions`, 아래쪽 단독 버튼 포함) |
| 필터 줄 | 데스크탑 한 줄, 태블릿 3칸(버튼은 칸 너비 가득), 휴대폰 한 칸씩 |
| 붙어 다니는 막대 | `position:sticky` 막대(웹훅 키 등)는 데스크탑·태블릿만. 휴대폰에서는 제자리에 두어 화면을 가리지 않는다 |
| 줄바꿈 | 한국어는 띄어쓰기 단위(`word-break:keep-all`), 칸보다 긴 낱말만 칸 안에서 끊는다(`overflow-wrap:break-word`). 키·코드·URL처럼 긴 값은 **한 줄 전체 폭**을 주고 그 안에서만 아무 데서나 끊는다(`anywhere`). 좁은 옆 칸에 긴 값을 두지 않는다(한 글자씩 세로로 늘어지는 원인) |
| 아이콘 | **Feather Icons만**(데스크탑·휴대폰 모두). 예외: 관리자 설정의 Notion 버튼·자동화 종류 표시(`.kind`)는 Notion 모양 아이콘을 그대로 쓴다(2026-10-12 사용자 지정). "↗ ▶ ✓ ＋" 같은 글자 기호나 브라우저 기본 아이콘(날짜 달력, 검색 지우기 ×, 접기 ▶)을 아이콘 대신 쓰지 않는다. 글자 옆 14, 칸 안·버튼 20. 새 탭 링크는 `.icon-ext`(arrow-up-right), 접기 제목은 `summary`(chevron-right) |

검사(`hada-ui-tests`의 `layout-extra.cjs`)가 모든 관리 화면·모든 폭에서 버튼 글자 줄바꿈, 좁은 칸에 끼인 글자, 라벨 줄바꿈, 글자 기호 아이콘, 28px 넘는 아이콘을 잡는다.

### 인쇄 문서 구역 (법정 서류)

- 출석부·수강생 대장·영수증 원부처럼 **인쇄해 보관하는 공식 서식**은 화면 토큰을 쓰지 않는다. 흰 바탕·검은 글자·회색 선, 인쇄 크기는 mm, 서식이 정한 칸 높이를 지킨다. 화면 디자인을 바꿔도 이 구역은 건드리지 않는다.
- CSS에서는 `/* design-lint: print-document */`와 `/* design-lint: end */` 사이에 둔다. 디자인 규칙 검사는 이 구역을 건너뛴다. 조회 화면(탭·필터·버튼·열 메뉴)은 구역 밖에 두고 토큰만 쓴다.
- 인쇄할 때(`@media print`)는 상단 바·제목·조회 카드·버튼 줄·꼬리말을 숨기고 출력 문서만 남긴다.
- 스크립트가 만드는 문서 표의 계산된 폭(`style="--day-count`, 열 너비 %)은 허용한다. 화면 HTML에 적힌 `style` 속성만 금지한다.

### 기기 화면 모드 (출결 키오스크)

- 학원 입구 태블릿처럼 한 화면을 꽉 채워 쓰는 화면은 `<html class="device">`로 둔다. 세로 카드(`--device-w` = `min(86vw, 52vh, 640px)`, 최소 높이 = 폭 ÷ 0.6)를 가운데 놓고, 기준 글자 크기(`--device-font` = `max(10px, min(3.82vw, 2.31vh, 28.4px))`, 카드 폭 ÷ 22.5)를 카드 폭에 비례시켜 모든 rem 토큰이 함께 커진다. 카드와 바깥 여백을 합쳐 화면 높이·폭 안에 들어오도록 정한 값이다(예전 `90vw`/`90vh × .68`은 카드가 화면보다 길어 태블릿에서 페이지가 스크롤됐다). 내용이 카드보다 크면(짧은 가로 화면) 카드가 늘어난다. CSS에서 길이를 길이로 나누는 식은 브라우저가 무시해 예전 키오스크는 항상 16px로 그려졌다. 최소 10px.
- 짧은 가로 화면(812×375, 568×320)에서는 카드가 화면 안에 다 들어오는 것을 우선한다. 이때는 버튼이 44px보다 작아질 수 있다(높이 375px 안에 숫자판 4줄과 등·하원 버튼을 모두 넣어야 하므로). 세로·데스크톱 화면(높이 600px 이상)에서는 44px 이상을 지킨다(`--hit-min`). 기기 모드에서는 스크롤바 자리를 비워 두지 않는다(모달 배경이 화면 끝까지 덮이게).
- 상단 바·제목 줄(`.shell`/`.top`) 대신 카드 안에 아이콘·제목·설명을 가운데 정렬한다. 로고는 넣지 않는다. 로그아웃 같은 부가 버튼은 카드 오른쪽 위 모서리에 둔다.
- 카드 위아래 여백은 같게 둔다(`--space-8`). 내용 높이가 바뀌는 요소(처리 결과 문구 등)를 카드 안에 두지 않고 **결과는 모달**(`dialog.result-dialog`: 아이콘·문구·확인)로 띄운다. 성공·이미 처리는 3초 뒤 자동으로 닫고, 오류는 확인을 눌러 닫는다.
- 카드 맨 아래 여백 안에 학원 이름(`.academy-name`, `--text-caption`, `--text-subtle`)을 한 줄로 작게 겹쳐 둔다(가운데 정렬에 영향 없음). 이름은 서버가 그 학원 Notion 연결이 걸린 루트 페이지(원본 "하다 학원관리 v2.0") 제목에서 가져오므로 화면에 적어 두지 않는다.
- 확인 화면 크기는 1부 10장 기준(375×812, 1280×900, 812×375, 568×320)과 768×1024(세로 태블릿)이다. 모든 경우 카드가 화면 안에 들어와야 한다.

## 2-4. 부품

`assets/hada-ui.css`에 있는 공용 부품만 쓰고, 같은 역할에 다른 모양을 만들지 않는다.

| 부품 | 클래스 | 규칙 |
| --- | --- | --- |
| 주 버튼 | `.primary` (`.inline`=내용 폭) | 한 화면(한 카드)에 하나. 가장 중요한 다음 행동(키오스크는 등원, 법정 서류는 조회) |
| 전환 탭 | `.tabs` | 리포트 `seg-toggle`과 같은 모양: 베이지 트랙(`--brand-soft`) 안에서 선택한 칸만 흰 표면·진한 글자. 같은 화면 안에서 종류를 바꿀 때(법정 서류 서류 종류) |
| 보조 버튼 | `.secondary` (`.wide`=가득 채움) | 1부 3장 "보조 버튼": `--brand-soft` 바탕 + `--brand-on-primary` 글자, 테두리 없음. 돌아가기, 하원, 인쇄, 로그아웃 등 |
| 작은 버튼 | `.ghost` | 상단 바, 대화상자 닫기, 다시 찾기 같은 부가 동작. 글자는 항상 한 줄(공간이 모자라면 버튼 줄이 아래로 내려간다) |
| 상단 메뉴 | `.top` 안 빈 `#app-nav` + `assets/hada-shortcuts.js` | 관리 화면(관리자 설정·법정 서류·학교 검색)을 오가는 탭(`.nav-tabs`, 지금 화면은 `aria-current`로 선택 표시)과 [키오스크] 링크. 관리 화면은 **같은 탭**에서 이동하고, 화면 전환(`@view-transition`, 상단 바 고정)으로 본문만 바뀌어 보인다. 기기에 따로 띄워 두는 출결 키오스크만 새 탭. 목록은 `hada-shortcuts.js` 한 곳에만 있다. 1080px 이하에서는 상단 바 아래 줄, 700px 이하에서는 탭 아이콘을 숨기고 키오스크는 아이콘만. 학부모 리포트는 학생별 주소라 넣지 않는다 |
| 로그인 공유 | `HadaAdminAuth.savedSession()` / `saveSession()` (`admin_auth.js`) | 관리자 설정·법정 서류·학교 검색은 서버가 같은 종류의 관리자 로그인을 주므로 한 번 로그인하면 **같은 탭 안에서** 공유한다(sessionStorage, 탭을 닫거나 어느 화면에서든 로그아웃하면 해제, 401이면 지운다). 초기 비밀번호(0000) 로그인은 관리자 설정 안에서만 쓰고 공유하지 않는다. 키오스크(30일 키오스크 권한, `admin_key`)는 따로 로그인한다 |
| 복사 버튼 | `.ghost.copy-btn` | 복사 아이콘(종이 두 장, 선형 SVG) + 짧은 이름(예: "웹훅", "헤더"). 자세한 값은 버튼 설명(title)에 둔다. 누르면 화면 아래 토스트로 "…을 복사했습니다"를 2초 보여 주고 버튼 아이콘이 잠시 체크로 바뀐다. 한 항목의 복사 버튼은 한 줄에 둔다. 반복해서 붙여 넣는 값(새 웹훅 키)은 화면 위에 고정한 막대(`.key-bar`)에서 언제든 다시 복사한다 |
| 자동화 트리거 줄 | `.trigger` + `.trig` / `.trig.box.on` | 항목 이름은 기능 이름만 짧게 두고, 조건은 `?` 대화상자 안에 한 줄로 그린다: "트리거 [＋ 페이지 추가] 조건 [☑ 개인정보 동의 체크됨]". 체크박스 칩은 Notion 체크박스 모양 SVG, 상태(체크됨/체크 해제됨)는 칩 안에 둔다. 캡처 이미지는 위치를 찾기 어려운 경우만 `?` 대화상자로 |
| 항목 설명 | `.help-desc` / `.note` | `?` 대화상자 안: 대략적인 기능 1~2문장(모든 항목), 평소와 다른 점(하위 주소, 추가 헤더)이 있으면 한 줄 더 |
| 카드 안 이동 링크 | `.link-chip` / `.link-chip.main` | 밑줄 없는 작은 버튼 + "↗"(다른 페이지로 이동). 이름은 열리는 곳 그대로(예: "웹훅 등록 ↗", "DB 열기 ↗"). 복사 버튼과 같은 크기. 가장 자주 쓰는 링크 하나만 `.main`(베이지 바탕), 나머지는 테두리만. 링크 밑줄과 구분선이 겹치지 않게 한다 |
| 토스트 | `.toast` | 화면 아래 가운데 짧은 결과 알림(2초). 위쪽 알림 줄이 스크롤로 안 보일 때 바로 알려야 하는 결과(복사 등)에 쓴다 |
| 도움말 버튼 | `.help-btn` | `?` 한 글자. 누르면 대화상자로 설명·이미지. 체크리스트처럼 항목이 반복되는 목록은 **모든 항목의 같은 자리(이름 줄 오른쪽 끝, `.item-help`)에 하나씩** 두고, 기능 설명·트리거·주의 사항·찾는 위치 이미지를 모두 그 대화상자에 넣는다. 처음 보이는 정보는 모든 항목이 같게(이름·종류·함수·복사 버튼) |
| 처리 중 | `.loading` (+ `aria-busy`) | 서버 요청 중 누른 버튼은 **크기를 그대로 두고** 글자 대신 가운데 회전 표시만 둔다(글자를 "조회 중…"처럼 바꾸면 버튼 폭과 옆 칸이 흔들린다). 진행 문구("조회 중…", 오래 걸리면 예상 시간)는 화면 위 알림 줄에 쓴다. 상태에 따라 글자가 바뀌는 버튼(예: 정렬 → 오름차순)은 가장 긴 글자에 맞춘 최소 폭을 준다. 키오스크(기기 화면)는 큰 버튼 안에 "확인 중…" 글자를 그대로 둔다 |
| 알림 줄 | `.notice` (+ `.info`, `.success`, `.error`) | 화면 위 연결 상태·결과 한 줄. 기본(노랑)은 주의·연결 확인, `.info`(흰 바탕)는 평소 안내·진행 중, `.success`(초록)는 저장·연결 완료, `.error`(빨강)는 실패. 같은 줄의 종류를 상황에 따라 바꾼다 |
| 상태 상자 | `.status`, `.status.warn` | 안내·주의 문단 |
| 카드 | `.card` | 본문 덩어리, 대화상자 |

| 입력 | `label` + `input` + `.help` + `.error` | 라벨은 위, 도움말은 아래, 오류는 빨간 글자 |
| 선택 상자 | `select` | 입력 칸과 같은 높이·안쪽 여백(글자 시작 위치가 같다). 브라우저 기본 화살표 대신 오른쪽 여백 안에 Feather `chevron-down`(20×20, `--icon-chevron-down`). 비활성은 옅은 바탕·옅은 글자 |

- 아이콘은 1부 12장(Feather 스타일 선형 SVG, 고정 정사각 박스)을 따른다. 새 아이콘은 Feather Icons(feathericons.com, MIT)의 원본 SVG 경로를 그대로 가져와 쓴다(2026-10-12 사용자 지정). 다른 외부 서비스의 아이콘 파일은 가져와 쓰지 않는다.
- CSS 배경으로만 그릴 수 있는 아이콘(선택 상자 화살표 등)은 `assets/hada-tokens.css`에 `--icon-*` 토큰(데이터 URL)으로 두고, 선 색은 그 토큰에만 적는다.
- 이미지 안내는 카드 안에 바로 넣지 않고 `?` 도움말 대화상자로 연다(카드 높이가 흔들리지 않게).

### 기타 화면 공통

- `html`에 `overflow-y: scroll; scrollbar-gutter: stable`(1부 14장)을 공용 스타일에서 건다.
- 로고와 학원 이름은 아래 "로고" 규칙을 따른다(Notion 에셋 "하다 워드마크" 기준).

## 2-5. 금지

- 토큰 밖의 색(16진수, rgb, white/black)을 화면 CSS에 직접 쓰기
- 간격·글자 크기·모서리·레이아웃 폭에 임의 px 쓰기
- HTML의 `style="..."` 속성
- 페이지 바탕을 `--canvas` 외의 색으로 하기, 그라데이션 배경
- 이모지 아이콘(1부 12장)
- 화면별 어두운 모드(브랜드는 밝은 테마 하나만 쓴다)
- `--brand-deep` 외의 포인트 색 추가

## 2-6. 작업 절차

1. 고치기 전 화면을 캡처한다(1280×900·375×812).
2. 토큰과 공용 부품으로 고친다. 새 값이 꼭 필요하면 먼저 `assets/hada-tokens.css`와 이 문서에 추가하고 이유를 적는다. 요청받지 않은 화면은 함께 바꾸지 않는다(1부 11장).
3. `node tests/design-lint.cjs`를 실행한다. 공용 파일(`hada-tokens.css`, `hada-ui.css`, `hada-shortcuts.js`, `admin_auth.js`, `admin_settings.js`)을 고쳤으면 먼저 `node tests/design-lint.cjs --fix`로 화면의 `?v=` 버전 표시를 갱신한다. 버전 표시는 파일 내용의 해시라서 내용이 바뀌면 주소가 바뀌고, 브라우저가 예전 파일(GitHub Pages는 10분 보관)을 쓰지 않는다. 갱신을 빠뜨리면 이 검사가 실패한다.
4. 화면 검사(1부 10장 크기에서 가로 넘침, 버튼 높이 44px 이상, 글자 잘림)를 실행하고 전후 캡처를 비교해 보고한다.
