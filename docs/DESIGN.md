# 하다 학원관리 웹 화면 디자인 기준

이 문서는 하다 학원관리 웹 화면 디자인의 **유일한 현재 기준**이다.

- 언제나 지금 화면이 따라야 하는 최신 기준만 적는다. 무엇을 언제 바꿨는지(버전·날짜·이전 모양)는 적지 않는다. 변경 기록은 `CHANGELOG.md`와 `docs/updates/vX.Y.md`에 둔다.
- 화면 디자인을 바꾸는 작업은 시작 전에 **0장 작업 관문**을 통과해야 한다.
- 기준이 바뀌면 화면보다 이 문서(와 토큰)를 먼저 고친다. 문서와 화면이 다르면 문서가 맞고 화면이 틀린 것이다(문서가 틀렸다면 문서를 먼저 고친 뒤 화면을 고친다).
- Notion "🎨 DESIGN — 웹앱 디자인 규칙"은 이 문서 1부의 옛 사본이다. 기준은 이 문서다.
- 카드뉴스·영상 같은 콘텐츠는 Notion "콘텐츠 디자인 기준"을 따른다. 색 팔레트는 같지만 웹앱의 페이지 바탕은 1부의 전체 캔버스(`#F7F8FA`)를 쓴다.

구성

- **0장 작업 관문**: 디자인 작업 전후에 반드시 거치는 절차
- **1부 웹앱 디자인 규칙**: 모든 웹 화면의 기준. 기준 화면은 학부모 리포트(`student_report.html`)
- **부품 기준표**: 화면 사이에 같아야 하는 부품의 기준 값과 지금 일치 상태
- **2부 관리 화면 공용 토큰·부품**: 1부를 토큰(`assets/hada-tokens.css`)·공용 부품(`assets/hada-ui.css`)·검사(`tests/design-lint.cjs`)로 지키는 규칙과 화면별 규칙

# 0장. 작업 관문

화면 디자인을 바꾸는 모든 작업(새 화면, 부품 추가, 모양 수정, 다른 화면에 맞추기)은 아래 순서를 지킨다.

**시작 전**

1. 이 문서에서 고칠 화면의 절(1부 해당 장, 2부 화면별 규칙)과 **부품 기준표**의 해당 줄을 읽는다.
2. 바꿀 부품이 부품 기준표에 있으면 그 기준 값을 따른다. 기준 화면(학부모 리포트)과 다른 값을 쓰려면 이유를 기준표에 먼저 적는다.
3. 기준에 없는 새 모양·새 값이 필요하면 **이 문서와 `assets/hada-tokens.css`를 먼저 고친다.** 그 뒤 화면을 고친다.
4. 같은 부품이 다른 화면에도 있으면(예: 기록 카드 = 리포트·수업 관리) 이번 작업에서 함께 맞출지, 기준표에 "불일치"로 남길지 정한다. 한쪽만 고치고 아무 데도 남기지 않는 것은 금지다.

**끝난 뒤**

5. `node tests/design-lint.cjs`(공용 파일·리포트 스크립트를 고쳤으면 먼저 `--fix`)를 통과한다.
6. 화면 검사(1부 10장 크기에서 가로 넘침, 누르는 요소 44px, 글자 잘림)와 전후 캡처 비교를 한다.
7. 부품 기준표의 일치 상태를 지금 화면에 맞게 고친다.
8. 이 문서를 다시 읽어 바뀐 기준이 반영됐는지 확인한다. 버전·날짜·"전에는" 같은 경과 설명은 넣지 않는다.

# 1부. 웹앱 디자인 규칙

## 1. 정보 노출 범위

### 학부모 화면에 표시

- 학생명과 등록 클래스
- 교재와 진도
- 출석 캘린더
- 학습기록·과제·평가
- 주간·월간 보고서와 선생님 한마디
- 학생에게 공개 가능한 일정과 휴원 안내

### 항상 제외

- 학교 성적과 성적 이력
- 수강료·교재비·결제금액
- 다른 학생·학부모 정보
- 보호자 전체 연락처와 형제 정보
- 상담 메모와 내부 운영 메모
- Notion 페이지 ID·내부 DB URL
- 관리자 키·토큰·service role key

학교 성적은 학원 내부 운영에서만 확인합니다. 학원 수업 중 진행한 평가와 평가 차트는 계속 표시합니다.

## 2. 화면 구조

- 첫 화면은 학생명·학교/학년과 등록 클래스 선택을 간결하게 보여줍니다. 요약 정보를 첫 화면에 늘리지 않습니다.
- 등록 상세는 홈, 교재, 캘린더, 학습기록, 보고서의 다섯 영역으로 이동하고, 반을 열면 홈이 먼저 보입니다.
- 홈은 그 반의 오늘(출석·남은 과제·다음 수업), 남은 과제, 교재 진도, 최근 선생님 한마디를 모아 보여줍니다. 각 항목은 해당 탭과 같은 카드 모양을 씁니다.
- 모바일에서는 하단 고정 탭바를 사용하고, 선택 탭은 배경과 글자색으로 분명하게 구분합니다.
- 데스크톱에서도 모바일과 같은 정보 순서와 정렬 기준을 유지합니다.
- 카드·달력·탭의 가로 중심선과 좌우 여백은 공통 콘텐츠 폭을 기준으로 맞춥니다.

### 상태 색: Notion 선택지 색을 따른다

선생님이 Notion에서 보는 선택지 색과 웹 화면 색을 같게 합니다. 새 상태가 생기면 Notion 선택지 색부터 정하고 웹을 맞춥니다.

| Notion 속성 | 선택지 → 색 | 웹에서 쓰는 곳 |
| --- | --- | --- |
| 출석 상태 | 출석 초록 · 보강 파랑 · 결석 빨강 | 출석 배지, 달력 출석 칸, 학생 목록 출석 알약 |
| 과제상태(학습활동) | 제출 파랑 · 미제출 빨강 | 제출 배지·알약, 기록 화면 [제출] 토글 |
| 과제상태(합계 수식) | 완료 초록 · 일부 완료 노랑 · 미제출 빨강 | 달력 과제 칸, 막대 칸, 범례 |

- 반 전체를 한 칸에 모은 상태(수업 관리 달력 칸·칩, "제출 n/전체" 알약)는 합계 수식과 같은 3색입니다: 전원·모두 초록, 50% 이상(딱 50% 포함) 노랑, 50% 미만 빨강.
- 색만으로 뜻을 전하지 않습니다. 색 옆에는 늘 글자(배지 글자, 범례 이름, 칩 이름)를 둡니다.
- 아직 결과가 없는 상태(앞으로의 수업, 마감 전, 오늘 미입력)는 색을 칠하지 않고 테두리만, 지난 수업의 미입력은 빗금입니다.

### 점수·비율 4구간

평가 점수와 출석률·과제이행률처럼 0~100으로 읽는 값은 4구간 색입니다.

| 구간 | 색 | 연한 바탕 / 진한 글자 | 도넛(중간 톤) |
| --- | --- | --- | --- |
| 90 이상 | 초록 | `#E8F7F0` / `#0F7B4E` | `#5DBB8A` |
| 70 이상 | 노랑 | `#FFF5D9` / `#7A5200` | `#F3C15A` |
| 50 이상 | 주황 | `#FFF1E0` / `#B54708` | `#F2A06B` |
| 50 미만 | 빨강 | `#FDEBEC` / `#B42318` | `#EC8A85` |

- 쓰는 곳: 평가 점수 알약(리포트 기록·보고서, 수업 관리 "평균 n점"), 리포트 보고서 도넛 세 개(출석률·과제이행률·평가 평균), 수업 관리 반 요약 숫자, 명부 `출석 n%`·`평가 n점` 알약.
- 도넛 트랙(빈 부분)은 `#F5EFE7`. 평가 추이 그래프 선·점은 브라운 그대로.

### 대비

| 쓰임 | 색 | 기준 |
| --- | --- | --- |
| 연한 바탕 위 글자(칸 숫자, 배지·알약, 분류 아이콘 칸의 아이콘·글자, 요약 숫자), 흰 바탕의 색 글자(토·일) | 진한 의미색: 성공 `#0F7B4E`, 오류 `#B42318`, 경고 `#7A5200`, 정보 `#1D5BBF`, 주황 `#B54708` | 글자 대비 4.5:1 이상 |
| 그림(범례 점, 막대 칸, 상태 테두리) | 의미색 그대로(성공 `#16A064`, 오류 `#E5484D`, 정보 `#3478F6`), 경고만 그림용 `#C27E00` | 그림 대비 3:1 이상(흰 바탕·연한 카드 바탕 모두) |
| 가운데 숫자로 값을 읽는 넓은 면적 그림(도넛) | 4구간 중간 톤(위 표) | 숫자가 값을 전하므로 그림 대비 기준 대상이 아님. 원색은 넓은 면적에서 튀어 쓰지 않음 |
| 연한 바탕 | 성공 `#E8F7F0`, 오류 `#FDEBEC`, 경고 `#FFF5D9`, 정보 `#EAF2FF`, 주황 `#FFF1E0` | 글자는 위 진한 의미색 |

- 기본 의미색을 글자에 쓰면 연한 바탕에서 2.0~3.6:1, 흰 바탕에서도 3.4~4.1:1이라 쓰지 않습니다.
- 옅은 글자 `#68727F`도 글자 기준을 넘습니다(흰 4.88, 캔버스 4.59, 연한 카드 4.61). 이보다 옅은 회색 글자(`#AAAAAA`, `#BBBBBB` 등)는 쓰지 않습니다.
- 예외: 도움말 그림 안에서 Notion 화면을 그대로 흉내 낸 부분(관리자 설정 `.mock-save` 등)은 Notion 색을 따릅니다.
- 막대 칸에는 중간 톤을 쓰지 않습니다(칸 색만으로 상태를 읽어야 해서 3:1이 필요).
- 분류 아이콘 색(학습 파랑, 과제 노랑, 평가 초록)은 종류를 나타내며 상태 색과 별개입니다.
- 글자색은 3장 색상표의 기본 `#191F28`·보조 `#4E5968`·옅은 `#68727F`만 씁니다(`#333` 같은 다른 회색 금지). Notion 본문 글자 꾸밈 색은 예외.

## 4. 타이포그래피

```css
font-family: -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
```

- 제목·카드 제목·헤더 이동경로는 명확한 볼드를 사용합니다.
- 설명과 보조정보는 기본 글자보다 한 단계 옅게 표시합니다.
- 너무 작은 글자를 사용하지 않고 모바일에서 확대 없이 읽을 수 있어야 합니다.
- 숫자·날짜·상태 배지는 같은 계층에서 크기와 굵기를 통일합니다.

### 소제목 4단계

| 단계 | 쓰임 | 위치 | 아이콘 | 글자 |
| --- | --- | --- | --- | --- |
| 1 탭 제목 | 교재·캘린더·학습기록·보고서 (홈은 상단 반 이름) | 맨 위, 카드 밖 | 18px | 17px 굵게, 기본색 + 12px 안내 |
| 2 섹션 제목 | 오늘·남은 과제·교재 진도·선생님 한마디·교재 상세의 학습기록 | 카드 밖 바로 위 | 16px | 15px 굵게, 기본색 |
| 3 묶음 라벨 | 학습기록 날짜, 캘린더 선택일, 카드 안 하위 구분(지난 과제·이번 과제·이번 평가·최근 평가 추이) | 카드 밖 또는 카드 안 | 없음 | 13px 중간 굵기, 옅은색 |
| 4 카드 안 작은 라벨 | 요약 칸(남은 과제·다음 수업 등) | 카드 안 | 14px 또는 없음 | 12px 이하, 보조색 |

- 보고서 탭도 같은 규칙이다: 세션 제목(학습·과제·평가·선생님 한마디, 주간·월간의 최근 평가 추이·선생님 한마디)과 묶음 라벨(지난 과제·이번 과제·이번 평가·최근 평가 추이)은 박스 밖, 기록은 하나마다 개별 박스. 요약 카드(출석 현황·과제 현황·평가 현황, 출석률·과제이행률·평가 평균)만 카드 제목(`.donut-title`)을 카드 안에 같은 크기로 가운데 정렬한다.
- 일간 보고서 세션 순서: 요약(출석·과제·평가) → 학습 → 과제(지난 과제 · 이번 과제) → 평가(이번 평가 · 최근 평가 추이) → 선생님 한마디. 기록 박스 머리는 "교재 · 범위" 제목과 단원·날짜만(표지·분류 아이콘 없음). 이번 과제는 출제일 기준, 지난 과제·이날 마감 과제는 마감일 기준이다.
- 기록 박스(보고서·학습기록 탭·교재 상세 공통): 흰 머리 + 박스 아래 끝까지 차는 베이지 본문. 본문은 "라벨 → 내용"을 한 덩어리로 보고, 선은 기록 쪽(수업 자료·출제 내용·평가 문항)과 활동 쪽(학습 결과·제출 내용·풀이·답안) 사이에만 하나 둔다(첫 선 없음). 학습기록 탭·교재 상세는 본문을 접어 두고, 보고서는 늘 펼쳐 둔다.

### 용어

화면마다 같은 뜻은 같은 말로 씁니다. 새 제목·라벨을 만들 때 이 표를 먼저 봅니다.

| 쓰는 말 | 쓰지 않는 말 | 쓰는 곳 |
| --- | --- | --- |
| 탭 제목 = 하단 탭 이름(교재, 학습기록) | 진도 교재, 학습기록 타임라인 | 각 탭 맨 위 제목 |
| 출석 현황 / 과제 현황 | 출결 현황, 출석, 이날 마감 과제 | 캘린더 전환, 일간 보고서 요약 카드 |
| 제출 / 일부 제출 / 미제출 | 완료, 부분완료, 일부 | 과제 배지, 캘린더 범례·막대 |
| 선생님 한마디 | 선생님 코멘트 | 홈, 일간·주간·월간 보고서 (Notion 출석 DB 속성 이름과 같음) |
| 남은 과제 | 곧 마감 | 홈 |
| 교재 진도 | 진도(제목) | 홈 |
| 최근 평가 추이 | 평가 기록(제목) | 일간·주간·월간 보고서 |
| 지난 과제 / 이번 과제 / 이번 평가 | — | 일간 보고서 묶음 이름 |
| 과제이행률 | — | 주간·월간 요약 도넛 |
| 평가 현황 / 평가 평균 | — | 일간 요약 카드 / 주간·월간 요약 도넛 |
| 진행중 / 완료 / 다음 | 진행 중(구분 탭 글자) | 교재 구분 탭 |

- 안내 문구는 "~어요"(해요체)로 씁니다. "~합니다", "~하세요"로 끝내지 않습니다.
- 화면 글자만 바꿉니다. 데이터 값과 CSS 클래스 이름(예: `부분완료`)은 그대로 둡니다.

## 5. 상세 헤더

- 접힌 헤더 높이는 `56px`을 기준으로 합니다.
- 헤더 내부는 높이의 정중앙에 수직 정렬합니다.
- 뒤로가기와 메뉴·새로고침 버튼은 `44×44px` 클릭 영역 안에 `20×20px` 선형 아이콘을 사용합니다.
- 아이콘 배경과 그림자는 사용하지 않고 투명하게 둡니다.
- 뒤로가기는 왼쪽, 메뉴·새로고침은 오른쪽에 대칭 배치합니다.
- 이동경로는 학생명·클래스명·페이지명을 **이모지 없이 텍스트로만** 표시합니다.
- 이동경로 전체를 동일한 볼드 굵기로 표시하며 마지막 항목만 일반 글자로 바꾸지 않습니다. 마지막(지금 화면)을 뺀 경로 글자는 누르면 그 화면으로 갑니다.
- 헤더 안 콘텐츠는 세로 중앙에 맞추고 화면 이동 시 위로 밀려 보이지 않도록 합니다.

## 6. 정렬과 간격

- 한 화면 안의 제목, 탭, 카드, 달력은 같은 좌우 기준선을 사용합니다.
- 등록 상세의 모든 탭(홈·교재·캘린더·학습기록·보고서)과 교재 상세는 본문 폭 `--feed-w`(640px) 하나를 씁니다. 제목·안내 문구·전환 탭·카드·캘린더가 모두 이 폭 안에서 같은 왼쪽 선에 맞춥니다. 캘린더는 폭을 줄이지 않고 화면 높이에 맞춰 칸 높이만 줄입니다.
- 폭을 맞춰야 하는 요소는 서로 다른 px 값을 쓰지 말고 같은 CSS 변수와 `max-width` 공식을 공유합니다.
- 섹션 제목과 첫 카드 사이, 카드와 카드 사이 간격을 화면별로 임의 변경하지 않습니다.
- 빈 상태 문구는 해당 카드나 목록의 중앙에 표시합니다.
- 하단 탭바와 겹치지 않도록 본문 마지막에 안전 여백을 둡니다.
- 새로고침은 떠 있는 버튼으로 두지 않습니다(카드를 가림). 모든 화면에서 오른쪽 위 44×44px 아이콘으로 둡니다: 첫 화면은 메뉴(≡) 왼쪽, 반·교재 상세는 접힌 헤더 오른쪽 끝.

### 크기 단계

- **간격·높이는 4px 단위**입니다: 4, 8, 12, 16, 20, 24, 32, 48. 6·10·14처럼 단계 밖 값은 쓰지 않습니다. 두 단계의 가운데 값이 필요해 보이면 여유 있는 큰 쪽을 씁니다.
- 0~3px는 선 두께·미세 정렬(알약 위아래 안쪽 2px 등)에만 씁니다.
- **글자 크기는 정해진 단계만** 씁니다: 11, 12, 13, 14, 15, 16, 17, 22, 32(모바일 28)px. 4의 배수가 아니어도 됩니다(Apple·Material도 11·13·15를 씀). 11px은 좁은 칸의 작은 라벨(하단 탭 글자, 범례, 칩 이름, 시간표 칸)에만 씁니다.
- **모서리는 정해진 단계만** 씁니다: 3(막대 칸), 6(배지·작은 칸), 10(버튼·칸·아이콘 칸·요약 칸), 14(카드·대화상자), 알약(전환 탭·배지 알약), 원.

### 누르는 영역

- 누르는 요소는 **누르는 영역 44×44px 이상**입니다.
- 보이는 크기는 디자인대로(예: 전환 탭 버튼 32, 펼치기 원 24) 두고, 위아래·옆 투명 여백으로 누르는 영역만 44px로 넓힙니다. 여백 때문에 모양·간격이 달라 보이면 안 됩니다.
- 예외: 캘린더 날짜 칸처럼 격자 때문에 44px을 못 채우는 칸은 칸 전체를 누르는 영역으로 하고 24×24px 이상을 지킵니다. 키오스크 짧은 가로 화면은 2-3 "기기 화면 모드"를 따릅니다.

## 7. 캘린더

- 일정과 출결 캘린더는 같은 폭·셀 크기·요일 헤더 구조를 공유합니다.
- 기간 제목은 좌우 버튼 폭이 같은 3열 구조로 화면 정중앙에 둡니다.
- 날짜 셀의 크기와 간격은 가로·세로 중 더 좁은 화면에 맞춰 줄어들어야 합니다.
- 출결 달력은 일정 달력과 같이 월요일부터 시작합니다.
- 맨 위에 `[출석 현황 | 과제 현황]` 전환 탭을 둡니다.
- 날짜를 탭하면 달력을 그 주 한 줄로 접고 아래에 [⌄ 월 전체 보기]와 그날 내용을 보여줍니다. 같은 날짜를 다시 누르거나 [월 전체 보기]·뒤로가기로 월 보기에 돌아갑니다.
- 수업이 있었던 날만 상태 배경색을 칠하고, 나머지 날짜는 흐리게 하지 않고 숫자만 둡니다. 지난 수업은 실제 출석 행만 기준으로 하고(시간표만으로 칠하지 않음), 출석 행은 있는데 출결 상태가 비어 있으면 연한 빗금(출결 미입력)으로 표시합니다. 앞으로 남은 수업일은 시간표 기준(휴원 제외)으로 베이지 테두리를 둡니다.
- 오늘은 빨간 테두리로 표시해 예정일(베이지 테두리)·선택일(갈색 테두리, 채우지 않음)과 구분합니다. 선택일·오늘·기록일의 테두리와 배경 역할이 서로 겹치지 않게 합니다.
- 칸 색은 3장 "상태 색"을 따릅니다. 수업 날 칸 = 연한 바탕 + 진한 글자.
    - 출석: 연한 초록 / 진한 초록 글자
    - 결석: 연한 빨강 / 진한 빨강 글자
    - 보강: 연한 파랑 / 진한 파랑 글자
- 과제 현황은 과제 마감일 기준입니다. 마감일 칸을 제출(초록)·일부 제출(노랑)·미제출(빨강)로 칠하고, 아직 마감 전인 과제의 마감일만 테두리로 표시합니다. 막대는 그달 마감 과제 수만큼 칸을 나눕니다.
- 범례는 진한 점(●, 그림 색)과 이름만 둡니다. 빗금·테두리는 범례 없이 알아볼 수 있어 범례에 넣지 않습니다.
- 월 보기 달력 위에는 막대 카드를 둡니다. 첫 줄에 `n월 수업`(과제 현황은 `n월 과제`)과 오른쪽 끝 숫자, 둘째 줄에 막대가 카드 폭 전체 한 줄입니다(한 달 20회여도 칸이 좁아지지 않게 글자와 막대를 한 줄에 두지 않음). 막대는 그달 수업 횟수만큼 칸을 나누고 지난 수업 칸부터 그림 색(3장 "대비")으로 채우며 남은 수업은 빈 칸입니다. 숫자는 퍼센트 대신 `지난 수업 / 전체 수업`(예: `3 / 8회`)으로 씁니다. 막대 아래에 상태별 횟수 칩 4개를 둡니다.
- 주간은 최대 26주 전, 월간은 최대 6개월 전까지 이동하도록 제한하고, 한계에 도달한 버튼은 시각적으로 비활성화합니다.

## 8. 카드와 상태 표시

- 카드 모서리·그림자·테두리는 같은 깊이에서 통일합니다.
- 학생 목록은 카드 여러 개보다 한 줄 목록과 얇은 구분선을 우선합니다.
- 일간 보고서 위쪽은 출석·과제·평가 세 칸 요약입니다. 칸마다 `작은 제목 / 상태 배지 / 아래 한 줄`이고, 아래 줄은 비어도 한 줄 높이를 지켜 세 칸 높이가 같습니다: 출석 = 키오스크 등원 시각 "16:52 등원"(하원 시각은 칸이 좁아 넣지 않음), 과제 = "n건", 평가 = "n건". 평가 배지는 1건이면 "90점", 2건 이상이면 "평균 90점"(색은 평가 기록 알약과 같은 단계), 없으면 "해당 없음".
- 주간·월간 보고서 위쪽은 출석률·과제이행률·평가 평균 세 도넛 카드입니다. 같은 크기의 도넛 카드 구조를 사용합니다. 평가 평균은 기간 안 평가 점수의 평균(소수 한 자리, 최근 평가 추이와 같음)을 브라운(평가 추이 선과 같은 색)으로 채우고 아래에 "(평가 n개)", 평가가 없으면 빈 도넛에 "–"와 "(평가 없음)". 폭 480px 이하에서는 세 칸이 들어가게 제목 13px·도넛 68px·배지를 조금 줄입니다.
- 도넛 내부에는 퍼센트, 아래에는 `(완료/전체)` 형식의 건수를 둡니다.
- 데이터가 있는 요약 칸·도넛 카드는 클릭 가능하게 하고, 클릭 시 해당 날·기간의 세부 목록을 평가·과제 상세 모달과 같은 카드 스타일로 보여줍니다(평가는 점수 알약, 기간이면 "날짜:" 줄).
- 교재 목록은 표지(없으면 교재 이름이 들어간 갈색 표지) + 제목 + 진도 막대 + 최근 학습 범위의 카드로 보여줍니다. 테두리 없는 흰 그림자 카드, 화살표 없음.
- 상태 배지 색상은 3장 "상태 색"(Notion 선택지 색)을 따릅니다: 출석 초록, 보강 파랑, 결석 빨강, 과제 제출 파랑, 미제출 빨강, 일부 노랑. 점수는 3장 "점수·비율 4구간". 배지 = 연한 바탕 + 진한 글자.
- 평가 추이는 같은 브라운 계열의 선·점·그리드 구조를 사용합니다.
- 데이터가 없으면 빈 그래프를 억지로 그리지 않고 안내 문구를 보여줍니다.

## 9. 학습기록

- 학습·과제·평가 카드는 같은 기본 구조(`.log-card`)를 사용합니다. 학습기록 탭, 캘린더 날짜 목록, 교재 상세의 기록은 모두 같은 카드 함수로 그린 **독립 카드**입니다. 한 카드 안에 여러 기록을 구분선으로 잇지 않습니다.
- 카드 구조: [분류 아이콘 칸(아이콘 + 구분 글자)] [교재 · 범위(교재 없으면 주제)] [알약: 과제 제출 상태, 평가 점수, 보강] / 아래 줄은 펼치지 않아도 보입니다: 단원(단원 번호마다 한 줄) → 내용(선생님이 적은 글) → 과제 마감. 펼치기(⌄)는 Notion 페이지 본문(글·목록·사진·파일·표)이 있을 때만 있고, 펼치면 본문만 보입니다. 예외: 수업 관리는 본문을 화면을 열 때 미리 읽지 않으므로(속도) 펼치기를 늘 두고, 펼칠 때 그 기록 본문만 읽어 보이며 본문이 없으면 "본문이 없어요"를 보입니다.
- 날짜는 카드 안에 반복하지 않고 날짜 그룹 제목으로 카드 밖에 표시합니다.
- 학습기록 탭은 날짜로만 묶은 타임라인입니다. 오늘 묶음이 맨 위("날짜 (요일) · 오늘", 오늘 카드는 1.5px `#DED1C0` 테두리) → 지난 날짜 최근부터 → 앞으로 날짜는 가까운 날부터 맨 아래. "지난 과제"처럼 따로 모은 묶음을 두지 않습니다.
- 과제 항목은 마감일이 아니라 수업일(출제일) 기준으로 날짜 그룹을 나눕니다. 날짜로 묶인 목록(학습기록 탭, 캘린더 날짜 목록, 교재 상세)에서는 출제일이 묶음 날짜와 같으므로 카드 안에 `마감: YYYY-MM-DD (요일)`만 둡니다. 날짜로 묶이지 않은 곳(기간 모달, 일간 보고서 "지난 과제")에는 `출제:`·`마감:` 두 줄을 둡니다.
- 다음과제·과제이행률처럼 앞으로의 일정을 안내하는 영역에는, 이미 과제상태 배지로 보여준 오늘 마감 과제를 반복하지 않고 마감일이 아직 남은 과제만 포함합니다.
- 과제 상태와 평가 점수는 의미 색상의 배지로 표시합니다.
- 단원·범위·내용은 정보 계층을 분리하고, 값이 없는 줄은 표시하지 않습니다.
- 교재 단원은 라이브러리 교재의 전체 단원 목록을 사용하고 숫자 단원 순서로 다시 정렬합니다.
- 진도가 나간 단원만 완료 표시하고 미진행 단원도 목록에서 숨기지 않습니다.

## 11. 변경 원칙

1. 요청받지 않은 화면과 스타일은 함께 바꾸지 않습니다. 단 같은 부품이 다른 화면에도 있으면 0장 4번을 따릅니다.
2. 비슷한 컴포넌트는 기존 클래스와 색상 함수를 재사용합니다.
3. CSS 숫자를 화면별로 복제하지 말고 공용 변수로 관리합니다.
4. 백엔드 필드를 추가하면 프론트 매핑과 렌더링까지 실제로 소비하는지 확인합니다. 화면에 보이지 않는 정보는 서버에서도 보내지 않습니다.
5. `student_report.html`은 전체 재작성하지 않고 부분 수정합니다.
6. JavaScript 문법 검사와 회귀 검사 후 배포합니다.
7. 실제 모바일·데스크톱 화면에서 정렬을 확인한 뒤 완료로 판단합니다.
8. 변경 기록은 이 문서가 아니라 `CHANGELOG.md`와 `docs/updates/vX.Y.md`에 남깁니다.

## 12. 아이콘

- 모든 아이콘은 이모지가 아니라 Feather Icons 스타일의 선형 SVG를 사용합니다.
- SVG 기준: `viewBox="0 0 24 24"`, `fill: none`, `stroke: currentColor`, `stroke-width: 2`, `stroke-linecap/linejoin: round`.
- 아이콘은 항상 고정된 정사각 박스(width/height)에 넣고 font-size로 크기를 조절하지 않습니다(이모지는 글자마다 폭이 달라 정렬이 틀어집니다).
- 탭바, 헤더(뒤로가기·메뉴·닫기·새로고침), 사이드 메뉴, 아코디언 화살표, 페이지·섹션 제목(`.page-title-icon`), 카드 안 상태·타임라인 아이콘까지 전부 이 규칙을 따릅니다.
- 분류 아이콘: 학습 edit-2, 과제 clipboard, 평가 file-text.
- 클래스(반) 구분색은 이모지 대신 `class_name` 문자열을 해시해 고정 팔레트에서 배경색·글자색 쌍을 고르는 방식(`pickClassColorPalette`)을 사용합니다. 같은 반은 항상 같은 색을 받습니다.

## 13. 텍스트 줄바꿈과 링크

- 반 이름처럼 짧은 한글 구(句)가 들어가는 배지·슬롯(예: 시간표 `.week-slot`)은 `word-break: keep-all`을 사용해 어절 단위로만 줄바꿈합니다.
- 다른 학생(형제자매) 정보처럼 페이지 내부로 이동하는 링크는 파란색 밑줄의 기본 `<a>` 스타일을 쓰지 않습니다. 본문 글자색을 유지하고, 밑줄 대신 옅은 점선 `border-bottom`과 작은 external-link 아이콘으로 클릭 가능함을 표시합니다(`.sibling-link`).

## 14. 스크롤바와 레이아웃 안정성

- `html`에 `overflow-y: scroll; scrollbar-gutter: stable;`을 적용해 스크롤바 유무에 따라 `margin: 0 auto` 중앙 정렬 콘텐츠가 좌우로 밀리지 않도록 고정합니다.

## 15. 뒤로가기

- 브라우저·휴대폰 뒤로가기는 페이지를 벗어나지 않고 앱처럼 직전 동작으로 돌아갑니다(History API, 주소는 바꾸지 않음).
- 열린 창(메뉴·서랍·모달·시트)부터 닫고, 없으면 한 화면 위로. 창을 닫는 ✕·바깥 누르기·Esc도 같은 길로 닫습니다.
- 하단 탭은 쌓지 않습니다: 홈 → 다른 탭만 한 칸이고 다른 탭끼리는 바꿔 씁니다. 다른 탭에서 뒤로가기는 홈으로, 홈에서 뒤로가기는 첫 화면으로.
- 캘린더 날짜 접힘·교재 상세는 한 칸. 처음 연 화면에서는 원래대로 페이지를 나갑니다. 앞으로 가기는 무시합니다.

### 간격

`--space-1` 4 · `--space-2` 8 · `--space-3` 12 · `--space-4` 16 · `--space-5` 20 · `--space-6` 24 · `--space-8` 32 · `--space-12` 48 (px)

- 같은 성격의 간격은 같은 단계를 쓴다: 카드 안쪽 32(휴대폰 20), 카드 사이 16~24, 폼 항목 사이 24, 제목과 설명 사이 12.
- 0~3px는 선·미세 정렬용으로만 직접 쓸 수 있다.
- 6·10·14 같은 단계 밖 값은 쓰지 않는다(1부 6장 "크기 단계"). 필요해 보이면 여유 있는 큰 쪽 단계를 쓴다.

### 모서리·크기

- 모서리(리포트 기준): `--radius-xs` 3(막대 칸) · `--radius-sm` 6(배지·코드) · `--radius-md` 10(버튼·입력칸·상태 상자·칸) · `--radius-lg` 14(카드·대화상자) · `--radius-pill`(전환 탭·숫자 배지·둥근 버튼)
- 카드: 1부 8장대로 모서리·그림자·테두리를 통일한다. 바깥 카드는 **테두리 없이** 흰 표면 + `--shadow-card`. 카드 안의 칸(대시보드 두 칸, DB 카드)은 그림자 없이 `--brand-border` 1px 선으로 나눈다.
- 폭: `--page-max` 1180(모든 화면의 바깥 폭 동일) · `--form-max` 560(입력 폼은 이 폭으로 가운데) · `--feed-w` 640(리포트·수업 관리 본문 폭, 1부 6장) · `--dialog-sm` 440 · `--dialog-md` 600
- 높이: `--control-h` 48(버튼·입력칸), `--control-lg` 56(키오스크 숫자판·등하원 버튼), `--header-h` 56(1부 5장 상세 헤더). 누르는 요소는 최소 44px(`--hit-min`).
- 아이콘 버튼: `--hit-area` 44×44 클릭 영역 안에 `--icon-md` 20×20 선형 아이콘, 배경·그림자 없음(1부 5장).
- 아이콘: `--icon-sm` 14 · `--icon-section` 16(섹션 제목) · `--icon-title` 18(탭 제목) · `--icon-md` 20 · `--icon-lg` 28. 선 아이콘은 `svg.line`(stroke 2, currentColor).

### 로고

- 파일: `assets/brand/hada-wordmark.png`. Notion 에셋 "하다 워드마크"의 brand-deep 버전(투명 배경)이다. 밝은 바탕에만 쓰고, 어두운 바탕이 생기면 같은 에셋의 화이트 버전을 추가한다. 블랙·라이트 원본은 쓰지 않는다.

- 높이: `--logo-h` 36px(모바일 28px), 가로는 비율대로. 늘리거나 색을 바꾸지 않는다.

## 2-3. 레이아웃

- 모든 관리 화면은 `.shell`(바깥 폭 `--page-max`) → `.top`(로고·상단 메뉴·상단 버튼) → `header`(h1·설명) → `.notice`(연결 상태 한 줄) → `.card`(본문) → `.foot` 순서다.
- 화면을 바꿔도 바깥 폭은 그대로 둔다. 입력이 하나뿐인 폼처럼 좁아야 하는 내용은 카드 안에서 `--form-max`로 **가운데** 놓고, 제목도 같이 가운데로 맞춘다.
- 나란히 놓는 구성(대시보드 두 칸, 안내+예시)은 860px 아래에서 위아래로 쌓는다. 카드 목록은 `repeat(auto-fill,minmax(320px,1fr))`, 700px 아래에서 한 줄.
- 확인 화면 크기는 1부 10장과 같다. 어느 크기에서도 가로 스크롤이 생기면 안 된다.
- 부가 정보(보안 설정 현황 등)는 본문을 좁히는 옆 칸 대신 상단 버튼으로 여는 대화상자에 둔다.

### 정렬·간격·줄바꿈 (화면 폭 3단계)

화면 폭은 세 단계로 나눠 본다: **데스크탑**(1081px 이상), **태블릿**(701~1080px), **휴대폰**(700px 이하).

| 대상 | 규칙 |
| --- | --- |
| 바깥 여백 | `.shell` 좌우 32(휴대폰 20). 카드 안쪽 32(휴대폰 20). 카드 안 칸(DB 카드·대시보드 칸)은 16 |
| 세로 간격 | 제목→설명 12, 라벨→입력 8, 입력→도움말 8, 폼 항목 사이 24, 카드 사이 16~24, 알림 줄→카드 24 |
| 입력·선택·날짜 칸 | 높이 48, 글자 시작 왼쪽 16(세 칸 모두 같음). 오른쪽 아이콘은 Feather 20×20, 오른쪽 16에서 세로 가운데(선택 상자 `chevron-down`, 날짜 칸 `calendar` — 기기·브라우저 기본 아이콘과 가운데 정렬은 끈다) |
| 버튼 | 높이 48, 글자는 **한 줄**. 같은 줄 버튼은 높이가 같다. 처리 중에도 크기 그대로(2-4 "처리 중"). 상태에 따라 글자가 바뀌면 가장 긴 글자에 맞춘 최소 폭 |
| 버튼 줄 | 데스크탑·태블릿은 오른쪽 정렬 또는 칸 끝. 휴대폰은 세로로 쌓고 가로 꽉(`.actions`, 아래쪽 단독 버튼 포함) |
| 필터 줄 | 데스크탑 한 줄, 태블릿 3칸(버튼은 칸 너비 가득), 휴대폰 한 칸씩 |

| 줄바꿈 | 한국어는 띄어쓰기 단위(`word-break:keep-all`), 칸보다 긴 낱말만 칸 안에서 끊는다(`overflow-wrap:break-word`). 키·코드·URL처럼 긴 값은 **한 줄 전체 폭**을 주고 그 안에서만 아무 데서나 끊는다(`anywhere`). 좁은 옆 칸에 긴 값을 두지 않는다 |
| 아이콘 | **Feather Icons만**. 예외: 관리자 설정의 Notion 버튼·자동화 종류 표시(`.kind`)는 Notion 모양 아이콘을 그대로 쓴다(사용자 지정). "↗ ▶ ✓ ＋" 같은 글자 기호나 브라우저 기본 아이콘(날짜 달력, 검색 지우기 ×, 접기 ▶)을 아이콘 대신 쓰지 않는다. 글자 옆 14, 칸 안·버튼 20. 새 탭 링크는 `.icon-ext`(arrow-up-right), 접기 제목은 `summary`(chevron-right) |

### 인쇄 문서 구역 (법정 서류)

- 출석부·수강생 대장·영수증 원부처럼 **인쇄해 보관하는 공식 서식**은 화면 토큰을 쓰지 않는다. 흰 바탕·검은 글자·회색 선, 인쇄 크기는 mm, 서식이 정한 칸 높이를 지킨다. 화면 디자인을 바꿔도 이 구역은 건드리지 않는다.
- CSS에서는 `/* design-lint: print-document */`와 `/* design-lint: end */` 사이에 둔다. 디자인 규칙 검사는 이 구역을 건너뛴다. 조회 화면(탭·필터·버튼·열 메뉴)은 구역 밖에 두고 토큰만 쓴다.
- 인쇄할 때(`@media print`)는 상단 바·제목·조회 카드·버튼 줄·꼬리말을 숨기고 출력 문서만 남긴다.
- 스크립트가 만드는 문서 표의 계산된 폭(`style="--day-count`, 열 너비 %)은 허용한다. 화면 HTML에 적힌 `style` 속성만 금지한다.

### 기기 화면 모드 (출결 키오스크)

- 학원 입구 태블릿처럼 한 화면을 꽉 채워 쓰는 화면은 `<html class="device">`로 둔다. 세로 카드(`--device-w` = `min(86vw, 52vh, 640px)`, 최소 높이 = 폭 ÷ 0.6)를 가운데 놓고, 기준 글자 크기(`--device-font` = `max(10px, min(3.82vw, 2.31vh, 28.4px))`, 카드 폭 ÷ 22.5)를 카드 폭에 비례시켜 모든 rem 토큰이 함께 커진다. 카드와 바깥 여백을 합쳐 화면 높이·폭 안에 들어오도록 정한 값이다. 내용이 카드보다 크면(짧은 가로 화면) 카드가 늘어난다. CSS에서 길이를 길이로 나누는 식은 브라우저가 무시하므로 쓰지 않는다. 최소 10px.
- 짧은 가로 화면(812×375, 568×320)에서는 카드가 화면 안에 다 들어오는 것을 우선한다. 이때는 버튼이 44px보다 작아질 수 있다(높이 375px 안에 숫자판 4줄과 등·하원 버튼을 모두 넣어야 하므로). 세로·데스크톱 화면(높이 600px 이상)에서는 44px 이상을 지킨다(`--hit-min`). 기기 모드에서는 스크롤바 자리를 비워 두지 않는다(모달 배경이 화면 끝까지 덮이게).
- 상단 바·제목 줄(`.shell`/`.top`) 대신 카드 안에 아이콘·제목·설명을 가운데 정렬한다. 로고는 넣지 않는다. 로그아웃 같은 부가 버튼은 카드 오른쪽 위 모서리에 둔다.
- 카드 위아래 여백은 같게 둔다(`--space-8`). 내용 높이가 바뀌는 요소(처리 결과 문구 등)를 카드 안에 두지 않고 **결과는 모달**(`dialog.result-dialog`: 아이콘·문구·확인)로 띄운다. 성공·이미 처리는 3초 뒤 자동으로 닫고, 오류는 확인을 눌러 닫는다.
- 카드 맨 아래 여백 안에 학원 이름(`.academy-name`, `--text-caption`, `--text-subtle`)을 한 줄로 작게 겹쳐 둔다(가운데 정렬에 영향 없음). 이름은 서버가 그 학원 Notion 연결이 걸린 루트 페이지 제목에서 가져오므로 화면에 적어 두지 않는다.
- 확인 화면 크기는 1부 10장 기준과 768×1024(세로 태블릿)이다. 모든 경우 카드가 화면 안에 들어와야 한다.

## 2-4. 부품

`assets/hada-ui.css`에 있는 공용 부품만 쓰고, 같은 역할에 다른 모양을 만들지 않는다.

| 부품 | 클래스 | 규칙 |
| --- | --- | --- |
| 주 버튼 | `.primary` (`.inline`=내용 폭) | 한 화면(한 카드)에 하나. 가장 중요한 다음 행동(키오스크는 등원, 법정 서류는 조회) |
| 전환 탭 | `.tabs` | 리포트 `seg-toggle`과 같은 모양(부품 기준표 "전환 탭"): 베이지 트랙(`--brand-soft`) 안에서 선택한 칸만 흰 표면·진한 글자. 같은 화면 안에서 종류를 바꿀 때 |

### 라이브러리 규칙 (`library.html`)

학교 검색과 같은 관리 화면 구조(상단 바 → 제목 → 알림 줄 → 카드)다. 제목 아래 전환 탭 `[라이브러리 열기 | 라이브러리 추가 | 시리즈 관리]`(`.tabs`, 아래 24)로 화면을 바꾼다. [라이브러리 추가]는 카드 두 개(위아래 24). 교재·단원은 아래에서 올라오는 창(휴대폰) / 가운데 창(넓은 화면)에서 고친다.

- **라이브러리 열기**: `교재명으로 찾기` 입력 → "교재 n권 · 시리즈 n개" → 시리즈마다 접기(`details.series`, 제목 17/700 + 옅은 "n권", 기본 펼침). 순서는 Notion 시리즈 선택지 순, 그 밖의 시리즈는 가나다순, 맨 끝 "시리즈 없음".
- **교재 칸**(`.book-btn`): `[표지] [교재명 / 단원 n개 · 사용 중 · 출판사]` 테두리 칸(모서리 `--radius-md`, 안쪽 12), 넓은 화면은 `repeat(auto-fill,minmax(280px,1fr))` 격자, 휴대폰은 한 줄. 누르면 단원 창.
- **라이브러리 추가**: 카드 ① "검색해서 추가": `[교재명 · 시리즈 · ISBN | 검색(보조 버튼)]`(한 글자부터) → 도움말 한 줄 → 체크하면 `.pick-bar`(`--brand-soft` 바탕, `[선택 n권 | 라이브러리에 추가]`, 카드의 주 버튼) → 결과 목록 → 출처 표시. 휴대폰은 막대 안이 위아래로 쌓이고 버튼 가득. 카드 ② "직접 추가": 제목 → 설명 한 줄 → [직접 추가](보조 버튼, 글자 폭, 휴대폰은 가득).
- **시리즈 관리**: 카드 하나. 제목 → 설명 → `[새 시리즈 | 추가(보조 버튼)]` → 머리 `[시리즈 n개 | 편집]`(단원 머리와 같은 `.units-bar`·`.act`) → 시리즈 줄(위 선 `--divider`, 위아래 12) → 맨 아래 도움말. 시리즈 줄 `.series-row`: `[이름 17/700 / 교재 n권] [이름 바꾸기] [삭제]`(삭제는 `.icon-btn` 44에 Feather trash-2 20, 교재가 있는 시리즈는 꺼진 아이콘 `--brand-border`). [이름 바꾸기]를 누르면 그 줄이 `[입력] [저장] [취소]`(Enter 저장, Esc 취소). 휴대폰은 버튼들이 이름 아래 줄 오른쪽 정렬.
  - 순서([라이브러리 열기] 묶음 순서)는 [편집]을 켰을 때만 바꾼다(휴대폰 스크롤과 섞이지 않게): 새 시리즈 입력은 숨기고, 머리는 "손잡이를 끌어서 순서를 바꾸세요", 줄은 `[손잡이 44(Feather menu 20) | 이름 / 교재 n권]`. 손잡이를 누른 채 끌면 그 줄이 따라가고(끄는 줄은 `--brand-soft` 바탕·카드 그림자), 화면 끝 근처에서는 조금씩 스크롤한다. 손잡이에서 위·아래 화살표 키로도 한 칸씩 옮긴다. 목록 아래 `[취소] [순서 저장]`(바뀐 게 없으면 저장 비활성, 휴대폰은 위아래 가득).
  - Notion 선택지에 id가 겹친 것이 있으면 목록 위에 안내 한 줄(다음 변경 때 빠짐).
- **시리즈·출판사 고르기**: 추가 창과 [편집]에서 교재명 아래 `[시리즈 ▾] [출판사 ▾]` 두 칸(라벨 위, 칸 사이 12, 휴대폰은 위아래). 선택지는 Notion 선택지 그대로 + 맨 위 "없음". 검색한 교재는 자동으로 맞춘 값이 미리 골라져 있다. 새 시리즈는 [시리즈 관리]에서 만든다(출판사 선택지는 Notion에서).
- **결과 한 줄**: `[선택 체크] [표지] [교재명 / 출판사 / 자세히] [등록됨]`. 출간일·정가·ISBN13은 기본으로 숨기고 [자세히](접기)를 누르면 한 줄로 보인다(추가에는 그대로 쓴다). 줄 사이는 `--divider` 선, 위아래 16. 교재명을 눌러도 체크된다.
- **선택 체크**(`.check`): 체크박스 20×20(`--icon-md`), 색 `--brand-deep`, 누르는 영역 44×44(`--hit-min`) 칸 가운데. 이미 있는 교재는 체크할 수 없다.
- **표지**(`.cover`): 폭 48(`--space-12`), 3:4, 모서리 `--radius-xs`, `--divider` 선, 빈 바탕 `--brand-soft`. 이미지 순서는 교보문고(ISBN 주소) → 국립중앙도서관·카카오 표지 → 같은 칸에 "표지 없음"(11px, `--text-subtle`). 화면에 보인 표지를 그대로 북커버로 넣는다.
- **등록됨**(`.done-tag`): `--success-soft` 바탕 · `--success-ink` 글자 12/700 알약.
- **창**(`dialog.card.sheet`): `[머리 | 본문 | 아래 버튼]`. 머리 `[닫기 | 제목 가운데 | 등록됨]`, 본문만 위아래로 스크롤. 넓은 화면은 가운데 `--dialog-md` 폭·화면 높이 88% 안, 휴대폰(700px 이하)은 화면 아래에 붙은 높이 92% 창(위 모서리 `--radius-lg`).
  - 직접 추가 교재는 같은 창에서 `교재명`(필수)·`ISBN13`·`표지 이미지 주소`(선택) 입력칸을 위아래로 두고 그 아래 시리즈·출판사 고르기(라벨 위, 칸 사이 16). 표지 주소를 바꾸면 왼쪽 표지만 바뀐다(창을 다시 그리지 않음).
  - 추가 창: 제목 "1 / 6", 아래 점(지금 교재는 길쭉한 점 `--brand-deep`, 추가한 교재는 `--success`). 본문 `[표지] [교재명 입력 / 시리즈·출판사 고르기 / 정보 한 줄(전체 쪽, 북커버)]` → 단원 줄 → [단원 추가] → `목차를 붙여넣어 단원 나누기`(접기, 목차가 없으면 펼친 채). 목차를 못 가져온 책은 안내 줄 아래 `[교보문고에서 보기]`(`.link-chip`, 새 탭, ISBN 검색)로 목차를 복사해 붙여넣게 한다. 아래 `[이전] [다음] [등록하고 다음]`(마지막은 [등록하고 마치기]). 휴대폰은 본문을 좌우로 밀어도 이전·다음. 넘겨도 고친 내용은 남는다.
  - 단원 창(열기): 제목 "단원목록", 본문 `[표지] [교재명 ↗ / 시리즈·출판사·사용]` → 단원 머리 `[단원 n개 | 편집]` → 단원 목록(글자만). 아래 `[닫기]`.
  - 교재명 줄의 Notion 링크는 글자 없이 ↗ 아이콘 버튼 하나(`.icon-btn.ext`, 아이콘 20·누르는 영역 44, 교재명 줄 오른쪽 끝, 새 탭). 추가 창의 "등록했어요" 줄도 같다.
  - 단원 머리 `.units-bar`: 왼쪽 "단원 n개"(12/700 `--text-muted`), 오른쪽 [편집](`.act`, 수업 관리 칸 머리 버튼과 같은 32 알약·12/700·`--brand-soft`, 누르는 영역 44).
  - [편집]을 켜면: 교재 정보 아래에 시리즈·출판사 고르기와 `표지 이미지 주소` 입력 + 작은 버튼 `[교보문고 표지] [다른 표지] [표지 지우기]`(ISBN이 없으면 [표지 지우기]만, 주소를 바꾸면 왼쪽 표지만 바뀜). 모든 단원 줄이 `[삭제 44] [단원명] [시작쪽]` 입력이 되고, 아래 [단원 추가]·목차 붙여넣기. 아래 버튼 `[취소] [저장 · 변경 n건]`(바뀐 것이 없으면 저장 비활성).
  - 삭제 버튼(`.icon-btn.del`, Feather trash-2 20): 누르면 그 줄에 취소선·옅은 글자·입력 잠김, 버튼은 `--danger-soft` 바탕·`--danger-ink` 아이콘(다시 누르면 되돌림). 새로 넣은 줄은 바로 사라진다. 시험범위 등 다른 곳에 연결된 단원은 삭제 버튼을 끄고(아이콘 `--brand-border`) 목록 아래에 "시험범위에 쓰인 단원 n개는 지울 수 없어요" 한 줄.
  - 고친 것을 저장하지 않고 [취소]·[닫기]·Esc를 누르면 버릴지 묻는다. 지운 단원은 Notion 휴지통으로 간다.
- **단원 줄**(`.unit`): `[체크 44] [단원명 입력] [시작쪽 입력 96(휴대폰 72)]`, 입력 높이 44(`--hit-area`). 체크를 끈 줄은 단원명에 취소선·옅은 글자. 대단원 이름은 단원이 아니라 그 묶음 위 12/700 옅은 글자(`.unit-big`). [단원 추가]는 다음 번호("2-2." 다음 "2-3. ")를 미리 채운 빈 줄을 만든다.
- 출처 표시는 [라이브러리 추가] 카드 아래 `.help.source-note`: "도서 정보 출처: 국립중앙도서관 ISBN 서지정보 · 카카오 책 검색 · 표지: 교보문고(없으면 국립중앙도서관·카카오)".

### 수업 관리 규칙 (`class_room.html`)

학부모 리포트와 같은 구조·모양을 쓰는 선생님용 화면이다. 리포트와 같은 부품은 **부품 기준표**를 따르고, 아래는 수업 관리에만 있는 규칙이다.

**공통**

- 본문 폭은 리포트와 같은 `--feed-w`(640): 본문·하단 탭·저장 막대는 `calc(var(--feed-w) + 2*var(--space-4))` 안에 두어 넓은 화면에서도 왼쪽 선이 같다. 모든 폭에서 한 줄 배치이고, 1081px 이상에서는 대화상자만 아래 시트 대신 가운데(`--dialog-md`).
- 상단 바는 화면 폭 전체, 바 안쪽 여백 `--space-2`에 아이콘 버튼(44px)을 붙여 아이콘 그림이 화면 끝에서 20px. 글자(제목·경로)가 바 끝에 오면 `--space-3` 더 들여 같은 20px 선. 첫 화면에는 상단 바가 없다. 로그인 화면 상단 바 제목은 "수업 관리".
- 상단 바 경로: 반 상세 `[← | 강사 › 반 › 탭 | 새로고침]`. 강사 이름 → 첫 화면, 반 이름 → 그 반 홈, "교재" → 교재 탭(지금 화면 글자는 누르지 않음, 누르는 영역 44px, 마우스를 올리면 밑줄). 그 화면이 방문 기록에 있으면 그만큼 뒤로 가고, 없으면 바로 연다. 기록 화면은 `← 클래스명 › 기록 구분` + 오른쪽 ↗. 테두리 버튼 없이 글자만.
- **칸 머리**: 탭·기록 화면은 같은 3줄 머리로 시작한다. ① 제목(탭 제목 단계, 줄 높이 32 고정) ② 안내 한 줄(집계 숫자를 앞에, 굵게) ③ 가운데 전환 탭 + 오른쪽 끝 버튼([편집]·↗). 양쪽 열을 같은 폭으로 고정해 버튼 수와 상관없이 탭이 가운데에 있다. 본문 첫 카드가 상단 바 아래 약 130px에서 시작한다.
- **칸 머리 버튼(`.act`)**: [편집]은 전환 탭과 같은 32px 알약·12px 글자, 누르는 영역 44px, `--brand-soft` 바탕. 칸 머리 오른쪽에만 둔다.
- **편집 모드와 저장**: 체크·입력(출석, 과제 제출, 점수)은 [편집]을 켜고 고친 뒤 아래 막대의 [저장]으로 한 번에 보낸다. 바뀐 줄은 왼쪽 진한 선, 막대에 "변경 n건". 저장하지 않고 나가면 묻는다. 만들기·출제·보강 배정, 메모·선생님 한마디 창은 누르면 바로 실행·저장한다.
- **Notion 링크(↗)**: Feather arrow-up-right 하나만(44px 칸). 상단 바 오른쪽 = 지금 화면의 중심 페이지, 제목 줄 오른쪽 끝 = 그 칸의 중심 페이지, 카드·목록 줄 오른쪽 끝 = 그 줄의 페이지. 주소는 `https://www.notion.so/<페이지 ID>`, 새 탭.
- 상단 바·탭·버튼·칩의 누르는 영역은 모두 44px 이상(전환 탭은 보이는 32px 버튼 위아래 투명 여백 6px, 1부 6장).
- 빈 상태 문구도 카드(`.list`) 안에 둔다. 설명 줄이 빈 목록 줄도 높이가 같다. 체크로 고르는 목록은 체크 칸을 44px 폭에 두어 이름 시작선을 맞춘다.
- 아래 막대와 알림: 저장 막대는 카드와 같은 16px 안쪽. 알림은 하단 탭·저장 막대가 있으면 그 위에 뜨고, 글자 폭만큼 넓게, 두 줄이면 `--radius-lg` 모서리.
- 뒤로가기는 1부 15장. 창·서랍(☰ 사이드바·기록 만들기·메모·보강 수업 만들기·교재 고르기)을 먼저 닫고(교재 고르기는 기록 만들기로), 반 상세·기록 화면·교재 상세·보강 대기실은 들어오기 전 화면으로. 같은 반 안에서 수업만 바꾸면(홈 ‹ ›, 캘린더 날짜) 칸을 쌓지 않는다. 저장하지 않은 편집이 있으면 먼저 묻는다. 학부모 리포트도 같은 규칙(`student_report_part2.js` 끝 "뒤로가기" 블록이 기존 함수를 감싼다).

**첫 화면**

- 리포트 첫 화면(`.intro-section`·`.class-btn`)처럼 상단 바 없이 배경 그대로. 화면 높이 칸 두 개(① 강사·클래스 ② 통합 시간표)를 위아래로 넘기면 칸 단위로 멈춘다(리포트 `.scroll-container`·`.snap-section`). 칸보다 길면 그 칸 안에서 이어서 내려가고, 내용은 위아래 여백으로 가운데에 두어 위가 잘리지 않는다.
- ① 가운데에 "수업 관리"(작은 글자) / 강사 이름(`--text-display` 굵게) / "역할 · 담당 클래스 n개" / 담당 클래스 카드(최대 440, `[이모지] [반 이름] [배지]`, 리포트 `.class-btn`처럼 높이 52·간격 10) / 보강 대기실(점선 카드, 대기 인원). 오른쪽 위 새로고침·☰. 아래 [통합 시간표 보기 ⌄](리포트 `.swipe-hint`)는 카드 아래에 붙는다.
- 클래스는 정렬 순서대로 위 4개만 보이고 나머지는 카드 폭의 옅은 줄 "다른 클래스 n개 ⌄"(`--brand-soft`, 44px, 접힌 반에 오늘 수업이 있으면 " · 오늘 n개 포함")로 접는다. 5개까지는 모두 보인다. 누르면 전부 펼치고 ⌄가 뒤집힌다(기억하지 않음).
- 클래스 카드 배지: 오늘 수업이 있으면 초록 "오늘 17:00", 없으면 다음 수업(이번 주면 요일 "수 19:00", 아니면 "10/21 19:00"), 없으면 "수업 없음". 오늘 수업이 있는 반을 시간순으로 위에, 나머지는 다음 수업 순(서울 날짜·시각 글자로 비교). 카드를 누르면 오늘 수업(진행 중 → 다음 → 마지막) → 다음 수업 → 가장 최근 수업의 반 상세 홈. 클래스는 오늘 앞뒤 4주의 수업(보강 제외)에서 뽑는다.
- ② 통합 시간표: 리포트와 같은 이름·아이콘 "통합 시간표"(17px·아이콘 18) / 안내 12px "담당 반들의 이번 주(10/12 ~ 10/18) 수업을 요일별로 합쳐서 보여줘요" / 카드(폭 `--tt-w` = 리포트 `--content-w`) 안 월~일 7칸(간격 6, 요일 12px, 날짜 숫자 없음, 오늘 요일 빨강) · 수업 칸 `[시작 시각 굵게 / 반 이름]` 11px(`--text-micro`)·안쪽 6/4·모서리 `--radius-sm`, 누르면 그 수업(44px). 위에 [⌃ 이전으로](리포트 `.up-hint`). 반 색은 `--class-1~8-bg/fg`(🟣🔵🟢🟠🔴🟡🟤⚪ 순서): 반 이모지가 이 동그라미면 그 색, 아니면 리포트와 같은 반 이름 해시.
- **☰ 사이드바**: 오른쪽에서 밀려 나오는 서랍(화면 높이 전체, 폭 폰 86%·최대 360px, 바깥은 어둡게, 바깥·✕·뒤로가기로 닫힘, 움직임 줄이기 설정이면 미끄러짐 없음). 머리 "메뉴"(`--text-title`) + ✕(44px), 안쪽 16. 강사 정보(첫 글자 원 + 이름·역할) / 요약 3칸(담당 클래스·학생·이번 주 수업) / [강사 바꾸기 ›](서랍 안이 강사 목록으로 바뀌고, 고르면 닫히며 첫 화면이 그 강사로) / [보강 대기실 ›] / 맨 아래 [이 기기에서 로그아웃].

**반 상세** — 하단 탭 `[홈 | 교재 | 캘린더 | 학습기록 | 학생]`(Feather home·book·calendar·edit-3·users, 리포트 `.reg-tabbar`처럼 아이콘 위·글자 아래). 홈 탭에서만 바 아래 베이지 머리(`[이모지] 반 이름` `--text-title` 굵게 + ↗ / "선생님 · 요일 시각", 요일은 이 반 앞뒤 2주 수업 요일).

- **홈**: "보고 있는 수업" 카드(날짜·시간 + ‹ › 같은 반 이전·다음 수업) / 그날 요약 3칸(리포트 `.home-stats`: 등원 n/전체 — 모두면 초록, 과제 제출 n/전체 — 모두면 초록·아니면 빨강, 다음 수업). "등원"·"과제 제출" 칸은 누르는 칸(라벨 끝 ›)이라 캘린더를 그 날짜로 접은 채 [학생 목록]·[학습 기록]을 연다 / 그날 마감 과제(누르면 그 과제 기록 화면에서 제출을 고친다) / 교재 진도(한 카드에 `[교재명 + 옅은 설명 / 진도 막대·%]`, 진행 중 교재만, 개별 교재 묶음은 "n명 모두" 한 줄, 누르면 교재 상세) / 이 수업 학습기록.
- **교재**: 이 수업 학생들의 교재를 교재 카드(부품 기준표 "교재 카드")로. 안내 "진행상황별로 교재를 볼 수 있어요", 구분 `[진행중 n | 완료 n | 다음 n]`(진행상태가 비어 있으면 진행중, "다음 교재"는 다음, 미사용은 숨김), 묶음(반 교재·개별·학생별)이 하나뿐이면 묶음 이름 생략. 카드를 누르면 교재 상세: 교재 카드(누를 수 없음) / [+ 이 교재로 기록 만들기](진행 중 교재만, 아니면 안내 한 줄) / 학생(이름·최근 범위, 개별 교재면 진도 %) / 이 교재 학습기록(날짜별). 상단 바 `← 반 › 교재 › 교재명` + ↗(진도교재), 하단 탭은 교재가 켜져 있다.
- **캘린더**: 맨 위 `[출석 현황 | 과제 현황]`, 처음엔 이 반 수업 한 달(1부 7장 구조). 리포트와 달리 칸 색은 반 전체 비율이다:
  - 비율 100% 초록(`--success-soft`) · 50% 이상 노랑(`--warning-soft`, 딱 50% 포함) · 50% 미만 빨강(`--danger-soft`).
  - 출석 현황 = 출석(또는 등원 찍음) ÷ 그 수업 학생 수(일부만 입력해도 전체 기준). 지난 수업에 출석을 하나도 넣지 않았으면 빗금, 오늘 아직 하나도 넣지 않았으면 테두리만.
  - 과제 현황 = 그날 마감 과제(앞 수업에서 낸 과제 포함)의 제출 ÷ 그날 마감 학습활동 수(서버 `class-sessions`의 `hwDone`/`hwTotal`). 그날 마감 과제가 없으면 테두리만.
  - 앞으로의 수업은 테두리만. 보고 있는 수업은 채우지 않고 갈색 테두리(`--brand-deep` 2px), 오늘 빨간 테두리.
  - 범례 점 세 개: 출석 `● 전원 출석 ● 50% 이상 출석 ● 50% 미만 출석` / 과제 `● 모두 제출 ● 50% 이상 제출 ● 50% 미만 제출`.
  - 막대 카드(1부 7장): 첫 줄 `n월 수업 … 지난/전체회`(과제 `n월 과제 … 제출/전체 제출`), 둘째 줄 수업마다 한 칸(칸 색 = 달력 칸 색). 칩 4개(출석: 전원 출석 · 50% 이상 · 50% 미만 · 남은 수업 / 과제: 모두 제출 · 50% 이상 · 50% 미만 · 마감 전)는 누르는 버튼(44px): 그 상태의 가장 최근 날(남은 수업·마감 전은 가장 가까운 날)로 접혀 열리고, 0회면 누를 수 없다.
  - 날짜를 누르면 그 수업으로 가며 그 주 한 줄로 접히고(달 이동 버튼 대신 제목만, 막대 카드·범례 없음) 아래 [⌄ 월 전체 보기] · 가운데 전환 탭 `[학생 목록 | 학습 기록]`(아래 한 줄에 집계와 [편집]·↗). 접힌 주에서 다른 날을 누르면 그 수업으로 바꾸고 고른 탭은 그대로.
  - [학생 목록] = 출석 체크(아래 "학생 한 줄"). [학습 기록] = 맨 위 그날 마감 과제 묶음(오늘이면 "지난 과제 · 오늘 마감", 다른 날이면 "날짜 (요일) 마감 과제") → "이 수업 기록"(위 묶음과 겹치는 과제는 한 번만) → [+ 이 수업에 기록 만들기]. 과제 카드를 누르면 그 기록 화면에서 학습활동 제출·미제출을 고친다.
  - Notion 수업 페이지 링크(`?session=`)로 열면 캘린더가 그 날짜로 접힌 채 [학생 목록]이 열린다. 반이 없는 보강 수업은 달력 없이 그 수업의 탭만 보인다.
- **학습기록**: 이 반 앞뒤 수업(9주 전 ~ 5주 뒤, 보강 제외 — 캘린더와 같은 범위)의 기록을 1부 9장 타임라인으로. 보고 있는 수업 날짜 묶음은 `--brand-deep` 글자. 안내 "이 반 최근 기록 · 학습 n · 과제 n · 평가 n". `[전체 · 학습 · 과제 · 평가]` + 오른쪽 아래 떠 있는 [+ 기록 만들기](`--brand-deep` 알약, 본문 오른쪽 끝·하단 탭 위). 반이 없는 보강 수업은 그 수업 기록만.
- **학생**: 위 카드에 반 요약 3칸(보고 있는 수업 달 출석률 · 그 달 과제이행률 · 최근 평가 평균 — 소수 한 자리, 숫자 색은 1부 3장 "점수·비율 4구간")과 "최근 평가 추이 · 반 평균" 그래프(리포트 `buildTestTrendChartHtml`·`.chart-wrap`과 같은 그림: 400×200, 0~100 눈금 20 간격, 선·점 `--brand-deep`, 점 위 "n.n점", 아래 "MM.DD", 폭 최대 480·비율 400:220, 최근 5개). 출석률 = (출석 + 보강, 또는 상태 없이 등원) ÷ 확인된 출석(출석·보강·결석), 미입력·앞으로의 수업 제외. 과제이행률 = 그 달에 마감인 과제 학습활동 중 제출 비율(마감 전 제외). 명부 줄: `[이름 학교 · 학년 … ↗]`(↗ = 학생 보고서 새 탭 `student_report.html?token=…`, 이름과 같은 높이) / 알약 `출석 n%`·`평가 n점`(4구간 색) / 연락처(`학생 010-…`·`우선 010-…`, 누르면 전화)와 보고서 링크 상태("보고서 꺼짐"·"보고서 없음")는 기록 카드와 같은 ⌄ 펼치기 안. 학생 탭을 열 때만 읽는다(`roster`, `class-stats`).
- **기록 카드**: 1부 9장과 부품 기준표 "기록 카드". 리포트와 다른 점: 알약은 학생 한 명의 상태 대신 반 전체 "제출 n/전체"(모두 제출이면 초록·50% 이상 노랑·50% 미만 빨강, 1부 3장 "상태 색"), 평가는 "평균 n점"(4구간 색). 펼치기는 늘 있고, 펼칠 때 그 기록 본문만 읽는다(읽는 동안 "본문을 불러오는 중…", 없으면 "본문이 없어요", 한 번 읽은 본문은 ⟳ 새로고침 전까지 다시 읽지 않음). 카드를 누르면 기록 화면.
- **기록 화면**: 교재 카드(누르면 교재 고르기) / 주제 / 범위 / 내용 / [기록 저장], 아래 학습활동 목록(과제는 제출·미제출, 평가는 맞힌 문항/전체 문항, [편집] → 저장). 학습활동이 없으면 [학생별 기록 만들기 · 과제 출제 · 평가 만들기] 버튼.

**입력 화면**

- **학생 한 줄**: `[이름] [출석 상태] [등원] [하원] [메모]` 한 줄(높이 52, 첫 글자 동그라미 없음). 위에 같은 칸의 열 제목 줄(12px 옅은 글자)을 두고 같은 격자·같은 안쪽 여백(왼쪽 16, 오른쪽 8)을 써서 열 가운데가 맞는다. 등원·하원은 키오스크 스탬프 시각(HH:MM, 없으면 "–", 숫자 폭 고정). 메모 칸은 Feather file-text(44px)이고 메모나 한마디가 있으면 `--brand-soft` 바탕. [편집] 중에는 `[이름] [출석|결석|보강]`만.
- **상태 색**: 1부 3장 "상태 색"·"점수·비율 4구간"·"대비". 연한 바탕 위 글자는 `-ink`, 점·막대는 의미색(노랑은 `--warning-graphic`).
- **메모 창**: 메모 아이콘을 누르면 창(폰은 아래, PC는 가운데)에 날짜·반·등원·하원과 `[메모 | 선생님 한마디]` 전환(전환 탭 기준: 위 안내 문구와 16, 아래 입력칸과 16), 고친 뒤 [저장]하면 바뀐 칸만 바로 저장(탭을 오가도 적던 글자 유지). 빠른 입력 "+ 교재 두고 옴 / + 과제 안 해 옴 / + 집중 좋음 / + 조퇴"는 메모에만, 끝에 ", "로 붙인다. 아래 안내: 메모는 학부모에게 안 보여요 / 선생님 한마디는 다음 리포트 새로고침 때 학부모 화면에 반영돼요.
- **+ 기록 만들기**: 한 장에서 클래스(보고 있는 날짜의 내 수업, 기본은 지금 수업, 반 이름만 — 같은 이름이 둘이면 시간을 붙임) → 교재 → 구분 `[학습 | 과제 | 평가]`(가로 3등분, 글자 앞 분류 아이콘 14px `-ink` 색) → 주제(교재 없이는 필수) → 범위 → 내용 → [기록 만들기]. 교재 칸은 고른 표시가 필요한 테두리 교재 카드: `[표지 3:4, 72×96] [교재명(한 줄) / 설명(반 교재·n명·쪽수) / 진도 막대·% / ✎ 최근 범위]`, 표지와 카드 테두리 사이 위·왼쪽·아래 12px. 고르기 전에는 점선 카드 "교재 비어 있음 / 눌러서 이 반 학생들의 교재 고르기", 누르면 같은 창이 "교재 고르기" 카드 목록(반 교재 / 개별 교재 "n명 모두"·학생별 / 학생별 교재 / 교재 없이)으로 바뀌고 고르면 적던 내용 그대로 돌아온다. 표지는 Notion 라이브러리 "북커버"(그림이 안 열리면 책 아이콘). 만든 뒤 기록이 하나면 그 기록 화면, 여럿이면 학습기록 목록. 보고 있는 날짜에 수업이 없으면 "Notion에서 수업 페이지를 먼저 만들어 주세요"만, 오늘이 아닌 날이면 "오늘 수업이 아닙니다. ○/○ 수업으로 기록을 만들까요?"를 묻는다. 기록 화면의 교재 칸도 같은 카드(지금 교재는 진행 중이 아니어도 보임, 이 수업 학생들의 교재 목록에 없으면 "연결된 교재").
- **내용 글머리**: 내용 칸은 줄 맨 앞 "- "·"* "를 "  • "로 바꾸고, 글머리 줄에서 Tab은 한 단계 들여쓰기("      ◦ " → "          ▪ ", 4칸씩·3단계까지), Shift+Tab은 내어쓰기. Enter는 다음 줄에 같은 단계 글머리, 빈 글머리 줄 Enter와 글머리 바로 뒤 Backspace는 한 단계 내어쓰고 첫 단계면 글머리를 지운다. 글머리가 아닌 줄의 Tab은 원래대로 다음 칸으로. 한글 조합 중에는 건드리지 않는다. 저장은 글자 그대로라 리포트·Notion에서도 "•"로 보인다.
- **수업 한 줄**: `[클래스 이모지] [클래스명] [등원 n/전체] [수업 시간]`. 이모지는 Notion 클래스 "이모지"(없으면 페이지 아이콘, 그것도 없으면 리포트와 같은 반 이름 색 이모지) — 데이터의 이모지라 1부 12장의 이모지 아이콘 금지와 별개. 등원 0명 회색, 일부 노랑, 모두 초록. 보강 수업은 이모지 자리에 "보강".

**캘린더 모양**: 학부모 리포트 캘린더(`.attendance-calendar`, `buildRegCalendarHtml`)와 같은 구조·모양: ‹ 2026년 10월 [오늘] ›, 월요일 시작, 토 파랑·일 빨강. 카드 안쪽 12, 제목 16, 이동 버튼 32, 요일 12, 칸 간격 4, 날짜 칸 가로 4 : 세로 5(칸 높이 최대 72px, 달력 폭 기준)·숫자 16·모서리 10. 리포트 일정 탭·캘린더 탭도 같은 값(`student_report.html` 끝 "캘린더 공통 모양"). 이동·오늘 버튼은 누르는 영역 44px, 날짜 칸은 7칸 격자라 좁은 폰에서 44px을 못 채우므로 44px 규칙의 예외(칸 전체가 버튼, 간격 4px).

### 기타 화면 공통

- `html`에 `overflow-y: scroll; scrollbar-gutter: stable`(1부 14장)을 공용 스타일에서 건다.
- 로고와 학원 이름은 2-2 "로고" 규칙을 따른다.

## 2-5. 금지

- 토큰 밖의 색(16진수, rgb, white/black)을 화면 CSS에 직접 쓰기
- 간격·글자 크기·모서리·레이아웃 폭에 임의 px 쓰기
- HTML의 `style="..."` 속성
- 페이지 바탕을 `--canvas` 외의 색으로 하기, 그라데이션 배경
- 이모지 아이콘(1부 12장)
- 화면별 어두운 모드(브랜드는 밝은 테마 하나만 쓴다)
- `--brand-deep` 외의 포인트 색 추가
- 이 문서에 버전·날짜·이전 모양 같은 변경 경과 적기(0장)

## 2-6. 버전 표시와 검사

- 공용 파일(`hada-tokens.css`, `hada-ui.css`, `hada-shortcuts.js`, `admin_auth.js`, `admin_settings.js`, `class_room.js`)이나 학부모 리포트 스크립트(`student_report_part1.js`, `student_report_part2.js`)를 고쳤으면 `node tests/design-lint.cjs --fix`로 화면의 `?v=` 버전 표시를 갱신한다. 버전 표시는 파일 내용의 해시라서 내용이 바뀌면 주소가 바뀌고, 브라우저가 예전 파일(GitHub Pages는 10분 보관)을 쓰지 않는다. 갱신을 빠뜨리면 검사가 실패한다.
- 학원별 설정 파일 `hada_config.js`는 일부러 버전 표시를 붙이지 않는다. 붙이면 학원마다 화면 파일 내용이 달라져 업데이트 때 화면 파일을 통째로 바꿀 수 없다.
- 작업 순서는 0장을 따른다.

## 2-7. 정한 것

- 인쇄 화면(법정 서류)은 "인쇄 문서 구역"으로 화면 토큰과 분리한다.
- 콘텐츠(카드뉴스·영상)는 Notion "콘텐츠 디자인 기준"(베이지 바탕), 웹앱은 1부(캔버스 `#F7F8FA` + 흰 카드)를 따른다.
- 색의 의미·대비, 크기 단계, 누르는 영역은 1부 3장·6장이 기준이다. 근거는 WCAG 2.2(글자 대비 1.4.3 4.5:1, 그림 대비 1.4.11 3:1, 누르는 영역 2.5.8 24px·2.5.5 44px), Apple HIG(44pt·글자 11~17pt), Material 3(48dp), GitHub Primer·IBM Carbon(4px 단위 간격, 의미 색 역할)이다.
