# v2.6.10 — 시간표 설정은 Notion 자동화로, 교재 생성은 개별 웹훅 + 큐로

- 날짜: 2026-10-15
- 이전 버전: v2.6.9
- 요약: Notion API 호출을 줄이는 웹훅 재정리 첫 단계. 시간표 설정을 서버 없이 Notion만으로 하고, 교재 생성을 등록마다의 개별 웹훅과 큐로 바꾼다.
- 매뉴얼 영향: 있음 → 수강 등록 5-2 버튼 설명(아래 "매뉴얼")
- 변경 유형: 함수(`sync-registration-textbook` 새 경로 `queue`, `process-sync-queue`), Notion 버튼·자동화(운영자 직접). DB 속성·Supabase 테이블·Secrets 변경 없음.
- 원칙: Notion으로 할 수 있는 자동화는 Notion으로, 일괄 작업은 개별 작업 여러 번으로 나누고 웹훅 본문 값을 써서 조회를 줄인다(`docs/설계-웹훅-재정리.md`).

---

## 항목 1. 함수 반영 (먼저)

- **유형**: AI 자동(원본 `supabase/functions/_shared/registrationTextbookTarget.ts`, `supabase/functions/sync-registration-textbook/index.ts`, `supabase/functions/process-sync-queue/index.ts`를 반영하면 함수 자동 배포)
- **선행 조건**: v2.6.9
- **동작**
  - 새 경로 `sync-registration-textbook/queue`: Notion 자동화 웹훅 본문에서 페이지 id와 `클래스`·`이름`을 꺼내 큐(`sync_queue`)에 넣고 바로 202. Notion을 읽지 않는다. `process-sync-queue`가 한 건씩 처리한다.
  - 처리: 클래스 교재 조회 1, 이 등록의 교재 조회 1(관계 25개 제한 없음), 없는 개별교재만 생성(교재명은 라이브러리 복사본, 없으면 라이브러리 페이지), 등록 쓰기 1(`진도교재` + `교재 상태` ✅ 완료 + `마지막 오류` 비우기). `🔄 작업중` 쓰기는 하지 않는다. 실패하면 `⚠️ 오류`와 `마지막 오류`를 쓰고 큐가 최대 3번 다시 시도한다(다시 실행해도 중복 생성 없음).
  - 그룹 교재는 등록의 `진도교재`에만 연결한다. 등록.`진도교재`와 진도교재.`등록`은 하나의 양방향 관계라 템플릿의 `등록`은 Notion이 맞춘다. 예전에는 템플릿 `등록`을 읽고-고치고-다시 썼는데 페이지 조회가 관계를 25개까지만 줘서, 25명이 넘는 반에서 나머지 연결이 지워질 수 있었다.
  - 종료 처리의 교재 정리도 같은 방식(그룹 교재는 등록 쪽에서만 뺀다).
  - 함수 로그: 웹훅 본문 전체를 남기던 곳(`webhookIngest` 공용, `generate-classes`, `sync-dashboard-link`, `sync-registration-class-session`, `sync-registration-textbook`, `sync-textbook-distribution`)을 페이지 id와 키 이름만 남기게 고쳤다. Notion 자동화 본문에는 연락처·리포트 토큰 같은 속성이, 예전 버튼 본문에는 adminKey가 들어 있을 수 있다.
  - 예전 경로 `create-individual`(등록 버튼 웹훅)·`create-class`(클래스 버튼 이어달리기)도 그대로 받고 같은 처리 함수를 쓴다. Notion을 바꾸기 전에 배포해도 그대로 동작한다.
- **Notion 호출(예: 그룹 교재 2, 개별 교재 3인 반의 학생 1명)**: 약 18회 → 6회. 클래스 버튼(6명)은 약 108회 → 36회이고 한 번에 몰리지 않고 큐에서 차례로.
- **검증(원본)**: 함수 테스트(큐 경로가 Notion을 읽지 않음, 처리 Notion 호출 6회·등록 쓰기 1번, 재실행 중복 없음, 실패 시 오류 상태와 재시도, 26번째 학생 연결 때 템플릿을 다시 쓰지 않고 앞 연결 유지, 종료 정리), 전체 Deno 테스트 258, 타입 검사, 회귀 가드. 원본 Notion 스키마에서 등록.`진도교재` ↔ 진도교재.`등록`이 한 쌍임을 확인.
- **미검증**: 실제 Notion 자동화 웹훅 본문 모양(속성 포함 방식)과 큐 처리, 클래스 버튼이 바꾼 등록마다 자동화가 도는지.

## 항목 2. 시간표 설정 버튼 → Notion만으로

- **유형**: 운영자 직접(등록(학원) DB `시간표 설정` 버튼)
- **작업**: 웹훅 보내기 작업을 지우고 "이 페이지 편집" 작업 하나로 세 속성을 정한다.
  - `등록일` → 사용자 지정 수식:
    ```
    if(empty(context("이 페이지").prop("등록일")), today(), context("이 페이지").prop("등록일"))
    ```
  - `종료일` → 비우기
  - `시간표` → 사용자 지정 수식:
    ```
    if(empty(context("이 페이지").prop("시간표")), context("이 페이지").prop("클래스").first().prop("시간표").filter(current.prop("수업 방식") != "개별 수업"), context("이 페이지").prop("시간표"))
    ```
- **확인**: 빈 등록에 누르면 오늘 날짜와 그룹 수업 시간표만, 손으로 바꾼 시간표는 그대로, 종료일이 있으면 지워지고 수강 중으로.
- **알아둘 점**: `등록 상태`·`등록 처리 시작 시각` 속성은 더 쓰지 않는다(지우지 않아도 됨). 등록번호는 법정 서류 화면이 필요할 때 발급한다(전과 같음).

## 항목 3. 교재 생성 버튼·자동화 (항목 1 배포 뒤)

- **유형**: 운영자 직접
- **3-1. 등록(학원) DB 자동화 새로 만들기**
  - 트리거: `교재 상태`가 `⚪ 대기`로 바뀔 때
  - 작업: 웹훅 보내기 → `https://<학원 Supabase 주소>/functions/v1/sync-registration-textbook/queue`, 헤더 `x-admin-key` = 다른 버튼과 같은 웹훅 키(값은 문서에 쓰지 않는다), 포함할 속성: `클래스`, `이름`
- **3-2. 등록 `교재 생성` 버튼**: 웹훅 작업을 지우고 "이 페이지 편집" → `교재 상태` = `⚪ 대기`
- **3-3. 클래스 `교재 생성` 버튼**: 웹훅 작업을 지우고
  1. 변수 정의 `등록학생`:
     ```
     context("이 페이지").prop("등록").filter(current.prop("수강상태") == "🟢 수강 중")
     ```
  2. "`등록학생` 편집" → `교재 상태` = `⚪ 대기`
  - 클래스의 `교재 생성 상태`는 더 쓰지 않는다(편집 작업에 넣지 않는다).
- **확인**: 등록 버튼 → 잠시 뒤 `교재 상태` ✅ 완료, 개별교재 생성·그룹 교재 연결. 클래스 버튼 → 수강 중 학생마다 차례로 ✅ 완료.
- **멈췄을 때**: `교재 상태`가 `⚪ 대기`에 그대로면 자동화가 꺼져 있거나 웹훅 키가 다르다(401). 이미 `⚪ 대기`인 등록은 버튼을 다시 눌러도 값이 그대로라 자동화가 돌지 않으니, 다른 값으로 한 번 바꾼 뒤 누른다.

## 매뉴얼

수강 등록 5-2 버튼 설명을 고친다:

> [시간표 설정]은 등록일이 비어 있으면 오늘로, 종료일은 지우고, 시간표가 비어 있으면 클래스의 그룹 수업 시간표를 연결해요(바로 반영). [교재 생성]을 누르면 교재 상태가 "대기"로 바뀌고, 잠시 뒤 "완료"가 되면 교재가 만들어진 거예요. 클래스의 [교재 생성]은 수강 중인 학생 모두에게 같은 처리를 차례로 해요.
