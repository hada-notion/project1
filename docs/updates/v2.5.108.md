# v2.5.108 — 수업 관리 속도 측정(0단계)

- 날짜: 2026-10-14
- 이전 버전: v2.5.107
- 요약: 수업 관리가 느린 곳을 숫자로 찾기 위해, 함수 `class-room`이 요청마다 서버 처리 시간과 Notion API 호출 수를 응답에 함께 보낸다. 수업 관리를 `?timing=1`로 열면 그 값을 화면 구석에 보여 준다. 데이터를 바꾸지 않고, 평소 화면과 동작은 그대로다. 측정 결과로 Supabase 복사본(다음 단계)의 범위와 순서를 정한다.
- 매뉴얼 영향: 없음
- 변경 유형: 함수 `class-room`(자동 배포) + 웹 화면(Pages). Notion·DB 변경 없음.

---

## 항목 1. 함수 `class-room` 측정값

- **유형**: AI 자동(`main` 병합 시 GitHub Actions가 배포)
- **대상 파일**: `supabase/functions/class-room/index.ts`
- **동작**: 이 함수 안에서만 `fetch`를 감싸 `https://api.notion.com/`으로 가는 요청 수와 기다린 시간을 센다(공용 Notion 모듈은 그대로). 응답 JSON에 `_timing: { ms, notion, notionWaitMs }`를 더한다 — `ms` = 로그인 확인부터 응답까지 서버 처리 시간, `notion` = Notion API 요청 수(재시도 포함), `notionWaitMs` = Notion 응답을 기다린 시간 합(동시에 보낸 요청은 겹쳐 더해짐). 같은 함수 인스턴스가 여러 요청을 동시에 처리하면 서로의 호출이 함께 세어질 수 있는 근사값이다.
- **검증(모의 데이터)**: 전체 함수 `deno check`, Deno 단위 테스트 197개, 회귀 가드.
- **미검증**: 운영 Supabase 런타임에서의 실제 값(배포 후 아래 항목 2로 확인).
- **실패 시 대처**: v2.5.107의 `supabase/functions/class-room/index.ts`로 되돌린다.

## 항목 2. 수업 관리 측정 칸

- **유형**: AI 자동(화면) / 운영자 직접(측정)
- **대상 파일**: `class_room.js`(`api`·`logTiming`), `class_room.html`(`.timing`), `docs/화면-데이터-목록.md`
- **동작**: 주소에 `?timing=1`이 있을 때만 오른쪽 아래(하단 탭 위)에 `동작 · 왕복ms · 서버ms · Notion n회`를 최근 12개까지 보인다(누르기를 막지 않음, 개발자 도구 콘솔에도 같은 값). 없으면 아무것도 하지 않는다.
- **측정 방법(운영자 직접)**: 수업 관리 주소 끝에 `?timing=1`을 붙여 열고 로그인 → 반 하나 열기 → 홈 · 교재 · 캘린더(날짜 하나 누르기, [학습 기록]) · 학습기록 · 학생 탭을 차례로 눌러 각 화면이 다 뜬 뒤 측정 칸을 캡처한다. 학생이 많은 반과 적은 반을 하나씩.
- **검증(모의 데이터)**: 수업 관리 흐름 검사 390·768·1280(평소에는 측정 칸 없음, `?timing=1`이면 `teachers · nms · 120ms · 3회`), 디자인 규칙 검사.
- **미검증**: 운영 측정값.
- **실패 시 대처**: v2.5.107의 `class_room.js`·`class_room.html`로 되돌린다.
