# v2.6.16 — 종료 처리를 Notion 버튼 + 출석 조정으로, 함께 쓰는 학습기록 보호

- 날짜: 2026-10-16
- 이전 버전: v2.6.15
- 요약: 등록 [종료 처리]는 Notion 버튼이 종료일 이후 수업의 명단에서 이 학생을 빼고 그 수업들을 출석 조정 대기로 바꾼다. 출석은 출석 조정 → 삭제 자동화로 지워진다("도착지는 수업", 출석을 지우는 길을 하나로). 출석을 지울 때 이 학생만의 학습기록(개별 진도)만 지우고, 다른 학생도 쓰는 학습기록(그룹 진도·주제로 만든 반 전체 기록)은 이 출석·학생 연결만 끊는다. 예전에는 한 학생을 종료하면 그 출석에 연결된 반 전체 학습기록이 휴지통으로 갔다.
- 매뉴얼 영향: 있음 → 수강 등록 [종료 처리] 설명(아래 "매뉴얼")
- 변경 유형: 함수(`cascade-delete`, `sync-registration-end`), Notion 버튼 1개(운영자 직접). Supabase 테이블·Secrets 변경 없음.
- **선행 조건: v2.6.11(수업 `출석 조정 정보`·출석 조정 자동화), 출석 `삭제 체크` → 삭제 자동화.**

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/learningRecordShare.ts`, `supabase/functions/_shared/cascadeDeleteTarget.ts`, `supabase/functions/_shared/registrationSync.ts`, `supabase/functions/_shared/registrationEndTarget.ts`를 반영하면 함수 자동 배포)
- **학습기록 판단(출석을 지울 때)**

  | 학습기록 | 처리 |
  |---|---|
  | `그룹 진도`가 아니고, 연결된 학생(`등록`)이 지우는 출석의 학생뿐(또는 없음) — 예: 개별 진도 | 함께 삭제 |
  | `그룹 진도`이거나 다른 학생도 연결됨 — 예: 반 전체 진도·교재 없이 주제로 만든 기록 | 삭제하지 않고 기록의 `출석`에서 그 출석, `등록`에서 그 학생만 뺌 |

  진도방식은 학습기록의 `진도교재` → `진도방식`으로 본다.
- **동작**
  - 삭제 자동화(`cascade-delete`): 출석을 지울 때 위 판단을 쓴다. 수업째 지울 때는 예전과 같다(그룹 진도 기록은 수업 연결만 해제, 나머지는 수업과 함께 삭제). 관계를 끊을 때 조회 결과의 관계 전체를 기준으로 써서, 학생이 25명을 넘는 기록에서 나머지 연결이 지워지지 않게 했다.
  - 예전 종료 처리(`sync-registration-end`, 예전 버튼 웹훅): 종료일 이후 출석을 지울 때 같은 판단을 쓴다(나머지 동작은 그대로).
- **검증(원본)**: 함수 테스트(판단: 개별 진도·교재 없는 나만의 기록 삭제, 반 전체 주제 기록·그룹 진도 연결만 해제, 예전 종료 처리 경로, 삭제 자동화 출석 삭제, 수업째 삭제는 예전과 같음), 전체 Deno 테스트, 타입 검사, 회귀 가드.

## 항목 2. 등록 [종료 처리] 버튼 → Notion 버튼 + 교재 정리 웹훅

- **유형**: 운영자 직접(등록(학원) DB `종료 처리` 버튼, 항목 1 배포 뒤)
- **작업**: 기존 웹훅(`sync-registration-end`)을 지우고 아래 순서로 만든다.
  1. 변수 정의 `종료기준`(종료일이 비면 오늘):
     ```
     if(empty(context("이 페이지").prop("종료일")), today(), context("이 페이지").prop("종료일"))
     ```
  2. 변수 정의 `대상수업`(종료기준 다음 날부터의 이 학생 수업, 보강 제외):
     ```
     context("이 페이지").prop("수업").filter(not current.prop("보강") and current.prop("수업일시") >= dateAdd(종료기준, 1, "days"))
     ```
  3. `대상수업` 편집: `등록` → **제거**: 이 페이지, `출석조정 상태` → `⚪ 대기`
  4. 이 페이지 편집: `종료일` → `종료기준`, `시간표` → 비우기
  5. 웹훅 보내기: `https://<학원 Supabase 주소>/functions/v1/sync-registration-textbook/cleanup-on-end`, 헤더 `x-admin-key` = 웹훅 키(값은 문서에 쓰지 않는다). 포함할 속성은 없어도 된다(페이지 id가 함께 감).
- **뜻**: 종료일 다음 날부터의 수업 명단에서 이 학생이 빠지고, 수업마다 출석 조정이 이 학생 출석에 `삭제 체크`를 해 삭제 자동화가 지운다(항목 1 판단으로 학습기록 처리). 종료일 전에 이미 만들어 둔 수업도 함께 정리된다. 시간표에서 빠지므로 다음 [수업추가]·일괄 생성 명단에도 들어가지 않는다. 교재는 예전처럼 "다음 교재"이고 학습기록이 없는 것만 정리된다.
- **알아둘 점**: 보강 수업은 출석 조정이 건너뛰므로 대상에서 뺐다(종료 뒤 보강은 손으로 정리). 다시 눌러도 대상 수업이 없으면 아무 일도 일어나지 않는다. 출석 삭제는 수업마다 큐에서 차례로 처리된다. 등록의 `종료 상태`는 더 쓰이지 않는다.
- **확인**: 종료일이 지난 학생에서 누르면 잠시 뒤 종료일 다음 날부터의 수업 명단·출석에서 그 학생이 빠지고(수업 `출석조정 상태` ✅ 완료), 수업 `생성 오류`의 `📅 날짜범위 밖`이 사라진다.
