# v2.6.24 — 보고서·수강료·교재비 안내 발송을 큐로

- 날짜: 2026-10-17
- 이전 버전: v2.6.23
- 요약: v2.6.20 일일 보고서와 같은 방식으로 바꾼다. 보고서 [보고서 전송], 수강료 [안내문 발송], 교재비 [안내문 전송], 발송함 [일괄 전송]은 대상 페이지의 전송 상태만 ⚪ 대기로 바꾸고, 각 DB 자동화가 `…/queue`로 보내 큐가 한 건씩 처리한다. 서버는 한 건당 페이지를 1번 읽고(⚪ 대기가 아니면 건너뜀 — 두 번 눌러도 한 번), 보낸 뒤 1번 쓴다(✅ 완료·일괄전송 선택 해제·오류 지움). 예전 "발송중" 잠금 쓰기 2번이 없어지고, 보고서는 같은 발송함끼리 공용 캐시와 `리포트 토큰` 롤업으로 리포트 최신화가 가벼워진다. 발송함 [일괄 전송]의 10건씩 이어달리기·전역 잠금이 필요 없어지고, 멈춰도 큐가 이어서 끝낸다.
- 매뉴얼 영향: 있음 → 아래 "매뉴얼"
- 변경 유형: 함수(`send-report`·`send-tuition-notice`·`send-textbook-notice` `/queue` 경로, `process-sync-queue`), 관리자 설정 웹훅 체크리스트, Notion 속성 6개·버튼 4개·자동화 3개(운영자 직접).
- **순서: 항목 1(함수) 배포 → 항목 2(속성) → 항목 3(자동화) → 항목 4(버튼).** 버튼을 먼저 바꾸면 자동화가 없어 아무 일도 일어나지 않는다.
- 호출 수(건당, 코드를 읽어 센 추정): 수강료 안내 약 6~8 → 3, 교재비 안내 약 6~8 → 4, 보고서 약 6 + 최신화 → 3 + 최신화(같은 발송함 둘째 학생부터 가벼움).

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/noticeQueue.ts`, 세 발송 함수, `process-sync-queue`, `admin_settings.js`·`admin_settings.html` 반영 시 자동 배포)
- **동작**:
  - `send-report/queue`, `send-tuition-notice/queue`, `send-textbook-notice/queue`: 큐에 넣고 바로 응답.
  - 큐 처리: 페이지 1번 읽기 → 전송 상태가 ⚪ 대기가 아니면 건너뜀 → (보고서만) 리포트 최신화 → 알림톡 설정(캐시)·수신자(우선 연락 대상이면 페이지의 연락처 롤업·수식) → 발송 → 전송 로그 1건 → 페이지 쓰기 1번.
  - 발송 전 단계에서 실패하면 `마지막 오류`만 적고 큐가 다시 시도한다(상태는 ⚪ 대기 그대로). 발송 단계에서 실패하면 다시 보내지 않고 ⚠️ 오류로 남긴다(이미 나갔을 수 있어 사람이 확인 후 다시 누른다).
  - 예전 버튼 웹훅(`/queue` 없이)과 `send-selected-notifications`도 그대로 동작한다.
- **관리자 설정**: 웹훅 체크리스트에서 보고서·수강료·교재비 안내를 자동화(`/queue`)로 바꾸고, 발송함 [일괄 전송]은 "(예전 방식)"으로 표시한다 — 버튼을 바꾸면 이 웹훅은 쓰지 않는다(39개 유지, 예전 함수는 모든 학원이 옮긴 뒤 정리).
- **검증(원본)**: 함수 테스트(보고서: 한 번 읽기·공용 캐시 키·토큰 롤업·쓰기 1번 / 이미 처리된 건 건너뜀 / 발송 전 실패 → 재시도 / 발송 실패 → ⚠️ 오류·실패 로그 / 교재비 안내문), 전체 Deno 테스트, 타입 검사, 회귀 가드, 관리자 보안 테스트, 디자인 규칙 검사, 화면 검사.

## 항목 2. Notion 속성 추가

- **유형**: 운영자 직접(원본은 커넥터로 추가함)

| DB | 속성 | 유형 |
| --- | --- | --- |
| 보고서(학원) | `전송 상태` | 선택: ⚪ 대기 / ✅ 완료 / ⚠️ 오류 |
| 보고서(학원) | `리포트 토큰` | 롤업: 등록 → 토큰(원래 값 표시) |
| 보고서(학원) | `마지막 오류` | 텍스트 |
| 수강료(학원) | `전송 상태` | 선택: ⚪ 대기 / ✅ 완료 / ⚠️ 오류 |
| 수강료(학원) | `마지막 오류` | 텍스트 |
| 교재비(학원) | `안내문 전송 상태` | 선택: ⚪ 대기 / ✅ 완료 / ⚠️ 오류 |

- 교재비에는 `마지막 오류`가 이미 있다(진도교재 담기와 같이 쓴다).
- (선택) 각 DB의 `실시간 처리상태` 수식이 예전 `발송중` 체크를 보고 있다면, 큐 방식에서는 `발송중`이 바뀌지 않는다. 진행 표시가 필요하면 `전송 상태`가 ⚪ 대기일 때 "전송 대기"를 보이도록 수식을 고친다.

## 항목 4. 버튼 4개 바꾸기

- **유형**: 운영자 직접. 각 버튼에서 웹훅 보내기를 지우고 아래 속성 편집만 남긴다.

| 버튼 | 속성 편집 |
| --- | --- |
| 보고서 [보고서 전송] | `실행자` = 클릭한 사용자, `전송 상태` = `⚪ 대기` |
| 수강료 [안내문 발송] | `실행자` = 클릭한 사용자, `전송 상태` = `⚪ 대기` |
| 교재비 [안내문 전송] | `실행자` = 클릭한 사용자, `안내문 전송 상태` = `⚪ 대기` |
| 발송함 [일괄 전송] | 아래 |

- **발송함 [일괄 전송]**:
  1. 변수 `대상보고서` = `context("이 페이지").prop("보고서").filter(current.prop("일괄전송 선택"))`
  2. 변수 `대상수강료` = `context("이 페이지").prop("수강료").filter(current.prop("일괄전송 선택"))`
  3. 다른 DB 페이지 편집 — 보고서(학원) DB, 대상 `var("대상보고서")`: `전송 상태` = `⚪ 대기`, `실행자` = 클릭한 사용자
  4. 다른 DB 페이지 편집 — 수강료(학원) DB, 대상 `var("대상수강료")`: `전송 상태` = `⚪ 대기`, `실행자` = 클릭한 사용자
  - 발송함 `진행 상황` 수식은 `일괄전송 선택` 기준이라 그대로 진행률을 보여 준다(보낸 건은 서버가 체크를 해제).
- **주의**: 전송 상태가 이미 ⚪ 대기인 건(멈춘 건)은 같은 값으로 다시 바꿔도 자동화가 돌지 않을 수 있다. 그때는 상태를 비우거나 ⚠️ 오류로 바꾼 뒤 버튼을 다시 누른다.
- **확인**: 원본 테스트 학생 1명으로 보고서·수강료·교재비 안내를 각각 한 번 보내 ✅ 완료·전송 로그·발송자를 본다(실제 발송이라 매번 승인).
