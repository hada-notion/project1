# v2.5.5 — 등록 DB 학습정보 수정일 속성 추가

- 날짜: 2026-10-06 (Asia/Seoul)
- 이전 버전: v2.5.4
- 요약: 등록(학원) DB에 `학습정보 수정일` 날짜 속성을 추가해 `mark-report-source-dirty` 공용 웹훅이 등록 페이지의 보고서 원본 변경 시각을 기록할 수 있도록 합니다.
- 매뉴얼 영향: 없음
- 작성자·출처: 강인희 요청·승인, Notion AI 프링글스 작성.
- 변경 유형: Notion 스키마. 실행 코드·Supabase·Secrets 변경 없음.

> 이 패치는 원본 코드가 이미 기대하는 속성을 운영 스키마에 추가하는 보정 패치입니다. 웹훅 자동화 연결과 실제 리포트 반영은 별도 검증 대상입니다.

---

## 항목 1. 등록(학원) DB 속성 추가

- **유형**: AI 자동
- **선행 조건**: 운영 소유자의 전체 계획 승인.
- **변경 이유·증상**: `mark-report-source-dirty`는 공용 상수 `학습정보 수정일`에 현재 시각을 기록하도록 구현되어 있지만, 등록(학원) DB에 해당 속성이 없으면 등록 페이지를 갱신할 수 없습니다.
- **대상 코드**: 없음 (Notion 스키마 변경)
- **Notion 변경**: 등록(학원) DB에 아래 속성을 추가합니다.
  - 날짜 **학습정보 수정일**
  - 표시 형식: `YYYY/MM/DD H:mm`
  - 설명: `보고서에 영향을 주는 원본값이 수정됐을 때 자동화 웹훅이 기록하는 시각.`
  - 초기값: 비워 둠. 기존 등록 페이지의 업무 데이터는 변경하지 않음.
  - 기존 **마지막 동기화** 속성은 유지함.
  - 내부 추적용 속성이므로 기존 수강정보 표 뷰의 표시 속성에는 추가하지 않음.
- **환경별 값**: 없음
- **필요한 Secret (이름만)**: 없음
- **마이그레이션 / 재배포**: 없음
- **검증**:
  1. 등록(학원) DB에 `학습정보 수정일`이 날짜 타입으로 존재하는지 확인한다.
  2. 원본 코드의 `PROP_SOURCE_MODIFIED_AT = "학습정보 수정일"`과 속성명이 일치하는지 확인한다.
  3. 기존 `마지막 동기화`와 기존 등록 페이지 값이 보존되는지 확인한다.
- **실패 시 대처**: 속성 생성이 실패하면 기존 등록 데이터·자동화·코드를 변경하지 않고 중단한다. 동명 속성이 다른 타입으로 이미 존재하면 덮어쓰지 않고 보고한다.
- **매뉴얼**: 변경 없음.

## 항목 2. 등록 DB 자동화 연결 확인

- **유형**: 운영자 직접
- **선행 조건**: 항목 1 완료.
- **변경 이유·증상**: 속성만 추가해도 Notion 자동화가 웹훅을 호출하지 않으면 수정 시각이 갱신되지 않습니다.
- **Notion 변경**: 등록(학원) DB의 보고서 영향 속성 편집 자동화가 운영 Supabase의 `mark-report-source-dirty` 엔드포인트를 호출하는지 확인합니다. 환경별 URL과 관리자 인증값은 운영 설정을 사용하며 이 문서에 기록하지 않습니다.
- **환경별 값**: 운영 Supabase 프로젝트의 `mark-report-source-dirty` 함수 URL과 운영 관리자 인증 설정을 사용합니다.
- **필요한 Secret (이름만)**: 운영 관리자 키
- **마이그레이션 / 재배포**: 없음
- **운영자 안내문**
  - 왜 필요한가: 등록 원본이 바뀌었을 때 보고서 동기화 대상임을 기록하기 위해 필요합니다.
  - 어디서: Notion의 등록(학원) DB → 자동화 설정.
  - 무엇을:
    1. 보고서에 영향을 주는 등록 속성이 편집될 때 실행되는 자동화를 찾습니다.
    2. 웹훅 본문에 현재 페이지의 `pageId`가 전달되는지 확인합니다.
    3. `학습정보 수정일` 자체의 변경은 트리거 대상에서 제외합니다.
  - 입력할 값의 이름: 운영 Supabase의 `mark-report-source-dirty` URL, 운영 관리자 인증값.
  - 끝났는지 확인하는 방법: 승인된 테스트 등록 1건에서 `학습정보 수정일`이 갱신되는지 확인합니다. 실제 학부모 발송은 자동으로 실행하지 않습니다.
  - 흔한 오류와 대처: 속성을 찾지 못한다는 오류가 나면 등록 DB의 속성명·타입과 웹훅 본문의 `pageId`를 확인하고, 관리자 키를 채팅에 기록하지 않습니다.
- **검증**: 자동화 설정을 직접 확인할 수 없는 경우 미검증으로 기록합니다. 실제 웹훅 호출과 학부모 리포트 반영은 별도 승인된 테스트로 진행합니다.
- **실패 시 대처**: 자동화 연결이 확인되지 않으면 속성은 보존하고, 웹훅을 반복 호출하거나 업무 데이터를 수정하지 않습니다.
- **매뉴얼**: 변경 없음.
