# v2.7.11 — 쓰지 않는 옛 웹훅 함수 정리

- 날짜: 2026-10-20
- 이전 버전: v2.7.10
- 요약: v2.7에서 버튼이 Notion 안 동작·큐로 바뀐 뒤 아무 곳에서도 부르지 않던 옛 웹훅 진입 함수 8개와 옛 경로·큐 처리기를 지운다. 관리자 설정 웹훅 체크리스트에서 "(예전 방식)" 5개가 빠져 새 기준 34개만 남는다.
- 매뉴얼 영향: 있음(새 학원 최초 설치·배포 단계 4의 웹훅 항목 — 원본 매뉴얼 반영 완료)
- 변경 유형: 코드(Edge Function 삭제 8개, 수정 4개, 관리자 설정 화면). 마이그레이션·Secrets·Notion 구조 변경 없음.

**선행 조건(필수)**: 운영 Notion 버튼이 v2.7 방식이어야 한다. 클래스 [월 수강료 생성]·[교재비 생성]·[보고서 생성], 발송함 [일괄 전송], 시험정보 [응시학생 등록], 등록 [시간표 설정]·[수업 생성]·[종료 처리], 수업 [보고서 일괄 전송]이 웹훅을 부르지 않아야 한다. 확인 방법은 항목 1. 아직 웹훅을 부르는 버튼이 있으면 이 버전을 적용하지 말고 v2.7 지침(`docs/updates/v2.7.md`)부터 적용한다.

---

## 항목 1. 버튼 방식 확인

- **유형**: AI 자동
- **선행 조건**: 없음
- **변경 이유·증상**: 아래 함수를 지우면, 아직 그 함수를 부르는 버튼은 404로 아무 일도 하지 않는다.
- **확인**: [적용 절차](../기준/적용-절차.md)대로 스캔해 지문과 비교한다. 위 버튼들의 지문이 "같음"이면 v2.7 방식이다. 관리자 설정(`admin_settings.html`) 웹훅 체크리스트의 "이전 키 호출"·"새 키 호출" 표시에 아래 함수가 최근 호출로 나오면 아직 옛 버튼이 남은 것이다.
  - Notion 각 DB 자동화 목록에 버튼과 연결되지 않은 옛 웹훅 자동화 기록(예: 클래스 "교재비 생성" → `from-class-carts`)이 남아 있을 수 있다. 화면에 보이지 않고 실행되지 않으므로 그대로 둔다. 원본 템플릿에도 남아 있다.
- **Notion 변경**: 없음

## 항목 2. 옛 웹훅 함수·경로 삭제 (코드)

- **유형**: AI 자동
- **선행 조건**: 항목 1에서 v2.7 버튼 확인
- **대상 코드**: 원본 `main`과 같게 맞춘다.
  - 저장소에서 삭제: `supabase/functions/` 아래 `generate-tuition`, `generate-report`, `sync-exam-scope`, `send-selected-notifications`, `sync-registration-enroll`, `sync-registration-class-session`, `sync-registration-end`, `send-class-daily-reports` 폴더. `_shared/`의 `generateReportTarget.ts`, `generateTuitionTarget.ts`, `generateShared.ts`, `examScopeTarget.ts`, `registrationEnrollTarget.ts`, `registrationClassSessionTarget.ts`, `registrationEndTarget.ts`, `registrationSync.ts`와 테스트 `generateReportDates_test.ts`, `generateConfigErrors_test.ts`, `examScope_test.ts`.
  - 원본 `main`으로 바꿈: `sync-textbook-distribution/index.ts`(경로는 `/from-cart/queue` 하나만 남음. 예전 `/from-cart`·`/from-class-carts` 삭제), `process-sync-queue/index.ts`(`generate-report`·`generate-tuition`·`from-class-carts` 큐 처리기 삭제), `status-watchdog/index.ts`(위 함수만 쓰던 상태 감시 9개 삭제), `_shared/textbookDistributionTarget.ts`, `_shared/webhookIngest.ts`(백그라운드 웹훅 헬퍼 삭제), `_shared/adminSecurity.ts`(웹훅 경로 목록), `_shared/adminSecurity_test.ts`, `_shared/learningRecordShare_test.ts`, `admin_settings.js`·`admin_settings.html`(체크리스트 "(예전 방식)" 5개 삭제), `scripts/check-known-regressions.sh`, `.github/workflows/deploy-supabase-functions.yml`(지운 테스트 파일 빼기).
  - 찾을 원문 (앵커): `admin_settings.js`의 `'class-tuition','월 수강료 생성 (예전 방식)'`. 없으면 이미 적용된 것이다.
- **환경별 값**: 없음. `admin_settings.html`은 원본 최신본으로 바꾸고 `hada_config.js`는 덮어쓰지 않는다.
- **필요한 Secret (이름만)**: 없음
- **Notion 변경**: 없음
- **마이그레이션 / 재배포**: 마이그레이션 없음. `main` 반영 시 배포 워크플로가 남은 함수를 재배포한다.
- **검증**:
  1. 모든 함수 `deno check`, `deno test`(배포 워크플로 목록), `bash scripts/check-known-regressions.sh` 통과.
  2. 관리자 설정 웹훅 체크리스트가 34개이고 "(예전 방식)" 항목이 없다.
- **실패 시 대처**: 이전 커밋으로 되돌려 재배포한다. 업무 데이터는 바꾸지 않는다.

## 항목 3. 서버에 남은 옛 함수 삭제

- **유형**: 운영자 직접(AI가 Supabase 함수 삭제 권한이 있으면 AI 자동)
- **선행 조건**: 항목 2 배포 성공
- **변경 이유**: 배포는 같은 이름 함수를 덮어쓰고 새 함수를 추가할 뿐, 저장소에서 지운 함수를 서버에서 지우지 않는다.
- **운영자 안내문**
  - 왜 필요한가: 쓰지 않는 옛 함수가 서버에 남아 있으면 옛 주소로 오는 호출을 계속 받는다.
  - 어디서: Supabase 대시보드 → Edge Functions
  - 무엇을: 위 8개 함수 이름이 목록에 있으면 하나씩 열어 삭제한다. 예전 정리 버전(v2.5.21·v2.5.51)에서 지운 `mark-report-source-dirty`, `sync-registration-timetable`, `sync-student-report`, `sync-school-schedules`가 남아 있으면 함께 삭제한다.
  - 끝났는지 확인하는 방법: Edge Functions 목록이 저장소 `supabase/functions/` 폴더 목록(`_shared` 제외)과 같다.
  - 흔한 오류와 대처: 삭제 전 함수 로그에 최근 호출이 있으면 멈추고 어디서 부르는지 확인한다(항목 1).
- **검증**: 서버 함수 목록과 저장소 목록 대조.
