# v2.6.20 — 일일 보고서를 큐로 한 건씩: 몰리지 않고 끝까지

- 날짜: 2026-10-16
- 이전 버전: v2.6.19
- 요약: 출석 [보고서 전송]·수업 [보고서 일괄 전송]은 출석의 `보고서 전송 상태`를 `⚪ 대기`로만 바꾸고, 출석 DB 자동화가 `send-daily-report/queue`로 출석마다 웹훅을 보낸다. 서버는 큐에 넣고 워커가 한 건씩 보낸다 — 연속 클릭·일괄 30명에도 Notion 호출이 몰리지 않고, 멈춘 건은 큐에 남아 이어서 끝난다. 한 건은 출석 1번 읽기 → 리포트 최신화(같은 수업 학생은 공용 캐시) → 발송 → 출석 쓰기 1번. 개별·일괄이 같은 길을 탄다.
- 매뉴얼 영향: 있음 → 아래 "매뉴얼"
- 변경 유형: 함수(`send-daily-report` 새 경로 `queue`, `process-sync-queue`, 알림톡 설정 재사용 5분), Notion 속성 2개·버튼 2개·자동화 1개(운영자 직접). Supabase 테이블·Secrets 변경 없음.

---

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/dailyReportQueue.ts`, `supabase/functions/_shared/dailyReportRefresh.ts`, `supabase/functions/_shared/adminShared.ts`, `supabase/functions/send-daily-report/index.ts`, `supabase/functions/process-sync-queue/index.ts`를 반영하면 함수 자동 배포)
- **한 건 처리(필요한 만큼만 읽기)**
  1. 출석 1번 읽기: 두 번 발송 막기(`전송완료 체크`)와 보고서 수식 값·`학부모 연락처`·`리포트 토큰`을 한 번에. 이미 보낸 건은 `⚠️ 오류`와 안내만 남긴다.
  2. 리포트 최신화(발송 전): 학부모가 링크를 열었을 때 오늘 기록이 보이도록. 같은 수업 학생들은 공용 캐시(5분 단위)로 반 공통 학습기록·교재 페이지를 한 번만 읽는다. `리포트 토큰`이 있으면 등록을 다시 읽지 않는다.
  3. 알림톡 설정(수신 대상·템플릿)은 5분 재사용. 수신 대상이 우선 연락 대상이면 출석의 `학부모 연락처`만 쓰고, 어머니·아버지 등이면 그때만 학생정보를 읽는다.
  4. 발송 → 전송 로그 1건 → 출석 쓰기 1번(`보고서 전송 상태` ✅ 완료, `전송완료 체크`, 오류 지움).
- **실패**: 발송 전 단계에서 실패하면 큐가 다시 시도한다(아직 보내지 않음). 발송 단계에서 실패하면 다시 보내지 않고 `⚠️ 오류`와 이유를 남긴다(실제로 나갔을 수 있어 사람이 확인 후 다시 누른다).
- **예전 경로**: 예전 버튼 웹훅(`send-daily-report` 경로 없음, `send-class-daily-reports`)도 그대로 받는다.
- **검증(원본)**: 함수 테스트(출석 1번 읽기·토큰 재사용·공용 캐시 키·발송 값·출석 쓰기 1번, 이미 보낸 건 건너뜀, 발송 실패 재발송 없음·발송 전 실패 재시도, queue 경로 인증·큐 적재·Notion 읽기 없음), 전체 Deno 테스트, 타입 검사, 회귀 가드.

## 항목 2. 출석(학원) DB 속성 2개 (항목 1 배포 뒤)

- **유형**: 운영자 직접
- `보고서 전송 상태`(선택): 선택지 `⚪ 대기`, `✅ 완료`, `⚠️ 오류`
- `리포트 토큰`(롤업): 관계 `등록` → 속성 `토큰` → "원본 표시"(페이지에서는 숨김). 없어도 동작하지만 있으면 학생마다 등록 읽기 1번이 줄어든다.

## 항목 3. 출석 DB 자동화 새로 만들기

- **유형**: 운영자 직접
- 트리거: `보고서 전송 상태`가 `⚪ 대기`로 바뀜
- 작업: 웹훅 보내기 → `https://<학원 Supabase 주소>/functions/v1/send-daily-report/queue`, 헤더 `x-admin-key` = 웹훅 키(값은 문서에 쓰지 않는다). 포함할 속성: `실행자`(없어도 됨, 출석 페이지 id는 자동으로 감)

## 항목 4. 버튼 2개 바꾸기

- **유형**: 운영자 직접
- **출석 [보고서 전송]**: 웹훅을 지우고 "이 페이지 편집" → `보고서 전송 상태` = `⚪ 대기`(누른 사람을 남기려면 `실행자` = 나 도 함께)
- **수업 [보고서 일괄 전송]**: 웹훅을 지우고
  1. 변수 정의 `대상출석`(아직 보내지 않은 이 수업 출석):
     ```
     context("이 페이지").prop("출석").filter(not current.prop("전송완료 체크"))
     ```
  2. `대상출석` 편집: `보고서 전송 상태` = `⚪ 대기`(필요하면 `실행자` = 나)
- **확인**: 출석 하나에서 [보고서 전송]을 누르면 잠시 뒤 알림톡이 가고 `보고서 전송 상태` ✅ 완료·`전송완료 체크`. 수업에서 [보고서 일괄 전송]을 누르면 학생마다 차례로 ✅ 완료가 된다.
- **알아둘 점**: 버튼은 예전 `보고서 전송중` 체크박스를 쓰지 않는다(예전 일괄 함수가 서버에서 켜는 칸이라, 트리거로 쓰면 두 번 발송될 수 있다). 수업 `보고서 일괄전송 상태`는 더 쓰이지 않는다(진행은 출석마다 상태로 본다).

## 항목 5. 관리자 설정 웹훅 체크리스트 맞추기

- **유형**: AI 자동(원본 `admin_settings.js`, `admin_settings.html` 반영 시 Pages 배포)
- **변경**: 웹훅 키 교체 때 보는 체크리스트를 v2.6.10~v2.6.20 버튼 변경에 맞춘다. 등록 교재 생성 → 자동화(`/queue`, 교재 상태 ⚪ 대기), 종료 처리 → 교재 정리 웹훅(`/cleanup-on-end`), 수업 출석 조정 → 자동화(`/queue`), 수업 날짜 이동 자동화(`/session-date`) 추가, 출석 보고서 전송 → 자동화(`/queue`, 보고서 전송 상태 ⚪ 대기). 웹훅이 없어진 시간표 설정·수업 생성·클래스 교재 생성·시간표 수업추가·수업 보고서 일괄 전송은 목록에서 뺀다(예전 웹훅 주소는 서버가 그대로 받음). 선택 속성 조건(예: `교재 상태 ⚪ 대기`)을 트리거 안내에 표시한다. 항목 44개 → 40개, 바뀐 항목은 새 id라 이전 체크 표시는 남지 않는다.
- **검증(원본)**: 관리자 보안 테스트(체크리스트 경로 = 서버 웹훅 허용 목록, 항목 id 중복 없음), 디자인 규칙 검사, 화면 검사(1280·768·375·812·568 가로 넘침·버튼 44px·글자 잘림, 교재 생성 도움말의 조건 표시).
