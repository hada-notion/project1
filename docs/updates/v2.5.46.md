# v2.5.46 — 관리자 설정도 로그인 공유

- 날짜: 2026-10-12
- 이전 버전: v2.5.45
- 요약: v2.5.44에서 법정 서류·학교 검색만 같은 탭 로그인을 공유했고 관리자 설정은 따로 로그인했다. 서버(`admin-security`)는 세 화면에 같은 종류의 관리자 로그인(같은 유효 시간)을 주므로 따로 받을 이유가 없어, 관리자 설정도 공유하게 했다. 세 화면 중 어디서 로그인하든 같은 탭에서는 비밀번호를 다시 묻지 않는다.
- 매뉴얼 영향: 있음 → v2.5.44 항목 3의 문구를 "관리자 설정·법정 서류·학교 검색은 한 번 로그인하면 같은 탭에서 함께 쓰임"으로 반영한다.
- 변경 유형: 웹 화면(GitHub Pages). 함수·마이그레이션·Secrets·Notion 변경 없음.

## 항목 1. 관리자 설정 로그인 공유

- **유형**: AI 자동
- **선행 조건**: v2.5.44(같은 탭 로그인 공유)
- **대상 파일**: `admin_settings.js`, `admin_settings.html`(`admin_auth.js` 불러오기, 안내 문구), `admin_auth.js`(설명), `legal_documents.html`·`school_search.html`(안내 문구), `docs/DESIGN.md`("로그인 공유"), `docs/updates/v2.5.44.md`(정정 한 줄)
- **변경 내용**
  - 관리자 설정 로그인을 같은 탭 공유 칸(sessionStorage `hada_admin_browser_session_v1`)에 둔다. 다른 두 화면에서 로그인해 두었으면 관리자 설정이 바로 열린다.
  - 초기 비밀번호(0000) 로그인은 공유하지 않는다(관리자 설정 안에서 비밀번호를 바꾸는 데만 쓴다). 바꾼 뒤 다시 로그인하면 공유된다.
  - 로그아웃(관리자 설정은 서버에서도 로그인 해제)하면 세 화면 모두 해제된다. 비밀번호를 바꾸면 서버가 기존 로그인을 모두 끊으므로 세 화면 모두 다시 로그인한다.
  - 저장된 로그인을 서버가 거절(401)할 때만 지운다. 네트워크 오류는 로그인 화면만 보여 주고 다른 화면의 로그인은 그대로 둔다.
  - 예전 관리자 설정 전용 칸(`hada_owner_session_v1`)은 한 번 읽고 지운다.
- **환경별 값 (중요)**: `attendance_kiosk.html`·`legal_documents.html`의 `SUPABASE_URL`·`SUPABASE_ANON_KEY`, `school_search.html`의 `ENDPOINT`는 **운영 값을 유지**한다.
- **검증**: Pages 반영 후 법정 서류에 로그인 → 상단 [관리자 설정]이 비밀번호 없이 열리는지, 관리자 설정에서 로그아웃 → [학교 검색]에서 로그인을 다시 묻는지 본다.
- **실패 시 대처**: v2.5.45의 해당 파일들로 되돌린다. 데이터 영향 없음.
