# v2.7.13 — 회귀 검사가 운영 업데이트 이력을 검사하지 않게

- 날짜: 2026-10-20
- 이전 버전: v2.7.12
- 요약: 회귀 검사(`scripts/check-known-regressions.sh`)의 "폐기한 웹훅 함수 이름" 검사가 운영 저장소의 `docs/operation-update-history.md`까지 검사했다. v2.7.11은 이 문서에 서버에서 지운 함수 목록을 적으라고 안내하므로, 안내대로 기록하면 검사가 실패했다. 이 문서는 패치노트·CHANGELOG처럼 이력이므로 검사에서 뺀다.
- 매뉴얼 영향: 없음
- 변경 유형: 검사 스크립트 1개. Edge Function·마이그레이션·Secrets·Notion·화면 변경 없음.

---

## 항목 1. 회귀 검사 스크립트 교체

- **유형**: AI 자동
- **선행 조건**: 없음
- **변경 이유·증상**: 운영 이력에 지운 함수 이름(`sync-registration-timetable` 등)을 적은 커밋에서 "Web and docs checks"의 `Run regression guard checks`가 "폐기한 웹훅 함수 이름이 다시 들어왔습니다"로 실패한다.
- **대상 코드**: `scripts/check-known-regressions.sh`를 원본 `main` 최신본으로 바꾼다.
  - 찾을 원문 (앵커): 18번 검사의 `--exclude=CHANGELOG.md \` 다음 줄 `--exclude=check-known-regressions.sh . || true)`. 바뀐 뒤에는 그 줄이 `--exclude=operation-update-history.md --exclude=check-known-regressions.sh . || true)`다. 이미 있으면 적용된 것이다.
- **환경별 값**: 없음
- **필요한 Secret (이름만)**: 없음
- **Notion 변경**: 없음
- **마이그레이션 / 재배포**: 없음. 함수가 바뀌지 않으므로 배포 작업이 함수를 다시 올리지 않는다.
- **검증**: `bash scripts/check-known-regressions.sh` 통과. 운영 이력에 지운 함수 이름이 있어도 실패하지 않는다.
- **실패 시 대처**: 스크립트를 이전 버전으로 되돌린다.
- 참고: 이 버전 전에 검사를 피하려고 운영 이력에서 함수 목록을 빼고 시스템 정보에만 둔 학원은 그대로 두어도 된다.
