# v2.7.7 — DB 보기 정리와 나머지 DB 레이아웃

- 날짜: 2026-10-19
- 이전 버전: v2.7.6
- 요약: 업무 DB의 기본 보기·`웹훅 등록` 보기 이름과 열을 한 규칙으로 맞추고(이름 없는 보기에 이름, 내부 열 빼기), v2.7.6에서 남긴 DB(교재배부·교재결제·시간표·시험정보·발송함·학교·일정)의 페이지 레이아웃을 같은 기준으로 맞춘다.
- 매뉴얼 영향: 없음(탭 이름·버튼 이름은 그대로, 버튼 위치만 헤더로 모임)
- 변경 유형: Notion DB 보기(이름·열·정렬), 페이지 레이아웃(화면 설정). 코드·마이그레이션·Secrets·Notion 속성 이름 변경 없음. 업무 데이터는 바꾸지 않는다.
- 기준 문서: [이름 규칙](../이름-규칙.md) 7장 "DB별 최종 형태"와 "DB 보기".

> 항목 1·2(보기)는 커넥터 `update-view`로 바꿀 수 있어 운영 AI가 직접 한다. 항목 3(레이아웃)은 Notion API로 바꿀 수 없어 v2.7.6처럼 넘김 메모로 원본 지원(브라우저)에 넘긴다. 레이아웃 편집기 쓰는 법은 [v2.7.6](v2.7.6.md) "공통"과 같다.

---

## 항목 1. 업무 DB 보기 이름·열 정리 (v2.7.6 DB)

- **유형**: AI 자동(커넥터 `update-view`)
- **선행 조건**: v2.7.3(버튼·상태 속성 이름 표준화)
- **변경 이유·증상**: 기본 보기 열이 2~3개로 줄어 있거나(수업·등록·출석) 반대로 상태·토큰·`일괄전송 선택`까지 다 보였고(보고서 14열), 이름 없는 보기·`표`·`웹훅등록`/`웹훅 등록`이 섞여 있었다. 출석 웹훅 보기에는 `리포트 토큰` 열이 보였다.
- **Notion 변경**: 아래 보기만. 필터는 바꾸지 않는다. 운영 DB에 같은 보기가 없거나 이름이 다르면 그 DB는 건너뛰고 보고한다.

| DB | 기본 보기 이름 → 열 | `웹훅 등록` 보기 |
| --- | --- | --- |
| 수업 | `수업` → 이름·수업일시·클래스·담당강사·출석현황·생성 오류·실시간 처리 상태 | `웹훅등록` → `웹훅 등록`, 열 출석 조정·학습기록 생성·보고서 일괄 전송·삭제·실시간 처리 상태(삭제 체크 뺌) |
| 등록 | `수강정보` → `수강 정보`, 이름·수강상태·클래스·등록일·종료일·수업 요일·학교·학년·실시간 처리 상태 | `웹훅등록` → `웹훅 등록`, 열 시간표 설정·교재 생성·수업 생성·학생 페이지 동기화·종료 처리·링크 재발급·오류 지우기·실시간 처리 상태 |
| 출석 | `표` → `출석`, 출석·수업일시·출석 상태·클래스·보고서 전송·전송완료 체크·전송 내역·실시간 처리 상태 | 삭제 체크·학생 페이지·리포트 토큰 열 뺌 |
| 학습기록 | 이름 없음 → `학습기록`, 학습·구분·수업일·진도교재·범위·학습활동 현황·실시간 처리 상태, 정렬 생성 일시 내림차순 | [단원 입력]·실시간 처리 상태 추가, 삭제 체크 뺌 |
| 학습활동 | 이름 없음 → `학습활동`, 학습활동·구분·수업일·교재·과제상태·과제 마감일·점수·메모, 정렬 생성 일시 내림차순 | 열 학습활동·삭제·수업일·실시간 처리 상태 |
| 보고서 | 이름 없음 → `보고서`, 보고서·보고서 구분·보고서 기간·등록·보고서 전송·발송 횟수·전송 내역·실시간 처리상태 | 보고서 전송 상태·실시간 처리상태 추가 |

- **운영자 안내문**
  - 왜 필요한가: DB를 열었을 때 기본 표에서 필요한 값만 보이고, 학부모 링크 토큰 같은 내부 값이 보이지 않게 한다.
  - 어디서: 운영 AI가 커넥터로 한다. 원장님은 할 일 없음.
  - 끝났는지 확인하는 방법: 각 DB를 열면 첫 보기 이름이 DB 이름이고, 위 열만 보인다.
  - 흔한 오류와 대처: 운영 DB에 원본에 없는 보기가 더 있으면 건드리지 않는다.
- **검증**: `update-view` 응답의 `name`·`displayProperties`가 위 표와 같은지 원문 비교. 관리자 설정 웹훅 체크리스트는 보기 이름을 띄어쓰기 무시하고 찾으므로 `웹훅 등록`으로 바꿔도 그대로 찾는다.
- **실패 시 대처**: 같은 도구로 이름·열을 되돌린다. 데이터 영향 없음.
- **매뉴얼**: 변경 없음

## 항목 3. 나머지 DB 레이아웃

- **유형**: 운영자 직접(원본 지원 브라우저)
- **선행 조건**: v2.7.6을 했으면 좋다(같은 기준). 필수는 아님.
- **변경 이유·증상**: 버튼이 정보 속성 사이에 끼어 있거나(시험정보·발송함) 패널에 있었고(시간표 [수업 추가]), 상태·시작 시각·내부 키가 패널에 보였다. 반대로 `마지막 오류`·`실행자`가 "항상 숨김"이라 오류가 나도 안 보였다(시간표·발송함).
- **Notion 변경**: 페이지 레이아웃(7장 표가 최종 형태)
  - 교재배부
    - 헤더: 결제 상태·라이브러리·배부일·교재비 금액·결제금액·교재비 수기입력 | [결제][삭제] | 실시간 처리 상태. `교재결제`는 헤더에서 내림
    - 패널: 교재결제·삭제 상태·삭제 처리 시작 시각·삭제 체크·클래스 → 항상 숨김. 교재비·등록·마지막 오류 → 비어 있으면 숨김
  - 교재결제(탭 없음)
    - 헤더: 결제일·결제 방법·결제 금액·교재·**결제상태** | **[삭제]** | **실시간 처리 상태**
    - 패널: 교재배부·교재비 안내·마지막 오류 → 비어 있으면 숨김. 삭제 상태·삭제 처리 시작 시각·삭제 체크 → 항상 숨김
  - 시간표(탭 없음)
    - 헤더: 클래스·담당강사·수업 방식·요일·교시·등원시간·하원시간 | **[수업 추가]**(패널 → 헤더) | 실시간 처리 상태
    - 패널: 마지막 오류 → 비어 있으면 숨김(예전 항상 숨김). 상태·처리 시작 시각·`기준일`·`수업 추가 정보` → 항상 숨김. 수업·`웹훅ID`는 그대로 숨김, [클래스 정보 입력]·등록은 그대로
  - 시험정보
    - 헤더 순서: 시험·학교·학년·응시학생 현황·시험일·시험일정 | [응시학생 등록][시험일정 추가] | 실시간 처리 상태
    - 패널: 상태·처리 시작 시각 → 항상 숨김
  - 알림톡 발송함
    - 헤더 순서: 구분·기간·진행 상황 | [일괄 전송] | 실시간 처리 상태
    - 패널: 실행자·마지막 오류 → 비어 있으면 숨김(예전 항상 숨김). 상태·처리 시작 시각 → 항상 숨김
  - 학교: 패널 `학사일정 가져오기 상태` → 항상 숨김(`학사일정 처리 현황`은 결과 건수라 그대로)
  - 일정: 패널 `NEIS 동기화키` → 항상 숨김
  - 시험·성적·라이브러리·대시보드: 변경 없음(이미 기준과 같음)
- **운영자 안내문**
  - 왜 필요한가: 페이지 위쪽에서 버튼을 바로 누르고, 오류가 나면 패널에 보이게 한다.
  - 어디서: 각 DB 보기 설정(⚙) → 추가 설정 → "페이지 레이아웃 사용자 지정"
  - 무엇을: 위 목록대로 헤더 고정 순서를 맞추고(버튼은 고정 해제 후 다시 고정하면 맨 끝으로 간다), 패널 눈 아이콘으로 표시 방식을 바꾼 뒤 [모든 페이지에 적용]
  - 끝났는지 확인하는 방법: 페이지 위쪽이 "정보 → 버튼 → 실시간 처리 상태" 순서다.
  - 흔한 오류와 대처: 패널의 "Add a property"는 새 속성을 만든다. 누르지 않는다.
- **검증**: 커넥터로 데이터 소스를 읽어 `page-layout`의 `pinnedProperties`·`sidebar`가 위와 같은지 원문 비교.
- **실패 시 대처**: 저장 전이면 [취소], 저장 뒤면 같은 편집기에서 다시 고친다(데이터 영향 없음).
- **매뉴얼**: 변경 없음

## 완료 후

1. 운영 AI는 시스템 정보의 현재 버전을 `v2.7.7`로 갱신하고, 이력에 날짜·변경 내용·적용 주체(항목 1·2 운영 AI, 항목 3 원본 지원 브라우저)를 기록한다.
2. 하지 않은 DB가 있으면 보류로 기록한다. DB마다 따로 해도 된다.
