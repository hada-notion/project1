## 항목 1. 함수 반영 (먼저)

- **유형**: AI 자동(원본 `supabase/functions/_shared/fixAttendanceTarget.ts`, `supabase/functions/fix-attendance/index.ts`, `supabase/functions/process-sync-queue/index.ts`를 반영하면 함수 자동 배포)
- **선행 조건**: v2.6.10
- **동작**
  - 새 경로 `fix-attendance/queue`: 자동화 본문의 수식 `출석 조정 정보`와 `클래스`·`수업일시`·`담당강사`·`보강`을 큐에 넣고 바로 202. 처리는 `process-sync-queue`가 한 건씩.
  - 처리: 계획의 `add`는 같은 날 수업 없는 출석이 있으면 연결, 없으면 새로 만든다(그 수업의 학습기록 함께 연결, 과제 마감 대기 연결은 전과 같음). `del`은 `삭제 체크` → 출석마다 삭제 자동화. `roster`가 있으면 수업 명단을 바꾸고 `✅ 완료`와 한 번에 쓴다.
  - 본문에 수식 값이 없으면 수업 페이지를 한 번 읽어 수식 결과를 쓴다(자동화가 여러 DB를 거치는 수식을 "권한 없는 DB 참조"로 막는 경우). 수식 속성 자체가 없으면 예전 방식(수업·등록·출석 조회)으로 맞춘다.
  - 안전장치: 다녀야 할 학생이 0명인데 출석을 지우라는 계획은 실행하지 않고 `⚠️ 오류`로 남긴다(반 전체 종료는 손으로 정리).
  - 고침: 예전 코드가 초과·중복 출석 표시를 출석의 `삭제`(버튼)에 써서 Notion이 거절했다. `삭제 체크`로 고쳤다(예전 경로도).
  - 로그: 본문 전체 대신 페이지 id와 키 이름만.
- **Notion 호출**: 할 일 없는 수업 1(완료 쓰기, 본문에 수식 값이 없으면 +1). 학생 n명 추가면 + n(+ 과제 마감 확인). 예전에는 수업 1건에 상태 3 + 조회 3 + 학생마다 조회 2 이상.
- **검증(원본)**: 함수 테스트(계획 해석·형식 오류 시 예전 방식, 새 출석·학습기록·미연결 출석 연결·삭제 체크·명단과 완료 한 번 쓰기, 보강·skip, 0명 안전장치, 실패 시 오류·재시도, 큐 경로 Notion 읽기 0, 본문에 계획이 없으면 페이지 1번 읽기), 전체 Deno 테스트, 타입 검사, 회귀 가드. 원본 수업 DB에서 수식 결과 확인(10/24 수업 6명 모두 출석 있음 → 할 일 없음).
- **미검증**: 실제 자동화 → 큐 → 출석 생성·연결·삭제 체크.

## 항목 2. 수업(학원) DB 수식 `출석 조정 정보`

- **유형**: 운영자 직접
- **작업**: 수식 속성 `출석 조정 정보`를 만들고 아래를 그대로 붙여 넣는다(페이지에서는 숨김).

```
if(prop("보강") or empty(prop("수업일시")),
  "{\"v\":1,\"skip\":\"" + if(prop("보강"), "보강 수업", "수업일시 없음") + "\"}",
  lets(
    sessionDateTime, prop("수업일시"),
    day, formatDate(prop("수업일시"), "YYYY-MM-DD"),
    roster, prop("등록"),
    sessRecs, prop("학습기록"),
    atts, prop("출석"),
    active, roster.filter(lets(reg, current,
      if(empty(reg.prop("등록일")), true, reg.prop("등록일") <= sessionDateTime) and
      if(empty(reg.prop("종료일")), true, sessionDateTime < dateAdd(reg.prop("종료일"), 1, "days"))
    )),
    activeIds, active.map(id(current)),
    attRegIds, atts.map(current.prop("등록").map(id(current)).join("")),
    addItems, active.filter(not attRegIds.includes(id(current))).map(lets(
      reg, current,
      unl, reg.prop("출석").filter(empty(current.prop("수업")) and formatDate(current.prop("수업일시"), "YYYY-MM-DD") == day),
      recs, reg.prop("학습기록").filter(sessRecs.includes(current)),
      "{\"reg\":\"" + id(reg) + "\",\"att\":\"" + if(empty(unl), "", id(unl.first())) + "\",\"rec\":[" + recs.map("\"" + id(current) + "\"").join(",") + "]}"
    )),
    delAtts, atts.filter(lets(a, current, i, index, rid, a.prop("등록").map(id(current)).join(""), rid != "" and (not activeIds.includes(rid) or attRegIds.slice(0, i).includes(rid)))),
    "{\"v\":1,\"day\":\"" + day + "\",\"add\":[" + addItems.join(",") + "],\"del\":[" + delAtts.map("\"" + id(current) + "\"").join(",") + "]" + if(active.length() == roster.length(), "", ",\"roster\":[" + activeIds.map("\"" + current + "\"").join(",") + "]") + "}"
  )
)
```

- **뜻**: 수업 명단(`등록`) 중 수업일에 수강 기간(`등록일 ≤ 수업일시`, 종료일은 그날 끝까지)인 학생 = 다녀야 할 학생. 그 학생 중 출석이 없으면 `add`(같은 날 수업 없는 출석이 있으면 `att`, 그 학생의 학습기록 중 이 수업 것 `rec`), 명단 밖·중복 출석은 `del`, 기간 밖 학생이 명단에 있으면 `roster`. 보강 수업은 `skip`.
- **확인**: 출석이 모두 있는 수업은 `{"v":1,"day":"YYYY-MM-DD","add":[],"del":[]}`.
- **수식 주의(만들며 겪은 것)**
  - 날짜를 글자로 바꿔 `<=`로 비교하면 Notion이 거짓으로 계산한다. 날짜끼리 비교한다.
  - `empty(종료일) or 수업일시 < dateAdd(종료일, 1, "days")`처럼 쓰면 종료일이 빈 학생도 뒤쪽을 계산해 거짓이 된다. `if(empty(...), true, ...)`로 쓴다. 기존 `생성 오류` 수식에도 같은 형태가 있다(`not(...)`으로 감싸 정상으로 보이지만 별도로 점검 필요).
  - 깊게 중첩된 안쪽에서 `prop("학습기록")`처럼 수업 자기 속성을 부르면 "유효한 속성이 아닙니다"가 난다. 맨 위 `lets`에서 변수로 받아 쓴다.
  - `시간표 → 등록`을 거쳐 학생을 가져오면 비어 나왔다. 수업 명단(`등록`)을 기준으로 한다.

## 항목 3. `출석 조정` 버튼·자동화 (항목 1 배포 뒤)

- **유형**: 운영자 직접
- **3-1. 수업(학원) DB 자동화 새로 만들기**
  - 트리거: `출석조정 상태`가 `⚪ 대기`로 바뀔 때
  - 작업: 웹훅 보내기 → `https://<학원 Supabase 주소>/functions/v1/fix-attendance/queue`, 헤더 `x-admin-key` = 웹훅 키(값은 문서에 쓰지 않는다), 포함할 속성: `출석 조정 정보`, `클래스`, `수업일시`, `담당강사`, `보강`. `출석 조정 정보`가 "이 속성은 내게 사용 권한이 없는 데이터베이스를 참조합니다"로 선택되지 않으면 **웹 브라우저의 Notion에서** 자동화를 열어 선택한다(원본에서 PC 앱은 안 되고 웹에서는 됐다). 그래도 안 되면 빼도 된다(서버가 수업 페이지를 한 번 읽음).
- **3-2. 수업 `출석 조정` 버튼**: 웹훅을 지우고 "이 페이지 편집" → `출석조정 상태` = `⚪ 대기`
- **확인**: 출석 하나의 수업 연결을 끊거나 지운 수업에서 누르면 잠시 뒤 출석이 다시 연결·생성되고 `출석조정 상태` ✅ 완료.
