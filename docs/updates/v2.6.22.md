# v2.6.22 — 학습활동 생성을 큐로, 서버는 만들기만

- 날짜: 2026-10-16
- 이전 버전: v2.6.21
- 요약: 학습기록 [학습활동 생성]을 출석 조정과 같은 방식으로 바꾼다. 무엇을 만들지는 학습기록 수식 `학습활동 계획`이 계산하고(출석마다 학생 1명, 과제는 그 학생의 다음 출석을 마감으로), 버튼은 `활동 생성 상태`만 ⚪ 대기로 바꾸며, 학습기록 DB 자동화가 큐로 보낸다. 서버는 학생마다 하던 출석 읽기·등록 읽기·다음 출석 찾기를 하지 않고 학습활동 만들기만 한다(6명 과제 기준 Notion 호출 약 33 → 약 9). 큐를 거치므로 중간에 멈춰도 이어서 끝나고, 만들기 전에 이 학습기록의 학습활동을 한 번 조회해 이미 있는 학생은 건너뛴다(두 번 눌러도 학생마다 하나).
- 매뉴얼 영향: 있음 → 아래 "매뉴얼"
- 변경 유형: 함수(`create-assignment` `/queue` 경로, `process-sync-queue`), 관리자 설정 웹훅 체크리스트, Notion 수식 1개·버튼 1개·자동화 1개(운영자 직접).
- **순서: 항목 1(함수) 배포 → 항목 2(수식) → 항목 3(자동화) → 항목 4(버튼).** 버튼을 먼저 바꾸면 자동화가 없어 아무 일도 일어나지 않는다.
- 기준(v2.6.21): 학습기록은 수업 기준, 학습활동은 출석 기준.

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/assignmentPlan.ts`, `create-assignment/index.ts`, `process-sync-queue/index.ts`, `admin_settings.js`·`admin_settings.html` 반영 시 자동 배포)
- **동작**:
  - `create-assignment/queue`: 큐에 넣고 바로 응답. 웹훅 본문에 `학습활동 계획` 값이 있으면 함께 넣고, 없으면 큐가 학습기록을 한 번 읽어 수식 값을 쓴다(Notion 자동화는 여러 DB를 거치는 수식을 웹훅 본문에 싣지 않을 수 있다).
  - 큐 처리: 학습활동 DB를 "이 학습기록"으로 한 번 조회 → 이미 있는 등록은 건너뜀 → 나머지 학생마다 학습활동 1개(제목·학습기록·등록·출석·수업, 과제는 🔴 미제출·과제 마감·자동 마감 기준) → `활동 생성 상태` ✅ 완료.
  - 수식 값 형식이 틀리면 만들지 않고 ⚠️ 오류(`마지막 오류`에 이유). 만들다 실패하면 큐가 다시 시도하고, 다시 할 때도 이미 만든 학생은 건너뛴다.
  - 수식이 없거나 값이 잘려 읽을 수 없으면 예전 방식(서버가 학습기록·출석·등록을 읽어 만듦)으로 처리한다.
  - 예전 버튼 웹훅(`create-assignment`, `/queue` 없이)도 그대로 동작한다.
- **관리자 설정**: 웹훅 체크리스트의 학습기록 [학습활동 생성]을 자동화(`/queue`, 활동 생성 상태 = ⚪ 대기)로 바꾼다.
- **검증(원본)**: 함수 테스트(계획 해석·형식 오류, 과제만 마감, 평가는 마감 없음, 이미 있는 학생 건너뜀·같은 학생 두 번 → 한 번, 계획 없으면 예전 방식), 전체 Deno 테스트, 타입 검사, 회귀 가드, 관리자 보안 테스트, 화면 검사.

## 항목 2. 학습기록(학원) DB 수식 `학습활동 계획` 추가

- **유형**: 운영자 직접(원본에는 있음)
- 속성: 이름 `학습활동 계획`, 유형 수식, 학습기록 페이지에서 숨김.

```
if(empty(prop("구분")),
  "{\"v\":1,\"skip\":\"구분 없음\"}",
  lets(
    cat, prop("구분"),
    doneRegs, prop("학습활동").map(current.prop("등록")).flat().map(id(current)),
    items, prop("출석").filter(lets(a, current,
      not empty(a.prop("등록")) and not doneRegs.includes(id(a.prop("등록").first()))
    )).map(lets(
      a, current,
      reg, a.prop("등록").first(),
      t, a.prop("수업일시"),
      nexts, reg.prop("출석").filter(not empty(current.prop("수업일시")) and current.prop("수업일시") > t and not current.prop("삭제 체크")),
      nxt, nexts.sort(current.prop("수업일시")).first(),
      "{\"a\":\"" + id(a) + "\",\"r\":\"" + id(reg) + "\"" +
        if(cat == "과제" and not empty(nxt), ",\"d\":\"" + id(nxt) + "\"", "") +
        ",\"t\":\"[" + cat + "] " + a.prop("출석").replaceAll("\"", "") + "\"}"
    )),
    "{\"v\":1,\"c\":\"" + cat + "\",\"s\":\"" + if(empty(prop("수업")), "", id(prop("수업").first())) + "\",\"items\":[" + items.join(",") + "]}"
  )
)
```

- 뜻: 이 학습기록의 출석마다(학생 1명) 출석·등록·제목을, 과제면 그 학생 등록의 다음 출석(이 출석 뒤, 삭제 체크 제외, 가장 이른 것)을 담는다. 이미 이 학습기록으로 학습활동이 있는 학생은 뺀다. 제목은 출석 이름("학생 MM.DD(요일)")을 쓰므로 날짜가 한국 시간 그대로다.
- **확인**: 과제 기록에서 학생마다 `"d":"…"`가 붙고, 그 값이 그 학생의 다음 출석인지 본다(원본에서 6명 대조 완료). 다음 출석이 아직 없으면 `d`가 없다 — 이때는 지금처럼 `backfill-assignment-deadlines`가 나중에 채운다.

## 항목 3. 학습기록(학원) DB 자동화 — 활동 생성 상태 ⚪ 대기 → 큐

- **유형**: 운영자 직접
- 트리거: `활동 생성 상태`가 `⚪ 대기`로 편집됨
- 동작: 웹훅 보내기 → `…/functions/v1/create-assignment/queue`, 헤더 `x-admin-key`(웹훅 키), 본문에 페이지 속성 포함(가능하면 `학습활동 계획` 포함. Notion이 넣지 못하게 막으면 빼도 된다 — 서버가 학습기록을 한 번 읽는다).
- 관리자 설정 → 웹훅 체크리스트의 학습기록 [학습활동 생성] 항목에서 주소와 키를 복사한다.

## 항목 4. 학습기록 [학습활동 생성] 버튼 바꾸기

- **유형**: 운영자 직접
- 웹훅 보내기를 지우고 `활동 생성 상태` = `⚪ 대기`로 바꾸는 속성 편집만 남긴다.
- **확인**: 버튼을 누르면 잠시 뒤 학생마다 학습활동이 생기고 `활동 생성 상태`가 ✅ 완료가 된다. 한 번 더 눌러도 새로 생기지 않는다.

## (v2.6.21 보충) 진도교재 롤업 정리

- **유형**: 운영자 직접
- 진도교재(학원) DB의 롤업 `수업(등록)`, `수업(클래스)`는 수업 진도교재 관계(v2.6.21)로 대신하므로 지운다. 지우기 전에 진도교재 수식(진행도·최근 학습 범위·최근 학습 내용·실시간 처리 상태)이 이 롤업을 쓰는지 본다.
