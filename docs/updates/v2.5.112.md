# v2.5.112 — 수업 관리 복사본 표 만들기(1단계)

- 날짜: 2026-10-14
- 이전 버전: v2.5.111
- 요약: 수업 관리가 Notion 대신 Supabase에서 읽도록 하는 작업(설계 `docs/설계-수업관리-복사본.md`)의 1단계로, 수업·출석·학습기록·학습활동 복사본 표 4개를 만든다. 이 단계는 빈 표만 만들고 아무 함수도 쓰지 않으므로 화면·동작 변화가 없다.
- 매뉴얼 영향: 없음
- 변경 유형: DB 마이그레이션(자동 적용) + 배포 워크플로 검사 1개. 함수·화면·Notion 변경 없음.

---

## 항목 1. 복사본 표

- **유형**: AI 자동(`main` 병합 시 GitHub Actions가 `supabase db push`로 적용)
- **대상 파일**: `supabase/migrations/20261014050000_class_room_copy.sql`
- **동작**: `cr_sessions`(수업), `cr_attendance`(출석), `cr_records`(학습기록), `cr_activities`(학습활동)를 만든다. 열은 수업 관리 화면이 쓰는 값만(`docs/화면-데이터-목록.md`), Notion 원문 시각 글자와 검색용 시각을 함께 둔다. 색인: 수업 시작 시각, 반·강사(배열), 출석·기록의 수업(배열), 출석 수업일시, 학습활동의 기록·마감일. RLS를 켜고 정책을 두지 않으며 `anon`·`authenticated` 권한을 회수한다(기존 원자료 표와 같음 — 함수의 서비스 역할만 접근). 학부모 리포트 표(`attendance_records` 등)와 분리해 리포트 동작에 영향이 없다. `if not exists`라 다시 적용해도 안전하다.
- **검증(로컬)**: PGlite에 두 번 적용 — 표 4개, 모든 표 RLS, `anon`·`authenticated` 권한 0, `notion_edited_at` 필수, 반·기간·배열·마감일 검색 결과 확인(`tests/class-room-copy-sql.cjs`). 기존 관리자 보안 SQL 검사, 회귀 가드.
- **미검증**: 운영 DB 적용(병합 후 배포 로그로 확인).
- **실패 시 대처**: 표만 있고 쓰는 곳이 없으므로 그대로 두어도 영향 없다. 지우려면 표 4개를 `drop table`하는 마이그레이션을 따로 만든다.

## 항목 2. 배포 전 검사

- **유형**: AI 자동
- **대상 파일**: `.github/workflows/deploy-supabase-functions.yml`, `tests/class-room-copy-sql.cjs`
- **동작**: 함수·마이그레이션 배포 워크플로가 운영 DB에 적용하기 전에 위 PGlite 검사를 돌린다(실패하면 배포 중단).
