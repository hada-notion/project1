## 항목 1. 예약 실행

- **유형**: AI 자동(`main` 병합 시 `supabase db push`로 적용)
- **대상 파일**: `supabase/migrations/20261014060000_class_room_copy_cron.sql`
- **동작**:
  - 도우미 함수 `class_room_copy_call(body)`(함수 주소 + Vault `sync_queue_admin_key` 헤더로 `sync-class-room-copy` 호출, 대기 150초), `class_room_copy_first_fill_step()`, `class_room_copy_incremental_step()`. 셋 다 `anon`·`authenticated`·`public` 실행 권한 회수.
  - `class-room-copy-first-fill`(3분마다): `sync_cursors`에 커서가 없는 첫 표(cr_sessions → cr_attendance → cr_records → cr_activities)를 reconcile. 네 표 모두 커서가 생기면 예약을 스스로 지운다.
  - `class-room-copy-incremental`(5분마다): 네 표 모두 커서가 있을 때만 incremental.
  - `class-room-copy-reconcile-sessions/attendance/records/activities`(UTC 18:00·18:05·18:10·18:15 = 한국 03:00~03:15): 표마다 reconcile(120일 전 ~ 60일 뒤).
  - 다시 적용해도 같은 이름의 예약을 먼저 지우고 등록해 겹치지 않는다.
- **부담**: 바뀐 것이 없으면 5분마다 Notion 질의 4회. 느려지면 incremental 주기를 10분으로 늘린다.
- **검증(로컬)**: PGlite에 가짜 pg_cron·pg_net·Vault를 두고 적용 2회 — 예약 6개, incremental은 커서 전 대기, 처음 채우기가 표 순서대로 부르고(커서가 생기기 전에는 같은 표를 다시), 끝나면 예약을 지움, 호출 주소·Vault 키 헤더·본문, 도우미 함수 실행 권한 없음(`tests/class-room-copy-cron-sql.cjs`). 복사본 표·관리자 보안 SQL 검사, 회귀 가드.
- **미검증**: 운영 처음 채우기 결과(병합 후 `cr_*` 행 수와 `sync_cursors`로 확인), 실행 시간.
- **실패 시 대처**: `select cron.unschedule('class-room-copy-…')`로 예약을 지우면 멈춘다. 복사본은 아직 아무도 읽지 않아 화면 영향이 없다.
- **학원 배포 시(운영자 직접)**: 다른 예약 작업처럼 마이그레이션의 함수 주소를 학원 프로젝트 주소로 바꾸고, Vault `sync_queue_admin_key`가 있는지 확인한다.
