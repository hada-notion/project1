## 항목 5. 평가 전용 반 서버 코드 (출석 없는 평가)

- **유형**: AI 자동
- **선행 조건**: 항목 4(Notion 칸). 칸이 없는 운영에서도 아래 코드는 칸을 건너뛰고 지금처럼 동작한다.
- **변경 이유·증상**: 출석·수업 없이 만든 평가는 ① 학생별 학습활동이 만들어지지 않고(계획의 학생마다 출석이 필요), ② 만들어도 날짜가 없어 학부모 리포트에서 빠졌다.
- **대상 코드**: `supabase/functions/_shared/assignmentPlan.ts`, `supabase/functions/_shared/createLearningRecordTarget.ts`, `supabase/functions/_shared/reportCacheBuilder.ts`를 원본 `main` 최신본으로 바꾼다(테스트 `assignmentPlan_test.ts`·`createLearningRecordPlan_test.ts`·`reportCacheBuilder_test.ts`, 배포 작업의 테스트 단계 포함).
  - 찾을 원문(앵커): `assignmentPlan.ts`의 `export const EVAL_TYPE_DAILY = "일일 평가"`, `createLearningRecordTarget.ts`의 `const PROP_RECORD_CLASS = "클래스"`, `reportCacheBuilder.ts`의 `export function standaloneEvalIso(`.
- **동작**
  - 학습활동 생성(`create-assignment` 큐): 구분이 평가이면 계획 항목의 출석(`a`)이 비어 있어도 등록만으로 학습활동을 만든다(출석 칸 없이). 학습·과제는 지금처럼 출석이 있어야 한다.
  - 출석·수업으로 만든 평가는 학습기록 `평가 구분`이 비어 있으면 `일일 평가`로 채운다. 값이 있으면 그대로 두고, 칸이 없거나 쓰기에 실패해도 학습활동 생성은 끝난다.
  - 학습기록 생성(수업 [학습기록 생성] 큐): 수업 수식 `학습기록 계획`이 `cls`(수업의 클래스)를 주면 새 학습기록의 `클래스`에 넣는다. 수식이 주지 않으면 칸을 쓰지 않는다(칸이 없는 운영 보호). 수식 변경은 이후 항목(Notion 화면 작업).
  - 리포트 캐시: 출석이 없는 평가는 학습기록 `평가 기간`의 끝 날짜(하루면 그날)를 평가 날짜로 쓴다. 그래서 평가 기간이 끝나야 리포트에 실린다. 평가 항목에 `eval_type`·`eval_start`·`eval_end`·`standalone`을, 상세에 클래스 `리포트 구성`(`report_mode`: `all`/`tests_only`)을 담는다. 화면 표시는 이후 항목.
- **환경별 값·Secret**: 없음
- **마이그레이션 / 재배포**: 학습활동 생성·학습기록 생성·리포트 캐시를 쓰는 함수 재배포(main 반영 시 배포 작업이 함께 올린다).
- **검증**: 모의 테스트(출석 없는 평가 계획·학습활동 속성, 평가 구분 채우기 4경우, 학습기록 `클래스`, 리포트 캐시의 평가 날짜·구분·기간·리포트 구성). 실제 화면 확인은 [평가 만들기] 버튼과 `학습활동 계획` 수식이 연결된 뒤 테스트 반에서 한다.
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌리고 함수를 재배포한다. 캐시에 남은 새 값은 옛 화면이 무시한다.

## 항목 6. Notion 수식·버튼·자동화 (평가 전용 반 연결)

- **유형**: 운영자 직접(화면 작업, 원본 지원 브라우저 가능). 수식·버튼·자동화는 API로 바꿀 수 없다.
- **선행 조건**: 항목 4(칸)·항목 5(서버 코드). 항목 5보다 먼저 바꾸면 출석 없는 평가의 [학습활동 생성]이 옛 서버에서 ⚠️ 오류가 난다(출석 값 없음).
- **변경 이유·증상**: 출석 없는 평가를 반에서 만들고(① [평가 만들기]), 학생별 학습활동을 만들고(② `학습활동 계획`), 주간·월간 보고서에 붙이려면(④ `[생성] 보고서`) Notion 쪽 계산도 바뀌어야 한다. ③은 새 학습기록에 반을 넣어 클래스 "평가" 탭에 보이게 한다.
- 원문의 `prop("…")`는 수식 편집기에서 속성 칩이 된다. 붙여 넣기 전에 기존 수식을 복사해 둔다(되돌리기용).

### ① 클래스(학원) DB 버튼 `평가 만들기` 동작

`자동화 편집`에서 작업 두 개:
1. `학습기록(학원) DB에 페이지 추가` — 값:
   - `학습`(제목, 수식): `lets(mon, dateSubtract(today(), mod(day(today()) + 6, 7), "days"), "[평가] " + context("이 페이지").prop("클래스명") + " " + formatDate(mon, "MM.DD") + "~" + formatDate(dateAdd(mon, 6, "days"), "MM.DD"))`
   - `구분`: 평가 / `평가 구분`: 주간 평가 / `클래스`: 이 페이지
   - `평가 기간`(수식): `lets(mon, dateSubtract(today(), mod(day(today()) + 6, 7), "days"), dateRange(mon, dateAdd(mon, 6, "days")))`
   - `등록`(수식): `context("이 페이지").prop("등록").filter(current.prop("수강상태") == "수강 중")`
2. `페이지 열기`: `페이지 추가됨`(중앙에서 보기)

뜻: 이번 주 월~일 주간 평가를 이 반의 수강 중 학생 전원으로 만들고 바로 연다. 선생님이 평가 구분·기간·교재·범위를 고친 뒤 [학습활동 생성]을 누른다.

### ② 학습기록(학원) DB 수식 `학습활동 계획`

```
if(empty(prop("구분")), "{\"v\":1,\"skip\":\"구분 없음\"}", lets(cat, prop("구분"), doneRegs, prop("학습활동").map(current.prop("등록")).flat().map(id(current)), ed, if(empty(prop("평가 기간")), "", " " + formatDate(dateEnd(prop("평가 기간")), "MM.DD")), items, if(empty(prop("출석")) and cat == "평가", prop("등록").filter(not doneRegs.includes(id(current))).map("{\"a\":\"\",\"r\":\"" + id(current) + "\",\"t\":\"[평가] " + current.format().replaceAll("\"", "") + ed + "\"}"), prop("출석").filter(lets(a, current, not empty(a.prop("등록")) and not doneRegs.includes(id(a.prop("등록").first())))).map(lets(a, current, reg, a.prop("등록").first(), t, a.prop("수업일시"), nexts, reg.prop("출석").filter(not empty(current.prop("수업일시")) and current.prop("수업일시") > t and not current.prop("삭제 체크")), nxt, nexts.sort(current.prop("수업일시")).first(), "{\"a\":\"" + id(a) + "\",\"r\":\"" + id(reg) + "\"" + if(cat == "과제" and not empty(nxt), ",\"d\":\"" + id(nxt) + "\"", "") + ",\"t\":\"[" + cat + "] " + a.prop("출석").replaceAll("\"", "") + "\"}"))), "{\"v\":1,\"c\":\"" + cat + "\",\"s\":\"" + if(empty(prop("수업")), "", id(prop("수업").first())) + "\",\"items\":[" + items.join(",") + "]}"))
```

- 바뀐 점: 출석이 없고 구분이 평가이면 `등록`마다 `{"a":"","r":"등록","t":"[평가] 등록이름 MM.DD"}`(날짜는 평가 기간 끝)를 담는다. 출석이 있으면 예전과 같다.

### ③ 수업(학원) DB 수식 `학습기록 계획`

마지막 줄만 바뀐다(`cls` 추가):
```
  "{\"v\":1," + if(mk, "\"mk\":1,", "") + "\"cls\":\"" + if(empty(prop("클래스")), "", id(prop("클래스").first())) + "\",\"items\":[" + items.join(",") + "]}"
```

### ④ 등록(학원) DB 자동화 `[생성] 보고서` — `보고서(학원) DB에 페이지 추가`의 두 값

`학습활동`:
```
lets(batch, context("페이지 실행").prop("클래스").first().prop("보고서 생성 대상").first(), startN, toNumber(formatDate(dateStart(batch.prop("기간")), "YYYYMMDD")), endN, toNumber(formatDate(dateEnd(batch.prop("기간")), "YYYYMMDD")), standalone, context("페이지 실행").prop("학습활동").filter(if(not empty(current.prop("출석")) or empty(current.prop("학습기록").first().prop("평가 기간")), false, lets(e, toNumber(formatDate(dateEnd(current.prop("학습기록").first().prop("평가 기간")), "YYYYMMDD")), e >= startN and e <= endN))), context("페이지 실행").prop("출석").filter(if(empty(current.prop("수업일시")), false, toNumber(formatDate(current.prop("수업일시"), "YYYYMMDD")) >= startN and toNumber(formatDate(current.prop("수업일시"), "YYYYMMDD")) <= endN)).map(current.prop("학습활동")).flat().concat(standalone).unique())
```
`학습기록`:
```
lets(batch, context("페이지 실행").prop("클래스").first().prop("보고서 생성 대상").first(), startN, toNumber(formatDate(dateStart(batch.prop("기간")), "YYYYMMDD")), endN, toNumber(formatDate(dateEnd(batch.prop("기간")), "YYYYMMDD")), standalone, context("페이지 실행").prop("학습기록").filter(if(current.prop("구분") != "평가" or not empty(current.prop("출석")) or empty(current.prop("평가 기간")), false, lets(e, toNumber(formatDate(dateEnd(current.prop("평가 기간")), "YYYYMMDD")), e >= startN and e <= endN))), context("페이지 실행").prop("출석").filter(if(empty(current.prop("수업일시")), false, toNumber(formatDate(current.prop("수업일시"), "YYYYMMDD")) >= startN and toNumber(formatDate(current.prop("수업일시"), "YYYYMMDD")) <= endN)).map(current.prop("학습기록")).flat().concat(standalone).unique())
```
- 바뀐 점: 발송함 기간 안의 출석에서 모으던 것에, 출석 없는 평가 중 `평가 기간` 끝 날짜가 발송함 기간 안인 것(`standalone`)을 더한다. `페이지 실행`은 자동화 화면의 "페이지 실행" 칩.

### ⑤ 클래스(학원) DB 버튼 `보고서 생성` 설명

"이 클래스 등록의 '보고서 생성 상태'를 ⚪ 대기로 바꿉니다. 실제 보고서는 등록 DB 자동화 [생성] 보고서가 보고서 생성 대상(발송함)의 기간으로 만듭니다." (지운 함수 이름이 남아 있던 것을 지금 동작으로)

- **검증**: ② 미리보기에서 출석 있는 기록은 예전 값과 같다. ③ 미리보기에 `"cls":"…"`. 원본에서 저장값을 내부 읽기로 다시 읽어 위 원문과 같음 확인(10/26). 실제 버튼·보고서 생성 확인은 항목 5 배포 뒤 테스트 반에서.
- **실패 시 대처**: 복사해 둔 기존 수식으로 되돌리고 ① 작업 두 개를 지운다.
