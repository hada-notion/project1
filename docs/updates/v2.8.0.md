## 운영 적용 순서 (한눈에)

이 표만 따라가면 된다. 각 줄의 자세한 값·수식은 해당 항목에 있다. **새 기능을 v2.8.0에 더할 때마다 이 표의 알맞은 단계에 줄을 넣고, 항목 번호를 붙인다**(항목 본문만 쓰고 표를 빼먹지 않는다).

원칙
- **속성(칸)은 코드 배포 전, 버튼·수식·자동화는 배포 후.** 칸은 옛 코드가 읽지 않아 먼저 넣어도 안전하고, 버튼·자동화는 새 함수 주소를 부르므로 배포 뒤에 바꾼다. 상태 감시가 새 상태 칸을 찾으므로 칸이 먼저 있어야 로그 오류가 없다.
- **코드는 한 번에.** 원본 `main` 최신본으로 운영 저장소를 맞추면 이 버전의 서버·화면이 모두 들어간다(학원 수업이 없는 시간).
- **카카오 템플릿 심사가 가장 오래 걸린다(영업일 2~3일).** 0단계에서 먼저 신청하고, 기능 적용은 기다리지 않고 진행한다(템플릿 ID가 없으면 해당 알림톡만 ⚠️로 막히고 나머지는 동작).
- **원본 템플릿의 학원 이름·문의 번호는 이 학원 것으로 바꾼다.** 원본 알림톡 설정 행의 본문은 "하다 수학학원"과 원본 학습문의 번호로 되어 있다. 이 행 본문은 템플릿 칸과 예시 칸 2단 콜아웃이다. 대상은 세 군데다: 솔라피 심사 신청(보조문구·본문 첫 줄·부가정보), 운영 알림톡 설정 행 본문 콜아웃 두 개, 행 `비고`의 검수자 참고 의견. 원본 이름이 남은 채 신청하지 않는다. 신청 전에 본문에서 "하다"·원본 번호를 찾아 하나도 없는지 확인하고, 운영 AI는 이 확인 결과를 원장님께 보고한다.
- **옛 것은 새 것 확인 뒤 지운다.** 지울 것은 6단계에만 모은다.
- 원장님(운영 소유자)께 부탁하는 일은 0·3·5단계에 모았다.
- **원본 재스캔 기준(10/27 사용자)**: 기능 하나가 끝날 때마다 한 번 + 출시 직전 마지막 한 번. 작은 수정마다는 하지 않는다. `docs/기준/노션-지문.json`은 출시 직전 스캔으로 맞춘다(운영 비교 기준).

## 항목 2. 리포트 캐시·학부모 리포트 스크립트 교체

- **유형**: AI 자동
- **선행 조건**: 없음(항목 1 전에 배포해도 칸이 없으면 반 평균을 보여 준다)
- **대상 코드**: `supabase/functions/_shared/reportCacheBuilder.ts`, `student_report_part1.js`, `student_report_part2.js`를 원본 `main` 최신본으로 바꾸고 `node tests/design-lint.cjs --fix`로 `student_report.html`의 스크립트 버전을 맞춘다.
  - 찾을 원문(앵커): `reportCacheBuilder.ts`의 `const classAverageOf = async (recordId?: string | null) =>`, `student_report_part2.js`의 `function classAvgOf(items)`, `student_report_part1.js`의 `function testCompareBarsHtml(t)`.
- **동작**
  - 서버: 표시되는 평가(최대 6개)마다 그 학습기록의 `학습활동` 관계로 형제 학습활동을 읽어 구분이 평가이고 전체 문항이 있는 점수만 평균 낸다. 3명 미만이거나 학생 등록의 클래스가 `반 평균 숨김`이면 `class_avg: null`. 평가 항목에 `class_avg`(소수 한 자리)·`class_count`를 더한다.
  - 화면: 그래프 점마다 그 점에 묶인 평가들의 `class_avg` 평균을 점선(#b9ab98)으로 그리고, 반 평균이 하나라도 있으면 그래프 위에 범례를 붙인다. 일일 보고서 "이번 평가", 평가 카드(학습기록 탭·캘린더 날짜 목록)와 그래프 점·기간 칸을 눌러 여는 평가 목록에, 점수 가로 막대("OOO 학생", 전체 문항이 있을 때 항상)와 반 평균이 있으면 "반 평균" 막대 한 줄을 더 붙인다(`testCompareBarsHtml`). 그래프 범례도 "OOO 학생 / 반 평균".
  - 개별진도·개별수업은 학습기록에 학생이 한 명이라 반 평균이 나오지 않는다.
- **알려진 한계**: 한 학생의 점수를 고치면 같은 평가를 본 다른 학생 리포트의 반 평균은 그 학생이 다음에 동기화될 때 바뀐다. 반 전체 점수를 입력한 뒤 클래스 [학생 페이지 동기화]를 한 번 누르면 모두 맞는다.
- **환경별 값·Secret**: 없음
- **마이그레이션 / 재배포**: 리포트 캐시를 만드는 함수 재배포(main 반영 시 배포 작업이 함께 올린다).
- **검증**: 점수가 3명 이상 입력된 그룹 평가가 있는 반에서 클래스 [학생 페이지 동기화] → 학생 리포트 일간·월간 "최근 평가 추이"에 점선과 범례가 보인다. `반 평균 숨김`을 체크하고 다시 동기화하면 사라진다. `node tests/design-lint.cjs` 통과.
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌리고 함수를 재배포한다. 캐시에 남은 `class_avg`는 옛 화면이 무시한다.

## 항목 4. Notion 학습기록·클래스 DB에 평가 전용 반 칸 추가

- **선행 조건**: 없음(칸만 추가, 지금 코드는 아직 이 칸을 읽지 않는다)

  - `학습기록 DB / 속성 / 평가 구분` — 선택: 일일 평가(회색)·주간 평가(노랑)·월간 평가(파랑)·종합 평가(초록)·기타(기본). 출석·수업으로 만든 평가는 일일 평가로 둔다. 종합 평가(교재·단원을 마칠 때, 진도교재에서 만듦)는 다음 버전에서 쓴다. 예전 이름 "단원 평가"가 있으면 "종합 평가"로 바꾼다(쓰인 기록이 있으면 값도 함께).

  - `클래스 DB / 속성 / 리포트 구성` — 선택: 전체(회색)·평가만(초록). 비어 있으면 전체.

    - 클래스 상단 버튼 줄은 그대로(`교재 생성` · `교재비 생성` · `보고서 생성` · `월 수강료 생성` · `학생 페이지 동기화`). 평가는 반이 아니라 발송함 [평가 생성]에서 만든다(항목 9).
    - 클래스 탭: `학습기록` 관계로 "평가" 탭(표, 구분 = 평가, 열 학습·수업일·평가 구분·평가 기간·학습활동 현황, 생성 일시 내림차순). 탭 순서는 수업 · 평가 · 일정.

    - 메뉴 "학습 보고서" 페이지 표에 "평가" 탭: 학습기록 DB 표(구분 = 평가, 열 학습·클래스·수업일·평가 구분·평가 기간·학습활동 현황, 생성 일시 내림차순).

## 항목 5. 평가 전용 반 서버 코드 (출석 없는 평가)

- **선행 조건**: 항목 4(Notion 칸). 칸이 없는 운영에서도 아래 코드는 칸을 건너뛰고 지금처럼 동작한다.

- **동작**
  - 학습활동 생성(`create-assignment` 큐): 구분이 평가이면 계획 항목의 출석(`a`)이 비어 있어도 등록만으로 학습활동을 만든다(출석 칸 없이). 학습·과제는 지금처럼 출석이 있어야 한다.

  - 학습기록 생성(수업 [학습기록 생성] 큐): 수업 수식 `학습기록 계획`이 `cls`(수업의 클래스)를 주면 새 학습기록의 `클래스`에 넣는다. 수식이 주지 않으면 칸을 쓰지 않는다(칸이 없는 운영 보호). 수식 변경은 이후 항목(Notion 화면 작업).
  - 리포트 캐시: 출석이 없는 평가는 학습기록 `평가 기간`의 끝 날짜(하루면 그날)를 평가 날짜로 쓴다. 그래서 평가 기간이 끝나야 리포트에 실린다. 평가 항목에 `eval_type`·`eval_start`·`eval_end`·`standalone`을, 상세에 클래스 `리포트 구성`(`report_mode`: `all`/`tests_only`)을 담는다. 화면 표시는 이후 항목.
- **환경별 값·Secret**: 없음
- **마이그레이션 / 재배포**: 학습활동 생성·학습기록 생성·리포트 캐시를 쓰는 함수 재배포(main 반영 시 배포 작업이 함께 올린다).
- **검증**: 모의 테스트(출석 없는 평가 계획·학습활동 속성, 평가 구분 채우기 4경우, 학습기록 `클래스`, 리포트 캐시의 평가 날짜·구분·기간·리포트 구성). 실제 확인은 항목 9 원본 확인(10/27)에서 했다.
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌리고 함수를 재배포한다. 캐시에 남은 새 값은 옛 화면이 무시한다.

### ② 학습기록(학원) DB 수식 `학습활동 계획`

```
if(empty(prop("구분")), "{\"v\":1,\"skip\":\"구분 없음\"}", lets(cat, prop("구분"), doneRegs, prop("학습활동").map(current.prop("등록")).flat().map(id(current)), ed, if(empty(prop("평가 기간")), "", " " + formatDate(dateEnd(prop("평가 기간")), "MM.DD")), items, if(empty(prop("출석")) and cat == "평가", prop("등록").filter(not doneRegs.includes(id(current))).map("{\"a\":\"\",\"r\":\"" + id(current) + "\",\"t\":\"[평가] " + current.format().replaceAll("\"", "") + ed + "\"}"), prop("출석").filter(lets(a, current, not empty(a.prop("등록")) and not doneRegs.includes(id(a.prop("등록").first())))).map(lets(a, current, reg, a.prop("등록").first(), t, a.prop("수업일시"), nexts, reg.prop("출석").filter(not empty(current.prop("수업일시")) and current.prop("수업일시") > t and not current.prop("삭제 체크")), nxt, nexts.sort(current.prop("수업일시")).first(), "{\"a\":\"" + id(a) + "\",\"r\":\"" + id(reg) + "\"" + if(cat == "과제" and not empty(nxt), ",\"d\":\"" + id(nxt) + "\"", "") + ",\"t\":\"[" + cat + "] " + a.prop("출석").replaceAll("\"", "") + "\"}"))), "{\"v\":1,\"c\":\"" + cat + "\",\"s\":\"" + if(empty(prop("수업")), "", id(prop("수업").first())) + "\",\"items\":[" + items.join(",") + "]}"))

      + if(dups.length() > 0, "⚠️ 중복 " + format(dups.length()) + "명: " + dups.map(format(current.prop("학생이름(등록)"))).join(", "), "")

## 항목 9. 발송함 [평가 생성] (진도교재 `평가 대상` → 교재별 주간·월간 평가)

- **유형**: AI 자동(서버 코드) + 운영자 직접(Notion 속성·수식·버튼·레이아웃)
- **선행 조건**: 항목 5(출석 없는 평가), 항목 8(반별 발송함). Notion 버튼·수식은 함수 배포 뒤.
- **변경 이유·증상**: 클래스 [평가 생성]를 지운 뒤 주간·월간 평가를 만들 곳이 없었다. 평가는 그 기간 보고서(반별 발송함)에 붙으므로 발송함에서 만든다. 수업 `오늘 학습` + [학습기록 생성]과 같은 짝: 발송함 진도교재 `평가 대상` + [평가 생성].

- **동작**
  - [보고서 생성]이 발송함을 만들거나 찾을 때 이 반의 진행 중 진도교재(`진행상태` = 진행 중, 학생별 개별교재 인스턴스 제외)를 발송함 `진도교재`에 더한다(이미 있던 것은 빼지 않음). 발송함에 `진도교재` 칸이 없으면 건너뛴다.

  - [학습활동 생성] 큐가 학습기록 수식 `학습활동 계획`(출석 없는 평가는 등록마다)으로 학생별 학습활동을 만들고, 그 기록이 발송함에 연결돼 있으면 학생별 보고서에 학습기록·학습활동을 더한다(이미 있으면 쓰지 않음). 기록에서 [학습활동 생성]을 다시 눌러도 같다. 출석 평가·일일 기록에는 호출이 늘지 않는다.
  - 대상 학생: 그룹 교재 = 이 발송함에 보고서가 있는 학생 전원, 개별 교재 = 그 교재(또는 개별교재) 학생 중 보고서가 있는 학생.

  wavg, if(wn == 0, 0, round(wk.map(current.prop("정답 문항") / current.prop("전체 문항") * 100).sum() / wn)),
  mavg, if(mn == 0, 0, round(mo.map(current.prop("정답 문항") / current.prop("전체 문항") * 100).sum() / mn)),
  dS, ifs(davg >= 90, style(format(davg) + "점", "b", "green"), davg >= 80, style(format(davg) + "점", "b", "yellow"), style(format(davg) + "점", "b", "red")),
  wS, ifs(wavg >= 90, style(format(wavg) + "점", "b", "green"), wavg >= 80, style(format(wavg) + "점", "b", "yellow"), style(format(wavg) + "점", "b", "red")),
  mS, ifs(mavg >= 90, style(format(mavg) + "점", "b", "green"), mavg >= 80, style(format(mavg) + "점", "b", "yellow"), style(format(mavg) + "점", "b", "red")),
  if(
    dn + wn + mn == 0,
    "📊 평가: 평가 없음",
    "📊 평가: "
      + if(dn == 0, "", if(wn + mn == 0, "평균 ", "일일 평균 ") + dS + " (" + format(dn) + "회)")
      + if(dn > 0 and wn > 0, " · ", "")
      + if(wn == 0, "", if(wn == 1, "주간 평가 " + wS, "주간 평가 평균 " + wS + " (" + format(wn) + "회)"))
      + if((dn > 0 or wn > 0) and mn > 0, " · ", "")
      + if(mn == 0, "", if(mn == 1, "월간 평가 " + mS, "월간 평가 평균 " + mS + " (" + format(mn) + "회)"))
  )
)
```

  9. 출석 `실시간 처리 상태` 수식에 수업 안내를 더한다(10/27 사용자, 원본 API로 반영): 기존 수식을 그대로 `prev`로 감싸고 `수업 안내 상태`가 ⚪ 대기면 "⏳ 수업 안내 대기", ⚠️ 오류면 "⚠️ 수업 안내: (수업 안내 오류)"(오류 칸이 비면 "⚠️ 수업 안내"), ✅·빈 값이면 아무것도 붙이지 않는다. 기존 상태가 있으면 " · "로 잇는다. `수업 안내 오류`는 출석 `마지막 오류`와 따로 두므로 기존 보고서·학습기록 상태 문장은 그대로다. 수업 `학생별 전송 상태`가 출석 `실시간 처리 상태`를 읽으므로 거기에도 같이 보인다. 바꾸기 전 원문은 부록.
```
lets(lnSt, format(prop("수업 안내 상태")), lnErr, prop("수업 안내 오류"), prev, <기존 수식 전체>, extra, ifs(lnSt == "⚪ 대기", "⏳ 수업 안내 대기", lnSt == "⚠️ 오류", "⚠️ 수업 안내" + if(empty(lnErr), "", ": " + lnErr), ""), if(extra == "", prev, if(empty(prev), extra, format(prev) + " · " + extra)))
```
- **환경별 값·Secret**: 없음(채널·템플릿은 알림톡 설정 행).
- **마이그레이션 / 재배포**: 새 함수·큐 워커 재배포(main 반영 시).
- **검증**: 모의 테스트 `lessonNotice_test.ts`(일시 표기, 처음·변경·같음 판단, 보강·메모 문구, 결석·일시 없음, 로그는 등록에만, 설정 꺼짐·발송 실패). 원본 확인(10/27, 어사이드 + 함수 로그): 설정 행 꺼짐 상태에서 일괄 6건·개별 1건 접수 → 모두 "설정 꺼짐" ⚠️(발송 없음), 결석 학생은 일괄 대상에서 빠지고 개별로 누르면 "결석" ⚠️. 두 버튼의 확인 창: [취소]면 상태가 바뀌지 않음 확인(10/27). 실제 발송은 템플릿 ID가 나온 뒤 원본 테스트 반(연락처를 본인 번호로 둔 학생)에서(미검증). 출석 `실시간 처리 상태` 표시(10/27, 어사이드, 테스트 출석 1건): ⚠️ 오류 표시가 머리 줄·수업 "출석" 탭·수업 `학생별 전송 상태`에 나오고, 두 칸을 비우면 사라짐. 원본에 배포된 서버가 오류 칸 분리 전이라 문구가 `마지막 오류`에 들어가 "⚠️ (문구) · ⚠️ 수업 안내" 모양으로 봄 — "⚠️ 수업 안내: (문구)" 모양과 `마지막 오류` 그대로는 배포 뒤 확인(미검증).
- **이름 변경(10/27)**: 수업 속성 `안내 메모` → `수업 안내 메모`(서버가 속성 이름으로 읽으므로 코드도 함께 바꿈). 운영에는 처음부터 `수업 안내 메모`로 만든다. 원본 반영(10/27, 어사이드): 이름 변경, [수업 안내 일괄 전송] 설명("…수업의 '수업 안내 메모'가 함께 갑니다…"), 두 확인 창 문구 "수업 안내 메모: …", 누른 뒤 [취소] → 상태 그대로. Notion을 영어 화면으로 쓰면 버튼 수식을 붙여 넣을 때 `context("이 페이지")` 대신 `context("This page")`로 넣어야 인식된다(저장 뒤에는 언어와 무관).
- **실패 시 대처**: 출석 자동화 `[웹훅] 수업 안내`를 끈다. 버튼은 상태만 바꾸므로 그대로 둬도 아무것도 보내지 않는다.


## 항목 11. 일정 안내 알림톡 (일정 한 건 안내, 리포트 일정 버그 수정)

> 10/27 개정: 처음에는 월간 일정 안내를 반별(클래스 [월간 일정 안내] → 그 반 학생)로 만들었으나, 수강료와 함께 **학생 단위로 바꿔 항목 12로 옮겼다.** 아래에서 월간 일정 안내의 내용(세 구역·표기·템플릿)은 그대로 쓰고, 대상·보내는 곳·중복 방지는 항목 12를 따른다.

- **유형**: AI 자동(서버 코드·마이그레이션) + 운영자 직접(Notion 속성·버튼·수식, 알림톡 템플릿 심사·설정 행)
- **선행 조건**: 카카오 템플릿 "일정 안내"·"월간 일정 안내" 심사 완료(템플릿 ID). 함수 배포 뒤 Notion 버튼. 발송 규칙은 항목 10과 같다.
- **변경 이유·증상**: 휴원·시험대비 같은 학원 일정과 상담·휴강 같은 개별 일정을 학부모에게 알릴 방법이 없었다. 수업을 "하는" 안내는 수업 안내(항목 10), 그 밖의 일정 안내는 이 항목.

- **동작**
  - **월간 일정 안내**: 학생 단위로 바뀌어 항목 12. 담는 일정(반·학원 전체·학교·학년, 이제 학생 개인 일정도)과 세 구역 변수는 같다: 일정 `구분`으로 💤 휴원 → `휴원일정`, 🏫 학사 일정 → `학사일정`, 그 밖 → `학원일정`. 구역마다 날짜순 최대 5줄("11/3(화) 휴원", 기간은 "11/9(월)~11(수) 이름" — 10/28 같은 달 기간은 끝의 "월/"을 뺌, 달이 넘어가면 "11/30(월)~12/2(수)"), 넘치면 "외 N건", 비면 "없음".
  - **일정 안내(한 건)**: 일정 [일정 안내 전송] → `/event` → 큐. 대상 = 일정에 연결된 학생(수강 중 등록 하나) + 연결된 클래스의 수강 중 학생(겹치면 한 번). 변수: 일정구분 = 일정 `안내 구분`(선택: 상담·테스트·휴강·휴원, 비면 💤 휴원 → "휴원", 🏫 → "학사", 그 밖 → "학원". 본문 첫 문장 "학생의 #{일정구분} 일정을"에 들어가 "일정"을 붙이지 않는다), 일정명 = 이름(비면 "휴강 일정"처럼 일정구분 + " 일정"), 일정일시 = 날짜("26.11.03(화)", 시각이 있으면 "26.11.03(화) 14:00~16:00", 기간이면 "26.11.09(월)~26.11.11(수)" — 10/28부터 시각 없는 같은 달 기간은 "26.11.09(월)~11(수)", 수업 안내와 같은 표기. 일정 `일정일시(일정안내)` 미리보기 수식은 예전 표기 그대로라 보낸 문구와 다를 수 있다), 전달사항 = 메모(50자, 비면 "없음"). 끝나면 일정 `일정 안내 일시` = 그때 날짜. 날짜가 같으면 다시 보내지 않고(⚠️) 바뀌었으면 다시 보낸다. 연결된 학생·반이 없으면 ⚠️. 학부모 공개 체크와 무관(직접 누른 안내).
  - 발송 규칙(항목 10과 같음): 알림톡 설정 행이 꺼졌거나 채널·템플릿 ID가 비면 그 학생은 보내지 않고 부모 페이지(클래스·일정) `마지막 오류`에 "학생: 이유"를 쌓는다. 연락처 없음도 같다. 발송 단계 실패는 다시 보내지 않는다. 마지막 학생 뒤 ✅(쌓인 오류가 있으면 ⚠️). 전송로그는 등록에.

## 항목 12. 수강료·가정통신문 (반 발송함 → 학생마다 한 통)

- **유형**: AI 자동(서버 코드) + 운영자 직접(새 DB·Notion 칸·버튼·자동화·수식·레이아웃·메뉴, 알림톡 템플릿 2개 심사)

- **변경 이유**: 두 반 이상 다니는 학생에게 수강료 안내와 월간 일정 안내가 반마다 따로 나갔다. 학부모는 학생 기준으로 한 달에 한 번 받는 게 자연스럽다. 10/28 사용자 결정으로 **보고서·수강료·가정통신문을 같은 모양**으로 맞췄다: 클래스에서 만들기 → 반 발송함 → 등록(학생 × 반) × 달마다 한 장 → 같은 학생의 그 달 장끼리 서로 잇기 → 보낼 때 그 묶음을 **한 통으로**. 학생 단위 문구는 Notion 변수 수식이 만들고, 학부모 발송은 담당자 클릭으로만(예약·자동 없음).
- **구조**
```
클래스 수학 A ─[월 수강료 생성]─▶ 수강료 발송함 "26년 12월 수강료 · 수학 A" ─▶ 수강료 "26.12 이도윤 수학 A 수강료" ─┐ 같은 달 수강료
클래스 영어 B ─[월 수강료 생성]─▶ 수강료 발송함 "26년 12월 수강료 · 영어 B" ─▶ 수강료 "26.12 이도윤 영어 B 수강료" ─┘ (서로 잇기 → 한 통)

클래스 수학 A ─[가정통신문 생성]─▶ 가정통신문 발송함 ─▶ 가정통신문 "26.12 이도윤 수학 A 가정통신문" ─┐ 같은 달 가정통신문
클래스 영어 B ─[가정통신문 생성]─▶ 가정통신문 발송함 ─▶ 가정통신문 "26.12 이도윤 영어 B 가정통신문" ─┘ (서로 잇기 → 한 통)
```

- **선행 조건**: 없음(새 함수 없음).

- **흐름**(사용자 기준 4단계)
  1. **결석**: 출석 `출석 상태` = 🔴 결석.
  2. **보강 여부 판단**: 결석마다 사람이 `보강 여부`(선택: 보강 필요 / 보강 없음)를 고른다. 결석 종류에 따라 보강 의무가 달라서 자동으로 채우지 않는다. 보강 없음이면 보강 대기와 남은 보강에서 빠진다(사유는 `메모`).

- **칸**(출석 DB)

  - `남은 보강`(출석·등록 수식): 이 학생 출석 중 `보강 필요` 수(배정 안 된 보강 의무).

## 항목 17. 예체능 프로그램: 라이브러리 `구분`·재료비 (작업 중)

- **방향(10/30 사용자 결정)**: 예체능은 구조를 바꾸지 않고 교재 자리를 "프로그램"이 맡는다. 라이브러리(프로그램 원본, `전체 페이지` = 총 차시, `단원목록` = 차시 목록) → 진도교재(학생·반의 프로그램) → 학습기록(그날 연습·작업, `범위`에 차시 번호). 진행도·진도 평가(점수 없으면 수료)는 그대로 동작. DB·속성 이름은 바꾸지 않는다.
- **1단계: 재료비(이번)** — 라이브러리 `구분`(교재/프로그램, 비어 있으면 교재) 추가(AI 자동, 원본 API). 프로그램 재료비는 교재비 흐름을 그대로 쓴다: 라이브러리 `가격` = 재료비. **프로그램은 가격이 있을 때만 교재비에 담는다**(재료비 없는 프로그램은 가격을 비움). 교재는 예전처럼 가격과 상관없이 담는다. 매달 고정 재료비는 수강료 쪽이라 이번에 넣지 않음(쓰는 학원이 생기면).
  - 서버: `_shared/textbookDistributionTarget.ts` `isBillableLibrary`(교재비에 `담기 계획` 수식이 없을 때 쓰는 예전 경로). 테스트 `cartPlan_test.ts`.
  - **운영자 직접**: 교재비 수식 `담기 계획`에 같은 조건 추가(다른 DB를 거치는 수식이라 화면에서 붙임). `.map(current.prop("라이브러리")).flat()` 다음에 `.filter(current.prop("구분") != "프로그램" or current.prop("가격") > 0)`.
  - 운영 적용 순서: 라이브러리 `구분` 추가 → 수식 → 함수 배포(순서 바뀌어도 `구분`이 없으면 모두 교재로 봄).
- **2단계: 리포트 교재 상세를 진도교재 단위로(AI 자동)** — 같은 교재·프로그램을 두 번 하면(한 권 완료, 한 권 진행 중) 교재 카드는 둘인데 어느 카드를 눌러도 이름이 같아 두 회차 기록이 섞여 보였다. 서버(`_shared/reportCacheBuilder.ts`)가 교재 카드(`books[].id`)와 학습·과제·평가 기록(`book_id`)에 진도교재 ID를 싣고, 화면(`student_report_part1.js` `inBook`·`openBookStudy(title, id)`, `student_report_part2.js`)은 둘 다 ID가 있으면 ID로, 아니면 예전처럼 이름으로 묶는다. 학습기록 진도교재가 반 교재(이 학생 진도교재의 `반별교재`)면 그 학생 진도교재로 본다. 리포트 캐시가 다시 만들어지기 전(ID 없음)에는 예전과 같다. 테스트 `reportCacheBuilder_test.ts`.
- **3단계: 학부모 리포트 글자(AI 자동)** — 라이브러리 `구분`이 프로그램인 교재는 리포트에서 교재→프로그램, 단원목록→차시 목록, "200쪽"→"총 12차시"로, 숫자뿐인 범위("3", "1-3")는 "3차시"로 보인다(서버가 `books[].kind`를 싣는다). 반 전체 이름(탭 "교재", 홈 "교재 진도", 교재 탭 제목·안내, 상세 경로)은 그 반 교재가 모두 프로그램일 때만 "프로그램". 학원 설정 파일을 따로 두지 않고 라이브러리마다 정하므로 교과·예체능이 섞인 학원도 그대로 된다. 수업 관리 화면(`class_room`) 글자는 관리웹 글자 정리(v2.8.0 마지막) 때 함께.
- **4단계: 진도교재 `주제`(10/30 사용자 결정)** — 진도교재에 `주제`(텍스트, AI 자동·원본 API, 오른쪽 "교재 연결" 맨 위) 칸. 적으면 학부모 리포트 카드·상세 제목·기록 제목이 주제("기억에 남는 풍경 그리기 · 3차시")로, 카드 아랫줄·상세 제목 아래에 라이브러리 교재명("수채화 1 · 총 12차시")이 보인다. 비우면 예전과 같다. 같은 프로그램을 두 번 해도 회차마다 주제를 달리 적으면 구분된다. 교과에도 쓸 수 있다. 진도 평가 알림톡 `#{교재명}`은 "주제(교재명)"(템플릿 그대로). 진도교재 페이지 제목(관리용 "교재명(반)")과 진도 평가 기록 제목은 그대로. 서버 `reportCacheBuilder.ts`(`books[].topic`)·`bookEvalNotice.ts`, 화면 `student_report_part1.js`·`part2.js`, 테스트 `bookEvalNotice_test.ts`.
- **다음 단계(예정)**: 작품 갤러리는 비아 이전 때. 교재비 안내 알림톡 문구("교재 내역")는 문구 일괄 점검 때.

### 작업 중 생긴 실수와 최종 반영 (반복하지 않기)
- 클래스 `해당기간 보고서 생성 내역`: `empty(종료일) or 숫자 비교`는 종료일이 빈 등록에서 빈 값이 되어 학생을 모두 뺀다 → 날짜끼리 비교(`current.prop("종료일") >= dateStart(per)`)로 쓴다(최종 원문에 반영됨).
- 보고서 `평가현황` 일일 경로: 출석 `과제`는 "그날 마감 과제"라 평가가 없다 → 보고서 `학습활동` 중 출석이 있는 평가를 쓴다(최종 원문에 반영됨).
- 수업 안내가 출석 `마지막 오류`(일일 보고서 칸)를 같이 써서 보고서 오류처럼 보이고 기존 보고서 오류 문장을 덮어썼다(원본 검수 10/27) → 출석 `수업 안내 오류` 칸을 따로 두고 서버는 그 칸만 쓴다(최종 반영). 새 기능의 오류는 그 기능 전용 칸에 쓴다.
- Notion 자동화 조건을 여러 개 넣을 때 대화 상자 아래 [완료]를 누르면 "모든(그리고)" 묶음으로 저장된다(10/27, 몇 분간 리포트 반영 자동화가 덜 돎) → 묶음을 "하나라도"로 먼저 바꾼 뒤 조건을 더한다.
- 이름 자동화가 서버가 지은 제목을 덮어쓴다(발송함·학습기록·학습활동): 자동화 수식을 감싸는 방식으로 해결(최종 반영). API로 속성을 바꾸면 이 자동화는 돌지 않지만 페이지 추가에는 돈다.
- 학습활동 이름 평가 분기에 등록 제목을 쓰면 반 이름이 두 번 나온다 → `학생이름(등록)`.
- 클래스 `해당월 수강료 생성 내역`(항목 12): `(empty(종료일) or 숫자 비교)`는 Notion `or`가 뒤쪽도 계산해 종료일 빈 등록에서 오류 → "0/0". `if(empty(종료일), true, …)`로 쓴다(최종 반영).
- 웹훅 버튼 헤더 키 값은 화면에 가려져 새 버튼에 다시 입력할 수 없다 → 키가 든 버튼을 속성 복제해 고친다(복제하면 본문 속성 체크도 따라오니 해제).
- 관계 `클래스`(발송함)는 API로 "한 페이지만" 제한을 걸 수 없어 제한 없이 둔다(서버는 한 반만 넣는다).
