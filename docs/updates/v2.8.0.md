## 운영 적용 순서 (한눈에)

이 표만 따라가면 된다. 각 줄의 자세한 값·수식은 해당 항목에 있다. **새 기능을 v2.8.0에 더할 때마다 이 표의 알맞은 단계에 줄을 넣고, 항목 번호를 붙인다**(항목 본문만 쓰고 표를 빼먹지 않는다).

원칙
- **속성(칸)은 코드 배포 전, 버튼·수식·자동화는 배포 후.** 칸은 옛 코드가 읽지 않아 먼저 넣어도 안전하고, 버튼·자동화는 새 함수 주소를 부르므로 배포 뒤에 바꾼다. 상태 감시가 새 상태 칸을 찾으므로 칸이 먼저 있어야 로그 오류가 없다.
- **코드는 한 번에.** 원본 `main` 최신본으로 운영 저장소를 맞추면 이 버전의 서버·화면이 모두 들어간다(학원 수업이 없는 시간).
- **카카오 템플릿 심사가 가장 오래 걸린다(영업일 2~3일).** 0단계에서 먼저 신청하고, 기능 적용은 기다리지 않고 진행한다(템플릿 ID가 없으면 해당 알림톡만 ⚠️로 막히고 나머지는 동작).
- **옛 것은 새 것 확인 뒤 지운다.** 지울 것은 6단계에만 모은다.
- 원장님(운영 소유자)께 부탁하는 일은 0·3·5단계에 모았다.

  - 출석·수업으로 만든 평가는 학습기록 `평가 구분`이 비어 있으면 `일일 평가`로 채운다. 값이 있으면 그대로 두고, 칸이 없거나 쓰기에 실패해도 학습활동 생성은 끝난다.
  - 학습기록 생성(수업 [학습기록 생성] 큐): 수업 수식 `학습기록 계획`이 `cls`(수업의 클래스)를 주면 새 학습기록의 `클래스`에 넣는다. 수식이 주지 않으면 칸을 쓰지 않는다(칸이 없는 운영 보호). 수식 변경은 이후 항목(Notion 화면 작업).
  - 리포트 캐시: 출석이 없는 평가는 학습기록 `평가 기간`의 끝 날짜(하루면 그날)를 평가 날짜로 쓴다. 그래서 평가 기간이 끝나야 리포트에 실린다. 평가 항목에 `eval_type`·`eval_start`·`eval_end`·`standalone`을, 상세에 클래스 `리포트 구성`(`report_mode`: `all`/`tests_only`)을 담는다. 화면 표시는 이후 항목.
- **환경별 값·Secret**: 없음
- **마이그레이션 / 재배포**: 학습활동 생성·학습기록 생성·리포트 캐시를 쓰는 함수 재배포(main 반영 시 배포 작업이 함께 올린다).
- **검증**: 모의 테스트(출석 없는 평가 계획·학습활동 속성, 평가 구분 채우기 4경우, 학습기록 `클래스`, 리포트 캐시의 평가 날짜·구분·기간·리포트 구성). 실제 확인은 항목 9 원본 확인(10/27)에서 했다.
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌리고 함수를 재배포한다. 캐시에 남은 새 값은 옛 화면이 무시한다.

## 항목 6. Notion 수식 2개 (출석 없는 평가 학습활동, 새 학습기록의 반)

- **유형**: 운영자 직접(화면 작업, 원본 지원 브라우저 가능). 수식은 API로 바꿀 수 없다.
- **선행 조건**: 항목 4(칸)·항목 5(서버 코드). 항목 5보다 먼저 바꾸면 출석 없는 평가의 [학습활동 생성]이 옛 서버에서 ⚠️ 오류가 난다(출석 값 없음).
- **변경 이유·증상**: 발송함 [평가 생성](항목 9)으로 만든 출석 없는 평가도 학생별 학습활동이 생기려면 ② `학습활동 계획`이 출석 대신 등록마다 계획을 내야 한다. ③은 수업 [학습기록 생성]으로 만든 기록에 반을 넣어 클래스 "평가" 탭에 보이게 한다.
- 작업 중에 넣었다 뺀 것(운영에는 적용하지 않음): 클래스 [평가 만들기] 버튼(평가는 발송함 [평가 생성], 항목 9), 등록 `[생성] 보고서` 자동화 수정(자동화 자체를 지움, 항목 8), 클래스 [보고서 생성] 설명(항목 8).
- 원문의 `prop("…")`는 수식 편집기에서 속성 칩이 된다. 붙여 넣기 전에 기존 수식을 복사해 둔다(되돌리기용).

### ② 학습기록(학원) DB 수식 `학습활동 계획`

```
if(empty(prop("구분")), "{\"v\":1,\"skip\":\"구분 없음\"}", lets(cat, prop("구분"), doneRegs, prop("학습활동").map(current.prop("등록")).flat().map(id(current)), ed, if(empty(prop("평가 기간")), "", " " + formatDate(dateEnd(prop("평가 기간")), "MM.DD")), items, if(empty(prop("출석")) and cat == "평가", prop("등록").filter(not doneRegs.includes(id(current))).map("{\"a\":\"\",\"r\":\"" + id(current) + "\",\"t\":\"[평가] " + current.format().replaceAll("\"", "") + ed + "\"}"), prop("출석").filter(lets(a, current, not empty(a.prop("등록")) and not doneRegs.includes(id(a.prop("등록").first())))).map(lets(a, current, reg, a.prop("등록").first(), t, a.prop("수업일시"), nexts, reg.prop("출석").filter(not empty(current.prop("수업일시")) and current.prop("수업일시") > t and not current.prop("삭제 체크")), nxt, nexts.sort(current.prop("수업일시")).first(), "{\"a\":\"" + id(a) + "\",\"r\":\"" + id(reg) + "\"" + if(cat == "과제" and not empty(nxt), ",\"d\":\"" + id(nxt) + "\"", "") + ",\"t\":\"[" + cat + "] " + a.prop("출석").replaceAll("\"", "") + "\"}"))), "{\"v\":1,\"c\":\"" + cat + "\",\"s\":\"" + if(empty(prop("수업")), "", id(prop("수업").first())) + "\",\"items\":[" + items.join(",") + "]}"))
```

- 바뀐 점: 출석이 없고 구분이 평가이면 `등록`마다 `{"a":"","r":"등록","t":"[평가] 등록이름 MM.DD"}`(날짜는 평가 기간 끝)를 담는다. 출석이 있으면 예전과 같다.

### ③ 수업(학원) DB 수식 `학습기록 계획`

마지막 줄만 바뀐다(`cls` 추가):
```

- **클래스 `해당기간 보고서 생성 내역` 수식 교체(원본 10/26)**: '보고서 생성 대상'(마지막으로 만든 발송함) 기준이던 것을 클래스 `보고서 구분`·`보고서 기간`과 이 반 발송함(관계 `알림톡 발송함`) 기준으로. 설명 "클래스의 보고서 구분·보고서 기간 기준으로, 이 반 발송함의 보고서 누락·중복을 보여줍니다. [보고서 생성] 누르기 전·후 확인용." 종료일이 빈 등록은 `empty(종료일) or 숫자 비교`가 빈 값이 되어 빠지므로 날짜끼리 비교한다. 원본 확인: 만든 주·기간만 바꾼 주·월간 ✅ 6명, 안 만든 주 "아직 없음 · 대상 6명", 발송함 관계를 뺀 보고서 1개 → "누락 1명: 이름", 빈 값 안내 두 가지.
```
lets(
  kind, format(prop("보고서 구분")),
  per, prop("보고서 기간"),
  sK, formatDate(dateStart(per), "YYYYMMDD"),
  eK, formatDate(dateEnd(per), "YYYYMMDD"),
  sN, toNumber(sK),
  eN, toNumber(eK),
  regs, prop("등록").filter(
    not empty(current.prop("등록일"))
    and toNumber(formatDate(current.prop("등록일"), "YYYYMMDD")) <= eN
    and (empty(current.prop("종료일")) or current.prop("종료일") >= dateStart(per))
  ),
  batch, prop("알림톡 발송함").filter(
    format(current.prop("구분")) == kind
    and formatDate(dateStart(current.prop("기간")), "YYYYMMDD") == sK
    and formatDate(dateEnd(current.prop("기간")), "YYYYMMDD") == eK
  ).first(),
  repIds, if(empty(batch), [], batch.prop("보고서").map(current.prop("등록").map(id(current))).flat()),
  missing, regs.filter(not repIds.includes(id(current))),
  dups, regs.filter(lets(rid, id(current), repIds.filter(current == rid).length() > 1)),
  label, "[" + kind + " " + formatDate(dateStart(per), "MM.DD") + "~" + formatDate(dateEnd(per), "MM.DD") + "] ",
  ifs(
    empty(kind) or empty(per), "보고서 구분·보고서 기간을 넣으면 생성 현황이 보입니다",
    sK == eK, "보고서 기간에 종료일을 넣어 주세요",
    empty(batch), label + "아직 없음 · 대상 " + format(regs.length()) + "명 ([보고서 생성]을 누르면 만듭니다)",
    missing.length() == 0 and dups.length() == 0, label + "✅ 대상 " + format(regs.length()) + "명 모두 생성",
    label
      + if(missing.length() > 0, "⚠️ 누락 " + format(missing.length()) + "명: " + missing.map(format(current.prop("학생이름(등록)"))).join(", ") + " ([보고서 생성]을 다시 누르면 빠진 학생만 만듭니다)", "")
      + if(missing.length() > 0 and dups.length() > 0, " / ", "")
      + if(dups.length() > 0, "⚠️ 중복 " + format(dups.length()) + "명: " + dups.map(format(current.prop("학생이름(등록)"))).join(", "), "")
  )
)
```

## 항목 9. 발송함 [평가 생성] (진도교재 `평가 대상` → 교재별 주간·월간 평가)

- **유형**: AI 자동(서버 코드) + 운영자 직접(Notion 속성·수식·버튼·레이아웃)
- **선행 조건**: 항목 5(출석 없는 평가), 항목 8(반별 발송함). Notion 버튼·수식은 함수 배포 뒤.
- **변경 이유·증상**: 클래스 [평가 생성]를 지운 뒤 주간·월간 평가를 만들 곳이 없었다. 평가는 그 기간 보고서(반별 발송함)에 붙으므로 발송함에서 만든다. 수업 `오늘 학습` + [학습기록 생성]과 같은 짝: 발송함 진도교재 `평가 대상` + [평가 생성].
- **대상 코드**: 새 공용 모듈 `supabase/functions/_shared/evaluationPlan.ts`(테스트 `evaluationPlan_test.ts`), `create-class-reports/index.ts`(경로 `/evaluations`), `_shared/classReportPlan.ts`(발송함에 진도교재 연결), `_shared/assignmentPlan.ts`(출석 없는 평가 학습활동을 발송함 보고서에 붙이기), `process-sync-queue/index.ts`(큐 처리기 `batch-evaluations`), `status-watchdog/index.ts`(발송함 `평가 생성 상태` 회수), `admin_settings.js`(체크리스트 "알림톡 발송함 > 평가 생성"), 배포 작업 테스트 단계.
- **동작**
  - [보고서 생성]이 발송함을 만들거나 찾을 때 이 반의 진행 중 진도교재(`진행상태` = 진행 중, 학생별 개별교재 인스턴스 제외)를 발송함 `진도교재`에 더한다(이미 있던 것은 빼지 않음). 발송함에 `진도교재` 칸이 없으면 건너뛴다.
  - 발송함 "진도교재" 탭에서 교재에 `평가 대상`을 체크하고 [평가 생성] → 웹훅(본문 `평가 계획`) → 큐. 발송함 `구분`이 주간·월간 보고서가 아니면(수강료 발송함) ⚠️ 오류. 체크된 교재가 없거나 대상 학생(이 발송함에 보고서가 있는 학생)이 없으면 ⚠️ 오류와 안내.
  - 교재마다: `평가 대상`이 풀려 있거나 이 발송함·이 교재 평가가 이미 있으면 건너뜀 → 체크 해제 → 평가 학습기록(제목 "[주간 평가] 교재 · 중2 B 10.19~10.25", 구분 평가, 평가 구분 주간·월간 평가, 평가 기간 = 발송함 기간, 클래스·진도교재·교재·과목·등록·`알림톡 발송함`) → 기존 [학습활동 생성] 큐에 넣는다.
  - [학습활동 생성] 큐가 학습기록 수식 `학습활동 계획`(출석 없는 평가는 등록마다)으로 학생별 학습활동을 만들고, 그 기록이 발송함에 연결돼 있으면 학생별 보고서에 학습기록·학습활동을 더한다(이미 있으면 쓰지 않음). 기록에서 [학습활동 생성]을 다시 눌러도 같다. 출석 평가·일일 기록에는 호출이 늘지 않는다.
  - 대상 학생: 그룹 교재 = 이 발송함에 보고서가 있는 학생 전원, 개별 교재 = 그 교재(또는 개별교재) 학생 중 보고서가 있는 학생.

  ek, ifs(k == "주간 보고서", "주간 평가", k == "월간 보고서", "월간 평가", "평가"),

```
lets(
  s, dateStart(prop("기간")),
  prop("수강료").map(lets(
    d, current.prop("등록").first().prop("등록일"),
    "• " + format(current.prop("클래스(수강료)")) + if(not empty(d) and d > s and formatDate(d, "YYYYMM") == formatDate(s, "YYYYMM"), "(" + formatDate(d, "MM.DD") + "~)", "") + ": " + current.prop("청구금액(표시)")
  )).sort().join("\n")
)
```

## 항목 13. 보강 배정·자동 차감 (결석 ↔ 보강 수업 연결)

- **유형**: AI 자동(서버 `fix-attendance` 보강 경로) + 운영자 직접(Notion 칸·수식·버튼·보기)
- **선행 조건**: 없음(서버 함수 추가 없음). 버튼은 기존 출석 조정 자동화를 쓴다.
- **변경 이유·증상**: 10/27 원본 사용성 점검(보강 관리). 결석 현황은 모든 결석을 계속 보여 주고, 결석과 보강이 연결되지 않아 보강했는지 알 수 없었다(월말에 "보강 안 된 결석"을 볼 수 없음). 10/27 결정(사용자): 결석마다 보강 수업을 골라 [보강 배정], 보강 수업에 출석하면 자동 차감, 수동 "보강 상태" 칸은 두지 않음.
- **동작**
  - 결석 현황(출석 보기)에서 결석 줄의 `보강 수업`(출석 → 수업 관계, 수업 쪽 `보강 대상`)을 고르고 [보강 배정] → 그 보강 수업 `등록`에 이 출석의 등록을 **추가**하고 `출석 조정 상태` = ⚪ 대기 → 수업 `[웹훅] 출석 조정` 자동화 → `fix-attendance`가 보강 수업이라 합치기만 해서 🔵 보강 출석을 만든다(등록 [수업 생성] 버튼과 같은 길). 원본 실측(10/27, 어사이드): 누르고 약 7초 뒤 출석 생성. 버튼이 서버를 직접 부르는 방식(3~5초 예상)도 검토했지만, 차이가 작고 노션 버튼은 배포·웹훅 키 없이 동작하며 출석이 생기는 길이 출석 조정 하나로 모여 이 방식으로 정했다(사용자). 여러 명을 한꺼번에 보강할 때는 보강 수업 `등록`에 학생들을 넣고 [출석 조정] 한 번. 보강 수업이 비었거나 `보강`이 꺼진 수업이거나 결석이 아니면 대상이 비어 아무것도 바뀌지 않는다(Notion 버튼은 숨길 수 없어서). 확인 창은 두지 않는다 — 누를 때마다 떠서 불편하고(10/27 사용자가 원본에서 지움), 잘못 누르면 아무 일도 없으며 이유는 `보강 상태` 칸으로 본다.
  - 완료 판단(수식 `보강 완료`): `보강 안 함` 체크, 또는 고른 보강 수업 날짜가 지났고(시간이 있으면 그 시각이 지남) 그 수업에 이 학생 출석이 🔴 결석이 아님. 키오스크 등원 기록은 보지 않는다.
  - `보강 필요` = 결석 + 보강 수업에서의 결석이 아님 + 보강 완료 아님. 결석 현황은 이것만 보인다. 등록 `남은 보강` = 이 학생 출석 중 `보강 필요` 수, 출석 `남은 보강`은 그 값을 보여 줌(결석 현황 열, 예전 `누적 결석` 열 대신).
  - 보강 수업에서의 결석은 남은 보강에 세지 않는다(이중 집계 방지). 원래 결석은 차감되지 않은 채 남아 다시 배정한다(`보강 상태` "❌ 보강도 결석").
  - `보강 상태`(표시용): 미배정 / 📌 배정 전 / 📅 MM.DD 예정 / ✅ MM.DD 보강 / ❌ 보강도 결석 / 보강 안 함 / 보강 수업 결석(집계 제외) / ⚠️ 보강 수업이 아님.
  - 이미 예전 방식으로 보강한 결석은 `보강 수업`만 고르면(버튼 없이) 그 수업의 보강 출석을 찾아 완료로 잡힌다.

평가목록, prop("학습활동").filter(current.prop("구분").first()=="평가"),
평가전체, 평가목록.length(),
평가평균, if(평가전체==0, 0, round(평가목록.map(current.prop("점수")).sum()/평가전체*10)/10),
평가텍스트, if(평가전체==0, "", "평가: ".style("b","green") + "평균 " + format(평가평균) + "점 (응시 " + format(평가전체) + "명)"),
```
마지막 줄은 `[학습텍스트, 과제텍스트, 평가텍스트].filter(current!="").join(" | ")`. 운영 대조는 평가 분기와 마지막 줄로 한다.

### 수업·출석 `수업일시(수업안내)` — 바꾸기 전 (항목 13)

lets(wk, ["일","월","화","수","목","금","토","일"], d, dateStart(prop("수업일시")), if(empty(prop("수업일시")), "", formatDate(d, "YY.MM.DD") + "(" + wk.at(day(d)) + ") " + formatDate(d, "HH:mm")))

### 작업 중 생긴 실수와 최종 반영 (반복하지 않기)
- 클래스 `해당기간 보고서 생성 내역`: `empty(종료일) or 숫자 비교`는 종료일이 빈 등록에서 빈 값이 되어 학생을 모두 뺀다 → 날짜끼리 비교(`current.prop("종료일") >= dateStart(per)`)로 쓴다(최종 원문에 반영됨).
- 보고서 `평가현황` 일일 경로: 출석 `과제`는 "그날 마감 과제"라 평가가 없다 → 보고서 `학습활동` 중 출석이 있는 평가를 쓴다(최종 원문에 반영됨).
- 수업 안내가 출석 `마지막 오류`(일일 보고서 칸)를 같이 써서 보고서 오류처럼 보이고 기존 보고서 오류 문장을 덮어썼다(원본 검수 10/27) → 출석 `수업 안내 오류` 칸을 따로 두고 서버는 그 칸만 쓴다(최종 반영). 새 기능의 오류는 그 기능 전용 칸에 쓴다.
- Notion 자동화 조건을 여러 개 넣을 때 대화 상자 아래 [완료]를 누르면 "모든(그리고)" 묶음으로 저장된다(10/27, 몇 분간 리포트 반영 자동화가 덜 돎) → 묶음을 "하나라도"로 먼저 바꾼 뒤 조건을 더한다.
- 이름 자동화가 서버가 지은 제목을 덮어쓴다(발송함·학습기록·학습활동): 자동화 수식을 감싸는 방식으로 해결(최종 반영). API로 속성을 바꾸면 이 자동화는 돌지 않지만 페이지 추가에는 돈다.
- 학습활동 이름 평가 분기에 등록 제목을 쓰면 반 이름이 두 번 나온다 → `학생이름(등록)`.
- 클래스 `해당월 수강료 생성 내역`(항목 12): `(empty(종료일) or 숫자 비교)`는 Notion `or`가 뒤쪽도 계산해 종료일 빈 등록에서 오류 → "0/0". `if(empty(종료일), true, …)`로 쓴다(최종 반영).
- 웹훅 버튼 헤더 키 값은 화면에 가려져 새 버튼에 다시 입력할 수 없다 → 키가 든 버튼을 속성 복제해 고친다(복제하면 본문 속성 체크도 따라오니 해제).
- 관계 `클래스`(발송함)는 API로 "한 페이지만" 제한을 걸 수 없어 제한 없이 둔다(서버는 한 반만 넣는다).
