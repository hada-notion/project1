## 항목 1. Notion 클래스 DB에 `반 평균 숨김` 추가

- **유형**: AI 자동
- **선행 조건**: 없음
- **변경 이유·증상**: 비교가 부담스러운 반(기초반, 레벨 차이가 큰 반 등)에서 반 평균을 끌 수 있어야 한다.
- **Notion 변경**
  - 항목: `클래스(학원) DB / 속성 / 반 평균 숨김` — 체크박스, 기본값 해제. 설명: "체크하면 이 반 학부모 리포트의 최근 평가 추이에 반 평균을 표시하지 않습니다. 반 평균은 같은 학습기록에 점수가 3명 이상일 때만 자동 표시됩니다."
  - 이미 있으면 건너뛴다. 이름이 다르면 멈추고 원본 요청.
  - 레이아웃: `클래스(학원) DB / 레이아웃 / 패널`에 "청구 설정" 다음, "처리 기록" 앞에 **리포트 설정** 구역을 만들고 `반 평균 숨김` 하나만 넣는다(항상 표시).
  - 지문: 원본 재스캔 후 `docs/기준/노션-지문.json`에 반영한다(이 버전 PR에서는 재스캔 전이라 지문 미갱신, 후속 커밋으로 맞춤).
- **검증**: 클래스 페이지 오른쪽 패널에 "리포트 설정 > 반 평균 숨김"이 보인다.
- **실패 시 대처**: 속성을 지운다. 칸이 없으면 서버는 반 평균을 보여 주는 쪽으로 동작한다.

## 항목 2. 리포트 캐시·학부모 리포트 스크립트 교체

- **유형**: AI 자동
- **선행 조건**: 없음(항목 1 전에 배포해도 칸이 없으면 반 평균을 보여 준다)
- **대상 코드**: `supabase/functions/_shared/reportCacheBuilder.ts`, `student_report_part1.js`, `student_report_part2.js`를 원본 `main` 최신본으로 바꾸고 `node tests/design-lint.cjs --fix`로 `student_report.html`의 스크립트 버전을 맞춘다.
  - 찾을 원문(앵커): `reportCacheBuilder.ts`의 `const classAverageOf = async (recordId?: string | null) =>`, `student_report_part2.js`의 `function classAvgOf(items)`, `student_report_part1.js`의 `function testCompareBarsHtml(t)`.
- **동작**
  - 서버: 표시되는 평가(최대 6개)마다 그 학습기록의 `학습활동` 관계로 형제 학습활동을 읽어 구분이 평가이고 전체 문항이 있는 점수만 평균 낸다. 3명 미만이거나 학생 등록의 클래스가 `반 평균 숨김`이면 `class_avg: null`. 평가 항목에 `class_avg`(소수 한 자리)·`class_count`를 더한다.
  - 화면: 그래프 점마다 그 점에 묶인 평가들의 `class_avg` 평균을 점선(#b9ab98)으로 그리고, 반 평균이 하나라도 있으면 그래프 위에 범례를 붙인다. 일일 보고서 "이번 평가", 평가 카드(학습기록 탭·캘린더 날짜 목록)와 그래프 점·기간 칸을 눌러 여는 평가 목록에, 점수 가로 막대("OOO 학생", 전체 문항이 있을 때 항상)와 반 평균이 있으면 "반 평균" 막대 한 줄을 더 붙인다(`testCompareBarsHtml`). 그래프 범례도 "OOO 학생 / 반 평균".
  - 개별진도·개별수업은 학습기록에 학생이 한 명이라 반 평균이 나오지 않는다.
- **알려진 한계**: 한 학생의 점수를 고치면 같은 평가를 본 다른 학생 리포트의 반 평균은 그 학생이 다음에 동기화될 때 바뀐다. 반 전체 점수를 입력한 뒤 클래스 [학생 페이지 동기화]를 한 번 누르면 모두 맞는다.
- **환경별 값·Secret**: 없음
- **마이그레이션 / 재배포**: 리포트 캐시를 만드는 함수 재배포(main 반영 시 배포 작업이 함께 올린다).
- **검증**: 점수가 3명 이상 입력된 그룹 평가가 있는 반에서 클래스 [학생 페이지 동기화] → 학생 리포트 일간·월간 "최근 평가 추이"에 점선과 범례가 보인다. `반 평균 숨김`을 체크하고 다시 동기화하면 사라진다. `node tests/design-lint.cjs` 통과.
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌리고 함수를 재배포한다. 캐시에 남은 `class_avg`는 옛 화면이 무시한다.

## 항목 4. Notion 학습기록·클래스 DB에 평가 전용 반 칸 추가

- **유형**: AI 자동
- **선행 조건**: 없음(칸만 추가, 지금 코드는 아직 이 칸을 읽지 않는다)
- **변경 이유·증상**: 출석·수업 없이 평가만 보는 반(모의고사반 등)을 위한 준비. 평가 종류를 나누고, 출석이 없는 평가도 날짜·반을 가질 수 있게 한다.
- **Notion 변경**
  - `학습기록 DB / 속성 / 평가 구분` — 선택: 일일 평가(회색)·주간 평가(노랑)·월간 평가(파랑)·단원 평가(초록)·기타(기본). 출석·수업으로 만든 평가는 일일 평가로 둔다.
  - `학습기록 DB / 속성 / 평가 기간` — 날짜(시작~끝 가능). 출석이 없는 평가의 날짜로 쓴다.
  - `학습기록 DB / 속성 / 클래스` — 클래스 DB와 양방향 관계, 클래스 쪽 이름 `학습기록`.
  - `클래스 DB / 속성 / 리포트 구성` — 선택: 전체(회색)·평가만(초록). 비어 있으면 전체.
  - `클래스 DB / 속성 / 평가 만들기` — 버튼. 이름·자리만 만들고 동작(웹훅)은 비워 둔다. 동작은 평가 전용 반 코드 항목에서 연결한다.
  - 레이아웃(10/26 사용자 확정)
    - 학습기록 오른쪽 패널: `등록` 아래 "평가 정보" 구역 [`평가 구분`, `평가 기간`, `클래스`], 셋 다 항상 표시. 나머지 숨김 칸은 그 아래 "시스템" 구역.
    - 클래스 상단 버튼 줄: `교재 생성` · `교재비 생성` · `평가 만들기` · `보고서 생성` · `월 수강료 생성` · `학생 페이지 동기화`.
    - 클래스 탭: `학습기록` 관계로 "평가" 탭(표, 구분 = 평가, 열 학습·수업일·평가 구분·평가 기간·학습활동 현황, 생성 일시 내림차순). 탭 순서는 수업 · 평가 · 일정.
    - 클래스 "리포트 설정" 구역에 [`리포트 구성`, `반 평균 숨김`] 순서. 클래스의 `학습기록` 관계는 시스템 구역에 숨김.
    - 메뉴 "학습 보고서" 페이지 표의 탭 순서: 클래스별 보고서 생성 · 클래스별 평가 만들기 · 평가 · 보고서 그룹 · 학습 보고서.
      - "클래스별 평가 만들기": 클래스 DB 표(클래스명·학생수·`평가 만들기`·리포트 구성·실시간 처리 상태, 클래스명 오름차순). 반 페이지와 같은 버튼 칸이라 어디서 눌러도 결과가 같다.
      - "평가": 학습기록 DB 표(구분 = 평가, 열 학습·클래스·수업일·평가 구분·평가 기간·학습활동 현황, 생성 일시 내림차순).
  - 기존 평가 학습기록의 `클래스`는 연결된 수업의 `클래스`로 채운다. 수업에 클래스가 없으면 비워 두고 원본에 알린다(추측해서 채우지 않음).
  - 이미 있으면 건너뛴다. 이름이 다르면 멈추고 원본 요청.
- **검증**: 평가 학습기록을 열면 오른쪽 패널 "평가 정보"에 세 칸이 비어 있어도 보인다. 클래스 페이지 버튼 줄에 [평가 만들기]가 `보고서 생성` 앞에 있고, "평가" 탭에 그 반 평가 기록만 보인다. 메뉴 "학습 보고서"에 두 탭이 보이고 [평가 만들기]가 반마다 보인다. 클래스 패널 "리포트 설정"에 두 칸이 보인다.
- **실패 시 대처**: 추가한 칸·버튼·탭을 지우고 레이아웃을 되돌린다. 기존 데이터와 자동화에는 영향이 없다(버튼은 동작이 없어 눌러도 아무 일도 없음).
