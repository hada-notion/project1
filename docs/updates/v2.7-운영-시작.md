# v2.7 운영 적용 시작 안내 (운영 AI가 먼저 읽는 문서)

- 대상: v2.6.5 학원이 v2.7.1~v2.7.4를 적용할 때
- 목적: 누가 무엇을 하는지 나눠, 운영 AI가 할 수 있는 일은 끝까지 하고 원장님 일은 몇 번에 모아서 짧게 끝낸다.
- 순서와 상세 절차: [v2.7 개요](v2.7.md), [v2.7.1](v2.7.1.md) → [v2.7.2](v2.7.2.md) → [v2.7.3](v2.7.3.md) → [v2.7.4](v2.7.4.md), Notion 원문 [v2.7-노션-작업](v2.7-노션-작업.md)

---

## 1. 역할

| 역할 | 하는 일 | 못 하는 일 |
| --- | --- | --- |
| **운영 AI** (그 학원의 AI) | 진행을 이끈다. 운영 저장소·Supabase 배포, Notion 커넥터로 속성 추가·이름 바꾸기·삭제·메뉴얼 수정, 상태값 조회, 기록 | Notion 화면에서만 되는 일(자동화 만들기·고치기, 버튼 동작 설정, 다른 DB를 거치는 수식 붙여넣기) |
| **원본 지원** (원본 배포 담당과 그 AI) | 운영 AI가 막힌 Notion 화면 작업을 그 학원 Notion에 브라우저로 들어가 대신한다 | 운영 저장소·Supabase 작업, 웹훅 키 값 입력(AI는 비밀값을 넣지 않는다) |
| **원장님** (운영 소유자) | 승인, 원본 지원 초대·해제, 웹훅 키 값 넣기, 테스트 알림톡 받기, 선생님 안내 | — |

- 이 문서와 v2.7 지침의 **운영자 직접** 항목은 원장님 대신 **원본 지원**이 맡을 수 있다. 원장님이 직접 하겠다고 하면 그대로 따른다.
- 운영 AI는 원본 지원이 한 작업도 확인하고 이 학원 기록에 남긴다. 기록의 주인은 운영 AI다.

## 2. 진행 방식: 운영 AI → (막히면) 원본 지원 → 운영 AI

1. 운영 AI가 v2.7.1부터 순서대로 진행한다. 커넥터로 되는 일은 모두 먼저 끝낸다.
2. 화면 작업에서 막히면 그 자리에서 멈추지 말고 **넘김 메모**에 모아 두고, 그 뒤에 할 수 있는 커넥터·저장소 작업을 계속한다. 단, 지침의 선행 조건(예: 버튼보다 자동화 먼저)을 어기면서 앞으로 가지 않는다.
3. 막힌 일이 모이면 원장님께 넘김 메모를 드리고 원본 지원에 전달을 부탁한다.
4. 원본 지원이 브라우저로 처리하고, 한 일과 못 한 일을 같은 메모에 적어 돌려준다.
5. 운영 AI가 결과를 확인(상태값 조회, 버튼 1회 확인)하고 기록한 뒤 다음 단계로 간다.

### 넘김 메모 형식

```text
[넘김 메모] ○○학원 / 단계 v2.7.x / 날짜
- 할 일: N-번호, DB 이름, 무엇을(예: 교재배부 `[웹훅] 삭제` 헤더 확인)
- 왜 못 했나: (예: 커넥터로 자동화를 고칠 수 없음)
- 확인 방법: (예: [삭제]를 테스트 건에 눌러 ✅ 완료)
- 결과(원본 지원이 적음): 완료 / 못 함(이유) / 키 값 입력 필요
```

- 메모에 웹훅 주소·키·토큰·Notion ID를 쓰지 않는다. DB 이름과 N-번호만 쓴다.

## 4. 원장님 부담 줄이기

원장님께는 아래 네 번만 부탁드리도록 모은다. 그 사이에 따로 묻지 않는다.

1. **시작할 때 한 번**: 전체 계획 승인, 테스트 학생, v2.7.2 배포 시간.
2. **원본 지원이 들어올 때 한 번**: 원본 배포 담당 계정을 학원 Notion에 초대(아래 5장), 웹훅 키 값을 넣어야 하는 곳을 한 자리에서 몰아서 넣기.
3. **실제 발송 확인 한 번**: 테스트 학생 번호로 알림톡이 왔는지.
4. **끝날 때 한 번**: N-33 삭제 승인, 원본 지원 초대 해제, 선생님 안내.

## 5. 원본 지원 접속 방법

- 원장님이 원본 배포 담당 계정을 학원 Notion에 초대한다. 원장님 계정 비밀번호나 구글 로그인을 넘기지 않는다.
- 먼저 **게스트**(작업할 DB에 "전체 허용")로 초대한다. 게스트로 DB 자동화를 고칠 수 없으면, 작업하는 동안만 **멤버**로 초대했다가 끝나면 해제한다(게스트 자동화 편집 가능 여부는 아직 확인하지 않았다).
- 원본 지원은 학원 작업에 원본 값(Notion ID, Supabase 주소, 키)을 쓰지 않고, 학원별로 작업을 나눠 섞이지 않게 한다.

## 6. 원본에서 실제로 걸린 것 (항목 0에서 꼭 볼 것)

- `[웹훅]` 자동화의 `x-admin-key` 헤더: 원본은 교재배부 `[웹훅] 삭제`에 헤더가 없었고, 넣은 뒤에도 값이 틀려 삭제가 반응하지 않았다. 헤더가 있는지는 화면으로, 값이 맞는지는 지워도 되는 테스트 건에 버튼을 눌러 확인한다.
- 웹훅 본문이 비어 "유효하지 않음"인 자동화: 원본 출석 `[웹훅] 보고서 전송`. 본문은 `실행자`.
- 시험정보 `[편집] 시험정보 이름` 트리거가 "과목 속성이 ○○ 값으로 설정됨"이면 "과목 속성 편집"으로.

## 7. 지킬 것

- 비밀값(웹훅 키, 토큰, 설정 링크)은 채팅·문서·로그·넘김 메모에 쓰지 않는다. 원장님께도 "있다/없다/같다/다르다"만 묻는다.
- 학생·등록 정보를 바로 지우지 않는다. 삭제 확인은 지워도 되는 테스트 건을 새로 만들어서 한다.
- 실제 알림톡은 테스트 학생에게만, 원장님 승인 후 보낸다.
- 결과는 "원문 비교 완료 / 목록만 확인 / 미검증 / 보류"로 나눠 보고한다. 원본 지원이 한 일도 운영 AI가 확인하기 전에는 "미검증"이다.

## 8. 운영 AI 첫 응답

이 문서를 읽은 운영 AI는 아래를 원장님께 먼저 알린다.

1. 시스템 정보의 현재 버전(v2.6.5가 아니면 멈추고 보고)
2. 이 학원에서 커넥터로 할 수 있는 일과, 원본 지원이 필요할 것으로 보이는 일(3장 표 기준)
3. 원장님께 부탁드릴 일 4가지(4장)와 첫 번째 부탁: 계획 승인, 테스트 학생, v2.7.2 배포 시간
