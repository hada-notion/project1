# v2.5.12 — 관리자 이메일 인증·비밀번호·웹훅 키 분리

기준: hada-notion/project1 main 7741043910ba6912b6aa635f7b0e9ec18c3671e0.
변경 유형: 코드·Supabase 스키마·설치/운영 안내. 기존 Notion 업무 DB 스키마와 업무 데이터는 변경하지 않는다.
코드 배포와 실제 보안 모드 활성화·메일 수신 검증은 별개다. 이 버전은 설정 전 기존 인증을 유지하며 자동으로 소유자·비밀번호·키를 교체하지 않는다.

## 동작과 인증 경계

- 관리자 설정 페이지: `admin_settings.html`. 공개 연결 주소만 `admin_config.json`에 두고, 비밀값은 HTML/JS/JSON에 넣지 않는다.
- 최초 설정: 학원별 일회용 링크 → 소유자 이메일 입력 → 이메일 OTP → 비밀번호 설정. 링크는 48시간, OTP는 10분, 오입력은 5회까지. 재발송은 60초 후, 발송 요청은 학원 단위로 시간당 10회 제한.
- 로그인: PBKDF2-SHA256 600,000회와 무작위 salt. 비밀번호를 브라우저에 저장하지 않으며 원문을 웹훅 헤더로 사용하지 않는다. 세션은 해시만 서버 저장, 유효시간 12시간. 기존 출결·서류·학교 화면은 세션으로 인증한다.
- 비밀번호 변경: 현재 비밀번호 + 등록 이메일 OTP. 비밀번호 해시·내부 무작위 키·Vault `sync_queue_admin_key`·변경일·이력을 **한 PostgreSQL 트랜잭션**에서 갱신. 실패 시 모두 rollback. 모든 기존 세션 폐기. 진행 중 서버 호출을 위해 이전 내부 키만 최대 5분 허용.
- 마지막 변경일과 3개월 권장 변경일 표시. 월말은 대상 월 마지막 날로 보정. 권장일이 지났다고 정상 업무를 강제로 차단하지 않는다. 페이지를 열지 않은 사람에게 정기 알림을 보내는 기능은 없음.
- 웹훅 키: 최초 설정 시 `WEBHOOK_SECRET`, 없으면 기존 `ADMIN_SECRET`에서 읽어 해시로 고정. 32자 이상 필요. Notion 헤더를 비밀번호 변경 때마다 수정하지 않는다. 웹훅 키는 허용된 업무 경로만 인증하며 관리자 로그인·설정 변경·개인자료 조회 전용 경로는 인증하지 못한다.
- **회전하는 내부 키의 실제 저장 위치는 서버 전용 DB/Vault다.** `getCurrentAdminKey`와 `getEffectiveAdminKey`가 이를 공통으로 읽는다. Supabase Edge Function Secrets의 기존 `ADMIN_SECRET` 문자열이나 GitHub Secret 값을 비밀번호 변경 때 수정하지 않는다. 기존 `ADMIN_SECRET`은 최초 웹훅 키 호환값으로 남는다. 프로젝트 전체 관리 토큰을 웹페이지나 함수에 추가하지 않는다.
- GitHub 출석 예약 작업의 기존 인증값은 웹훅 범위로 유지. DB 예약 작업은 갱신된 Vault 키로 인증.
- `mark-report-source-dirty`는 기존 코드에서 키 인증이 없었다. 새 보안 모드에서 헤더 또는 body.adminKey 인증이 필요하므로 활성화 전에 해당 자동화의 인증값을 반드시 확인한다.

## AI 자동: 코드 준비와 배포

1. 저장소·브랜치·기준 커밋·승인 확인. 원본은 배포 담당자의 승인된 작업에서만 수정한다. 각 학원은 자기 운영 저장소와 설정에 적용한다.
2. 새 마이그레이션 `20261011010000_admin_security.sql`을 적용한다. 기존 테이블·Vault 값은 이 마이그레이션만으로 변경하지 않는다. 새 인증 테이블은 anon/authenticated/service_role 직접 접근을 차단하고 service_role 전용 RPC만 허용한다.
3. 전체 함수 타입 검사, 기존 104개 테스트, 신규 인증 24개 테스트, PostgreSQL 50개 검사, 회귀 가드를 실행한다. DB 테스트는 PGlite와 트랜잭션 Vault 모의 함수이며 실제 Vault 암호화·클라우드 배포 검증과 구분한다.
4. 승인된 기존 CI로 Edge Functions와 Pages를 배포하고, 실제 파일과 CI 결과를 확인한다. `ADMIN_SECURITY_ENABLED`가 설정되지 않았거나 false이면 기존 인증을 유지한다. 메일 키와 소유자 키를 생성/출력하지 않는다.
5. `scripts/setup-new-academy.py`가 새 운영의 공개 주소를 `admin_config.json`에도 치환하는지 확인한다. 이 파일에는 URL 외 이메일·키·설정 링크를 넣지 않는다.

## 운영자 직접 또는 권한을 가진 설치 도구: 최초 1회 연결

키는 채팅·Notion·공개 Git에 붙이지 않는다. 서비스 설정 화면 또는 비밀값을 노출하지 않는 승인된 배포 도구만 사용한다.

1. **기존 운영은 유지보수 시간을 잡는다.** 키 불일치를 추정하지 않는다. 기존 웹훅 인증값·GitHub 출석 예약 인증값·기존 KV/admin_settings 값의 차이를 비공개로 확인한다. 서로 다르면 이 패치를 활성화하지 말고 전환 계획부터 정한다.
2. Supabase Secrets에 `ADMIN_MAIL_API_KEY`(Resend 전송 권한 키), `ADMIN_MAIL_FROM`(Resend에서 검증된 발신 도메인/주소), `ADMIN_ALLOWED_ORIGINS`(실제 관리 페이지의 origin, 쉼표로 복수 지정)를 등록한다. 수신자 이메일은 이 단계에 등록하지 않는다. Resend 도메인 검증·요금·전송 한도·데이터 처리 정책은 운영자가 확인한다. 다른 메일 서비스를 사용하려면 sendCode 어댑터만 별도 구현·검수한다.
3. `WEBHOOK_SECRET`을 설정하는 경우 기존 헤더와 **동일한 값**을 사용한다. 기존 ADMIN_SECRET을 그대로 사용할 수 있으면 별도 WEBHOOK_SECRET 설정은 불필요. 현재 키가 32자 미만이면 안전한 학원 전용 키로 최초 변경하고 해당 헤더를 함께 정비해야 한다. 평소 교체와 최초 설치를 혼동하지 않는다.
4. `mark-report-source-dirty`를 사용하는 자동화에 동일한 고정 웹훅 키가 있는지 확인한다. 다른 기존 헤더도 실제 값을 확인하되 임의로 교체하지 않는다.
5. 배포 담당자만 접근할 수 있는 로컬 환경에 SB_URL/SB_SERVICE_ROLE_KEY를 안전하게 주입하고 `python3 scripts/provision-admin-setup.py --page-url <해당 학원의 관리자 설정 HTTPS 주소> --output <비공개 로컬 파일>`을 실행한다. 토큰 원문은 0600 파일에만 저장하고 stdout에 출력하지 않는다. 파일은 .gitignore로 제외된다. 이 명령은 재발급 시 기존 미완료 링크·OTP를 무효화하며 설정 완료 후에는 실행을 거부한다. 링크는 원장에게 비공개로 전달한다.
6. 준비가 끝난 유지보수 시간에 `ADMIN_SECURITY_ENABLED=true`로 활성화한다. 미설정 상태에서는 관리자 업무·웹훅·내부 호출 인증을 차단하므로, 바로 일회용 링크로 이메일 인증·비밀번호 설정을 완료한다. 새 학원은 실사용 시작 전에 한다. 활성화 전/후 혼재와 진행 중 작업을 확인한다.
7. 원장님이 관리 페이지에서 설정 완료 후 새 비밀번호로 로그인한다. 실제 이메일 수신, 잘못된 번호·만료·재사용 차단, 기존 세션 폐기, 웹훅 정상 인증과 잘못된 키 거부, 내부 큐/예약 작업 정상 인증을 확인한다. 업무 데이터 삭제·실출결·학부모 발송은 별도 승인 없이 검수하지 않는다.
8. 실제 결과·미완료 항목·적용 버전을 운영 `docs/operation-update-history.md`와 비공개 시스템 정보에 기록한다. 이 문서만으로 활성화 완료를 판단하지 않는다.

## 실패와 복구

- 코드 배포 후 활성화 전: 새 인증 테이블과 RPC를 유지해도 기존 인증은 그대로다. 기존 키를 임의로 바꾸지 않고 코드만 기준 커밋으로 복구할 수 있다.
- 설정/변경 트랜잭션 실패: 비밀번호·키·Vault·변경일은 바뀌지 않는다. 오류를 해결하고 유효한 링크/인증번호로 다시 진행한다. 네트워크 응답이 유실되면 새 비밀번호 로그인/변경일로 실제 완료 여부부터 확인하고 무조건 재교체하지 않는다.
- 활성화 후: `ADMIN_SECURITY_ENABLED=false`만 설정하는 것을 완전한 복구로 간주하지 않는다. 이전 KV/admin_settings·고정 웹훅 키·갱신된 Vault와 기존 세션 정책이 다르므로, 작업을 중단하고 권한을 가진 담당자가 인증 경로와 Vault를 안전하게 맞춘 뒤 재개한다. 학원 업무 데이터는 삭제하지 않는다.
- 비밀번호 분실·소유자 이메일 변경·웹훅 키 유출 시 일괄 교체는 이번 웹페이지 기능에 없음. 해당 서비스 소유권 확인과 별도 승인된 복구 작업이 필요하다. 웹훅 키 유출 시 Notion 헤더 수동 변경이 필요하며 내부 키 회전만으로 해결되지 않는다.

## 이번 보안 범위에 포함되지 않는 공개 경로

- `sync-report-cache`의 단건 경로(`registrationId`/`pageId`, `awaitCompletion` 없음)는 학생 보고서 공개 페이지가 anon 키만으로 호출하므로 의도적으로 인증하지 않는다. 키 검사를 추가하면 학생 화면의 동기화 버튼이 동작하지 않는다. 이 경로가 있는 한 "모든 경로가 인증된다"고 말하지 않는다. 호출량 제한은 별도 검토 항목이다.
- `mark-report-source-dirty`는 활성화 후 키를 요구한다. Notion 자동화에 키 헤더가 없으면 401이 되어 보고서 수정 표시가 멈추므로, 활성화 전에 헤더 유무를 확인한다.
- 보안 기능이 꺼져 있는 동안 `admin-security`는 허용 도메인 설정 없이도 고정 503 응답을 브라우저가 읽을 수 있게 하여 기존 로그인을 유지한다. 켜진 뒤에는 `ADMIN_ALLOWED_ORIGINS`에 없는 도메인을 거부한다.

## 미확인 사항

실제 메일 서비스 연결·발신 도메인 검증·수신, 실제 Supabase Vault 암호화·RLS·동시 작업, 사용자 브라우저에서 OTP/변경 실행, Notion 버튼 액션·자동화 헤더·기존 저장값의 직접 비교는 각 운영에서 추가 확인한다. 모의 검사와 CI 성공은 이 실사용 검증을 대신하지 않는다.
