# v2.5.12 — 관리자 비밀번호와 웹훅 키 분리

기준: hada-notion/project1 main 7741043910ba6912b6aa635f7b0e9ec18c3671e0.
변경 유형: 코드·Supabase 스키마(마이그레이션 2개)·설치/운영 안내. 기존 Notion 업무 DB 스키마와 업무 데이터는 변경하지 않는다.
코드 배포와 보안 모드 활성화는 별개다. `ADMIN_SECURITY_ENABLED=true`를 설정하기 전에는 기존 인증을 그대로 유지한다.

## 목적

키오스크·관리자 서류·학교 검색 화면의 관리자 비밀번호를 운영에서 직접 바꿀 수 있게 하되, 비밀번호를 바꿔도 Notion 버튼·자동화 웹훅의 헤더를 고칠 필요가 없게 한다. 이전에는 관리자 비밀번호와 웹훅 키가 같은 `ADMIN_SECRET` 하나였다.

## 동작과 인증 경계

- 관리자 설정 페이지: `admin_settings.html`. 공개 연결 주소만 `admin_config.json`에 두고, 비밀값은 HTML/JS/JSON에 넣지 않는다.
- **초기 비밀번호 `0000`**: 보안 모드 활성화 후 첫 요청에서 서버가 초기 상태를 만든다(초기 비밀번호 해시, 내부 키, Vault `sync_queue_admin_key`, 웹훅 키 해시). 초기 비밀번호로는 관리자 설정 페이지에서 **비밀번호 변경만** 할 수 있다. 키오스크·서류·학교 화면은 초기 비밀번호 로그인을 거부하고(409), 변경 전에는 어떤 브라우저 세션도 업무 함수를 호출할 수 없다.
- **비밀번호 변경**: 현재 비밀번호 + 새 비밀번호(앞뒤 공백 없이 8~128자, `0000` 불가). 비밀번호 해시·내부 무작위 키·Vault `sync_queue_admin_key`·변경일·이력을 **한 PostgreSQL 트랜잭션**에서 갱신. 실패 시 모두 rollback. 모든 기존 세션 폐기. 진행 중 서버 호출을 위해 이전 내부 키만 최대 5분 허용.
- 로그인: PBKDF2-SHA256 600,000회와 무작위 salt. 5회 오입력 시 15분 잠금. 비밀번호를 브라우저에 저장하지 않는다. 세션은 해시만 서버 저장, 유효시간 12시간.
- 키오스크 세션: 출결 키오스크(`attendance_kiosk.html`)에서 로그인하면 30일 유효한 키오스크 전용 세션을 받는다. 이 세션은 `kiosk-checkin`과 최소 목록 `list-students?kiosk=1`만 호출할 수 있고, 보고서 토큰이 포함된 일반 학생 목록·관리자 설정·비밀번호 변경·다른 업무 함수는 호출하지 못한다. 비밀번호를 변경하면 키오스크 세션도 함께 폐기되므로 키오스크에서 다시 로그인한다.
- 인증 범위 판정: 각 키(내부·웹훅·관리자 세션·키오스크 세션)가 호출할 수 있는 함수는 요청 주소 맨 앞의 함수 이름으로 판정한다. 하위 경로(`sync-registration-textbook/create-class`, `sync-textbook-distribution/from-cart` 등)는 상위 함수 이름으로 판정하며, 주소 뒤에 다른 함수 이름을 덧붙여 범위를 넓힐 수 없다.
- 마지막 변경일과 3개월 권장 변경일 표시. 권장일이 지났다고 업무를 차단하지 않는다.
- **웹훅 키**: Edge Function Secrets의 `WEBHOOK_SECRET`, 없으면 기존 `ADMIN_SECRET`을 초기화 때 해시로 고정한다. Notion 헤더를 비밀번호 변경 때마다 수정하지 않는다. 웹훅 키는 허용된 업무 경로만 인증하며 관리자 로그인·설정 변경·개인자료 조회 전용 경로는 인증하지 못한다. 32자 미만이면 관리자 설정 상태 응답에 `webhook_key_weak`로 표시된다(동작은 허용).
- **회전하는 내부 키의 실제 저장 위치는 서버 전용 DB/Vault다.** `getCurrentAdminKey`와 `getEffectiveAdminKey`가 이를 공통으로 읽는다. Supabase Secrets의 `ADMIN_SECRET` 문자열은 비밀번호 변경 때 바뀌지 않는다. 웹페이지에서 Supabase Secrets를 바꾸는 기능은 만들지 않는다(서버에 프로젝트 관리 토큰을 두어야 하므로).
- 출석 동기화 워크플로(`sync-attendance-*-cron.yml`)는 GitHub Actions Secret `ADMIN_SECRET`을 보낸다. v2.5.13부터 정기 예약은 해제되어 수동 실행할 때만 쓰인다. 수동 실행하는 운영은 이 값이 고정 웹훅 키와 같아야 한다. 수동 실행을 쓰지 않으면 필요 없다.
- `mark-report-source-dirty`는 기존 코드에서 키 인증이 없었다. 보안 모드에서 헤더 또는 body.adminKey 인증이 필요하다. Notion 자체 자동화(속성 직접 기록)로 수정일을 기록하는 운영은 이 웹훅을 호출하지 않으므로 영향이 없다.
- 이메일 인증·일회용 설정 링크는 쓰지 않는다. 메일 서비스와 소유자 이메일은 필요 없다.

## AI 자동: 코드 준비와 배포

1. 저장소·브랜치·기준 커밋·승인 확인. 원본은 배포 담당자의 승인된 작업에서만 수정한다. 각 학원은 자기 운영 저장소와 설정에 적용한다.
2. 마이그레이션 `20261011010000_admin_security.sql`, `20261012010000_admin_password_simplify.sql`을 순서대로 적용한다. 기존 테이블·Vault 값은 마이그레이션만으로 변경하지 않는다. 인증 테이블은 anon/authenticated/service_role 직접 접근을 차단하고 service_role 전용 RPC만 허용한다.
3. 전체 함수 타입 검사, 전체 Deno 테스트, PostgreSQL 검사, 회귀 가드를 실행한다. DB 테스트는 PGlite와 트랜잭션 Vault 모의 함수이며 실제 Vault 암호화·클라우드 배포 검증과 구분한다.
4. 승인된 기존 CI로 Edge Functions와 Pages를 배포하고, 실제 파일과 CI 결과를 확인한다. **함수를 먼저 배포한 뒤 화면(Pages)을 배포한다.** 새 화면이 아직 없는 `admin-security`를 호출하면 기존 로그인이 실패할 수 있으므로, 함수 배포 워크플로를 먼저 실행해 완료를 확인한 다음 화면이 포함된 변경을 main에 반영한다.
5. `scripts/setup-new-academy.py`가 새 운영의 공개 주소를 `admin_config.json`에도 치환하는지 확인한다. 이 파일에는 URL 외 값을 넣지 않는다.

## 운영자 직접: 활성화

키는 채팅·Notion·공개 Git에 붙이지 않는다. 서비스 설정 화면에만 입력한다.

1. Supabase Edge Function Secrets에 `ADMIN_ALLOWED_ORIGINS`(실제 관리 페이지의 origin, 예: `https://계정.github.io`, 쉼표로 복수 지정)를 등록한다. `ADMIN_SECRET`(또는 `WEBHOOK_SECRET`)이 Notion 웹훅 헤더와 같은 값인지 확인한다. 값이 다르면 활성화하지 않는다.
2. 학원이 쉬는 시간에 `ADMIN_SECURITY_ENABLED=true`를 등록한다. 이때부터 키오스크·서류·학교 화면은 `0000` 로그인을 거부하므로, 바로 다음 단계를 진행한다. Notion 웹훅과 DB 예약 작업은 계속 동작한다.
3. 원장님이 `admin_settings.html`에서 `0000`으로 로그인해 새 비밀번호를 설정한다.
4. 키오스크·관리자 서류·학교 검색 화면에서 새 비밀번호로 로그인되는지, Notion 버튼 하나가 정상 동작하는지 확인한다. 업무 데이터 삭제·실출결·학부모 발송은 별도 승인 없이 검수하지 않는다.
5. 실제 결과·미완료 항목·적용 버전을 운영 `docs/operation-update-history.md`와 비공개 시스템 정보에 기록한다.

`0000`은 공개된 값이므로, 활성화 후 원장님이 바꾸기 전까지는 관리자 설정 주소를 아는 다른 사람이 먼저 비밀번호를 정할 수 있다. 이때도 업무 데이터는 노출되지 않으며, 아래 초기화로 되찾는다. 활성화와 변경은 같은 시간에 이어서 진행한다.

## 비밀번호 분실·초기화 (배포 담당자)

Edge Function Secrets의 `ADMIN_SECRET`을 바꿔도 관리자 비밀번호는 초기화되지 않는다. 비밀번호는 서버 DB에 해시로 저장된다.

1. 배포 담당자만 접근할 수 있는 컴퓨터에서 해당 학원의 `SB_URL`, `SB_SERVICE_ROLE_KEY`를 환경 변수로만 설정한다(명령 인자·파일·채팅에 남기지 않는다).
2. `python scripts/reset-admin-password.py --confirm`을 실행한다. 모든 관리자·키오스크 로그인이 해제되고, 다음 요청 때 초기 비밀번호 `0000`이 다시 적용된다. 웹훅 키와 내부 키는 바뀌지 않는다.
3. 원장님이 `0000`으로 로그인해 새 비밀번호를 설정한다.

## 매뉴얼 갱신 (사용법 변경)

- 관리자 설정: 처음에는 `0000`으로 로그인해 바로 비밀번호를 바꾼다. 비밀번호를 잊으면 배포 담당자에게 초기화를 요청한다.
- 출결 키오스크: 보안 모드 활성화 후에는 관리자 비밀번호로 로그인한다. 로그인은 30일 유지되며, 비밀번호를 변경하면 키오스크에서 다시 로그인한다. 시스템 운영 페이지의 키오스크 문제 해결 순서 "관리자 키 → …"는 "키오스크 로그인 상태 → …"로 바꾼다.
- 관리자 서류·학교 검색: 관리자 비밀번호로 로그인하고 12시간 후 다시 로그인한다.

## 실패와 복구

- 코드 배포 후 활성화 전: 인증 테이블과 RPC가 있어도 기존 인증은 그대로다. 코드만 기준 커밋으로 복구할 수 있다.
- 변경 트랜잭션 실패: 비밀번호·키·Vault·변경일은 바뀌지 않는다. 응답이 유실되면 새 비밀번호 로그인으로 실제 완료 여부부터 확인한다.
- 활성화 후: `ADMIN_SECURITY_ENABLED=false`로 되돌리면 기존 `ADMIN_SECRET` 인증으로 돌아간다. 단, 초기화 이후 Vault `sync_queue_admin_key`는 서버가 만든 내부 키로 바뀌어 있으므로, 되돌릴 때는 Vault 값을 기존 `ADMIN_SECRET`과 같게 다시 맞춰야 DB 예약 작업이 동작한다. 학원 업무 데이터는 삭제하지 않는다.
- 웹훅 키 유출 시: 비밀번호 변경이나 내부 키 회전으로는 막히지 않는다. 웹훅 키 교체와 Notion 헤더 수정이 필요하다(웹훅 키 교체 화면은 다음 패치 범위).

## 이번 보안 범위에 포함되지 않는 공개 경로

- `sync-report-cache`의 단건 경로(`registrationId`/`pageId`, `awaitCompletion` 없음)는 학생 보고서 공개 페이지가 anon 키만으로 호출하므로 의도적으로 인증하지 않는다. 키 검사를 추가하면 학생 화면의 동기화 버튼이 동작하지 않는다. 이 경로가 있는 한 "모든 경로가 인증된다"고 말하지 않는다.
- 보안 기능이 꺼져 있는 동안 `admin-security`는 허용 도메인 설정 없이도 고정 503 응답을 브라우저가 읽을 수 있게 하여 기존 로그인을 유지한다. 켜진 뒤에는 `ADMIN_ALLOWED_ORIGINS`에 없는 도메인을 거부한다.

## 미확인 사항

실제 Supabase Vault 암호화·RLS·동시 작업, 사용자 브라우저에서 초기 비밀번호 변경 실행, Notion 버튼 액션·자동화 헤더와 `ADMIN_SECRET`의 일치는 각 운영에서 추가 확인한다. 모의 검사와 CI 성공은 이 실사용 검증을 대신하지 않는다.
