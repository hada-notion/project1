## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/cartPlan.ts`, `sync-textbook-distribution/index.ts`, `process-sync-queue/index.ts`, `admin_settings.js`·`admin_settings.html` 반영 시 자동 배포)
- **동작**: `/from-cart/queue`는 큐에 넣고 바로 응답한다. 큐 처리: (본문에 `담기 계획`이 없거나 읽을 수 없으면 교재비 1번 읽기) → 그 등록의 교재배부 1번 조회 → 아직 없는 교재만 교재배부 만들기(이름 = 교재명, 등록, 라이브러리, 배부일 = 오늘, 교재비) → 교재비 쓰기 1번(담기 상태 ✅ 완료, 오류 지움, 마지막 동기화). 계획 형식이 틀리면 만들지 않고 ⚠️ 오류(재시도 없음), 만들다 실패하면 큐가 다시 시도한다. 수식이 없으면 예전 방식. 예전 `/from-cart`도 그대로 동작한다.
- **관리자 설정**: 웹훅 체크리스트에서 [진도교재 담기] 주소를 `/from-cart/queue`로, 클래스 [교재비 생성]은 "(예전 방식)"으로 표시한다(39개 유지).
- **검증(원본)**: 함수 테스트(계획 해석·형식 오류 / 이미 배부된 교재 건너뜀·쓰기 1번 / 담을 교재 없음 / 수식 없으면 예전 방식 / 형식 오류는 재시도 없음), 전체 Deno 테스트, 타입 검사, 회귀 가드, 관리자 보안 테스트, 디자인 규칙 검사, 화면 검사.

## 항목 2. 교재비(학원) DB 수식 `담기 계획`

- **유형**: 운영자 직접(원본에는 있음, 값 확인 완료)

```
lets(
  done, prop("교재배부").map(current.prop("라이브러리")).flat().map(id(current)),
  libs, prop("등록").map(current.prop("진도교재")).flat()
    .filter(current.prop("진행상태") == "진행 중")
    .map(current.prop("라이브러리")).flat()
    .filter(not done.includes(id(current))).unique(),
  "{\"v\":1,\"r\":\"" + prop("등록").map(id(current)).join("") + "\",\"items\":[" +
    libs.map("{\"l\":\"" + id(current) + "\",\"t\":\"" + current.format().replaceAll("\"", "") + "\"}").join(",") + "]}"
)
```

- 진도교재·교재배부 DB의 관계 이름이 `정규교재`(옛 이름)이면 `라이브러리`를 `정규교재`로 바꾼다.
- **확인**: 이미 다 담긴 교재비는 `"items":[]`, 아직 담지 않은 교재가 있으면 그 교재명이 나온다.

## 항목 3. 교재비 [진도교재 담기] 버튼

- **유형**: 운영자 직접
- 웹훅 주소 끝을 `/from-cart`에서 `/from-cart/queue`로 바꾼다. 헤더 `x-admin-key`는 그대로. 본문 속성은 `담기 계획`만 고른다(Notion이 막으면 비워도 된다 — 서버가 교재비를 한 번 읽는다).

## 항목 4. 클래스 [교재비 생성]을 Notion 자동화로

- **유형**: 운영자 직접
1. 등록(학원) DB에 선택 속성 `교재비 생성 상태`(⚪ 대기 / ✅ 완료)를 추가한다(원본에는 있음). 등록 페이지에서는 숨긴다.
2. 등록(학원) DB 자동화
   - 트리거: `교재비 생성 상태`가 `⚪ 대기`로 편집됨
   - 동작 1: 교재비(학원) DB에 페이지 추가 — `이름` = 수식 `context("페이지 실행").prop("이름") + " 교재비"`, `등록` = 페이지 실행(트리거 페이지), `알림톡 설정` = 알림톡 설정(학원) DB의 "교재비 안내" 행
   - 동작 2: 페이지 실행 편집 — `교재비 생성 상태` = `✅ 완료`
3. 클래스(학원) [교재비 생성] 버튼: 웹훅 보내기를 지우고
   - 변수 `대상등록` = `context("이 페이지").prop("등록").filter(current.prop("수강상태") == "🟢 수강 중" and current.prop("교재비").empty())`
   - 페이지 편집 — `var("대상등록")`: `교재비 생성 상태` = `⚪ 대기`
- **확인**: 교재비가 없는 수강 중 학생에게만 "학생 클래스 교재비" 페이지가 하나씩 생기고, 교재비가 이미 있는 학생은 그대로다. 다시 눌러도 새로 생기지 않는다.

## 항목 5. (보충) Notion 수식 2개

- **유형**: 운영자 직접(원본 반영 완료)
- 보고서(학원) DB `보고서기간(보고서)` — 월간 보고서 알림톡 제목이 "10월 1주차 월간 보고서"로 나가던 것을 "10월 월간 보고서"로:
```
lets(
  s, dateStart(prop("보고서 기간")),
  format(month(s)) + "월" + if(prop("보고서 구분") == "주간 보고서", " " + format(ceil(date(s) / 7)) + "주차", "")
)
```
- 학습활동(학원) DB "학습활동명" 자동화의 제목 수식 — 같은 날 교재가 다른 과제가 둘이면 제목이 같아 구분이 안 되던 것을 교재명(없으면 학습기록 주제)을 붙여 구분:
```
lets(
  p, context("페이지 실행"),
  rec, p.prop("학습기록").first(),
  book, if(empty(rec), "", if(empty(rec.prop("교재")), rec.prop("주제"), rec.prop("교재").first().format())),
  if(p.prop("구분").empty(), "", "[" + p.prop("구분") + "] ") + p.prop("출석").format() + if(empty(book), "", " " + book)
)
```
  - 기존 학습활동 제목은 바꾸지 않아도 된다(출석·학습기록이 다시 편집될 때 바뀐다).
