# v2.6.18 — 수업 날짜 이동을 서버로: 출석 날짜·이름, 학습기록·학습활동 제목까지

- 날짜: 2026-10-16
- 이전 버전: v2.6.17
- 요약: 수업을 캘린더에서 옮기면(수업 `수업일시` 편집) 수업 DB 자동화가 웹훅을 보내고, 서버가 그 수업 출석의 `수업일시`를 수업과 같게 맞춘다. 서버가 바꾼 변경이라 출석 DB "이름 조정" 자동화가 출석마다 돌아 "학생 이름 + 새 날짜"로 제목을 다시 만든다. 학습기록·학습활동 제목 안의 날짜(`MM.DD(요일)`)도 서버가 새 날짜로 바꾼다. v2.6.17 항목 5(Notion 자동화가 출석 날짜를 직접 바꿈)를 대신한다.
- 왜: Notion 자동화가 바꾼 변경으로는 다른 자동화가 돌지 않는다(원본 확인 — 출석 "이름 조정" 자동화에 `수업일시` 편집 트리거가 있어도 돌지 않음). 그래서 v2.6.17 방식은 출석 날짜만 바뀌고 이름은 예전 날짜로 남았다. 수업 자동화에 출석 이름 편집을 넣으면 수식이 수업 기준으로 한 번만 계산돼 모든 출석에 같은 값(반 학생 전원 이름)이 들어간다. 서버(API)가 바꾼 변경으로는 자동화가 돈다(출석 생성 → 이름 조정, `삭제 체크` → 삭제 자동화로 확인됨).
- 매뉴얼 영향: 없음(v2.6.17 "수업 날짜" 문구 그대로)
- 변경 유형: 함수(`fix-attendance` 새 경로 `session-date`, `process-sync-queue`), Notion 자동화 1개 바꾸기(운영자 직접). Supabase 테이블·Secrets 변경 없음.
- **선행 조건: 출석(학원) DB "이름 조정" 자동화(트리거에 `수업일시` 편집 포함, 아래 항목 2).**

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/sessionDateMove.ts`, `supabase/functions/fix-attendance/index.ts`, `supabase/functions/process-sync-queue/index.ts`를 반영하면 함수 자동 배포)
- **동작**: `fix-attendance/session-date`는 큐에 넣고 바로 202. 워커가 수업을 한 번 읽어(여러 번 옮겨도 마지막 날짜로) 그 수업의 출석·학습기록·학습활동을 조회하고, 날짜가 다른 출석만 `수업일시`를 바꾸며, 학습기록(`학습`)·학습활동(`학습활동`) 제목의 마지막 `MM.DD(요일)`만 한국 날짜로 바꾼다(날짜 표시가 없거나 같으면 쓰지 않음). 출석 제목은 서버가 쓰지 않는다(Notion 이름 자동화).
- **Notion 호출(수업 하나 이동)**: 수업 읽기 1 + 조회 3 + 바뀐 출석 수 + 바뀐 기록 제목 수.
- **검증(원본)**: 함수 테스트(한국 날짜·요일, 제목 날짜만 교체, 이미 같은 출석은 그대로, 출석은 날짜만 쓰고 이름은 쓰지 않음, 경로 인증·큐 적재·Notion 읽기 없음), 전체 Deno 테스트, 타입 검사, 회귀 가드.

## 항목 2. 수업(학원) DB "출석 날짜 자동 동기화" 자동화 바꾸기 (항목 1 배포 뒤)

- **유형**: 운영자 직접
- **작업**
  - 트리거: `수업일시` 속성 편집(그대로)
  - 동작: v2.6.17의 "변수 정의 `대상출석`"과 "`대상출석` 편집"(출석 날짜·이름 편집)을 **지우고**, "웹훅 보내기"만 둔다
    - 주소: `https://<학원 Supabase 주소>/functions/v1/fix-attendance/session-date`
    - 헤더: `x-admin-key` = 웹훅 키(값은 문서에 쓰지 않는다)
    - 포함할 속성: 없어도 된다(수업 페이지 id가 함께 감)
  - 이 자동화에 출석 이름 편집을 넣지 않는다(모든 출석에 같은 이름이 들어간다).
- **출석(학원) DB "이름 조정" 자동화 확인**: 트리거에 `페이지 추가`·`수업일시` 편집·`등록` 편집이 있고, 동작은 이 페이지의 `출석`(제목)을 아래 값으로 설정. 자동화 수식에서 트리거 페이지는 `context("페이지 실행")`이다. `day()`는 일요일이 0이다.
  ```
  if(context("페이지 실행").prop("등록").empty(),"학생이름",
  context("페이지 실행").prop("등록").map(current.prop("학생정보")).flat().format()) + " " +
  if(context("페이지 실행").prop("수업일시").empty(),"출석",
  context("페이지 실행").prop("수업일시").formatDate("MM.DD")+
  ifs(
  context("페이지 실행").prop("수업일시").day()==1,"(월)",
  context("페이지 실행").prop("수업일시").day()==2,"(화)",
  context("페이지 실행").prop("수업일시").day()==3,"(수)",
  context("페이지 실행").prop("수업일시").day()==4,"(목)",
  context("페이지 실행").prop("수업일시").day()==5,"(금)",
  context("페이지 실행").prop("수업일시").day()==6,"(토)",
  context("페이지 실행").prop("수업일시").day()==0,"(일)")
  )
  ```
- **이미 이름이 잘못 바뀐 출석**(v2.6.17 자동화에 이름 편집을 넣어 반 학생 전원 이름이 들어간 경우): 항목 2를 마친 뒤 그 수업을 하루 옮겼다가 되돌리면, 서버가 출석 날짜를 바꿀 때마다 이름 조정 자동화가 다시 계산해 학생별 이름으로 돌아온다.
- **확인**: 수업 하나를 캘린더에서 하루 옮기면 잠시 뒤 출석 날짜·이름, 학습기록·학습활동 제목의 날짜가 새 날짜로 바뀐다.
