- 날짜: 2026-10-14
- 이전 버전: v2.5.112
- 요약: v2.5.112에서 만든 복사본 표(`cr_sessions`·`cr_attendance`·`cr_records`·`cr_activities`)를 Notion에서 채우고 맞추는 함수를 추가한다. Notion은 읽기만 하고, 수업 관리 화면은 아직 이 표를 읽지 않는다(읽기 전환은 5단계). 설계: `docs/설계-수업관리-복사본.md`.
- 매뉴얼 영향: 없음
- 변경 유형: 새 함수(자동 배포) + 수동 워크플로 + 관리자 설정 웹훅 점검 목록(Notion 밖 함수 목록). 화면·Notion·DB 구조 변경 없음.

## 항목 1. 함수 `sync-class-room-copy`

- **유형**: AI 자동(`main` 병합 시 배포)
- **대상 파일**: `supabase/functions/sync-class-room-copy/index.ts`, `supabase/functions/_shared/classRoomCopy.ts`(+ `_test.ts`), `supabase/functions/_shared/adminSecurity.ts`(웹훅 경로 목록), `admin_settings.js`(Notion 밖 함수 목록), `.github/workflows/deploy-supabase-functions.yml`(새 테스트)
- **동작**(관리자 키 `x-admin-key` 필요):
  - `{ mode: "reconcile", table, fromDays=120, toDays=60 }`: 표 하나를 기간 전체 Notion과 대조해 upsert. 수업·출석은 "수업일시"가 기간 안, 학습기록·학습활동은 Notion 생성 시각이 기간 시작 이후. 수업·출석은 기간 안인데 Notion에 없는 행을 지운다(학습기록·학습활동은 지우지 않음 — 읽을 때 수업·기록의 관계에 있는 것만 쓴다). 처음이면 커서(`sync_cursors`의 `cr_*`)를 시작 시각으로 둔다.
  - `{ mode: "incremental", table? }`: 커서 − 2분 이후 Notion에서 바뀐 페이지만 upsert하고 커서를 옮긴다. 커서가 없으면 "처음 채우기를 하지 않았습니다" 오류.
  - `{ mode: "class", sessionId }`: 그 수업이 속한 반의 앞뒤 수업(9주 전 ~ 5주 뒤)과 그 출석·기록·학습활동만.
  - 반 이름·이모지, 교재 이름(기록 제목용)은 동기화할 때 한 번 읽어 저장한다.
- **검증(모의 데이터)**: 단위 테스트 4개(행 변환, reconcile 기간·삭제·커서, incremental 커서·2분 여유, class 범위), 전체 함수 `deno check`·테스트 201개, 회귀 가드, 관리자 설정 UI 검사.
- **미검증**: 운영 Notion에서의 처음 채우기(항목 2), 실행 시간.
- **실패 시 대처**: 이 함수는 복사본 표에만 쓰고 아직 아무도 그 표를 읽지 않으므로 화면 영향이 없다. 함수를 되돌리거나 표를 비우면 된다.

## 항목 2. 처음 채우기(수동)

- **유형**: 운영자 직접(승인 후 실행)
- **대상 파일**: `.github/workflows/class-room-copy-sync.yml`
- **동작**: GitHub Actions → "Class room copy sync (manual)" → mode `reconcile`(기본 120일 전 ~ 60일 뒤)로 실행. 함수 실행 시간 한도(150초) 안에 끝나도록 표 4개를 하나씩 부르고, 표마다 결과(`read`·`upserted`·`deleted`·`ms`)를 로그에 남긴다. Notion은 읽기만 한다. 실패하면 그 표부터 다시 실행해도 안전하다(같은 행은 덮어씀).
