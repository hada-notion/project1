- 이전 버전: v2.7.18

- 변경 유형: Edge Function 2개(`sync-report-cache`, `send-daily-report`), 학부모 리포트 스크립트 2개와 버전 표시, 워크플로 4개, 문서. Notion·Secrets·마이그레이션 변경 없음.

## 항목 1. 서버 함수 교체

- **유형**: AI 자동
- **선행 조건**: 등록(학원) DB [학생 페이지 동기화] 버튼의 웹훅에 `x-admin-key` 헤더가 있다(원본 지문 `등록(학원) DB / 버튼 / 학생 페이지 동기화`). 헤더가 없거나 키가 틀리면 이 버전부터 그 버튼이 401로 실패한다. 없으면 먼저 헤더를 넣는다(운영자 직접, 관리자 설정 웹훅 체크리스트의 키).
- **대상 코드**: `supabase/functions/sync-report-cache/index.ts`, `supabase/functions/send-daily-report/index.ts`를 원본 `main` 최신본으로 바꾼다.
  - 찾을 원문(앵커): `sync-report-cache`의 `const keyed = req.headers.has("x-admin-key")`, `send-daily-report`의 `console.log("send-daily-report finished:", attendanceId)`. 있으면 적용된 것이다.
- **동작**: 키(웹훅·관리자)가 맞으면 지금과 같다. 키가 없으면 ① `registrationId`와 그 등록의 보고서 `token`이 맞을 때만 갱신, ② 라이브러리·일정 자동화처럼 등록이 아닌 페이지는 지금처럼 갱신, ③ 등록 페이지를 지정하면 401. 키 없는 요청의 오류 응답은 "동기화하지 못했습니다."로만(자세한 내용은 함수 로그).
- **환경별 값·Secret**: 없음
- **마이그레이션 / 재배포**: 두 함수 재배포(main 반영 시 배포 작업이 함께 올린다).
- **검증**: 키 없이 등록 페이지 ID만 보내면 401, 틀린 토큰도 401. 학부모 리포트 오른쪽 아래 새로고침이 그대로 된다(항목 2와 같이 적용). 라이브러리 교재를 고치면 리포트 반영 자동화가 그대로 된다.
- **실패 시 대처**: 두 파일을 이전 버전으로 되돌려 재배포.

## 항목 2. 학부모 리포트 스크립트 교체

- **유형**: AI 자동
- **선행 조건**: 항목 1과 같이 배포한다. 함수만 새것이면 옛 화면의 새로고침이 토큰을 보내지 않아 401이 난다.
- **대상 코드**: `student_report_part1.js`·`student_report_part2.js`를 원본 `main` 최신본으로 바꾸고 `student_report.html`의 두 스크립트 주소 버전을 `node tests/design-lint.cjs --fix`로 맞춘다.
  - 찾을 원문(앵커): `student_report_part1.js`의 `function safeUrl(u)`·`function jsArg(v)`, `student_report_part2.js`의 `async function requestSyncForRegistrationId(registrationId, token)`.
- **검증**: 리포트에서 새로고침 → "최신 정보로 갱신했어요". 학습기록 본문 링크·사진·파일이 그대로 열린다. `node tests/design-lint.cjs` 통과.
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌린다.

## 항목 3. GitHub Actions 권한

- **유형**: AI 자동
- **대상**: 운영 저장소의 `.github/workflows/deploy-supabase-functions.yml`, `web-checks.yml`, `sync-attendance-incremental.yml`, `sync-attendance-reconcile.yml`. 파일을 통째로 바꾸지 않는다(배포 작업의 지역 주소 등 운영 값 보존). `jobs:` 바로 위에 아래 세 줄만 넣는다(이미 `permissions:`가 있으면 건너뜀).

  ```yaml
  permissions:
    contents: read
  ```

- **검증**: 다음 배포·검사 작업이 성공한다.
- **실패 시 대처**: 세 줄을 지운다.
