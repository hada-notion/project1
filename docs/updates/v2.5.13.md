# v2.5.13 — 출석 정기 예약 동기화 해제

- 날짜: 2026-10-12
- 이전 버전: v2.5.12
- 요약: GitHub Actions의 출석 정기 예약 동기화(매시간 증분, 매일 정합성 점검)를 해제한다. 학부모 리포트는 보고서 발송 직전과 "학생 페이지 동기화" 버튼에서만 최신화되어, 정리된 상태만 학부모 화면에 반영된다.
- 매뉴얼 영향: 있음 → 항목 2
- 변경 유형: 코드(워크플로·주석)·매뉴얼. Supabase 마이그레이션·Secrets·Notion 스키마·업무 데이터 변경 없음.

> 배경: 원본의 두 예약 워크플로는 확인 가능한 기록(2026-09-16~10-11) 전체에서 응답이 `{"error":"인증 실패"}`였지만, `curl`에 실패 감지 옵션이 없어 job은 성공으로 표시됐다. 그 기간에도 보고서 발송 직전 최신화(삭제분 포함, 실패 시 발송 중단)와 수동 동기화 버튼이 리포트를 정확히 유지했다. 정기 실행은 GitHub 지연으로 4~7시간 간격이었고, 수업 중 정리되지 않은 출석 상태를 학부모 화면에 자동 노출할 수 있었다.

---

## 항목 1. 예약 해제와 실패 표시

- **유형**: AI 자동
- **선행 조건**: 운영 소유자의 전체 계획 승인.
- **변경 이유·증상**: 위 배경 참고. 정기 실행이 필요하지 않고, 실패가 성공으로 표시되어 문제를 가렸다.
- **대상 코드**
  - `.github/workflows/sync-attendance-incremental-cron.yml`, `.github/workflows/sync-attendance-reconcile-cron.yml`
  - 찾을 원문 (각 파일의 `on:` 아래 예약 블록):

    ```
      schedule:
        - cron: '15 * * * *'      (incremental)
        - cron: '0 16 * * *'      (reconcile)
    ```

- **변경 내용**
  - `schedule:` 블록만 삭제하고 `workflow_dispatch: {}`는 유지한다(수동 실행 가능).
  - `curl -sS -X POST` → `curl -sS --fail-with-body -X POST`. HTTP 오류를 job 실패로 표시하고 응답 본문은 로그에 남긴다.
  - `supabase/functions/sync-attendance/index.ts` 첫 줄 주석을 "정기 예약 해제, 필요할 때 수동 실행"으로 수정. 실행 코드는 바꾸지 않는다.
- **환경별 값**: 없음.
- **필요한 Secret (이름만)**: 없음. 수동 실행을 쓰는 운영만 GitHub Actions Secret `ADMIN_SECRET`이 서버의 유효 키와 같아야 한다(보안 모드에서는 고정 웹훅 키).
- **Notion 변경**: 없음 (항목 2의 매뉴얼 문구만)
- **마이그레이션 / 재배포**: 없음. 예약은 기본 브랜치(main)의 워크플로 파일 기준이므로 main 반영 시점부터 적용된다. 함수 주석 변경으로 기존 CI가 함수 전체를 재배포하지만 동작 변화는 없다.
- **검증**:
  1. main 반영 후 Actions 탭에서 두 워크플로에 예약 실행이 더 이상 생기지 않는지 확인한다.
  2. 운영이 수동 실행을 쓰는 경우, 수동 실행 1회의 로그에서 응답이 `{"synced":...}`인지 확인한다. 인증 실패면 job이 실패로 표시되어야 한다.
  3. 테스트용 등록에서 "학생 페이지 동기화" 후 학부모 리포트 출석이 반영되는지 확인한다. 실제 학부모 발송은 하지 않는다.
- **실패 시 대처**: 예약 블록을 원래 문구로 되돌리면 이전 상태로 복구된다. 업무 데이터 변경 없음.
- **매뉴얼**: 항목 2

## 항목 2. 매뉴얼 문구

- **유형**: AI 자동
- **선행 조건**: 항목 1을 main에 반영한 뒤. 운영의 해당 페이지와 섹션이 없거나 원문이 다르면 그 문구만 보류하고 보고한다.
- **시스템 운영(큐·예약 실행·문제 해결) / 14. 예약 실행**
  - 표에서 `매시간 15분 | 출석 증분 동기화(sync-attendance incremental) | GitHub Actions` 행과 `매일 01:00 KST | 출석 전체 정합성 점검·삭제분 반영(sync-attendance reconcile) | GitHub Actions` 행을 삭제한다. pg_cron 3행은 유지한다.
  - 찾을 원문: `출석 증분 동기화와 전체 정합성 점검은 GitHub Actions의 정기 실행입니다.`로 시작해 `전체 정합성 점검은 삭제분까지 출석 원자료만 반영하며 보고서 캐시 전체를 재계산하지 않습니다.`로 끝나는 문단
  - 바꿀 원문:

    ```
    출석 원자료는 정기 예약으로 동기화하지 않습니다(v2.5.13). 보고서 발송 직전과 "학생 페이지 동기화" 버튼에서 해당 등록의 출석을 Notion에서 다시 읽어 원자료와 보고서 캐시를 최신화하며, Notion에서 삭제된 출석도 이때 함께 정리됩니다. 전체 출석을 한 번에 대조해야 할 때만 GitHub Actions의 Sync Attendance 워크플로를 수동 실행합니다.
    ```

  - 찾을 원문: `GitHub Actions 2건은 이 저장소의 .github/workflows에서, Supabase pg_cron 3건은`
  - 바꿀 원문: `Supabase pg_cron 3건은`
- **버튼 → Edge Function 웹훅 매핑**: 출석 안내 문단의 `출석 원자료는 매시간 증분 동기화와 보고서 발송 전 등록 단위 최신화로 반영합니다.`를 `출석 원자료는 보고서 발송 전과 "학생 페이지 동기화" 버튼의 등록 단위 최신화로 반영합니다.`로 바꾸고, 같은 문단의 `매일 전체 정합성 점검은 출석 원자료의 삭제분까지 대조합니다.` 문장과 `발송 없이 수정한 내용은 다음 증분 동기화까지 학부모 페이지에 늦게 반영될 수 있습니다.` 문장을 `발송 없이 수정한 내용은 다음 보고서 발송이나 학생 페이지 동기화 때 학부모 페이지에 반영됩니다.`로 바꾼다.
- 학부모·원장 사용 안내: 학부모 리포트는 보고서를 보낼 때 갱신된다. 보내기 전에 바로 보여줘야 하면 해당 등록의 "학생 페이지 동기화"를 누른다.
