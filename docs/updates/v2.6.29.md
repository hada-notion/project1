# v2.6.29 — 수업 [학습기록 생성]을 수식 계획 + 큐로

- 날짜: 2026-10-17
- 이전 버전: v2.6.28
- 요약:
  - 수업 수식 `학습기록 계획`이 만들 학습기록(명단 학생들의 진도교재 중 `오늘 학습`이 체크된 교재마다 1개 — 제목·출석·등록·교재·과목·보강)을 계산하고, 버튼 웹훅 본문에 실어 보낸다. 큐는 교재마다 `오늘 학습` 확인 → 체크 해제 → 학습기록 만들기만 한다. 서버가 하던 수업·출석 전부·등록 전부·진도교재 전부·라이브러리·클래스 읽기와 진도교재 상태 쓰기가 없어진다(6명, 체크된 교재 2권 기준 약 31 → 약 9 호출, 그중 4번은 상태 표시).
  - 결과는 예전과 같다: 그룹 진도(보강 아님)는 수업 출석·명단 전원, 개별 진도와 보강 수업은 그 교재를 가진 학생의 출석·등록만. 제목 `[학습] 교재(반) MM.DD(요일)`, 구분 학습, 보강 수업이면 `보강` 체크.
  - 두 번 누르거나 큐가 다시 시도해도 `오늘 학습`이 이미 풀린 교재는 건너뛴다(예전과 같은 중복 방지).
- 매뉴얼 영향: 없음(버튼 쓰는 법 그대로)
- 변경 유형: 함수(`create-learning-record`, `_shared/createLearningRecordTarget.ts`), Notion 수식 1개·버튼 본문 1개(운영자 직접).
- **순서: 항목 1(함수) 배포 → 항목 2 → 항목 3.** 항목 2·3을 안 해도 예전 방식으로 그대로 동작한다.

---

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/create-learning-record/index.ts`, `_shared/createLearningRecordTarget.ts` 반영 시 자동 배포)
- **동작**: 본문에 `학습기록 계획`이 있으면 클릭된 페이지를 다시 읽지 않고 큐에 넣는다. 큐 처리: (본문 값이 없거나 읽을 수 없으면 수업 1번 읽기) → 교재마다 진도교재 1번 읽기(`오늘 학습` 아니면 건너뜀) → `오늘 학습` 해제 → 학습기록 만들기 → 수업 `학습기록 상태` ✅ 완료. 계획 형식이 틀리면 만들지 않고 ⚠️ 오류(재시도 없음). 수식이 없는 운영은 예전 방식. 진도교재의 `학습기록 상태`는 이 방식에서 바꾸지 않는다(수업 쪽 상태만 표시).
- **검증(원본)**: 함수 테스트(계획 해석·형식 오류 / 체크된 교재만 해제 후 만들기·속성 값 / 두 번 눌러도 안 만듦·교재 없음), 전체 Deno 테스트, 타입 검사, 회귀 가드.

## 항목 2. 수업(학원) DB 수식 `학습기록 계획`

- **유형**: 운영자 직접(Notion API로는 다른 DB를 거치는 수식을 만들 수 없다)
- 수업(학원) DB에 수식 속성 `학습기록 계획`을 추가하고 아래를 넣는다. 수업 페이지에서는 숨긴다.

```
lets(
  mk, prop("보강"),
  cls, prop("클래스").map(current.format()).join("").replaceAll("[\"\\]", ""),
  dt, formatDate(prop("수업일시"), "MM.DD") + "(" + ["일","월","화","수","목","금","토","일"].at(day(prop("수업일시"))) + ")",
  regs, prop("등록").map(id(current)),
  atts, prop("출석"),
  books, prop("등록").map(current.prop("진도교재")).flat().unique().filter(current.prop("오늘 학습")),
  items, books.map(lets(
    bk, current,
    lib, bk.prop("라이브러리").first(),
    grp, bk.prop("진도방식") == "그룹 진도" and not mk,
    own, bk.prop("등록").map(id(current)).filter(regs.includes(current)),
    myAtts, if(grp, atts, atts.filter(own.includes(current.prop("등록").map(id(current)).join("")))),
    myRegs, if(grp, regs, own),
    "{\"b\":\"" + id(bk) + "\",\"l\":\"" + if(empty(lib), "", id(lib)) +
    "\",\"s\":[" + if(empty(lib), "", lib.prop("과목").map("\"" + id(current) + "\"").join(",")) +
    "],\"a\":[" + myAtts.map("\"" + id(current) + "\"").join(",") +
    "],\"r\":[" + myRegs.map("\"" + current + "\"").join(",") +
    "],\"t\":\"[학습] " + if(empty(lib), "", lib.format().replaceAll("[\"\\]", "")) + if(cls == "", "", "(" + cls + ")") + " " + dt + "\"}"
  )),
  "{\"v\":1," + if(mk, "\"mk\":1,", "") + "\"items\":[" + items.join(",") + "]}"
)
```

- 진도교재 DB의 관계 이름이 `정규교재`(옛 이름)이면 `라이브러리`를 `정규교재`로 바꾼다.
- **확인**: `오늘 학습`이 체크된 교재가 없으면 `{"v":1,"items":[]}`, 체크하면 그 교재마다 `{"b":…,"t":"[학습] 교재(반) 10.17(토)"}`가 나온다. 제목의 날짜·요일이 수업일과 같은지 본다.

## 항목 3. 수업 [학습기록 생성] 버튼

- **유형**: 운영자 직접
- 웹훅 주소·헤더 `x-admin-key`는 그대로. 본문 속성에서 `학습기록 계획`만 고른다(Notion이 막으면 비워도 된다 — 서버가 수업을 한 번 읽는다).
- **확인**: 진도교재 하나에 `오늘 학습`을 체크하고 누르면 학습기록이 하나 생기고 체크가 풀린다. 다시 눌러도 새로 생기지 않는다. 그룹 진도는 출석 전원, 개별 진도는 그 학생만 연결된다.

## 되돌리기
