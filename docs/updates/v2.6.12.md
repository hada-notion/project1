# v2.6.12 — 출석 만드는 길을 [출석 조정] 하나로 (수업추가·수업 생성)

- 날짜: 2026-10-16
- 이전 버전: v2.6.11
- 요약: 시간표 [수업추가]·메뉴 [다음주 수업 일괄 생성]은 수업 페이지만 만들고, 등록 [수업 생성]은 Notion 버튼만으로 대상 수업에 신호를 준다. 출석은 모두 [출석 조정](v2.6.11)이 만든다. 웹훅 재정리 3단계.
- 매뉴얼 영향: 있음 → 수강 등록 5-2 [수업 생성], 시간표 [수업추가] 설명(아래 "매뉴얼")
- 변경 유형: 함수(`generate-classes`, `fix-attendance` 출석 조정 처리), Notion 버튼(운영자 직접). DB 속성·Supabase 테이블·Secrets 변경 없음.
- **선행 조건: v2.6.11 항목 2·3(수업 DB 수식 `출석 조정 정보`, 출석 조정 자동화)이 끝나 있어야 한다.** 수식이 없으면 출석 조정 큐가 예전 방식으로 출석을 만들어 결과는 같지만 호출이 많다.

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/generate-classes/index.ts`, `supabase/functions/_shared/fixAttendanceTarget.ts`, `supabase/functions/_shared/assignmentDeadline.ts`를 반영하면 함수 자동 배포)
- **동작**
  - 수업추가(`generate-classes`): 수업 페이지를 명단(`등록`)과 함께 `생성 상태` ✅ 완료로 만들고, 명단이 있으면 그 수업을 출석 조정 큐(`fix-attendance`)에 넣는다. 학생별 과제 조회·미연결 출석 조회·출석 생성·수업 상태 작업중→완료 쓰기를 하지 않는다. 메뉴 [다음주 수업 일괄 생성]도 같은 함수라 같이 바뀐다.
  - 출석 조정: 새로 만들거나 연결하는 출석에 그 학생의 대기 과제를 `과제마감 백필 대상`으로 넣고 `과제마감 백필 상태` ⏳ 대기열로 둔다(수업추가가 쓰던 방식, `자동 마감 기준`·미제출만). 학생 전원의 대기 과제를 수업당 한 번에 조회한다. 예전 출석 조정은 학생마다 활동·출석을 하나씩 읽어 바로 연결했고 자동 마감 기준을 보지 않았다.
- **Notion 호출(6명 반 수업 하나)**: 약 22회 → 약 10회(준비 조회 4 + 수업 생성 1 + 출석 조정 큐: 수업 읽기 1·대기 과제 1·출석 6·완료 1, 수식 값이 본문에 오면 수업 읽기 없음). 출석 생성은 큐에서 한 건씩.
- **검증(원본)**: 수업추가 테스트(월수금 날짜순 수업 3개 생성, 출석 0·명단·완료, 출석 조정 큐 3건 → 출석 6건·학생별 백필 대상·대기 과제 조회 수업당 1번, 백필 워커 역순 실행 후 마감이 각 학생의 다음 출석, 재실행 시 새로 만들지 않음), 전체 Deno 테스트, 타입 검사, 회귀 가드.
- **미검증**: 실제 [수업추가]·[다음주 수업 일괄 생성]으로 만든 수업의 출석 생성과 과제 마감 연결.

## 항목 2. 등록 [수업 생성] 버튼 → Notion만으로

- **유형**: 운영자 직접(등록(학원) DB `수업 생성` 버튼)
- **작업**: 웹훅 작업을 지우고
  1. 변수 정의 `대상수업`: 이 등록의 시간표 수업 중 **내 출석이 없고** 등록일~종료일(그날까지) 안인 수업

     ```
     context("이 페이지").prop("시간표").map(current.prop("수업")).flat().filter(lets(s, current, not s.prop("출석").some(current.prop("등록").includes(context("이 페이지"))) and if(empty(context("이 페이지").prop("등록일")), true, s.prop("수업일시") >= context("이 페이지").prop("등록일")) and if(empty(context("이 페이지").prop("종료일")), true, s.prop("수업일시") < dateAdd(context("이 페이지").prop("종료일"), 1, "days"))))
     ```
  2. `대상수업` 편집: `등록` → **추가**: 이 페이지, `출석조정 상태` → `⚪ 대기`
- **뜻**: 이 학생이 지금 연결된 시간표의 수업 중 수강 기간 안 수업에는 모두 이 학생의 출석이 1건씩 있어야 한다. 버튼은 빠진 수업만 골라 명단에 넣고 출석 조정을 대기시킨다. 다 맞으면 대상이 0개라 아무 일도 일어나지 않는다.
- **알아둘 점**: 보강 수업은 시간표가 없어 대상이 아니다. 시간표를 바꾸면 예전 시간표 수업은 대상이 아니다(종료 처리나 그 수업의 [출석 조정]으로 정리). 클래스 단위 일괄 [수업 생성]은 두지 않는다(새 수업은 메뉴 → 시간표, 새 학생은 등록 버튼).
- **확인(원본, 2026-10-16)**: 고1 A 10/9~10/23 수업 6개의 출석을 (수업, 등록)별로 세어 모두 1건, 등록일이 10/15인 학생은 10/16 이후 4개만, 빠진 출석이 채워지고 중복 0.
