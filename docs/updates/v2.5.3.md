## 항목 1. [AI 자동] 로그 DB 속성 추가 (코드보다 먼저)

- 운영에서 전송로그 관계의 대상인 자동화 로그(학원) DB를 확인하고 현재 스키마 스냅샷을 기록합니다. 이름이 다른 운영은 이름만으로 추정하지 말고 실제 관계 대상인지 확인합니다.
- select **출결 구분** 추가, 옵션 **등원**(green) / **하원**(blue). 설명: `키오스크 알림톡의 실제 등원/하원 구분. 성공·실패 로그 모두 기록하며 일반 보고서와 과거 구분 없는 로그는 비워둡니다.`
- 동일 타입/옵션이면 재생성하지 않습니다. 동명 다른 타입이면 중단합니다. 기존 select 옵션/기록/발송자/관계를 바꾸지 않습니다.
- 모든 기존 기록의 새 속성은 비워둡니다. 과거 기록의 발송시각과 출석 스템프를 비교해 등원/하원을 추측하거나 일괄 백필하지 않습니다.

## 항목 3. [AI 자동] 출석 DB 전송 내역 수식

- 운영의 출석 DB에서 **전송 내역** formula를 찾아 변경 전 원문을 스냅샷으로 남깁니다. 전송로그 관계 대상의 출결 구분 속성이 있어야 합니다.
- 아래 변경 전 원문과 같거나 정확한 최종 원문으로 이미 반영된 상태인지 확인합니다. 다른 수식이면 일괄 덮어쓰지 않고 해당 항목을 보류합니다. 같은 속성 식별자/타입을 유지하고 수식만 바꿉니다.
- 구분 없는 기존 키오스크 로그는 **등하원**, 일반 보고서 등은 기존 사람 발송자/담당자 미기록, 실패 상태/사유 및 최신 로그 선택 방식·날짜 포맷은 보존합니다. 시간대 변경은 이 패치에 포함하지 않습니다.

변경 전 원문:
```text
lets(
  allLogs, prop("전송로그"),
  maxDate, if(allLogs.empty(), empty(), allLogs.map(current.prop("발송일시")).sort().last()),

      if(latest.prop("발송자").empty(), "담당자 미기록", latest.prop("발송자").map(current.name()).join(", "))
       + formatDate(latest.prop("발송일시"), " (MM.DD HH:mm)") + " "
    )
  )
)
```

## 검증·복구·완료

1. 로그 DB의 새 select/두 옵션과 출석 수식 원문을 다시 읽어 확인합니다. 기존 관계·발송자 person·발송 구분은 그대로여야 합니다.
2. 모의 코드 테스트와 CI 성공은 실제 알림톡 수신/새 Notion 로그 생성 테스트와 구분합니다. 기존 구분 없는 로그의 실제 수식 계산에서 등하원 fallback을 읽을 수 있지만 등원/하원 새 로그의 실제 표시까지 검증한 것은 아닙니다. 자동으로 실제 출결/알림톡을 생성하거나 과거 기록을 수정하지 않습니다.
3. 실제 정상 업무 발송 후 출결 구분과 화면 시각/표시를 운영자가 확인합니다. 수식 도구와 사용자 화면의 시간대 표시는 별도로 확인하며 시각을 임의 보정하지 않습니다.
4. 매뉴얼은 `docs/키오스크-처리-흐름.md`의 등원·하원 전송내역 섹션을 함께 사용합니다. v2.5.2 지침의 후속 v2.5.3 링크를 함께 전달합니다.
5. 배포 실패면 완료로 기록하지 않습니다. 되돌릴 때 코드와 출석 수식만 스냅샷으로 복구합니다. 새 속성과 이미 기록된 등하원 값은 데이터 보존을 위해 자동 삭제하지 않습니다. 과거 데이터/키를 초기화하지 않습니다.
6. 시스템 정보에 적용 주체·배포 커밋·CI·원문 비교와 미검증 범위를 기록합니다. 미적용 이전 버전이 있으면 현재 버전을 일괄 최신으로 올리지 않습니다.
