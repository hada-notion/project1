# v2.7.8 — 시간표 [클래스 정보 입력] 버튼과 점검용 보기 정리

- 날짜: 2026-10-19
- 이전 버전: v2.7.7
- 요약: 시간표에서 클래스를 고른 뒤 `등록`·`담당강사`를 한 번에 채우는 [클래스 정보 입력] 버튼을 문서에 넣고 헤더에 보이게 한다(원본에는 있었지만 지침에 없었고, 패널에서 "비어 있으면 숨김"이라 버튼이 보이지 않았다). 수업 DB의 점검용 보기 `시간표 비어있음`을 지운다.
- 매뉴얼 영향: 있음 → 시간표 [클래스 정보 입력] 한 줄(아래 "매뉴얼")
- 변경 유형: Notion 버튼 1개, 페이지 레이아웃, DB 보기 1개 삭제. 코드·마이그레이션·Secrets 변경 없음. 업무 데이터는 바꾸지 않는다.

---

## 항목 1. 시간표 [클래스 정보 입력] 버튼

- **유형**: 운영자 직접
- **선행 조건**: 없음. 시간표(학원) DB에 같은 이름의 버튼이 이미 있으면 동작만 아래와 같은지 확인한다.
- **변경 이유·증상**: 시간표를 만들 때 `등록`(반 학생)과 `담당강사`를 하나씩 고르느라 오래 걸린다. 클래스를 고르고 버튼 하나로 채운다.
- **Notion 변경**: 시간표(학원) DB 버튼 속성 `클래스 정보 입력`
  - 동작: "이 페이지 편집"
    - `등록` → 새로운 값:

      ```
      context("이 페이지").prop("클래스").map(current.prop("등록")).flat()
      ```

    - `담당강사` → 새로운 값:

      ```
      context("이 페이지").prop("클래스").map(current.prop("담당강사")).flat()
      ```

  - 웹훅 없음. 수업 [클래스 정보 입력](v2.7.3 N-19)과 이름은 같지만 수식이 다르다(시간표는 날짜 조건 없이 클래스의 등록 전체).
- **레이아웃**: 시간표 헤더 `… 하원시간 | [클래스 정보 입력][수업 추가] | 실시간 처리 상태`. 패널에 남아 있으면 헤더로 고정한다(버튼은 "비어 있으면 숨김"이면 보이지 않는다).
- **운영자 안내문**
  - 왜 필요한가: 시간표의 반 학생·담당강사를 한 번에 채운다.
  - 어디서: 시간표(학원) DB → 아무 시간표 → 속성 추가 → 버튼, 이름 `클래스 정보 입력`
  - 무엇을: 위 두 속성을 "새로운 값"으로 설정하고 저장. 그다음 레이아웃 편집에서 헤더에 고정
  - 끝났는지 확인하는 방법: 클래스만 고른 테스트 시간표에서 버튼을 누르면 `등록`에 그 반 학생, `담당강사`에 반 담당강사가 들어간다.
  - 흔한 오류와 대처: `등록`에 종료된 학생까지 들어가면 손으로 뺀다(클래스의 등록 전체를 가져온다). 다른 시간표에서 누르면 그 시간표의 기존 `등록`이 덮어써지므로 누르기 전에 클래스를 확인한다.
- **검증**: 위 확인 방법. 커넥터로 시간표 데이터 소스를 읽어 `pinnedProperties`에 `클래스 정보 입력`이 `수업 추가` 앞에 있는지 본다.
- **실패 시 대처**: 버튼 속성을 지우면 이전과 같다. 이미 바뀐 `등록`·`담당강사`는 손으로 되돌린다.
- **매뉴얼**: 아래 "매뉴얼"

## 항목 2. 수업 보기 `시간표 비어있음` 삭제

- **유형**: 운영자 직접(보기 삭제는 커넥터로 할 수 없다)
- **선행 조건**: 없음
- **변경 이유·증상**: 원본 점검 때 만든 갤러리 보기다. 이름과 달리 필터가 "학습기록 있음"이고, 코드·문서·자동화가 쓰지 않는다.
- **Notion 변경**: 수업(학원) DB 보기 탭 `시간표 비어있음` → 우클릭 → 보기 삭제. 운영 DB에 이 보기가 없으면 건너뛴다.
- **검증**: 수업 DB 보기가 `수업`·`캘린더`·`웹훅 등록`(운영에서 따로 만든 보기는 그대로)
- **실패 시 대처**: 데이터 영향 없음. 필요하면 같은 보기를 다시 만든다.
- **매뉴얼**: 변경 없음
