# v2.5.111 — 수업 관리 기록 본문을 펼칠 때 읽기

- 날짜: 2026-10-14
- 이전 버전: v2.5.110
- 요약: 운영 측정에서 학습기록 탭(`class-records`)이 서버 3.5초·Notion 16회였고, 그중 상당수가 기록마다 본문을 미리 읽는 호출이었다. 본문은 카드를 펼칠 때만 보이므로 펼칠 때 그 기록 본문만 읽도록 바꿨다. 본문이 있는지 미리 알 수 없어 펼치기 버튼을 늘 둔다(사용자 결정). 설계안 `docs/설계-수업관리-복사본.md` 0단계.
- 매뉴얼 영향: 없음(수업 관리 기록 카드의 펼치기가 늘 보임)
- 변경 유형: 함수 `class-room`(자동 배포) + 웹 화면(Pages). Notion·DB 변경 없음.

---

## 항목 1. 함수 `class-room`

- **유형**: AI 자동(`main` 병합 시 GitHub Actions가 배포)
- **대상 파일**: `supabase/functions/_shared/classRoom.ts`(`loadClassRecords`·`loadSession`이 본문을 읽지 않음, 새 `loadRecordBody`·`record-body` 동작), `supabase/functions/_shared/classRoom_test.ts`
- **동작**: `class-records`·`session` 응답의 기록 `body`는 빈 목록. `record-body`(기록 id 하나)는 그 기록의 Notion 본문 블록(feedBody.ts와 같은 형식)을 돌려준다. 기록 id 형식이 아니면 400.
- **검증(모의 데이터)**: Deno 단위 테스트(목록에 본문 없음, `record-body`로 본문, 잘못된 id 400), 전체 함수 `deno check`·테스트 197개, 회귀 가드.
- **미검증**: 운영 재측정(`?timing=1`로 `class-records`·`session` 호출 수 감소, `record-body` 시간).
- **실패 시 대처**: v2.5.110의 `classRoom.ts`로 되돌린다.

## 항목 2. 수업 관리 기록 카드

- **유형**: AI 자동
- **대상 파일**: `class_room.js`(`recCard`, `fillBody`, 펼치기 처리, 새로고침), `docs/DESIGN.md`(1부 9장 예외, 수업 관리 기록 카드)
- **동작**: 기록 카드에 펼치기(⌄)를 늘 둔다. 처음 펼치면 "본문을 불러오는 중…" 뒤 본문, 없으면 "본문이 없어요", 실패하면 "본문을 불러오지 못했어요. 다시 펼쳐 주세요."(다시 펼치면 다시 시도). 받은 본문은 ⟳ 새로고침 전까지 다시 읽지 않는다. 학부모 리포트(본문을 미리 만든 캐시에서 읽음)는 지금처럼 본문이 있을 때만 펼치기.
- **검증(모의 데이터)**: 수업 관리 흐름 검사 390·768·1280(본문 있는 카드는 펼치면 본문, 없는 카드도 펼치기가 있고 "본문이 없어요", 같은 카드를 다시 펼쳐도 다시 읽지 않음), 디자인 규칙 검사.
- **미검증**: 운영 데이터·실기기.
- **실패 시 대처**: v2.5.110의 `class_room.js`로 되돌린다.
