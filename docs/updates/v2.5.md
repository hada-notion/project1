## 증상·원인

기존 '등록' 버튼은 시간표 연결과 수강 재시작 보완을 수행한다. '시간표 설정'은 실제 작업을 더 명확히 나타낸다. '수업 생성'은 새 수업 일정 생성이 아니라 기존 수업·출석 연결임을 설명에 명시한다.

## 항목 1. 기존 버튼 이름·설명 수정

- 유형: **AI 자동**
- 선행 조건: 승인 완료. 시스템 정보 이력에 대상 4개 버튼의 현재 이름·설명·속성 식별자 및 확인 가능한 액션/자동화 정보를 스냅샷으로 남긴다. 확인 불가능한 액션은 미검증으로 명시한다.
- 대상: 학생과 클래스·시간표를 연결하는 등록(학원) DB. 다른 DB의 동명 버튼은 제외.
- 기존 '등록' / '시간표 입력' / 이미 변경된 '시간표 설정' 중 기존 sync-registration-enroll 기능을 담당하는 버튼 1개를 찾는다. 후보가 여러 개면 추정하지 않고 보류한다. 이름만 시간표 설정으로 변경한다. 속성 식별자·타입·액션·웹훅·인증·트리거는 유지한다. '등록 상태' 및 '시간표 상태' 등 상태 속성은 변경하지 않는다.
- 설명은 아래 최종 원문으로 수정한다. 기존 설명과 동일하면 건너뛴다. 기존 설명이 아래 변경 전 원문과 다르면 동일 기능임을 확인하고 환경별 연결 안내를 보존한다. 기능이 다르면 보류한다.
- 교재 생성 설명의 기존 Edge Function 안내는 유지한다. 환경별 연동 정보가 별도로 있으면 유지하며 비밀값을 패치에 옮기지 않는다.
- 뷰의 표시 속성 등 이름 참조가 있으면 기존 순서·노출을 그대로 유지하고 바뀐 버튼 이름만 맞춘다.

3. `school_search.html`의 안내 문자열 `학사일정 동기화는 별도로 켭니다.`를 `학사일정은 Notion의 ‘학사일정 가져오기’ 버튼으로 가져옵니다.`로 바꾼다. 운영의 ENDPOINT·호스팅 주소·인증 코드는 그대로 보존한다.
4. 운영의 기존 승인된 배포 절차로 school-api와 검색 화면을 배포한다. 타입 검사·회귀 검사 및 실제 배포 결과를 확인한다. 이 원본의 GitHub Actions 경로는 전체 함수 배포와 기존 마이그레이션 확인도 수행하므로 해당 범위를 인지하고 실행한다. 새 마이그레이션·Secret 변경은 없다. CI 성공/함수 목록 확인과 배포된 코드 직접 비교는 별개다.
5. 배포 완료를 확인한 뒤 학교 DB의 **학사일정 동기화** checkbox만 삭제한다. 이미 없으면 건너뛴다. 동명 다른 타입이면 중단한다. 뷰에 표시돼 있었다면 해당 표시 참조만 제거한다. **학사일정 가져오기**, 처리 상태·현황·오류·마지막 동기화 및 모든 관계를 유지한다. 버튼을 실행하거나 학교를 새로 연결하는 실제 데이터 테스트는 별도 승인 없이 하지 않는다.
6. `docs/학교-학사일정-연결.md`의 `자동 동기화 체크박스는 사용하지 않습니다.`를 `` `학사일정 동기화` 체크박스는 v2.5.1에서 삭제되었습니다. 체크 없이 버튼으로 실행합니다. ``로 수정한다. 운영에 이 문서를 쓰지 않는 경우 해당 없음으로 기록한다. 신규 배포 템플릿에는 checkbox를 만들지 않으며, v2.3의 오래된 생성 안내보다 이 폐기 지침을 우선한다.

### 검증·실패 시 대처

- DB 재조회: 대상 checkbox가 없고, 수동 버튼·처리 상태 속성·수식·관계가 유지되는지 확인한다.
- 실행 소스에서 checkbox 이름·속성 ID의 읽기/쓰기가 남아 있지 않은지 확인한다. 문서의 역사 설명은 삭제 대상이 아니다.
- 실제 배포 실패/미확인 상태면 DB 삭제를 보류한다. CI 성공만으로 버튼 실행 또는 학교 연결 기능 테스트를 완료했다고 표시하지 않는다.
- 속성 삭제 후 코드 롤백이 필요하면 먼저 스냅샷 기준 checkbox를 복원하고 값을 복구한 뒤 기존 쓰기 코드를 되돌린다. 재생성 시 속성 ID가 달라지므로 뷰·참조 복원 여부도 확인한다.
- 완료 후 시스템 정보에 변경·배포 커밋·검증/미검증 범위를 남긴다. 미적용 이전 패치가 있으면 현재 버전은 유지한다.
