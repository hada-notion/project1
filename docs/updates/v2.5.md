- 변경 범위: 기존 '등록' 또는 '시간표 입력' 버튼을 '시간표 설정'으로 변경하고 4개 버튼의 기존 설명을 수정. 새 버튼 생성·버튼 실행·데이터 삭제 없음.
- 기준 저장소: hada-notion/project1, main. 작성 시 읽은 기준 커밋: 0ce1e18e05fbe47159d5a71e629fe8ef054a106a.
- 기준 원문: 이 문서에 첨부된 최종 이름·설명·매뉴얼 치환 쌍. 환경별 Notion ID·주소·Secrets를 복사하지 않음.
- 적용 전제: 운영 소유자의 승인 및 해당 운영 DB의 이름·역할·현재 원문 확인. 동일 동작의 기존 버튼을 확인할 수 없으면 보류.

## 증상·원인

기존 '등록' 버튼은 시간표 연결과 수강 재시작 보완을 수행한다. '시간표 설정'은 실제 작업을 더 명확히 나타낸다. '수업 생성'은 새 수업 일정 생성이 아니라 기존 수업·출석 연결임을 설명에 명시한다.

## 항목 1. 기존 버튼 이름·설명 수정

- 유형: **AI 자동**
- 선행 조건: 승인 완료. 시스템 정보 이력에 대상 4개 버튼의 현재 이름·설명·속성 식별자 및 확인 가능한 액션/자동화 정보를 스냅샷으로 남긴다. 확인 불가능한 액션은 미검증으로 명시한다.
- 대상: 학생과 클래스·시간표를 연결하는 등록(학원) DB. 다른 DB의 동명 버튼은 제외.
- 기존 '등록' / '시간표 입력' / 이미 변경된 '시간표 설정' 중 기존 sync-registration-enroll 기능을 담당하는 버튼 1개를 찾는다. 후보가 여러 개면 추정하지 않고 보류한다. 이름만 시간표 설정으로 변경한다. 속성 식별자·타입·액션·웹훅·인증·트리거는 유지한다. '등록 상태' 및 '시간표 상태' 등 상태 속성은 변경하지 않는다.
- 설명은 아래 최종 원문으로 수정한다. 기존 설명과 동일하면 건너뛴다. 기존 설명이 아래 변경 전 원문과 다르면 동일 기능임을 확인하고 환경별 연결 안내를 보존한다. 기능이 다르면 보류한다.
- 교재 생성 설명의 기존 Edge Function 안내는 유지한다. 환경별 연동 정보가 별도로 있으면 유지하며 비밀값을 패치에 옮기지 않는다.
- 뷰의 표시 속성 등 이름 참조가 있으면 기존 순서·노출을 그대로 유지하고 바뀐 버튼 이름만 맞춘다.

### 시간표 입력 → 시간표 설정

변경 전 설명:
```text
종료된 등록을 다시 등록 상태로 되돌린다. 등록일이 비어있으면 오늘 날짜로 채우고, 종료일을 제거하며, 시간표가 비어있으면 클래스 기준 시간표를 연결한다 (이후 수동 조정 가능).
```

최종 설명:
```text
시간표가 비어 있으면 클래스의 기본 그룹 수업 시간표를 학생에게 연결합니다. 개별 수업 시간표는 직접 연결하고, 연결 후 학생별로 요일·시간을 조정할 수 있습니다. 등록일이 비어 있으면 오늘로 채우고, 기존 종료일은 지워 수강을 다시 시작할 수 있도록 합니다.
```

### 교재 생성 → 교재 생성

변경 전 설명:
```text
이 등록의 진도교재를 생성/동기화합니다. sync-registration-textbook Edge Function 웹훅 연결 필요 (처리 중에는 '교재 상태'가 🔄 작업중으로 바뀌며 실시간 처리 상태에 표시됨).
```

최종 설명:
```text
이 학생의 등록 정보를 기준으로 진도교재를 생성하거나 동기화합니다. 그룹 진도 교재는 클래스의 반별교재에 연결하고, 개별 진도 교재는 학생용으로 생성합니다. sync-registration-textbook Edge Function 웹훅 연결 필요 (처리 중에는 '교재 상태'가 🔄 작업중으로 바뀌며 실시간 처리 상태에 표시됨).
```

### 수업 생성 → 수업 생성

변경 전 설명:
```text
연결된 시간표의 기존 수업 각각에 대해 이 등록의 출석을 생성/연결한다. 종료일 변경 등으로 다시 눌러도 안전 (재실행 가능).
```

최종 설명:
```text
등록 기간과 연결된 시간표에 해당하는 기존 수업에 학생을 연결하고, 누락된 출석 기록을 생성합니다. 새로운 수업 일정을 만드는 버튼은 아닙니다. 이미 연결된 수업과 출석은 중복 생성하지 않으므로 종료일 변경 후 다시 실행할 수 있습니다.
```

### 종료 처리 → 종료 처리

변경 전 설명:
```text
종료일 기준으로 교재 정리(규칙에 따라 유지/연결해제/삭제), 시간표 연결 해제, 종료일 이후 수업 연결 해제 및 출석 삭제를 즉시 실행한다.
```

최종 설명:
```text
종료일을 기준으로 교재를 규칙에 따라 유지·연결 해제·삭제하고, 시간표 연결을 해제합니다. 종료일 이후의 수업 연결을 해제하고 해당 출석 기록을 삭제합니다. 종료일을 확인한 뒤 실행하세요.
```

## 검증·완료 조건

1. DB를 다시 읽어 버튼 4개의 타입이 button이고, 이름 1개·설명 4개가 최종 원문과 일치하는지 확인한다. 변경 전후 속성 식별자는 같아야 한다.
2. 해당 뷰의 버튼 노출 및 순서가 유지됐는지 확인한다.
3. 매뉴얼 5-2 및 매핑 표의 지정 원문을 비교한다. 호출 함수는 기존과 같아야 한다.
4. 버튼은 누르지 않는다. 실제 학생 데이터 생성·종료·삭제 및 자동화 기능 테스트는 이 문구 패치 범위 밖이다. 액션/자동화 보존을 직접 확인하지 못했으면 미검증으로 보고한다.
5. Edge Function, Supabase 마이그레이션, GitHub Pages 실행 파일 재배포는 필요 없다. 실행 파일 수정 없음. 문서 배포 커밋과 읽기 확인 결과를 별도로 기록한다. CI 여부는 별도 확인 수준으로 보고한다.

## 실패 시 중단·복구

예상과 다른 버튼·원문·오류가 있으면 해당 항목을 중단한다. 수정한 이름·설명·문구만 사전 스냅샷으로 복원하고, 버튼을 삭제·재생성하거나 자동화를 재연결하지 않는다. 환경별 URL·Secrets는 건드리지 않는다.
