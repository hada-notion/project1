# v2.3.3 — school-api 배포 및 school_search.html 환경별 주소 분리

- 날짜: 2026-10-04
- 이전 버전: v2.3.2
- 요약: "학교 검색" 기능이 백엔드 함수 미배포와 환경별 주소 하드코딩 때문에 운영 워크스페이스에서 동작하지 않습니다. (1) `school-api` Edge Function을 운영 Supabase에 배포하고, (2) `school_search.html`을 운영 워크스페이스마다 자체 호스팅해 그 안의 Supabase 주소를 운영 값으로 바꾸고, (3) v2.3.1에서 만든 Notion "학교 검색" formula가 원본 전용 주소를 가리키던 것을 운영 자체 호스팅 주소로 고칩니다.
- 매뉴얼 영향: 없음
- 유형: 전 항목 **AI 자동**

> 작성 규칙은 `docs/updates/_TEMPLATE.md` 참고. 이 문서 자체가 "환경별 값 치환"의 실제 사례입니다 — 운영 AI는 항목 2의 자체 호스팅 주소를 반드시 자신의 것으로 바꿔야 합니다.

## 항목 1. school-api Edge Function 배포

- **유형**: AI 자동
- **선행 조건**: 없음
- **변경 이유·증상**: `school_search.html`이 호출하는 `school-api` 함수가 운영 Supabase 프로젝트에 배포되어 있지 않으면 학교 검색·연결이 전부 실패합니다.
- **대상 코드**: 원본 저장소(main 브랜치)의 `supabase/functions/school-api/index.ts`를 그대로 가져와 운영 Supabase 프로젝트에 배포합니다. 이 함수가 쓰는 `_shared/adminShared.ts`, `_shared/notionClient.ts`, `_shared/neisSchool.ts`, `_shared/schoolNotion.ts`도 운영 버전과 원본을 비교해 차이가 있으면 맞춥니다(이미 v2.3에서 대부분 배포했을 수 있음 — 배포돼 있으면 건너뛴다).
- **변경 내용**: 신규 생성/배포이므로 "찾을 원문" 비교 없음.
- **환경별 값**: 하드코딩된 주소 없음. 기존 `NOTION_TOKEN`, `ADMIN_SECRET`, `NEIS_API_KEY`(v2.3에서 이미 등록) 환경변수를 재사용합니다.
- **필요한 Secret (이름만)**: 없음 (신규 Secret 불필요. `NEIS_API_KEY`가 아직 없다면 v2.3을 먼저 적용한다)
- **Notion 변경**: 없음
- **마이그레이션 / 재배포**: 재배포 함수: `school-api` (신규)
- **검증**:
  1. Supabase 함수 목록에 `school-api`가 배포되어 있는지 확인한다.
- **실패 시 대처**: 함수 미배포 상태로는 학교 검색이 안 될 뿐 다른 기능에는 영향이 없습니다. 재배포만 다시 시도하면 됩니다.
- **매뉴얼**: 변경 없음

## 항목 2. [환경별 값 포함] school_search.html 자체 호스팅 및 ENDPOINT 치환

- **유형**: AI 자동
- **선행 조건**: 항목 1 완료 후
- **변경 이유·증상**: 원본 저장소의 `school_search.html`은 `https://hada-notion.github.io/project1/school_search.html`이라는 **원본 전용 GitHub Pages 주소 하나**를 모든 운영 워크스페이스가 공유하도록 되어 있고, 파일 내부의 `ENDPOINT` 상수도 원본의 Supabase 프로젝트 주소로 고정되어 있습니다. 운영 워크스페이스가 이 주소를 그대로 쓰면 자신의 Notion 데이터가 아니라 원본의 백엔드를 호출하게 되어 인증 실패로 항상 막힙니다.
- **대상 코드**
  - 파일 경로: `school_search.html` (원본 저장소 루트)
  - 찾을 원문 (앵커):

    ```
    const ENDPOINT='https://twczhsxybkcvjkdfdxvs.supabase.co/functions/v1/school-api';
    ```

  - 변경 내용 (찾을 원문 → 바꿀 원문): 위 줄의 Supabase 프로젝트 주소 부분만 운영 Supabase 프로젝트의 `school-api` 함수 주소로 바꾼다. 나머지 HTML/JS는 원본 그대로 사용한다.
- **배포 방법**: 이 파일은 운영 워크스페이스 소유의 정적 호스팅(예: 운영 학원 자신의 GitHub Pages 저장소, 또는 기존에 쓰고 있는 다른 정적 호스팅)에 올린다. 원본 저장소의 GitHub Pages에는 올리지 않는다(원본 저장소에 대한 쓰기 권한이 운영 AI에는 없고, 있어도 모든 운영 워크스페이스가 같은 주소를 공유하게 되어 이번 문제가 반복된다).
- **환경별 값**: `ENDPOINT` 상수는 운영 Supabase 프로젝트의 `school-api` 함수 URL로 치환해야 한다(원본 값 그대로 쓰지 않는다). 호스팅 후 생기는 최종 URL(예: `https://<운영자 GitHub 계정>.github.io/<저장소>/school_search.html`)을 항목 3에서 사용한다.
- **필요한 Secret (이름만)**: 없음
- **Notion 변경**: 없음 (항목 3에서 처리)
- **마이그레이션 / 재배포**: 없음
- **검증**:
  1. 자체 호스팅한 URL로 직접 접속해 페이지가 열리는지 확인한다.
  2. 관리자 키를 입력했을 때 학교 목록이 정상적으로 뜨는지 확인한다(= `ENDPOINT`가 운영 프로젝트를 가리키고 있다는 뜻).
- **실패 시 대처**: 자체 호스팅 전까지는 기존처럼 검색이 안 될 뿐 다른 기능에는 영향이 없습니다.
- **매뉴얼**: 변경 없음

## 항목 3. [환경별 값 포함] Notion "학교 검색" formula 주소 보정 (v2.3.1 오류 수정)

- **유형**: AI 자동
- **선행 조건**: 항목 2 완료 후
- **변경 이유·증상**: v2.3.1에서 만든 "학교 검색" formula가 원본 전용 주소 `https://hada-notion.github.io/project1/school_search.html`을 그대로 썼습니다. 이 항목이 그 값을 운영 자체 호스팅 주소로 바꿉니다.
- **대상 코드**: 없음 (Notion 수식 변경)
- **Notion 변경**: "학교(학원) DB"의 formula 속성 **학교 검색**을 아래처럼 바꾼다. 이미 운영 자체 주소로 되어 있으면(= 이 패치를 이미 적용했으면) 건너뛴다.

  ```
  찾을 원문 (v2.3.1 기본값):
  link("학교 검색·연결", "https://hada-notion.github.io/project1/school_search.html?pageId=" + id())

  바꿀 원문:

  ```

- **환경별 값**: 위 수식의 호스팅 주소 부분은 운영 워크스페이스마다 다르다(항목 2 결과값을 그대로 넣는다).
- **필요한 Secret (이름만)**: 없음
- **마이그레이션 / 재배포**: 없음
- **검증**:
  1. 학교 DB 페이지에서 "학교 검색" 링크를 열어 운영 자체 호스팅 주소로 이동하는지 확인한다(주소창에 `hada-notion.github.io`가 아니라 운영 자체 주소가 떠야 한다).
  2. 해당 페이지에서 검색·연결이 정상 동작하는지 확인한다.
- **실패 시 대처**: formula만 되돌리면 이전 상태(원본 주소)로 복구되며, 다른 기능에는 영향이 없다.
