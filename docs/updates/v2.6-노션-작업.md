# v2.6 Notion 작업 목록 (운영 워크스페이스)

- 대상: v2.5.11을 쓰는 운영 워크스페이스를 v2.6으로 올릴 때 Notion에서 직접 하는 일 전부.
- 이 문서 하나로 Notion 작업을 끝낸다. 버전 지침(`v2.6.1`·`v2.6.3`·`v2.6.4`·`v2.6.5`)은 이 문서의 항목 번호(N-1 …)를 가리킨다.
- DB는 이름·역할로 적는다. 운영 DB 이름이 다르면 같은 역할의 DB에 적용한다. 원본 ID·주소·키는 쓰지 않는다.
- 시점 표시
  - **[배포 전]** v2.6.1. v2.5.11 코드는 이 속성들을 읽지 않으므로 언제 해도 안전하다. v2.6.2(코드 배포) 전에 끝낸다.
  - **[배포 후]** v2.6.3(N-9~N-13), v2.6.4(N-14 매뉴얼). v2.6.2 배포가 끝난 뒤에 한다. 먼저 하면 v2.5.11 코드가 학습기록 단원을 못 읽는다.
  - **[선택]** v2.6.5. 필요할 때만.
- 공통: 시작 전에 바꿀 DB의 속성 목록(이름·타입)과 바꿀 수식 원문을 운영 시스템 정보에 스냅샷으로 남긴다. 수식은 교체 전 원문을 복사해 둔다.

## N-1. 최상위 페이지 제목 = 학원 이름 [배포 전]

- **왜**: 출결 키오스크 카드 아래에 학원 이름을 보여 준다. 이름은 학원관리 Notion 최상위 페이지 제목에서 자동으로 읽는다(원본 이름 "하다 학원관리 v2.0").
- **무엇을**
  1. 학원관리 최상위 페이지 제목을 학원 이름으로 바꾼다(예: `○○수학학원`).
  2. 그 페이지 오른쪽 위 ··· → 연결에 학원관리 Notion 연결(integration)이 있는지 본다.
- **확인**: v2.6.2 뒤 키오스크에서 로그아웃 후 다시 로그인하면 카드 아래에 학원 이름이 보인다(서버가 최대 1시간 재사용).
- **못 하면**: 키오스크 아래 이름 칸이 비어 보일 뿐 출결은 동작한다.

## N-2. 수업(학원) DB — 체크박스 `보강` [배포 전]

- **속성**: 이름 `보강`, 타입 체크박스, 기본값 해제.
- **설명(속성 설명 칸에 그대로)**: `보강 수업이면 체크. 시간표·클래스 없이 만든 임시 수업(1:1·그룹). 출석 조정은 이 수업을 건너뛰고, 이 수업에서 만든 학습기록은 "보강"이 체크되어 진도교재 진행도에서 빠짐.`
- **페이지 배치**: 속성 목록 맨 아래, "비어 있으면 숨기기".
- **이미 있으면**: 건너뛴다(타입이 체크박스인지만 확인).
- **코드 영향**: 없으면 모든 수업을 "보강 아님"으로 본다. 수업 관리의 [보강 수업 만들기]는 이 속성에 체크한다.

## N-3. 수업(학원) DB — 수식 `생성 오류` 교체 [배포 전]

> 최신 수식은 [v2.7 Notion 작업](v2.7-노션-작업.md) N-4(날짜범위 계산 바로잡음). 새로 붙여 넣을 때는 그 수식을 쓴다.

- **선행**: N-2(`보강`이 있어야 수식이 저장된다).
- **왜**: 보강 수업은 시간표·등록과 맞지 않아 "누락·초과"로 보이던 것을 `🔵 보강 수업(출석 수)`로 표시한다. 초과 목록에서 같은 등록이 두 번 세지던 것도 한 번만 센다. 정규 수업 결과는 그대로다.
- **방법**: 수업(학원) DB → `생성 오류` 속성 → 수식 편집 → 기존 수식을 복사해 두고, 내용을 모두 지운 뒤 아래 수식을 그대로 붙여 넣는다(Notion API가 이 수식을 받지 않아 화면에서 붙여 넣는다).
- **운영 수식이 원본과 다르게 고쳐져 있으면**: 붙여 넣기 전에 차이를 운영 AI에게 알리고, 운영 고유 부분이 있으면 그 부분을 살린 수식을 따로 만든다.

```
lets(
  sessionDateTime, prop("수업일시"),
  registeredRegistrations, prop("등록"),

  registeredOutOfRangeNow,
    registeredRegistrations.filter(
      lets(
        reg, current,
        not (
          (empty(reg.prop("등록일")) or reg.prop("등록일") <= sessionDateTime) and
          (empty(reg.prop("종료일")) or sessionDateTime < dateAdd(reg.prop("종료일"), 1, "days"))
        )
      )
    ),

  attendanceRegistrations, prop("출석").map(current.prop("등록")).flat(),

  missingRegistrations,
    registeredRegistrations.filter(lets(reg, current, not attendanceRegistrations.includes(reg))),

  duplicateRegistrations,
    registeredRegistrations.filter(
      lets(reg, current, prop("출석").filter(current.prop("등록").includes(reg)).length() > 1)
    ),

  extraRegistrations,
    attendanceRegistrations.filter(not registeredRegistrations.includes(current)).unique(),

  missingNames, missingRegistrations.map(current.prop("학생정보").first().format()).join(", "),
  duplicateNames, duplicateRegistrations.map(current.prop("학생정보").first().format()).join(", "),
  extraNames, extraRegistrations.map(current.prop("학생정보").first().format()).join(", "),
  outOfRangeNames, registeredOutOfRangeNow.map(current.prop("학생정보").first().format()).join(", "),

  duplicateNote,
    if(duplicateRegistrations.empty(), "",
      "\n🔁 중복(" + duplicateRegistrations.length() + "): " + duplicateNames),

  baseResult,
    ifs(
      missingRegistrations.empty() and extraRegistrations.empty(),
        "✅ 정상(" + prop("출석").length() + ")",
      not missingRegistrations.empty() and extraRegistrations.empty(),
        "⚠️ 누락(" + missingRegistrations.length() + "): " + missingNames,
      missingRegistrations.empty() and not extraRegistrations.empty(),
        "⚠️ 초과(" + extraRegistrations.length() + "): " + extraNames,
      "⚠️ 누락(" + missingRegistrations.length() + "): " + missingNames +
      "\n⚠️ 초과(" + extraRegistrations.length() + "): " + extraNames
    ),

  regularResult,
    if(registeredOutOfRangeNow.empty(), baseResult + duplicateNote,
      baseResult + duplicateNote + "\n📅 날짜범위 밖(" + registeredOutOfRangeNow.length() + "): " + outOfRangeNames),

  if(prop("보강"),
    "🔵 보강 수업(" + prop("출석").length() + ")" + duplicateNote,
    regularResult)
)
```

- **확인**: 정규 수업이 전과 같은 결과(예: `✅ 정상(6)`)인지, `보강`을 체크한 수업이 `🔵 보강 수업(…)`인지 본다.
- **되돌리기**: 복사해 둔 이전 수식을 다시 붙여 넣는다.

## N-4. 출석(학원) DB — 텍스트 `메모` [배포 전]

- **속성**: 이름 `메모`, 타입 텍스트.
- **설명**: `내부용 메모(출결 사정·특이사항 등). 학부모 리포트에 보이지 않음. 학부모에게 전할 말은 "선생님 한마디"에 적음.`
- **페이지 배치**: 본문 탭에서 `선생님 한마디` 바로 아래.

## N-5. 학습기록(학원) DB — 텍스트 `주제` [배포 전]

- **속성**: 이름 `주제`, 타입 텍스트.
- **설명**: `이 기록의 주제(예: 실험 정리, 단원 정리 특강). 교재가 없는 기록은 학부모 리포트에 교재명 대신 주제가 보임(교재명 → 주제 → 구분 순).`
- **페이지 배치**: 본문 탭 맨 위(`범위` 위).
- **코드 영향**: 수업 관리에서 교재 없이 주제로 기록을 만들 때 이 속성에 쓴다. 없으면 그 기록 만들기가 실패한다.

## N-6. 등록(학원) DB — `안내 링크` → `학생 페이지` [배포 전]

- **무엇을**: 학부모 리포트 링크 수식 속성 이름만 `학생 페이지`로 바꾼다. 수식 내용(운영 GitHub Pages 주소)은 그대로 둔다.
- **이미 `학생 페이지`면**: 건너뛴다.
- **확인**: 등록 페이지의 `학생 페이지` 링크를 누르면 리포트가 열린다.
- **코드 영향**: 없음(함수는 이 속성을 읽지 않는다). 매뉴얼·안내 문구를 맞추기 위한 이름이다.

## N-7. 출석(학원) DB — 롤업 `학생 페이지` [배포 전, 선택]

- **속성**: 롤업 `학생 페이지` → 관계 `등록`, 속성 `학생 페이지`, 계산 "원본 표시". 사이드바 "기타"에 숨김.
- **쓰임**: 수업 페이지 출석 표에서 학생 리포트를 바로 연다.

## N-8. 지운 웹훅 함수를 부르는 자동화 정리 [배포 전]

- **왜**: v2.6 코드에서 `sync-registration-timetable`, `mark-report-source-dirty`, `sync-student-report`(그리고 정기 학사일정 수집 `sync-school-schedules`)를 지웠다. 배포만으로 서버의 옛 함수가 지워지지는 않아 바로 깨지지는 않지만, 나중에 서버에서 지우면(v2.6.5 항목 4) 그 자동화가 실패한다.
- **어디서**: 각 DB 오른쪽 위 번개 모양(자동화) 목록. 특히 등록(학원) DB.
- **무엇을**
  1. 웹훅 주소가 `/sync-registration-timetable`로 끝나는 자동화(보통 등록 DB "클래스 연결")는 끈다(또는 삭제). 시간표 연결은 [시간표 설정], 종료 정리는 [종료 처리], 수업·출석 생성은 [수업 생성] 버튼이 한다.
  2. 웹훅 주소가 `/mark-report-source-dirty`로 끝나는 자동화는 같은 트리거로 **Notion 자체 동작** "속성 편집 → `학습정보 수정일` = 트리거 시각(현재 시각)"으로 바꾼다. 트리거 속성 목록에서 `학습정보 수정일` 자체와 상태·처리 시각·오류·메모·버튼 속성은 뺀다(무한 반복 방지). 등록 DB의 트리거 속성 기준: 학생정보, 클래스, 시간표, 진도교재, 등록일, 종료일, 토큰, 링크 비활성화.
  3. `/sync-student-report`, `/sync-school-schedules`를 부르는 버튼·자동화가 있으면 끈다.
- **확인**: 각 DB 자동화 목록에 위 주소가 없다.
- **못 찾으면**: 그대로 진행한다. 옛 함수를 서버에서 지우는 v2.6.5 항목 4를 하지 않으면 영향이 없다.

## N-9. 학습기록(학원) DB — 단원을 관계 하나로 [배포 후]

- **순서(한 번에 하나씩 — 두 이름을 한꺼번에 바꾸면 Notion이 "단원 1"처럼 이름을 바꿀 수 있다)**

  2. 관계 속성 `단원`을 새로 만든다: 대상 `단원목록(학원) DB`, "단원목록(학원) DB에 표시" 켬, 그쪽 이름 `학습기록`(양방향).
  3. `단원` 설명: `이 학습기록의 단원(단원목록 연결). [단원 입력]으로 범위에 맞게 채우거나 수업 관리에서 직접 고릅니다.`

- **확인**: 학습기록 페이지 본문 탭에 `주제` → `범위` → `단원` → `내용` 순서로 보인다. 단원목록 페이지에 `학습기록` 관계가 생겼다.

## N-10. 학습기록(학원) DB — 버튼 `단원 입력` [배포 후]

- **선행**: N-9.
- **무엇을**: 버튼 속성 `단원 입력` 추가 → 동작 "웹훅 보내기"
  - URL: `https://<학원 Supabase 주소>/functions/v1/fill-record-units`
  - 헤더: `x-admin-key` = 다른 버튼과 같은 Notion 웹훅 키(값은 문서·채팅에 쓰지 않는다)
  - 페이지 배치: 사이드바 "비어 있으면 숨기기"(원본 기준). 자주 누르면 본문 탭 `단원` 옆에 두어도 된다.
- **동작**: 누르면 그때의 `범위`로 교재(라이브러리) 단원을 찾아 `단원` 관계를 새로 채운다(덮어쓰기, 토글 아님). 범위는 쉼표로 여러 구간(`12-24, 31-35`, `p.12-24` 가능). 각 구간 안에서는 가장 작은 수 ~ 가장 큰 수, 단원 i는 시작쪽 ~ 다음 단원 시작쪽 − 1.
- **확인**: 범위가 있는 기록 하나에서 누르면 `단원`에 해당 단원이 연결된다. 학부모 리포트(학생 페이지 동기화 후)·수업 관리에 그 단원이 보인다.
- **흔한 오류**: 401 → 헤더 키가 다르다. 단원을 찾지 못했다는 안내 → 라이브러리 화면에서 그 교재의 단원과 시작쪽을 먼저 넣는다.

## N-11. 기존 학습기록 단원 채우기 [배포 후]

- **선행**: N-10.
- **왜**: 예전 기록은 관계 `단원`이 비어 있다. 비어 있으면 리포트·수업 관리가 `단원(수식)` 값을 대신 보여 주지만, N-12에서 수식을 지우면 단원이 사라진다.
- **방법(택1)**
  - 운영 AI: `범위`가 있는 학습기록을 모아 기록마다 `fill-record-units`를 한 번씩 호출한다(서버 웹훅 키는 운영 Secrets에서만 읽고 채팅에 쓰지 않는다). **업무 데이터 대량 변경이므로 대상 건수를 먼저 보고하고 AI·관리자 작업 규칙 16-4에 따라 승인받는다.** 교재에 단원이 없는 기록은 건너뛰고 건수를 보고한다.
  - 운영자: 기록마다 [단원 입력]을 누른다(기록이 적을 때).
- **확인**: 대상 건수와 채운 건수·건너뛴 건수가 맞다.

## N-12. 학습기록(학원) DB — `단원(수식)` 삭제 [배포 후]

- **선행**: N-11.
- **먼저 확인(운영 AI가 수식 원문을 읽을 수 없으면 운영자가 화면에서 확인)**: 아래 수식이 `단원(수식)`을 쓰지 않는지 본다.
  - 학습기록(학원) DB: `진행도`, `동기화 필요`, `학습활동 현황`
  - 진도교재(학원) DB: `최근 학습 범위`, `최근 학습 내용`, `진행도`
  - 출석(학원) DB: `일일 학습 현황`
  - 학습활동(학원) DB: `내용`
  - 위 DB의 롤업 중 학습기록 `단원(수식)`을 가리키는 것
- **쓰는 수식이 있으면**: 그 부분을 관계 `단원`의 단원 이름으로 바꾼 수식을 만들어 붙여 넣은 뒤 지운다. 바꿀 수식이 있으면 원문을 아래 자리에 붙여 두고 운영 AI에게 고친 수식을 요청한다.

```
(쓰는 수식이 있을 때만: 속성 이름과 현재 수식 원문을 여기에 붙여 넣기)
```

- **삭제**: 모두 쓰지 않으면 `단원(수식)`을 지운다. 지운 뒤 코드는 관계 `단원`만 읽는다(비어 있으면 단원 없음).
- **원본 기준**: 원본은 위 수식이 모두 쓰지 않음을 확인하고 2026-10-14에 지웠다.

## N-13. 라이브러리 이름 맞추기 [배포 후, 권장]

- **왜**: 원본은 "정규교재"를 "라이브러리"로 바꿨다("진도교재"와 헷갈림). 코드는 관계 이름 `라이브러리`와 옛 이름 `정규교재`를 모두 읽으므로 바꾸지 않아도 동작한다. 다만 관리자 설정의 웹훅 체크리스트는 DB 제목 "라이브러리(학원)"로 카드를 찾는다.
- **무엇을(배포 후에 — v2.5.11 코드는 새 관계 이름을 모른다)**
  1. 관계 속성 이름 `정규교재` → `라이브러리`: 진도교재(학원)·교재배부(학원)·단원목록(학원)·과목(학원) DB. 속성 종류·연결은 그대로, 이름만. 학습기록 DB의 `교재`는 그대로 둔다.
  2. DB 제목 `정규교재(학원) DB` → `라이브러리(학원) DB`, 메뉴 페이지 `정규교재` → `라이브러리`.
- **확인**: 진도교재 페이지의 `북커버`·`진행도`가 그대로 보인다(수식·롤업은 속성을 내부 ID로 가리켜 이름을 바꿔도 동작).
- **Notion 연결 권한**: 라이브러리 화면의 [시리즈 관리]는 라이브러리 DB의 `시리즈` 선택지를 고친다. 학원관리 연결에 그 DB 편집 권한이 있어야 한다(교재 페이지를 만드는 권한과 같음).

## N-14. 매뉴얼 갱신 [배포 후]

원본 메뉴얼(메뉴 > 8. 기타 설정 > 메뉴얼)의 최신 문구를 기준으로 운영 매뉴얼의 아래 부분을 맞춘다. 운영 고유 내용(학원 이름·주소·운영 규칙)은 지키고, 원본 ID·주소는 복사하지 않는다.

- 1장 관리자 비밀번호·상단 메뉴: 상단 메뉴(관리자 설정·라이브러리·시험 관리(준비 중)·학교 검색·법정 서류 + 새 탭 키오스크·수업 관리), 오른쪽 위 ⋯(보안 설정 현황·로그아웃), 휴대폰은 오른쪽 위 ☰, 관리 화면끼리 같은 탭에서 로그인 공유.
- 수업·출석 6-4 키오스크: 키보드 입력, 설정(톱니: 체크 방식 1일 1회/매번 기록·지금 동기화·로그아웃), 카드 아래 학원 이름, 로그인 유지(관리자 비밀번호를 바꿀 때까지, 보안 모드를 켠 경우).
- 시스템 운영 §13~§15: 예약 실행 표(pg_cron: 큐 워커 매분, 워치독 15분, 동기화 실패 점검 30분, 과제 마감 백필 10분, 키오스크 오늘 출석 준비 매일 04:00, 수업 관리 복사본 3분·5분·매일 밤, 라이브러리 복사본 10분), **출석 정기 동기화 해제**(학부모 리포트는 보고서 발송 직전과 [학생 페이지 동기화]에서 최신화, GitHub Actions 출석 동기화는 수동 실행만), 키오스크 점검 경로.
- 교재·학습 7-1·7-3·7-6·7-7: 라이브러리 화면(교재 보기·추가·단원 편집·북커버·시리즈 관리), 국립중앙도서관·카카오 책 검색, 학습기록 `주제`·`단원`·[단원 입력]과 쉼표 범위.
- 수업 관리(새 화면 `class_room.html`) 사용 안내: 관리 화면과 같은 값으로 로그인(보안 모드에서는 관리자 비밀번호, 12시간), 첫 화면(강사·담당 클래스·통합 시간표), ☰ 사이드바, 반 상세 [홈·교재·캘린더·학습기록·학생], 캘린더 날짜 → 출석 체크, 기록 만들기(구분·클래스·교재·주제·범위·단원 고르기·내용), 보강 대기실·보강 수업, 메모·선생님 한마디, 달력 첫 요일 버튼.
- 학부모 리포트 안내(있다면): 홈 탭, 교재·캘린더·보고서(평가 칸)·학습기록, 뒤로가기, 일간 보고서 등원 시각, 달력 첫 요일 버튼.
- 웹훅 매핑 요약: 학습기록 [단원 입력] → `fill-record-units` 추가, 지운 함수 3개 행 삭제, 라이브러리 표기.
- 웹페이지(학원) DB: 관리자 설정·라이브러리·수업 관리 행, "법정 서류" 이름.
- 키 발급 매뉴얼: `NL_CERT_KEY`·`KAKAO_REST_KEY`(선택), `ALADIN_TTB_KEY`는 쓰지 않음, 데이터소스 19개, Vault 키가 쓰이는 예약 실행 목록.

## N-15. (선택) 보안 모드를 켤 때 — "웹훅등록" 보기 [선택]

- 관리자 설정의 웹훅 키 교체 체크리스트는 각 DB에서 이름이 `웹훅등록`(띄어쓰기 무시)인 보기를 찾아 링크를 단다. 보기가 없으면 링크만 비고 체크리스트는 동작한다.
- 원본 템플릿을 복제한 운영은 보기가 이미 있다. 없으면 각 DB에 버튼 속성만 보이는 표 보기 `웹훅등록`을 만든다.
- 체크리스트 항목은 원본 템플릿 기준이다. 운영 자동화 개수가 다르면 항목과 실제 자동화를 직접 대조한다: 대시보드(학원) DB 웹훅 자동화 2개(날짜 속성 편집·페이지 추가), 라이브러리(정규교재)·일정 DB 웹훅 자동화 2개씩(속성 편집·페이지 추가), 수업·출석·학습기록·학습활동·교재비·교재배부·교재결제 DB의 "삭제 체크" 자동화.
