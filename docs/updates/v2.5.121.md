## 항목 1. 단원 편집과 북커버 수정

- **유형**: AI 자동(`main` 병합 시 함수·Pages 반영)
- **대상 파일**: `supabase/functions/_shared/textbookSearch.ts`, `supabase/functions/_shared/textbookSearch_test.ts`, `supabase/functions/textbook-api/index.ts`, `library.html`, `assets/hada-tokens.css`(삭제 아이콘), `docs/DESIGN.md`, 공용 스타일 버전 표시(`*.html`)
- **동작**:
  - 단원 창 머리: `[표지] [교재명 ↗ / 시리즈·출판사·사용]`, 그 아래 `[단원 n개 | 편집]`.
  - [편집]: 단원명·시작쪽 고치기, 줄마다 삭제(다시 누르면 되돌림), [단원 추가]·목차 붙여넣기, 표지 이미지 주소·[교보문고 표지]·[다른 표지]·[표지 지우기]. [저장 · 변경 n건] 한 번으로 보낸다. 저장 전 [취소]·[닫기]·Esc는 버릴지 묻는다.
  - 삭제는 Notion 휴지통(30일 안에 Notion에서 복구 가능). 단원목록 DB에서 라이브러리 말고 다른 관계(시험정보 DB의 시험범위 등)에 연결된 단원은 지우지 않는다(화면에서 삭제 버튼이 꺼지고, 서버도 막는다). 이름·쪽은 고칠 수 있다.
  - 서버는 고치거나 지우는 단원이 그 교재의 단원인지 확인한다. 같은 이름의 단원은 새로 만들지 않는다. 표지는 https 주소만.
  - 단원 이름을 바꿔도 시험범위·리포트 연결은 그대로다(페이지가 같다). 학부모 리포트의 단원 목록은 다음 캐시 갱신 때 새 이름으로 보인다.
- **검증(모의 데이터)**: 함수 테스트(다른 곳 연결 수, 수정·삭제·추가 한 번에, 연결된 단원 보호, 다른 교재 단원·빈 이름·잘못된 쪽 거부, 표지 https·지우기·다른 DB 거부), 전체 테스트·타입 검사·회귀 가드·디자인 검사, 라이브러리 UI 검사 6개 크기(↗ 링크, 편집·삭제·추가·표지, 버릴지 묻기).
- **미검증**: 실제 Notion에서 단원 수정·휴지통 이동·북커버 변경.
- **실패 시 대처**: 저장 중 멈추면 화면에 몇 개까지 반영됐는지 나온다. 창을 다시 열어 확인하고, 잘못 지운 단원은 Notion 휴지통에서 복구한다.
