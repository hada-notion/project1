# v2.6.30 — 시험정보 [응시학생 등록]을 Notion 자동화로, 시험범위 속성 이름을 시험정보로

- 날짜: 2026-10-17
- 이전 버전: v2.6.29
- 요약:
  - 시험정보 [응시학생 등록]이 서버 없이 성적 행을 만든다. 버튼이 대상 학생(같은 학년, 학교를 지정했으면 같은 학교, 등록 중, 이 시험의 성적이 아직 없음 — 예전 서버와 같은 조건)의 `응시 등록`에 이 시험을 넣으면, 학생 DB 자동화가 성적 행을 만들고 `응시 등록`을 비운다(서버 호출 0, 예전 서버는 학생 10명 기준 약 14 호출).
  - 시험정보 DB로 가는 관계 중 이름이 `시험범위`인 속성 5개(성적·단원목록·학년·학교·시험 DB)를 `시험정보`로 바꾼다. 2.4에서 DB 이름을 바꿀 때 남았던 옛 이름이다.
  - 성적 이름을 성적 DB 이름 자동화와 같은 형식 "학생 학년 시험 (과목)"으로 통일한다(예: "김하윤 중3 2학기 중간고사 (수학)").
  - 예전 `sync-exam-scope` 웹훅은 성적 DB의 관계 이름을 `시험정보`로 먼저 찾고, 없으면 `시험범위`로 찾는다(이름을 바꾼 운영과 아직 안 바꾼 운영 모두 동작). 예전 웹훅의 성적 이름은 "학생 - 시험" 그대로다.
- 매뉴얼 영향: 있음 → 아래 "매뉴얼"
- 변경 유형: 함수(`_shared/examScopeTarget.ts`, `constants.ts`), Notion 속성 이름 5개·속성 1개·보기 1개·자동화 1개·버튼 1개(운영자 직접), 관리자 설정 웹훅 체크리스트(표시만).
- **순서: 항목 1(함수) 배포 → 항목 2 → 항목 3 → 항목 4 → 항목 5.**

---

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/examScopeTarget.ts`, `constants.ts` 반영 시 자동 배포)
- **동작**: 예전 `sync-exam-scope`만 해당. 성적 조회를 `시험정보`로 먼저 하고, "속성이 없다"는 오류일 때만 `시험범위`로 한 번 더 조회한다. 성적을 만들 때도 찾은 이름을 쓴다. 다른 오류는 예전처럼 ⚠️ 오류.
- **검증(원본)**: 함수 테스트(새 이름 우선·예전 이름 대체·다른 오류는 다시 묻지 않음), 전체 Deno 테스트, 타입 검사, 회귀 가드.

## 항목 2. 속성 이름 `시험범위` → `시험정보`

- **유형**: 운영자 직접(원본에는 반영됨)
- 시험정보(학원) DB와 연결된 아래 DB에서 이름이 `시험범위`인 관계 속성을 `시험정보`로 바꾼다. 이미 쓰는 Notion 수식·자동화는 이름 변경을 자동으로 따라간다.
  - 성적(학원), 단원목록(학원), 학년(학원), 학교(학원), 시험(학원)
- 일정(학원) DB의 `시험일정`과 학생(학원) DB의 `성적`은 이름이 달라 그대로 둔다.

## 항목 3. 학생(학원) DB 속성 `응시 등록`과 보기

- **유형**: 운영자 직접(원본에는 있음)
1. 관계 속성 `응시 등록` → 시험정보(학원) DB, **단방향**. 학생 페이지에서는 비어 있으면 숨김. 평소엔 비어 있다.
2. 학생 DB에 보기 `응시 등록`을 만들고 필터를 "`응시 등록` 비어 있지 않음"으로 둔다. 항목 4 자동화가 이 보기에만 걸리므로 **필터를 바꾸지 않는다.**

## 항목 4. 학생(학원) DB 자동화 "응시 등록"

- **유형**: 운영자 직접
- 적용 범위: 항목 3의 `응시 등록` 보기(자동화 편집 상단 "~의 모든 페이지에 적용"에서 고름). Notion 트리거에서 관계의 "비어 있지 않음" 조건을 고를 수 없어 보기로 거른다. 누가 `응시 등록`을 손으로 비워도 돌지 않는다.
- 트리거: `응시 등록`이 편집됨
- 동작 1: 성적(학원) DB에 페이지 추가

| 속성 | 값 |
| --- | --- |
| 이름 | 아래 수식 |
| 학생 | 페이지 실행 |
| 시험정보 | `context("페이지 실행").prop("응시 등록")` |
| 학년 | `context("페이지 실행").prop("학년")` |
| 학교 | `context("페이지 실행").prop("학교")` |

이름("학생 학년 시험 (과목)")
```
lets(
  exam, context("페이지 실행").prop("응시 등록").first(),
  context("페이지 실행").prop("학생이름") + " " +
  context("페이지 실행").prop("학년").format() + " " +
  exam.prop("시험").map(current.prop("지필고사") + current.prop("모의고사(수능)")).join("") +
  " (" + exam.prop("과목") + ")"
)
```
- 동작 2: 페이지 실행 편집 — `응시 등록` 비우기
- **동작 2를 빠뜨리지 않는다.** 빠지면 학생이 보기에 남아 다음 시험에서 자동화가 돌지 않는다.
- 성적 DB에 이미 있는 이름 자동화는 손으로 추가한 성적용으로 그대로 둔다(자동화가 만든 페이지에서는 다른 자동화가 돌지 않아 이름을 여기서 넣는다).

## 항목 5. 시험정보(학원) [응시학생 등록] 버튼

- **유형**: 운영자 직접
1. 웹훅 보내기 동작을 지운다.
2. 변수 `대상학생`
```
lets(
  sid, id(context("이 페이지")),
  schools, context("이 페이지").prop("학교").map(id(current)),
  context("이 페이지").prop("학년").map(current.prop("학생")).flat().filter(
    current.prop("등록상태") == "🟢 등록 중" and
    if(schools.empty(), true, current.prop("학교").map(id(current)).some(schools.includes(current))) and
    not current.prop("성적").map(current.prop("시험정보").map(id(current)).join("")).includes(sid)
  )
)
```
3. 페이지 편집 — `var("대상학생")`: `응시 등록` = 이 페이지
- **확인**: 같은 학년(학교)의 등록 중인 학생마다 성적이 하나씩 생기고 이름이 "학생 학년 시험 (과목)"이다. 학생들의 `응시 등록`은 다시 비어 있다. 다시 눌러도 새로 생기지 않는다.
- 시험정보의 `상태`·`마지막 동기화`는 이 방식에서 바뀌지 않는다.

## 매뉴얼

- 시험·성적: "[응시학생 등록]을 누르면 그 학년(학교) 등록 중인 학생의 성적이 바로 생겨요. 이미 있는 학생은 건너뛰어요. 이름은 '학생 학년 시험 (과목)'이에요."
