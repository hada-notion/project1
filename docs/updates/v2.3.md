# v2.3 — 학교 학사일정 수동 동기화(NEIS 연동) 반영

- 날짜: 2026-10-04
- 이전 버전: v2.2
- 요약: 학교(학원) DB에 나이스(NEIS) 학사일정을 수동으로 가져오는 기능을 추가합니다. 코드는 원본 저장소에 이미 존재하지만 지금까지 CHANGELOG/지침 문서가 없어 운영 워크스페이스에 전달되지 않았습니다. 이번 패치로 그 공백을 메웁니다.
- 매뉴얼 영향: 있음 → "매뉴얼" 항목 참고 (신규 문서 `docs/학교-학사일정-연결.md`, `docs/버튼-웹훅-매핑.md`에는 이미 반영되어 있음)

> 작성 규칙은 `docs/updates/_TEMPLATE.md` 참고.

## 항목 1. Edge Function 배포 — sync-school-calendar 및 신규 공용 모듈

- **구분**: 담당자 필요 (Supabase 함수 배포 권한 필요. 배포 명령 자체는 AI가 안내 가능)
- **되돌리기 어려움**: 아니오 (함수 배포는 재배포로 되돌릴 수 있음)
- **변경 이유·증상**: 학교(학원) DB에 "학사일정 가져오기" 버튼을 추가해도, 아래 함수들이 운영 Supabase 프로젝트에 배포되어 있지 않으면 버튼이 동작하지 않습니다.
- **대상 코드**
  - 원본 저장소(main 브랜치)의 아래 경로를 그대로 가져와 운영 Supabase 프로젝트에 배포합니다.
    - `supabase/functions/sync-school-calendar/index.ts` (신규 함수)
    - `supabase/functions/_shared/backgroundTask.ts` (신규)
    - `supabase/functions/_shared/neisManual.ts` (신규)
    - `supabase/functions/_shared/neisManual_test.ts` (신규, 테스트)
    - `supabase/functions/_shared/neisSchool.ts` (신규)
    - `supabase/functions/_shared/neisSchool_test.ts` (신규, 테스트)
    - `supabase/functions/_shared/schoolNotion.ts` (신규)
  - 함께 쓰이는 기존 공용 파일 `_shared/adminShared.ts`, `_shared/notionClient.ts`도 원본 저장소의 현재 버전과 운영 버전이 다르면 함께 맞춰야 합니다. 운영 AI는 배포 전 두 파일을 원본과 비교하고, 차이가 있으면 보고 후 지시를 받으세요(이 두 파일은 다른 기능과도 공유되므로 임의로 덮어쓰지 않습니다).
- **변경 내용**: 위 파일들을 원본 저장소 내용 그대로 생성/배포합니다. 기존 운영 코드에 같은 이름의 파일이 없으므로 "찾을 원문" 비교 없이 신규 생성합니다.
- **환경별 값**: 하드코딩된 Supabase 프로젝트 주소 없음. `sync-school-calendar`는 기존에 설정된 `SB_URL`, `SB_SERVICE_ROLE_KEY`, `NOTION_TOKEN`, `ADMIN_SECRET`, `DATA_SOURCE_SCHEDULE_EVENT_ID` 환경변수를 재사용합니다(새로 발급할 필요 없음).
- **필요한 Secret (이름만)**: `NEIS_API_KEY` (신규 — 나이스 교육정보 개방 포털 Open API 키)
- **Notion 변경**: 없음 (항목 2에서 별도 처리)
- **마이그레이션 / 재배포**: 항목 3 참고. 재배포 함수: `sync-school-calendar` (신규)
- **검증**:
  1. Supabase 함수 목록에 `sync-school-calendar`가 배포되어 있는지 확인한다.
  2. `NEIS_API_KEY` Secret이 설정되어 있는지 확인한다(값은 확인하지 않고 존재 여부만).
  3. 항목 2·3 완료 후 학교 DB에서 버튼을 눌러 상태가 "🔄 작업중" → "✅ 완료"로 바뀌는지 확인한다.
- **실패 시 복구**: 함수 미배포 상태로는 버튼이 실행되지 않을 뿐 기존 기능에는 영향이 없습니다. 실패 시 함수 배포만 재시도하면 됩니다.
- **매뉴얼**: 변경 없음 (원본 저장소의 `docs/학교-학사일정-연결.md`, `docs/버튼-웹훅-매핑.md`를 그대로 복사해 운영 문서로 사용)

## 항목 2. [되돌리기 어려움] Notion 변경 — 학교(학원) DB 속성·버튼 추가

- **구분**: AI 가능 (Notion 속성/버튼 생성까지는 가능하나, 버튼 안 웹훅 액션 연결은 Notion MCP로 불가능 — 담당자가 수동 연결 필요. 아래 "Notion 변경"의 버튼 항목 참고)
- **되돌리기 어려움**: 예 (select/버튼 등 속성 추가 자체는 삭제로 되돌릴 수 있으나, 이미 쌓인 학사일정 데이터와 연결된 상태라면 삭제 시 데이터 유실)
- **변경 이유·증상**: 학사일정 동기화 상태를 저장하고 버튼을 실행할 속성이 없으면 기능을 쓸 수 없습니다.
- **대상 코드**: 없음 (Notion 스키마 변경)
- **Notion 변경**: "학교(학원) DB" (학교·교육기관 목록을 관리하며 학년/반/시험 등 다른 DB와 연결된 DB)에 아래 속성·뷰를 추가합니다. 이미 같은 이름의 속성이 있으면 건너뜁니다.
  - select **학사일정 처리 상태**, 옵션: `⚪ 대기`(회색), `🔄 작업중`(파랑), `✅ 완료`(초록), `⚠️ 오류`(빨강)
  - text **학사일정 처리 현황**
  - text **학사일정 오류**
  - date **학사일정 마지막 동기화**
  - checkbox **학사일정 동기화** (설명: "정기 동기화는 사용하지 않습니다. 학사일정 가져오기 버튼은 이 체크 값과 무관하게 실행됩니다.")
  - formula **실시간 처리 상태** (결과 타입: 텍스트), 수식:

    ```
    ifs(
      prop("학사일정 처리 상태") == "⚠️ 오류",
      "⚠️ 오류: " + if(empty(prop("학사일정 오류")), "원인을 확인하고 다시 시도하세요.", prop("학사일정 오류")),
      prop("학사일정 처리 상태") == "🔄 작업중",
      "🔄 " + if(empty(prop("학사일정 처리 현황")), "학사일정 가져오는 중", prop("학사일정 처리 현황")),
      ""
    )
    ```

  - button **학사일정 가져오기** (설명: "현재 학년도 전체 학사일정을 수동 동기화합니다. 웹훅 액션 연결이 필요합니다.")
  - 참고: **교육청 코드**(형식 `A99`), **학교 코드**(형식 `0000000`) 속성은 학교 검색 기능에서 이미 쓰이고 있어야 하는 기존 속성입니다. 운영 DB에 없다면 이 패치보다 먼저 학교 검색 기능 자체가 누락된 것이니 별도로 확인하세요.
  - 뷰: 기존 뷰 또는 새 뷰(예: "학교 검색·연결")에 위 속성들을 표시하면 운영자가 상태를 보기 편합니다(선택 사항, 매뉴얼에는 영향 없음).
- **버튼 안 액션 연결(담당자 필요, AI 불가)**: 운영 AI가 버튼 속성까지 만든 뒤, 담당자가 버튼 편집 화면에서 "액션 추가 → 웹훅 보내기"로 `https://<운영 Supabase 프로젝트 ref>.supabase.co/functions/v1/sync-school-calendar`를 연결하고, 사용자 지정 헤더 `x-admin-key`에 운영 관리자 키를 넣어야 합니다. 자세한 절차는 `docs/학교-학사일정-연결.md`의 "마지막 1회 설정" 항목을 그대로 따르세요.
- **환경별 값**: 웹훅 URL은 운영 Supabase 프로젝트 주소로, 헤더 값은 운영 관리자 키로 치환해야 합니다(원본 문서에는 값 없음).
- **필요한 Secret (이름만)**: 없음 (Notion 쪽에는 Secret을 저장하지 않음, 관리자 키는 Notion 웹훅 액션 설정 화면에만 입력)
- **마이그레이션 / 재배포**: 없음
- **검증**:
  1. 학교 DB에 위 6개 속성과 버튼이 모두 존재하는지 확인한다.
  2. 테스트용 학교 페이지에서 버튼을 눌러 "학사일정 처리 상태"가 변하는지 확인한다.
- **실패 시 복구**: 속성만 추가된 상태(액션 미연결)는 버튼을 눌러도 아무 반응이 없을 뿐 안전합니다.
- **매뉴얼**: 변경 없음 (원본 `docs/학교-학사일정-연결.md`를 운영 문서로 그대로 사용)

## 항목 3. [되돌리기 어려움] Postgres 마이그레이션 — neis_school_jobs / neis_manual_runs

- **구분**: 담당자 필요 (마이그레이션 적용은 DB 변경 권한 필요)
- **되돌리기 어려움**: 예 (테이블·함수 생성. 삭제 시 진행 중이던 동기화 기록 유실)
- **변경 이유·증상**: `sync-school-calendar` 함수가 호출하는 `rpc/begin_neis_manual_run`, `rpc/claim_neis_manual_run`과 테이블 `neis_manual_runs`가 없으면 함수가 오류를 반환합니다.
- **대상 코드**
  - 마이그레이션 파일(원본 저장소 그대로 적용):
    - `supabase/migrations/20261003010000_school_schedule_jobs.sql` — 테이블 `neis_school_jobs`, 함수 `claim_neis_school_job()` 생성(현재 코드에서는 사용하지 않는 예비 테이블이지만 원본과 동일하게 함께 적용)
    - `supabase/migrations/20261003030000_manual_neis_school_calendar.sql` — 기존 `neis-schools-daily-enqueue`/`neis-schools-process`라는 이름의 pg_cron 예약이 있으면 해제(다른 예약에는 영향 없음), 테이블 `neis_manual_runs`, 함수 `begin_neis_manual_run(...)`/`claim_neis_manual_run(uuid)` 생성
- **변경 내용**: 두 파일을 운영 Supabase 프로젝트에 그대로 적용합니다(파일 내용 수정 없음).
- **환경별 값**: 없음(마이그레이션에 환경별 주소 없음)
- **필요한 Secret (이름만)**: 없음
- **Notion 변경**: 없음
- **마이그레이션 / 재배포**: 위 두 마이그레이션 파일 적용. 재배포 함수 없음(마이그레이션만)
- **검증**:
  1. `neis_manual_runs`, `neis_school_jobs` 테이블이 생성되었는지 확인한다.
  2. 운영 프로젝트에 `neis-schools-daily-enqueue`/`neis-schools-process`라는 pg_cron 예약이 실제로 있었다면 해제되었는지 확인한다(없었다면 영향 없음).
- **실패 시 복구**: 마이그레이션 미적용 상태에서는 버튼을 눌러도 함수가 오류를 반환할 뿐, 기존 기능에는 영향이 없습니다.
- **매뉴얼**: 변경 없음
