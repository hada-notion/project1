# v2.6.2 — 코드 배포 (함수·마이그레이션·화면 한 번에)

- 날짜: 2026-10-14
- 이전 버전: v2.6.1
- 요약: 원본 v2.6 코드를 운영 저장소에 한 커밋으로 반영한다. 함수 6개 추가·4개 정리, 마이그레이션 15개(복사본 표·예약 실행 포함), 관리 화면·키오스크·학부모 리포트 교체, 새 화면 수업 관리·라이브러리. 웹 화면 연결값은 새 학원 파일 `hada_config.js`로 옮긴다.
- 매뉴얼 영향: 없음(매뉴얼은 v2.6.4)
- 변경 유형: Supabase 함수·DB 마이그레이션·GitHub 워크플로·웹 화면(Pages). Notion·Secrets 변경 없음(Vault 확인만).

> **학원 수업이 없는 시간에** 한다. 보안 모드(`ADMIN_SECURITY_ENABLED`)는 켜지 않은 채로 진행한다(켜기는 v2.6.5).
>
> **서버와 화면을 나눠 올리지 않는다.** 함수 배포 워크플로의 테스트가 `admin_settings.js`(새 화면 파일)를 읽어 서버 허용 목록과 대조하고, 회귀 가드가 화면 파일이 `hada_config.js`를 쓰는지 검사한다. v2.5.11 화면이 남은 채 서버만 올리면 배포가 테스트에서 막힌다.
>
> 한 커밋을 올리면 Pages(1~2분)가 함수 배포(수 분)보다 먼저 끝나, 잠시 새 화면이 아직 없는 새 함수(`admin-security`, `class-room`, `kiosk-prepare`, `textbook-api` 등)를 부를 수 있다. 수업이 없는 시간에 하고, 함수 배포가 끝날 때까지 화면 확인을 미룬다.

## 항목 3. 운영 값으로 치환 (`hada_config.js`·마이그레이션·README)

- **유형**: AI 자동
- **선행 조건**: 항목 2
- **환경별 값**: 웹 화면은 Supabase 주소·anon 공개 키를 `hada_config.js` 한 파일에서 읽는다. pg_cron 마이그레이션 8개에는 함수 주소가 들어 있다(덮어쓰면 기존 6개도 원본 주소로 돌아간다). 아래 스크립트가 한 번에 바꾼다. 원본 값은 공개 값이며 원본 `hada_config.js`에서 읽는다.

  ```bash
  python3 scripts/setup-new-academy.py \
    --old-url <원본 hada_config.js의 supabaseUrl> \
    --new-url https://<운영 Supabase 프로젝트 ref>.supabase.co \
    --old-anon-key <원본 hada_config.js의 supabaseAnonKey> \
    --new-anon-key <운영 anon 공개 키> \
    --old-pages-path project1 \
    --new-pages-path <운영 GitHub 저장소 이름>
  ```

  - 대상: `hada_config.js`, `README.md`, 마이그레이션 8개(`20260918190000_create_sync_queue`, `20260921020000_process_sync_queue_cron_auth`, `20260922150000_status_watchdog_cron`, `20260923010000_sync_queue_audited_at`, `20260924010000_backfill_assignment_deadlines_cron`, `20260926020000_status_watchdog_cron_15min`, `20261013030000_kiosk_today`, `20261014060000_class_room_copy_cron`).
- **이후 규칙**: `hada_config.js`는 학원 파일이다. 다음 원본 업데이트부터는 덮어쓰지 않는다.
- **검증**
  1. `git diff --stat HEAD -- supabase/migrations`: 기존 마이그레이션은 차이 없음, 새 파일 15개만 추가.
  2. 저장소 전체에서 원본 Supabase 프로젝트 ref를 `grep`하면 0건(문서의 예시 문구 제외). 운영 주소가 `hada_config.js`·`20261013030000_kiosk_today.sql`·`20261014060000_class_room_copy_cron.sql`에 들어갔다.
  3. `bash scripts/check-known-regressions.sh`, `node tests/design-lint.cjs` 통과(화면 파일에 주소·키가 없고 모든 화면이 `hada_config.js`를 부른다).
- **실패 시 대처**: 치환 결과가 다르면 커밋하지 않고 멈춘다. 원본 주소가 남은 채 배포하면 예약 실행이 원본 서버로 운영 키를 보내고, 화면이 원본 서버를 부른다.

## 항목 4. 커밋·배포

- **유형**: AI 자동(운영 저장소 `main` 반영은 승인된 계획 범위)
- **선행 조건**: 항목 3
- **무엇을**
  1. 가능하면 로컬에서 `deno check supabase/functions/*/index.ts`와 함수 테스트를 돌린다(워크플로도 같은 검사를 한다).
  2. 한 커밋으로 `main`에 반영한다. "Deploy Supabase Functions"가 테스트 → 함수 전체 배포 → `supabase db push`, Pages가 화면을 배포한다.
- **새 함수**: `admin-security`, `class-room`, `fill-record-units`, `kiosk-prepare`, `sync-class-room-copy`, `textbook-api`
- **새 마이그레이션**(순서대로 자동 적용): `20261011010000_admin_security`, `20261012010000_admin_password_simplify`, `20261012020000_admin_security_safeupdate`, `20261013010000_webhook_key_rotation`, `20261013020000_webhook_checklist`, `20261013030000_kiosk_today`, `20261013040000_neis_run_created_keys`, `20261014010000_class_password`, `20261014020000_unify_admin_password`(앞 파일이 만든 수업용 비밀번호를 지움 — 정상), `20261014030000_attendance_stamps`, `20261014050000_class_room_copy`, `20261014060000_class_room_copy_cron`, `20261014070000_class_room_copy_read`, `20261014080000_library_copy`, `20261014090000_record_selected_units`
- **검증(서버)**
  1. 함수 배포 워크플로 성공(테스트·함수 배포·마이그레이션 단계 모두). 실패하면 단계 이름과 오류를 기록하고 멈춘다. CLI 설치 단계에서 멈췄다면 한 번 다시 실행한다.
  2. 새 함수 6개에 `OPTIONS` 요청이 200.
  3. 예약 실행: `select jobname, schedule from cron.job order by jobname;`에 `kiosk-prepare-daily`, `class-room-copy-first-fill`, `class-room-copy-incremental`, `class-room-copy-reconcile-sessions`·`-attendance`·`-records`·`-activities`, `library-copy-reconcile`이 기존 예약과 함께 보인다.
  4. 15~30분 뒤 `select source, last_synced_at from sync_cursors order by source;`에 `cr_sessions`·`cr_attendance`·`cr_records`·`cr_activities`·`lib_books`가 생긴다(수업 관리 처음 채우기는 표 하나씩 3분 간격, 끝나면 `class-room-copy-first-fill` 예약이 스스로 사라진다). `cron.job_run_details`에 401이 있으면 Vault 키와 `ADMIN_SECRET`이 다른 것이다.
- **검증(화면)** — 함수 배포가 끝난 뒤
  1. Pages 배포 성공, 공개 사이트 파일이 운영 `main`과 같다(`curl`로 몇 개 비교).
  2. 학부모 리포트 한 명이 열리고, 키오스크·법정 서류·학교 검색·라이브러리·수업 관리 로그인 화면이 "학원 연결 설정" 안내 없이 열린다(설정 파일이 잘못되면 그 안내가 보인다).
  3. 관리 화면에 `ADMIN_SECRET` 값으로 로그인된다(보안 모드 꺼짐). 관리자 설정은 "관리자 보안 기능의 최초 서버 설정이 필요합니다"가 정상이다.
  4. 실제 출결·발송·삭제는 하지 않는다.
- **실패 시 대처**
  - 운영 저장소를 이전 커밋으로 되돌려 다시 배포한다(함수·화면이 v2.5.11로 돌아간다).
  - 마이그레이션은 표·열을 더하기만 해서 되돌리지 않아도 v2.5.11 코드에 영향이 없다. 예약 실행을 멈추려면 `select cron.unschedule('<이름>');`.
  - 이 단계는 Notion 업무 데이터를 쓰지 않는다(복사본은 Notion을 읽기만 한다).
