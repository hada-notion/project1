# v2.6.14 — 일괄 생성 수업 1개를 Notion 호출 1번으로

- 날짜: 2026-10-16
- 이전 버전: v2.6.13
- 요약: 시간표 수식 `수업추가 정보`가 기준일 날짜의 수업 내용(시간·클래스·클래스 이름·담당강사·그날 수강 중인 명단)을 한 줄로 계산한다. 메뉴 [다음주 수업 일괄 생성]은 시간표 DB를 한 번 조회할 때 이 값을 함께 받아 큐에 담고, 큐는 그 값으로 수업 페이지만 만든다. 시간표당 Notion 호출 6회 → 1회. 웹훅 재정리 3단계 보완.
- 매뉴얼 영향: 없음(버튼 동작·결과 같음)
- 변경 유형: 함수(`generate-classes`, `process-sync-queue`의 수업 만들기 처리), Notion 수식 1개(운영자 직접). 버튼·자동화·Supabase 테이블·Secrets 변경 없음.
- **선행 조건: v2.6.12 항목 2(시간표 수식 `기준일`).** 수식 `수업추가 정보`가 없으면 v2.6.13과 똑같이 동작한다.

---

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/_shared/timetableSessionPlan.ts`, `supabase/functions/_shared/generateClassesQueue.ts`, `supabase/functions/generate-classes/index.ts`를 반영하면 함수 자동 배포)
- **동작**
  - 메뉴 일괄 생성(`?mode=bulk`): 시간표 DB 조회 결과에 `수업추가 정보`가 있으면 큐 항목에 그 값을 담는다. 워커는 그 값으로 수업 페이지를 명단과 함께 ✅ 완료로 만들고 출석 조정 큐에 넣는다. 시간표 읽기·시간표 상태(작업중/완료) 쓰기·클래스 읽기·등록 조회를 하지 않는다.
  - 값은 쓰기 전에 확인한다: 형식이 맞고, 날짜가 그 시간표의 `기준일`과 같고, 클래스가 시간표의 클래스와 같을 때만 쓴다. 아니면 예전처럼 시간표를 읽어 만든다.
  - 만들기가 실패하면 같은 값으로 다시 하지 않는다(Notion이 이미 만들었을 수 있음). 값 없는 항목을 큐에 다시 넣어, 그때 시간표를 새로 읽고 기준일이 이미 지났으면(수업이 실제로 만들어짐) 건너뛴다(v2.6.13 방식).
  - 시간표를 읽는 경로(예전 시간표 버튼 웹훅, 위 재시도)도 `수업추가 정보`가 있으면 클래스 읽기·등록 조회를 건너뛴다.
  - `generate-classes/queue`(시간표 자동화용, 필수 아님)도 본문에 `수업추가 정보`가 오면 큐 항목에 담는다.
- **Notion 호출(시간표 하나)**: 약 6회(시간표 읽기, 상태 2, 클래스 읽기, 등록 조회, 수업 만들기) → 1회(수업 만들기). 일괄 생성 전체는 + 시간표 DB 조회 1회. 출석은 전처럼 출석 조정 큐(수업 하나에 학생 수 + 2회 안팎).
- **검증(원본)**: 함수 테스트(수식 값 해석·기준일/클래스 불일치·형식 오류 시 쓰지 않음, 일괄 생성 큐 항목에 값 포함, 워커 Notion 호출 = 만들기 1번, 수업 이름·시간(KST)·명단·담당강사·완료·출석 조정 큐, 시간표 상태 그대로, 만들기 실패 시 값 없는 항목으로 다시 넣음, 시간표를 읽는 경로도 클래스 읽기·등록 조회 없음, queue 경로 본문 값), 전체 Deno 테스트, 타입 검사, 회귀 가드.
- **미검증**: 실제 메뉴 [다음주 수업 일괄 생성] → 큐 → 수업·출석 생성.

## 항목 2. 시간표 수식 `수업추가 정보`

- **유형**: 운영자 직접(시간표(학원) DB, 페이지에서는 숨김)
- **작업**: 수식 속성 `수업추가 정보`를 만들고 아래를 그대로 붙여 넣는다. 명단 조건은 [수업추가] 버튼의 `등록`과 같다.

```
lets(
  base, prop("기준일"),
  classes, prop("클래스"),
  cls, classes.first(),
  startTime, prop("등원시간(HH:mm)"),
  endTime, prop("하원시간(HH:mm)"),
  regs, prop("등록").filter(lets(r, current,
    if(empty(r.prop("등록일")), true, r.prop("등록일") <= base) and
    if(empty(r.prop("종료일")), true, base < dateAdd(r.prop("종료일"), 1, "days"))
  )),
  if(empty(base) or empty(classes), "",
    "{\"v\":1,\"date\":\"" + formatDate(base, "YYYY-MM-DD") +
    "\",\"start\":\"" + startTime +
    "\",\"end\":\"" + endTime +
    "\",\"cls\":\"" + id(cls) +
    "\",\"name\":\"" + replaceAll(cls.prop("클래스명"), "\"", "'") +
    "\",\"tch\":[" + cls.prop("담당강사").map("\"" + id(current) + "\"").join(",") +
    "],\"reg\":[" + regs.map("\"" + id(current) + "\"").join(",") + "]}"
  )
)
```

- **확인**: 시간표 행에 `{"v":1,"date":"기준일","start":"17:00","end":"18:00","cls":"…","name":"클래스 이름","tch":["…"],"reg":["…", …]}`처럼 나오고, `reg` 개수가 [수업추가]로 만들 때의 명단 수와 같다. 기준일이 비면 빈칸.
- **뜻**: 서버가 읽어 오던 것(클래스 이름·담당강사·그날 명단)을 Notion이 미리 계산해 둔다. 시간표 DB 조회 한 번에 모든 시간표의 값이 함께 온다.
