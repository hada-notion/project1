# v2.7.6~v2.7.8 운영 반영 묶음 (넘김 메모용)

- 대상 버전: [v2.7.6](v2.7.6.md), [v2.7.7](v2.7.7.md), [v2.7.8](v2.7.8.md). 이 문서는 세 지침을 반영 순서대로 묶은 것이다. 원문·확인 방법·실패 시 대처는 각 버전 문서가 기준이다.
- 선행 조건: v2.7.3(버튼·상태 속성 이름 표준화)까지 끝났을 것. v2.7.5(수업 `학습기록 계획` 수식)도 권장. 시스템 정보의 현재 버전부터 확인한다.
- 최종 형태 기준: [이름 규칙](../이름-규칙.md) 7장 "DB별 최종 형태"와 "DB 보기".
- 업무 데이터·코드·Secrets는 바꾸지 않는다.

---

## 1단계. 운영 AI (커넥터, AI 자동)

v2.7.7 항목 1·2. 각 DB를 `fetch`해 보기 ID를 찾고 `update-view`로 이름·열·정렬을 바꾼다. 필터는 바꾸지 않는다. 운영 DB에 같은 보기가 없거나 원본과 이름이 다르면 그 DB는 건너뛰고 보고한다.

| DB | 기본 보기 | `웹훅 등록` 보기 |
| --- | --- | --- |
| 수업 | `수업`: 이름·수업일시·클래스·담당강사·출석현황·생성 오류·실시간 처리 상태 | `웹훅등록` → `웹훅 등록`, 출석 조정·학습기록 생성·보고서 일괄 전송·삭제·실시간 |
| 등록 | `수강정보` → `수강 정보`: 이름·수강상태·클래스·등록일·종료일·수업 요일·학교·학년·실시간 | `웹훅등록` → `웹훅 등록`, 시간표 설정·교재 생성·수업 생성·학생 페이지 동기화·종료 처리·링크 재발급·오류 지우기·실시간 |
| 출석 | `표` → `출석`: 출석·수업일시·출석 상태·클래스·보고서 전송·전송완료 체크·전송 내역·실시간 | 삭제 체크·학생 페이지·리포트 토큰 열 빼기 |
| 학습기록 | → `학습기록`: 학습·구분·수업일·진도교재·범위·학습활동 현황·실시간, 생성 일시 내림차순 | [단원 입력]·실시간 추가, 삭제 체크 빼기 |
| 학습활동 | → `학습활동`: 학습활동·구분·수업일·교재·과제상태·과제 마감일·점수·메모, 생성 일시 내림차순 | 학습활동·삭제·수업일·실시간 |
| 보고서 | → `보고서`: 보고서·보고서 구분·보고서 기간·등록·보고서 전송·발송 횟수·전송 내역·실시간 | 보고서 전송 상태·실시간 추가 |
| 교재배부 | → `교재배부`: 배부일·이름·등록·라이브러리·클래스·교재비 금액·결제 상태·결제금액·실시간 | 결제·삭제·실시간(삭제 체크 빼기) |
| 교재결제 | → `교재결제`: 이름·결제일·결제 방법·결제 금액·교재·결제상태·실시간 | 삭제·실시간(삭제 체크 빼기) |
| 시간표 | `표` → `시간표` | 그대로 |
| 시험정보 | → `시험정보` | 그대로 |
| 학교 | → `학교` | `웹훅등록` → `웹훅 등록` |
| 일정 | → `일정` | (없음) |
| 알림톡 발송함 | `전체 발송함`: 이름·구분·기간·진행 상황·실시간·실행자 | 그대로 |

- 관리자 설정 웹훅 체크리스트는 보기 이름을 띄어쓰기 무시하고 찾으므로 `웹훅 등록`으로 바꿔도 된다.
- 확인: `update-view` 응답의 `name`·`displayProperties`를 위 표와 원문 비교.

## 2단계. 원본 지원 (브라우저, 운영자 직접)

### 2-1. 수식 하나 먼저 (v2.7.6 항목 1)

학습활동 `점수`: `정답 문항 / 전체 문항 * 100` → `if(empty(전체 문항) or 전체 문항 <= 0, empty(), 정답 문항 / 전체 문항 * 100)`. 원문이 다르면 멈추고 보고.

### 2-2. 시간표 버튼 만들기 (v2.7.8 항목 1)

시간표(학원) DB에 버튼 `클래스 정보 입력`이 없으면 만든다(있으면 수식만 대조). "이 페이지 편집":

- `등록`: `context("이 페이지").prop("클래스").map(current.prop("등록")).flat()`
- `담당강사`: `context("이 페이지").prop("클래스").map(current.prop("담당강사")).flat()`

### 2-3. DB별 레이아웃 (한 DB를 열 때 해당 버전 변경을 모두 하고 [모든 페이지에 적용])

- 확인: 끝난 DB마다 운영 AI가 커넥터로 데이터 소스를 읽어 `page-layout`(헤더 고정 속성·탭·패널 섹션·표시 방식)을 7장 표와 원문 비교.

## 3단계. 매뉴얼 (운영 AI)

- 탭 이름: 이번과제·평가결과·과제·평가 → "학습활동 탭"(과제검사 탭은 그대로), 등록의 캘린더 → "출석 탭"([v2.7.6 매뉴얼](v2.7.6.md))
- 버튼 위치: 보고서 [보고서 전송], 클래스 [교재비 생성]·[보고서 생성]·[월 수강료 생성], 학습기록 [단원 입력], 학생 [접수안내 전송]은 페이지 위쪽
- 학습활동 `점수`는 문항 수를 넣기 전에는 비어 있음
- 시간표: "[클래스 정보 입력]을 누르면 고른 클래스의 학생과 담당강사가 채워져요. 빼야 할 학생은 `등록`에서 지워요."
- 운영 매뉴얼 고유 문장은 살리고 바뀐 사실만 반영한다.

## 완료 기록

- 시스템 정보 현재 버전: 끝난 버전까지만 올린다(`v2.7.6` → `v2.7.7` → `v2.7.8`). 이력에 버전별 날짜·적용 주체(1단계 운영 AI, 2단계 원본 지원)를 남긴다.
- 못 한 DB는 버전과 DB 이름으로 보류 기록. DB마다 나눠 해도 된다.
