# v2.6.17 — 수업 중심 정리: 보강 수업 출석 조정(합치기만), 수업 없는 학습기록 막기, 수업 날짜 이동

- 날짜: 2026-10-16
- 이전 버전: v2.6.16
- 요약: 모든 학습 관리는 수업을 거친다(1:1·보강 포함). 수업 없는 출석(보강 대기실)으로는 학습기록을 만들지 않고, 보강 수업을 만들어 배정한 뒤 기록한다. 보강 수업도 [출석 조정]이 되지만 예외로 "합치기만" 한다(명단에 있는데 출석이 없으면 만들거나 같은 날 🔵 보강 출석을 연결, 출석은 있는데 명단에 없으면 명단에 추가, 지우기 없음). 수업 [클래스 정보 입력] 버튼으로 시간표와 관계없는 수업(보강)을 빠르게 만든다. 수업 날짜를 옮기면 출석 날짜가 따라온다.
- 매뉴얼 영향: 있음 → 아래 "매뉴얼"
- 변경 유형: 함수(`create-learning-record`, `fix-attendance` 출석 조정 처리), Notion 수식 3개·버튼 1개·자동화 1개(운영자 직접). Supabase 테이블·Secrets 변경 없음.
- **선행 조건: v2.6.11(수업 `출석 조정 정보`·출석 조정 자동화).**
- **순서: 항목 1(함수) 배포 → 항목 2(수식) → 나머지.** 항목 2 수식을 먼저 바꾸면 예전 함수는 보강 수업의 계획을 정규 수업처럼 처리할 수 있다.

## 항목 1. 함수 반영

- **유형**: AI 자동(원본 `supabase/functions/create-learning-record/index.ts`, `supabase/functions/_shared/createLearningRecordTarget.ts`, `supabase/functions/_shared/fixAttendanceTarget.ts`를 반영하면 함수 자동 배포)
- **동작**
  - 학습기록 생성: 수업에 연결되지 않은 출석에서 [학습기록 생성]을 누르면 기록을 만들지 않고 그 출석의 `마지막 오류`에 "보강 대기실에서 보강 수업을 만들어 배정한 뒤 그 수업에서 만들어 주세요"를 남긴다(예전 v2.6.x의 출석 단독 경로는 쓰지 않음, 이미 만든 기록은 그대로). 요청 본문 전체를 로그에 남기던 것을 페이지 id·키 이름만 남기게 고침.
  - 출석 조정: 수식 계획에 `"mk":1`(항목 2)이 있거나 수업 `보강`이 체크돼 있으면 보강 수업으로 처리 — 지우기(`삭제 체크`)를 하지 않고, 새 출석은 `출석 상태` 🔵 보강·제목 `날짜 보강`, 클래스가 없어도 처리, 과제 마감 백필을 연결하지 않는다(정규 수업의 다음 출석이 마감). 예전 수식(보강이면 `skip`)은 그대로 건너뛴다. 수식이 없는 운영의 예전 방식도 보강 수업을 건너뛴다.
- **검증(원본)**: 함수 테스트(수업 없는 출석 버튼 → 큐에 넣지 않고 안내, 배포 전 큐 항목도 기록 없이 오류, 보강 계획: 🔵 보강 출석 생성·대기실 출석 연결·명단 합치기·지우기 없음·과제 마감 조회 없음, 예전 skip), 전체 Deno 테스트, 타입 검사, 회귀 가드.

## 항목 2. 수업(학원) DB 수식 `출석 조정 정보` 교체 (항목 1 배포 뒤)

- **유형**: 운영자 직접
- **작업**: 기존 수식을 복사해 두고 아래로 바꾼다. 정규 수업 계산은 v2.6.11과 같고, 보강 수업만 다르다.

```
if(empty(prop("수업일시")),
  "{\"v\":1,\"skip\":\"수업일시 없음\"}",
  lets(
    isMakeup, prop("보강"),
    sessionDateTime, prop("수업일시"),
    day, formatDate(prop("수업일시"), "YYYY-MM-DD"),
    roster, prop("등록"),
    sessRecs, prop("학습기록"),
    atts, prop("출석"),
    active, if(isMakeup, roster, roster.filter(lets(reg, current,
      if(empty(reg.prop("등록일")), true, reg.prop("등록일") <= sessionDateTime) and
      if(empty(reg.prop("종료일")), true, sessionDateTime < dateAdd(reg.prop("종료일"), 1, "days"))
    ))),
    activeIds, active.map(id(current)),
    attRegIds, atts.map(current.prop("등록").map(id(current)).join("")),
    addItems, active.filter(not attRegIds.includes(id(current))).map(lets(
      reg, current,
      unl, reg.prop("출석").filter(empty(current.prop("수업")) and formatDate(current.prop("수업일시"), "YYYY-MM-DD") == day and if(isMakeup, current.prop("출석 상태") == "🔵 보강", true)),
      recs, reg.prop("학습기록").filter(sessRecs.includes(current)),
      "{\"reg\":\"" + id(reg) + "\",\"att\":\"" + if(empty(unl), "", id(unl.first())) + "\",\"rec\":[" + recs.map("\"" + id(current) + "\"").join(",") + "]}"
    )),
    delAtts, if(isMakeup, [], atts.filter(lets(a, current, i, index, rid, a.prop("등록").map(id(current)).join(""), rid != "" and (not activeIds.includes(rid) or attRegIds.slice(0, i).includes(rid))))),
    extraIds, if(isMakeup, attRegIds.filter(current != "" and not activeIds.includes(current)).unique(), []),
    rosterIds, if(isMakeup, activeIds.concat(extraIds), activeIds),
    "{\"v\":1," + if(isMakeup, "\"mk\":1,", "") + "\"day\":\"" + day + "\",\"add\":[" + addItems.join(",") + "],\"del\":[" + delAtts.map("\"" + id(current) + "\"").join(",") + "]" +
      if(rosterIds.length() == roster.length() and extraIds.empty(), "", ",\"roster\":[" + rosterIds.map("\"" + current + "\"").join(",") + "]") + "}"
  )
)
```

- **뜻**: 정규 수업은 v2.6.11과 같다. 보강 수업(`보강` 체크)은 명단 전원이 대상(수강 기간을 보지 않음), 출석이 없으면 같은 날 수업 없는 🔵 보강 출석을 연결하거나 새로 만든다. 출석은 있는데 명단에 없는 학생은 명단(`roster`)에 더한다. 지울 출석(`del`)은 항상 비어 있다. 앞에 `"mk":1`이 붙는다.
- **확인**: 정규 수업은 전과 같은 값(예: `{"v":1,"day":"…","add":[],"del":[]}`), 보강 수업은 `{"v":1,"mk":1,"day":"…",…}`.

## 항목 3. 수업 [클래스 정보 입력] 버튼

- **유형**: 운영자 직접(수업(학원) DB에 버튼 속성 추가)
- **작업**: "이 페이지 편집"
  - `담당강사`: `context("이 페이지").prop("클래스").first().prop("담당강사")`
  - `등록`(수업일에 수강 중인 반 학생):
    ```
    context("이 페이지").prop("클래스").first().prop("등록").filter(lets(r, current, if(empty(r.prop("등록일")), true, r.prop("등록일") <= context("이 페이지").prop("수업일시")) and if(empty(r.prop("종료일")), true, context("이 페이지").prop("수업일시") < dateAdd(r.prop("종료일"), 1, "days"))))
    ```
- **쓰는 법(간편 보강)**: 수업 DB에서 새 페이지 → `수업일시`·`클래스` 입력, `보강` 체크 → [클래스 정보 입력] → 명단(`등록`)에서 오지 않는 학생 빼기 → [출석 조정]. 잘못 만든 출석은 직접 지운다(보강 수업은 출석 조정이 지우지 않음).

## 항목 4. 학습활동(학원) DB 수식 2개에 9시간 더하기

- **유형**: 운영자 직접
- **이유**: 학습기록 `수업일`은 9시간을 더해 한국 날짜로 바꾸는데 학습활동 수식은 그렇지 않아, 오전 9시 전에 시작하는 수업에서 하루 전 날짜가 나올 수 있다.
- `수업일`:
  ```
  prop("출석").map(current.prop("수업일시").dateAdd(9, "hours").formatDate("YYYY-MM-DD").parseDate()).flat().first()
  ```
- `과제 마감일`:
  ```
  prop("과제 마감").map(current.prop("수업일시").dateAdd(9, "hours").formatDate("YYYY-MM-DD").parseDate()).flat().first()
  ```

## 항목 5. 수업 날짜 이동 → 출석 날짜 따라오기 (자동화)

> **v2.6.18에서 바뀜**: 이 항목의 Notion 자동화(출석 날짜 직접 편집)는 출석 이름을 바꾸지 못한다(자동화가 바꾼 변경으로는 출석 이름 자동화가 돌지 않음). [v2.6.18](v2.6.18.md) 항목 2대로 웹훅 하나로 바꾼다. 이 자동화에 출석 이름 편집을 넣지 않는다(모든 출석에 같은 값이 들어감). 자동화 수식의 트리거 페이지는 `context("페이지 실행")`이다.

- **유형**: 운영자 직접(수업(학원) DB 자동화)
- **작업**: 트리거 `수업일시` 편집 → 변수 정의 `대상출석` = `context("트리거 페이지").prop("출석")`(화면에서는 "페이지 실행"·트리거 페이지 항목) → `대상출석` 편집: `수업일시` = 트리거 페이지의 `수업일시`
- **뜻**: 수업에 연결된 출석은 항상 수업과 날짜가 같다. 캘린더에서 수업을 끌어 옮기면 출석이 따라오고, 학습기록·학습활동 `수업일`·`과제 마감일`은 출석을 보는 수식이라 함께 바뀐다. 제목 안의 날짜 글자는 바뀌지 않는다.
- **알아둘 점**: 보강은 원래 수업 출석의 날짜를 바꾸지 않고(결석으로 둠) 다른 날 보강 수업으로 한다. 수업 삭제는 [삭제] 버튼으로만(Notion에서 직접 휴지통으로 보내면 하위 출석이 남는다).
