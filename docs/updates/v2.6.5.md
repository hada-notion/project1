## 항목 1. 관리자 보안 모드 켜기

- **유형**: 운영자 직접
- **선행 조건**: v2.6.2. 학원 수업이 없는 시간.
- **켜면 달라지는 것**
  - 웹 화면 로그인 값이 Notion 웹훅 키(`ADMIN_SECRET`)에서 **관리자 비밀번호**로 바뀐다. 처음 비밀번호는 `0000`이며 관리자 설정에서 바로 바꿔야 키오스크·법정 서류·학교 검색·라이브러리·수업 관리를 쓸 수 있다.
  - Notion 버튼·자동화의 웹훅 키는 그대로 쓴다(헤더를 고치지 않는다). 웹훅 키는 업무 함수만, 관리자 로그인은 화면 함수만 부를 수 있게 범위가 나뉜다.
  - 관리 화면 로그인 12시간(같은 탭에서 공유), 수업 관리 12시간(그 기기), 키오스크는 관리자 비밀번호를 바꿀 때까지 유지(키오스크 로그인으로는 등원·하원만).
  - 관리자 설정에서 비밀번호 변경, Notion 웹훅 키 교체(DB별 체크리스트·복사 도구)를 쓸 수 있다.
  - 서버가 Vault `sync_queue_admin_key`를 내부 키로 바꾸고 비밀번호를 바꿀 때마다 함께 갱신한다. 켠 뒤에는 Vault 값을 손으로 바꾸지 않는다.
- **필요한 Secret (이름만)**: `ADMIN_ALLOWED_ORIGINS`(운영 관리 화면 origin, 예 `https://<계정>.github.io`, 저장소 경로·끝 슬래시 없이, 원본 값 복사 금지), `ADMIN_SECURITY_ENABLED`(`true`)
- **운영자 안내문**
  1. Supabase → Edge Functions → Secrets에 `ADMIN_ALLOWED_ORIGINS`를 등록한다. `ADMIN_SECRET`이 Notion 버튼 헤더의 웹훅 키와 같은 값인지 확인한다(다르면 켜지 않는다).
  2. `ADMIN_SECURITY_ENABLED` = `true`를 등록하고, 바로 관리자 설정(`admin_settings.html`)에서 `0000`으로 로그인해 새 비밀번호(8~128자, `0000` 불가)를 정한다. 켜고 바꾸기 전까지 관리자 설정 주소를 아는 다른 사람이 먼저 정할 수 있으니 이어서 한다.
  3. 키오스크·법정 서류·학교 검색·라이브러리·수업 관리에 새 비밀번호로 로그인하고, Notion 버튼 하나(예: [학생 페이지 동기화])가 동작하는지 본다.
  4. 출석 수동 동기화(GitHub Actions)를 쓰면 GitHub Secret `ADMIN_SECRET`이 웹훅 키와 같아야 한다.
  5. 선생님들께 수업 관리 로그인 값이 관리자 비밀번호로 바뀐 것을 학원 안에서 직접 알린다. 관리자 비밀번호를 아는 사람은 관리자 설정·법정 서류(개인정보)도 열 수 있다.
- **끝났는지 확인하는 방법**: 관리자 설정 대시보드에 비밀번호 마지막 변경일이 보이고, 위 화면들이 새 비밀번호로 열린다.
- **흔한 오류와 대처**
  - 관리 화면 로그인이 모두 거부되면 `ADMIN_ALLOWED_ORIGINS`가 실제 주소와 다르다.
  - 비밀번호를 잊으면 배포 담당자가 `scripts/reset-admin-password.py --confirm`(해당 학원 `SB_URL`·`SB_SERVICE_ROLE_KEY`를 환경 변수로만)으로 `0000`으로 되돌린다. 웹훅 키·내부 키는 바뀌지 않는다.
  - 되돌리기: `ADMIN_SECURITY_ENABLED`를 `false`로. 이때 Vault `sync_queue_admin_key`를 `ADMIN_SECRET`과 같은 값으로 다시 맞춰야 예약 실행이 동작한다.
- **웹훅 키 교체**(유출이 의심될 때만): 관리자 설정 → 웹훅 키 교체 → 새 키를 화면 위 막대에서 복사해 DB별 체크리스트대로 버튼·자동화 헤더를 바꾸고 체크 → 이전 키 호출이 더 늘지 않으면 [교체 완료 (이전 키 삭제)]. 체크리스트의 DB 링크는 각 DB의 `웹훅등록` 보기를 찾는다([Notion 작업 목록 N-15](v2.6-노션-작업.md)).
- **매뉴얼**: 1장 관리자 비밀번호 문단, 키오스크 로그인, 키 발급 매뉴얼 `ADMIN_SECRET`·`sync_queue_admin_key` 설명을 보안 모드 기준으로.

## 항목 2. 라이브러리 책 검색 키

- **유형**: 운영자 직접(학원 계정으로 따로 발급, 원본 키를 나눠 쓰지 않는다)
- **필요한 Secret (이름만)**: `NL_CERT_KEY`(국립중앙도서관 ISBN 서지정보, 국내 도서·목차), `KAKAO_REST_KEY`(카카오 책 검색, 수입 원서 보완). 하나만 있어도 동작한다.
- **운영자 안내문**
  1. 국립중앙도서관(nl.go.kr) 회원가입 → ISBN 서지정보 Open API 사용 신청 → 승인(1~2 영업일) 후 인증키 확인.
  2. 카카오 디벨로퍼스에서 앱을 만들고 REST API 키 확인(책 검색은 별도 심사 없음).
  3. Supabase → Edge Functions → Secrets에 등록한다. 키 값은 채팅·문서에 쓰지 않는다.
- **끝났는지 확인하는 방법**: 라이브러리 [라이브러리 추가]에서 교재명 하나와 ISBN 하나를 찾아 결과·표지가 나온다. 키가 없으면 검색만 안 되고 [라이브러리 열기]·[직접 추가]는 동작한다.
- `ALADIN_TTB_KEY`는 등록하지 않는다(알라딘 OpenAPI 2026-10-30 종료, 코드에서 읽지 않음).
- 키 없이 쓰는 방법: [v2.7](v2.7-노션-작업.md) N-31 교보문고에서 가져오기. 키 발급이 번거로우면 이 항목은 보류한다.

## 항목 3. 수업 관리를 Supabase 복사본에서 읽기

- **유형**: 운영자 직접(함수 설정값)
- **선행 조건**: v2.6.2 뒤 매일 밤 대조가 한 번 지나 `sync_cursors`에 `cr_*` 4개가 있다.
- **필요한 Secret (이름만)**: `CLASS_ROOM_SOURCE`
- **왜**: 수업 관리가 Notion 대신 복사본을 읽어 화면이 빨라진다(반·날짜·수업 상세·캘린더·학습기록·반 요약). 저장은 지금처럼 Notion에 쓰고 복사본도 바로 맞춘다. 복사본에 없으면 그 요청만 Notion에서 읽는다.
- **운영자 안내문**
  1. `CLASS_ROOM_SOURCE` = `shadow`로 저장 → 하루 이상 평소처럼 쓴 뒤 `class-room` 함수 로그에서 `[class-room shadow]`를 찾아 "다름"이 없는지(또는 설명된 차이뿐인지) 본다.
  2. `CLASS_ROOM_SOURCE` = `copy`로 바꾼다. 화면이 이상하면 `notion`으로 되돌린다(즉시 원래대로).
- **확인**: `class_room.html?timing=1`에서 동작마다 `[복사본]` 표시, Notion 호출 0~1회.

## 항목 4. 서버에 남은 옛 함수 삭제

- **유형**: 운영자 직접
- **선행 조건**: v2.6.1 항목 6(자동화 정리)
- **운영자 안내문**: Supabase → Edge Functions에서 `sync-registration-timetable`, `sync-student-report`, `mark-report-source-dirty`, `sync-school-schedules`의 최근 7일 호출(Invocations)이 없는지 보고, 없으면 삭제한다. 호출이 있으면 지우지 말고 그 호출을 보낸 Notion 자동화를 찾는다. 하지 않아도 동작에는 영향이 없다.

## 항목 5. 지난 출석 등원 시각 채우기

- **유형**: 운영자 직접(실행 승인 후)
- **왜**: 학부모 리포트 일간 보고서의 "16:52 등원" 표시는 v2.6.2 뒤 출석이 다시 동기화될 때 채워진다. 지난 출석까지 한 번에 채우려면 출석 전체 대조를 한 번 돌린다.
- **방법**: 운영 GitHub → Actions → `Sync Attendance (daily reconcile)` 수동 실행. GitHub Secret `ADMIN_SECRET`(보안 모드면 웹훅 키와 같은 값)·`SUPABASE_PROJECT_ID`·`SUPABASE_ANON_KEY`가 있어야 한다. 없으면 이 항목은 보류한다(학생별 [학생 페이지 동기화]로도 그 학생은 채워진다).
- **확인**: 워크플로 성공, 리포트 일간 보고서 출석 칸 아래 등원 시각.
