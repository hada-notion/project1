# v2.5.51 — 코드·문서·매뉴얼 정합성 정리

- 날짜: 2026-10-12
- 이전 버전: v2.5.50
- 요약: 코드·GitHub 문서·Notion 매뉴얼을 서로 대조해 어긋난 곳을 고쳤다. 관리자 로그인 권한을 실제로 쓰는 범위로 줄이고, 쓰지 않는 함수 하나를 지우고, 화면만 바꾼 PR에도 자동 검사를 돌게 했다. 화면 이름은 "법정 서류"로 통일했다.
- 매뉴얼 영향: 있음 → 항목 6
- 변경 유형: Supabase 함수(공용 인증 모듈, 함수 1개 삭제), GitHub 워크플로, 웹 화면 문구, 문서. 마이그레이션·Secrets·Notion DB 변경 없음.

---

## 항목 1. 관리자 로그인 권한 축소

- **유형**: AI 자동
- **선행 조건**: 없음
- **대상 파일**: `supabase/functions/_shared/adminSecurity.ts`(+ `_test.ts`)
- **변경 내용**: 보안 모드에서 관리자 로그인(관리 화면 3개)으로 부를 수 있는 함수를 `list-students`, `kiosk-checkin`, `get-legal-document-data`, `school-api` 4개로 줄였다. `toggle-report-link`, `sync-school-calendar`는 Notion 버튼·자동화가 웹훅 키로만 부른다(웹훅 키 범위는 그대로). 브라우저에서 이 함수들을 부르는 화면은 없어 동작 변화는 없다. 보안 모드가 꺼진 운영은 영향 없음.
- **환경별 값**: 없음
- **검증**: 함수 배포 후 Notion "링크 재발급"·"학사일정 가져오기" 버튼이 그대로 동작하는지 하나씩 본다.

## 항목 2. 쓰지 않는 함수 정리 — `sync-school-schedules`

- **유형**: AI 자동(코드), 운영자 직접(서버 복사본 삭제, 선택)
- **선행 조건**: 없음
- **대상 파일**: 삭제 `supabase/functions/sync-school-schedules/`. 수정 `scripts/check-known-regressions.sh`(폐기 목록), `docs/학교-학사일정-연결.md`
- **변경 내용**: 정기 학사일정 수집을 폐지한 뒤(마이그레이션 `20261003030000`에서 예약 해제) 410만 돌려주던 함수다. 호출하는 화면·버튼·예약 실행이 없다. 회귀 가드가 이 이름이 다시 들어오면 실패한다.
- **운영자 안내문(서버 복사본 삭제, 선택)**
  - 왜 필요한가: 코드에서 지워도 서버에 예전 배포본이 남는다. 쓰지 않는 공개 주소를 줄이는 정리이며, 하지 않아도 동작에는 영향이 없다.
  - 어디서: Supabase 대시보드 → Edge Functions → `sync-school-schedules`
  - 무엇을: Invocations에서 기간을 최근 7일 이상으로 두고 호출이 없으면 삭제한다. 호출이 있으면 삭제하지 말고 배포 담당자에게 알린다.
  - 끝났는지 확인하는 방법: 함수 목록에 없다.

## 항목 3. 화면 이름 "법정 서류"

- **유형**: AI 자동
- **대상 파일**: `legal_documents.html`(제목), `admin_settings.html`·`admin_settings.js`(안내 문구), `README.md`, `LEGAL_DOCUMENTS.md`, `docs/새-학원-이식-체크리스트.md`
- **변경 내용**: "관리자 서류", "관리자 서류 출력", "법정 서류 출력"을 상단 메뉴와 같은 "법정 서류"로 통일했다. 파일 이름(`legal_documents.html`)과 기능은 그대로.
- **환경별 값 (중요)**: `attendance_kiosk.html`·`legal_documents.html`의 `SUPABASE_URL`·`SUPABASE_ANON_KEY`, `school_search.html`의 `ENDPOINT`는 **운영 값을 유지**한다.

## 항목 4. 자동 검사·워크플로

- **유형**: AI 자동
- **대상 파일**: 신규 `.github/workflows/web-checks.yml`. 이름 변경 `sync-attendance-incremental-cron.yml` → `sync-attendance-incremental.yml`, `sync-attendance-reconcile-cron.yml` → `sync-attendance-reconcile.yml`
- **변경 내용**: 함수 배포 워크플로는 `supabase/**` 변경에만 돌아서, 화면만 바꾼 PR에서는 관리자 설정 체크리스트↔서버 허용 목록 대조와 디자인 검사(공용 파일 `?v=` 버전 표시 누락 포함)가 돌지 않았다. `web-checks.yml`이 모든 PR과 `supabase/**` 밖의 main 푸시에서 디자인 규칙·체크리스트 대조 테스트·회귀 가드를 확인한다(배포 없음). 출석 동기화 워크플로는 v2.5.13부터 수동 실행 전용이라 파일명의 `-cron`을 뺐다(Actions 탭의 이름 "Sync Attendance (incremental/daily reconcile)"은 그대로).
