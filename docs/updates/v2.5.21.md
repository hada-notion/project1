# v2.5.21 — 쓰지 않는 웹훅 함수 정리

- 날짜: 2026-10-13
- 이전 버전: v2.5.20
- 요약: 호출하는 곳이 없는 웹훅 함수 3개(`sync-registration-timetable`, `sync-student-report`, `mark-report-source-dirty`)를 코드·서버 허용 목록·웹훅 체크리스트·기준 문서에서 지웠다. 체크리스트는 41개에서 40개가 되고, 항목에는 실제 호출 기록이 있을 때만 "새 키 호출 확인"·"이전 키 호출 있음"을 표시한다("교체 후 호출 기록 없음" 문구 삭제). 폐기한 이름이 다시 들어오면 회귀 가드가 배포를 막는다.
- 매뉴얼 영향: 있음 → 항목 4 참고

---

## 항목 1. 이 웹훅을 쓰는 Notion 자동화 확인 (먼저)

- **유형**: 운영자 직접
- **선행 조건**: 없음
- **변경 이유·증상**: 세 함수는 원본 템플릿에서 더 이상 호출하지 않는다. 운영 워크스페이스에 예전 자동화가 남아 있으면, 나중에 서버에서 함수를 지울 때 그 자동화가 실패한다.
  - `sync-registration-timetable`: 등록(학원) DB의 "클래스 연결"(속성 편집) 자동화가 부르던 함수. 시간표 연결은 "시간표 설정" 버튼, 종료일 이후 정리는 "종료 처리" 버튼, 수업·출석 생성은 "수업 생성" 버튼이 한다.
  - `mark-report-source-dirty`: v2.5.5에서 `학습정보 수정일` 기록용으로 안내했던 웹훅. 지금은 Notion 자체 자동화로 기록한다.
  - `sync-student-report`: 호출하는 화면·버튼이 없다.
- **운영자 안내문**
  - 왜 필요한가: 지워진 함수를 부르는 자동화가 남아 있지 않게 하기 위해서다.
  - 어디서: Notion 등록(학원) DB 등 각 DB 오른쪽 위 번개 모양(자동화) 목록.
  - 무엇을:
    1. 웹훅 주소가 `/sync-registration-timetable`로 끝나는 자동화(보통 이름 "클래스 연결")가 있으면 끈다(또는 삭제).
    2. 웹훅 주소가 `/mark-report-source-dirty`로 끝나는 자동화가 있으면, 같은 트리거로 "속성 편집 → `학습정보 수정일` = 현재 시각(트리거 시각)"을 하는 Notion 자체 자동화로 바꾼다. `학습정보 수정일` 자체는 트리거 속성에서 뺀다(무한 루프 방지).
    3. `/sync-student-report`를 부르는 버튼·자동화가 있으면 끈다.
  - 입력할 값의 이름: 없음
  - 끝났는지 확인하는 방법: 각 DB 자동화 목록에 위 세 주소가 없다.
  - 흔한 오류와 대처: 찾지 못하면 그대로 진행해도 된다. 코드 반영(항목 2)만으로는 이미 배포된 함수가 서버에서 지워지지 않아 기존 자동화가 바로 깨지지 않는다.

## 항목 2. 코드 반영

- **유형**: AI 자동
- **선행 조건**: 항목 1 확인
- **대상 파일**
  - 삭제: `supabase/functions/sync-registration-timetable/`, `supabase/functions/sync-student-report/`, `supabase/functions/mark-report-source-dirty/`, `supabase/functions/_shared/registrationTimetableTarget.ts`
  - 수정: `supabase/functions/_shared/adminSecurity.ts`(`SECURITY_WEBHOOK_ROUTES`·`SECURITY_BROWSER_ROUTES`에서 세 함수 제거), `supabase/functions/status-watchdog/index.ts`(등록 DB "시간표 상태" 감시 항목 제거), 다른 함수 주석의 언급 정리
  - 수정: `admin_settings.js`(체크리스트 "클래스 연결" 항목 제거, `OUTSIDE_NOTION`은 `sync-attendance`만, 호출 기록 없을 때 문구 숨김), `admin_settings.html`(자동화 예시 문구)
  - 수정: `docs/버튼-웹훅-매핑.md`, `docs/새-학원-이식-체크리스트.md`(수정일 기록은 Notion 자체 자동화)
  - 수정: `scripts/check-known-regressions.sh`(18번: 폐기한 함수 이름이 코드·현재 문서에 다시 들어오면 실패. `docs/updates`와 `CHANGELOG.md`는 이력이라 제외)
- **환경별 값**: 없음
- **필요한 Secret**: 없음
- **Notion 변경**: 없음(항목 1은 운영자 확인)
- **마이그레이션 / 재배포**: 마이그레이션 없음. `main` 반영 시 함수 자동 재배포(`admin-security`를 포함해 `adminSecurity.ts`를 쓰는 함수, `status-watchdog`). 배포 명령은 남은 함수를 올리기만 하고 지운 함수를 서버에서 삭제하지 않는다.
- **검증**:
  1. 전체 함수 `deno check`, Deno 테스트(체크리스트 함수 = 서버 웹훅 허용 목록), 회귀 가드, SQL 테스트 통과.
  2. 관리자 설정 → 웹훅 키 교체 현황: 등록 카드 8개 항목, "클래스 연결"·"호출 기록 없음" 없음, 전체 40개.
- **실패 시 대처**: 이전 버전 파일로 되돌린다. 데이터 영향 없음.

## 항목 3. 서버에 남은 옛 함수 삭제 (선택)

- **유형**: 운영자 직접
- **선행 조건**: 항목 1·2 완료
- **운영자 안내문**
  - 왜 필요한가: 코드에서 지워도 서버에는 예전에 배포된 함수가 남아 있다. 쓰지 않는 공개 주소를 줄이기 위한 정리이며, 하지 않아도 동작에는 영향이 없다.
  - 어디서: Supabase 대시보드 → Edge Functions
  - 무엇을:
    1. `sync-registration-timetable`, `sync-student-report`, `mark-report-source-dirty`의 최근 호출(Invocations/Logs)이 없는지 본다.
    2. 호출이 없으면 각 함수를 삭제한다. 호출이 있으면 삭제하지 않고 항목 1로 돌아가 호출한 자동화를 찾는다.
  - 끝났는지 확인하는 방법: 함수 목록에 세 함수가 없다.

## 항목 4. 매뉴얼·Notion 문서

- **유형**: AI 자동(운영 소유자 승인 범위에서)
- **변경 내용**: Notion "버튼 → Edge Function 웹훅 매핑" 요약표에서 `sync-registration-timetable`을 지우고, "배포 후 버튼·자동화 설정 및 점검 가이드"의 시간표 설정 항목에서 이 함수에 대한 메모를 지운다. 등록 DB "시간표 상태"·"시간표 처리 시작 시각" 속성은 더 이상 쓰지 않는다. 지울 때는 수식·보기에서 쓰는지 먼저 확인하고 운영자가 직접 지운다.
