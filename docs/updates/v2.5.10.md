# v2.5.10 — 출석 생성·편집 개별 웹훅 제거

- 날짜: 2026-10-08
- 이전 버전: v2.5.9
- 변경 유형: 코드·매뉴얼
- 요약: 출석 DB의 생성·편집마다 호출하던 개별 동기화 경로를 폐기합니다. 예약 동기화·발송 전 최신화는 유지합니다.
- 기준 저장소·브랜치·커밋: `hada-notion/project1`, `main`, `91e224113c405f8838c51ebf31fd2c22f534c8d5`.
- 환경별 주소·ID·Secrets 변경, 마이그레이션, 업무 데이터 생성·삭제·대량 변경 없음.

## 항목 1. 기존 개별 웹훅 연결 제거

- **유형:** 운영자 직접(해당 자동화가 남아 있는 운영만).
- **선행 조건:** 운영 소유자의 전체 계획 승인. 기준 코드·현재 배포·예약 실행 경로 확인.
- **운영자 안내문:** 출석(학원) DB → 자동화에서 생성·편집 시 `sync-attendance`를 호출하는 액션이 있는지 확인합니다. 이 액션만 제거합니다. 없다면 추가 작업 없이 ‘해당 없음’으로 기록합니다. 수정일 기록 자동화, 학습기록 생성·보고서 전송·삭제 버튼과 다른 웹훅은 유지합니다. 이름만 보고 자동화 전체를 지우지 않습니다. 웹훅과 수정일 기록이 같은 자동화에 있으면 웹훅 액션만 제거합니다.
- **완료 확인:** 출석 생성·편집 시 `sync-attendance` 개별 호출이 없고 기존 수정일 기록은 유지됨을 확인합니다. 자동화 원문을 AI가 조회하지 못하면 운영자의 확인과 직접 조회 여부를 구분해 기록합니다.

## 항목 3. Notion 매뉴얼 갱신

- **유형:** AI 자동. 운영의 역할·제목으로 대상 페이지를 찾습니다. 원본 페이지 URL이나 환경별 DB ID를 복제하지 않습니다.
- **버튼 → Edge Function 웹훅 매핑:** 다음 출석 행을 치환합니다.

찾을 원문:

```
| 출석(학원) | 학습기록 생성, 보고서 전송, 삭제, (자동)레코드 생성/편집 | <code>create-learning-record</code>, <code>send-daily-report</code>, <code>cascade-delete</code>, <code>sync-attendance</code> |
```

바꿀 원문:

```
| 출석(학원) | 학습기록 생성, 보고서 전송, 삭제 | <code>create-learning-record</code>, <code>send-daily-report</code>, <code>cascade-delete</code> |
```

기존 삭제 버튼 공용 안내 직전에 다음 문단을 추가합니다. 이미 동일 문단이 있으면 중복 삽입하지 않습니다. 해당 안내가 없으면 추정 위치에 넣지 않고 차이를 보고합니다.

```
출석 생성·편집 시 <code>sync-attendance</code> 개별 웹훅은 연결하지 않습니다. 출석 원자료는 매시간 증분 동기화와 보고서 발송 전 등록 단위 최신화로 반영합니다. 매일 전체 정합성 점검은 출석 원자료의 삭제분까지 대조합니다. 마지막 수정일을 기록하는 기존 자동화와 학습기록 생성·보고서 전송·삭제 버튼은 유지합니다. 발송 없이 수정한 내용은 다음 증분 동기화까지 학부모 페이지에 늦게 반영될 수 있습니다.
```

- **시스템 운영(큐·예약 실행·문제 해결) / 14. 예약 실행:** 예약 실행 표는 유지하고 설명 문단을 치환합니다.

찾을 원문:

```
위 5개 모두 해당 버튼/자동화가 적재된 직후 한 번씩 즉시 깨우는 트리거(지연 축소용)를 함께 가지고 있고, 표의 주기는 그 즉시 트리거가 실패·유실되거나 처리 자체가 중단됐을 때를 위한 안전망입니다. GitHub Actions 2건은 이 저장소의 <code>.github/workflows</code>에서, Supabase pg\_cron 3건은 <code>supabase/migrations</code>의 <code>cron.schedule</code>로 관리됩니다 — 예약 실행이 안 되는 것 같으면 GitHub Actions의 "Actions" 탭과 Supabase의 <code>cron.job</code>을 각각 확인합니다.
```

바꿀 원문:

```
출석 증분 동기화와 전체 정합성 점검은 GitHub Actions의 정기 실행입니다. 출석 DB의 생성·편집 시 <code>sync-attendance</code> 개별 웹훅은 사용하지 않습니다. 증분 동기화는 Notion 페이지의 마지막 편집 시각(<code>last_edited_time</code>)으로 수정분을 찾아 출석 원자료와 영향받은 보고서 캐시를 갱신합니다. DB에서 별도로 기록하는 수정일 속성이 이 조회 필터를 대신하지는 않습니다. 전체 정합성 점검은 삭제분까지 출석 원자료만 반영하며 보고서 캐시 전체를 재계산하지 않습니다.

보고서 발송 전에는 해당 등록의 출석 원자료와 보고서 캐시를 다시 최신화하며, 최신화 실패 시 발송하지 않습니다. 발송 없이 수정한 내용은 다음 증분 동기화까지 반영이 지연될 수 있고, 예약 실행 지연·실패 시 더 오래 남을 수 있습니다.

GitHub Actions 2건은 이 저장소의 <code>.github/workflows</code>에서, Supabase pg\_cron 3건은 <code>supabase/migrations</code>의 <code>cron.schedule</code>로 관리됩니다. 즉시 트리거 유무는 작업별로 다르므로 위 5개에 동일한 즉시 트리거가 있다고 가정하지 않습니다. 예약 실행이 안 되는 것 같으면 GitHub Actions의 "Actions" 탭과 Supabase의 <code>cron.job</code>을 각각 확인합니다.
```

## 검증·완료 판정

1. 신규 15개 테스트: 예전 pageId/Notion payload·누락/미지원 mode·비정상 JSON은 400이며 네트워크 부작용 없음. 두 mode의 미인증/잘못된 키는 401. 증분 필터·페이지네이션·커서 안전 여유·등록별 캐시 호출, reconcile 삭제·커서, 원자료 쓰기 실패 시 후속 삭제/커서 이동 없음, OPTIONS 유지.
2. 기존 61개 테스트·함수 41개 타입 검사·회귀 가드 통과. 모의 네트워크로 실행하며 실제 출석·알림톡을 임의로 생성/발송하지 않습니다. 신규 증분 테스트의 캐시 확인은 토큰 없는 모의 등록에 대한 호출 확인이며, 완성된 실제 학부모 캐시 생성 테스트는 아닙니다.
3. CI·배포 결과와 변경 파일의 원문 일치를 확인합니다. CI 성공·함수 목록 확인과 배포 함수 소스 직접 비교를 구분합니다.
4. 허용된 테스트 환경에서 출석 수정 후 증분 반영·삭제 후 reconcile·발송 전 최신화를 확인합니다. 실데이터 쓰기나 실발송 승인이 없으면 해당 항목은 미검증으로 기록합니다. 예약 워크플로는 HTTP 오류를 job 성공과 구분해 확인합니다.
5. 실패 시 영향을 받는 작업을 중단합니다. 기준 커밋의 대상 함수로 되돌려 재배포하고, 개별 웹훅 재연결 여부는 운영 소유자와 확인합니다. 본 패치는 업무 데이터를 바꾸지 않으며 코드 롤백을 데이터 복구로 표현하지 않습니다.
6. 원본 배포 완료는 다른 학원 운영 적용 완료가 아닙니다. 운영 AI는 실제 적용·미검증 범위를 `docs/operation-update-history.md`에 기록합니다. 필수 항목 완료 후 버전 기록을 갱신합니다.
