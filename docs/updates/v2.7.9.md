- 날짜: 2026-10-19
- 이전 버전: v2.7.8
- 요약: 정규 수업이 없는 날 키오스크로 등원·하원하면 출석을 새로 만드는데, 출석 `클래스`가 `등록`을 거친 롤업인 학원(원본 기준)에서는 이 출석 생성이 거절될 수 있었다. 클래스를 넣어 만들다가 `클래스` 때문에 거절되면 클래스 없이 다시 만든다(롤업이 등록에서 채운다). 출석 `클래스`를 직접 관계로 둔 학원은 예전처럼 클래스를 넣는다.
- 매뉴얼 영향: 없음
- 변경 유형: 코드(Edge Function 1개). 마이그레이션·Secrets·Notion 변경 없음. 업무 데이터는 바꾸지 않는다.

## 항목 1. kiosk-checkin 보강 방문 출석 생성

- **유형**: AI 자동
- **선행 조건**: 없음
- **변경 이유·증상**: 원본 출석(학원) DB의 `클래스`는 롤업인데, 보강 방문 출석을 만들 때 `클래스`에 관계 값을 넣어 Notion이 요청을 거절할 수 있다. 원본에는 이 경로로 만든 출석이 아직 없어 실제 실패는 확인하지 않았다(코드 검토로 발견).
- **대상 코드**
  - `supabase/functions/_shared/kioskPolicy.ts`: `walkInAttendanceProperties`, `isClassPropertyError` 추가
  - `supabase/functions/kiosk-checkin/index.ts`: 정규 수업이 없는 날 출석을 새로 만드는 부분
  - 찾을 원문 (앵커):

    ```
    if (classIds.length) properties["클래스"] = { relation: classIds.map((id) => ({ id })) }
    ```

- **변경 내용**: 원본 `main`의 세 파일(`kioskPolicy.ts`, `kioskPolicy_test.ts`, `kiosk-checkin/index.ts`)로 바꾼다. 클래스를 넣어 만든 뒤, `클래스` 때문에 400으로 거절되면 클래스 없이 한 번 더 만든다. 다른 오류는 예전처럼 그대로 실패로 처리한다.
- **환경별 값**: 없음
- **필요한 Secret (이름만)**: 없음
- **Notion 변경**: 없음
- **마이그레이션 / 재배포**: 마이그레이션 없음. `kiosk-checkin` 재배포(원본 `main` 병합 시 자동 배포 워크플로가 함께 배포).
- **검증**:
  1. `deno test --allow-env supabase/functions/_shared/kioskPolicy_test.ts` 통과.
  2. 정규 수업이 없는 날 테스트 학생으로 키오스크 등원 → 출석이 `🔵 보강`으로 생기고, 출석 `클래스`가 롤업이면 등록의 클래스가, 직접 관계면 넣은 클래스가 보이는지 확인(운영 실사용 때).
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌려 재배포한다. 업무 데이터는 바뀌지 않는다.
- **매뉴얼**: 변경 없음
