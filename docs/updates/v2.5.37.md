# v2.5.37 — 키오스크 "오늘 출석 준비"(새벽 자동 준비)

- 날짜: 2026-10-12
- 이전 버전: v2.5.36
- 요약: 매일 04:00(KST)에 오늘 수강 중인 등록과 오늘 출석 페이지를 Notion에서 한 번에 읽어 Supabase 표에 저장한다. 키오스크 등원·하원은 이 표로 Notion 조회(DB ID, 등록·학생 확인, 오늘 출석 찾기)를 건너뛰고 바로 기록한다. v2.5.35 측정에서 이 조회가 약 2.1~2.3초였다. 새벽 준비가 없으면 키오스크를 열 때 서버가 뒤에서 자동으로 준비하고, 키오스크 아래에 "오늘 출석 준비 HH:mm"을 연하게 표시한다. 표에 없거나 기록이 실패하면 예전 방식으로 처리한다.
- 매뉴얼 영향: 없음(키오스크 아래 준비 시각 표시만 추가)
- 변경 유형: 마이그레이션 1개(표 2개 + 예약 실행), Supabase 함수(신규 `kiosk-prepare`, 수정 `kiosk-checkin`·`list-students`), 공용 모듈, 웹 화면. Secrets·Notion 변경 없음.

---

## 항목 1. 표와 새벽 예약 실행

- **유형**: AI 자동
- **선행 조건**: v2.5.36 적용. Vault `sync_queue_admin_key`가 있어야 한다(다른 예약 실행과 같음).
- **대상 파일**: 신규 `supabase/migrations/20261013030000_kiosk_today.sql`
- **변경 내용**
  - `public.kiosk_today`: 오늘 등록별 행(등록 ID, 날짜, 학생 이름, 클래스 ID, **전화번호 해시**, 오늘 출석 페이지 ID, 출석 상태, 등원·하원 시각).
  - `public.kiosk_prepared`: 한 줄(오늘 날짜, 준비 시각, 준비 방식 cron/auto, 학생·출석 DB ID, 행 수).
  - 두 표 모두 RLS를 켜고 anon·authenticated 권한을 없앤다(서버 함수만 읽고 씀).
  - pg_cron `kiosk-prepare-daily`: 매일 19:00 UTC(= 04:00 KST)에 `kiosk-prepare`를 내부 키로 호출.
- **환경별 값 (중요)**: 마이그레이션의 예약 실행 URL `https://twczhsxybkcvjkdfdxvs.supabase.co/functions/v1/kiosk-prepare`는 **원본 주소**다. 운영 적용 전 `scripts/setup-new-academy.py`의 URL 치환(이 파일이 대상 목록에 추가됨)을 다시 실행하거나 직접 그 학원 프로젝트 주소로 바꾼 뒤 원문 비교로 확인한다.
- **개인정보**: 전화번호는 원문이 아니라 SHA-256 해시로만 저장한다. 오늘 것만 남고 다음 준비 때 지난 날짜 행은 지워진다. 학부모 리포트 원자료(`attendance_records`, `report_cache`)와는 별개다.

## 항목 2. 함수와 화면

- **유형**: AI 자동
- **선행 조건**: 항목 1(마이그레이션이 먼저 적용돼야 한다. 배포 워크플로는 마이그레이션 → 함수 순서로 진행한다)
- **대상 파일**: 신규 `supabase/functions/_shared/kioskToday.ts`(+ `_test.ts`), `supabase/functions/kiosk-prepare/index.ts`. 수정 `supabase/functions/kiosk-checkin/index.ts`, `supabase/functions/list-students/index.ts`, `attendance_kiosk.html`, `.github/workflows/deploy-supabase-functions.yml`(테스트 추가)
- **변경 내용**
  - `kiosk-prepare`: 오늘 준비를 만든다(내부 키 필요).
  - `list-students?kiosk=1`: 응답에 `kioskPrepared`(준비 시각, 오늘 준비 여부, 준비 중 여부). 오늘 준비가 없으면 방금 읽은 목록으로 응답 뒤에 자동 준비한다.
  - `kiosk-checkin`: 오늘 준비 행이 있고 날짜·전화번호 해시가 맞으면 Notion 조회 없이 그 출석 페이지에 바로 기록하고 행의 시각을 맞춘다(같은 날 두 번 처리 방지). 이미 기록돼 있으면 "이미 처리"로 응답. 행이 없거나 출석 페이지가 없거나(보강 생성) 기록이 실패하면 예전 방식으로 처리한다. 예전 방식도 준비된 DB ID를 쓰고, 클래스 페이지는 보강 출석을 만들 때만 읽는다.
  - 키오스크: 학원 이름 아래 "오늘 출석 준비 HH:mm"(연한 회색). 준비 중이면 "오늘 출석 준비 중"이고 30초 뒤 한 번 다시 확인한다.
- **환경별 값 (중요)**: `attendance_kiosk.html`의 `SUPABASE_URL`·`SUPABASE_ANON_KEY`는 **운영 값을 유지**한다.
- **검증**:
  1. 배포 후 키오스크를 새로고침해 아래 표시를 본다(처음엔 "오늘 출석 준비 중" → 30초 뒤 시각).
  2. 등원·하원을 처리하고 함수 로그 `kiosk-checkin timing`에서 `cache`, `attendance_write`만 있고 `db_ids`·`verify`·`attendance_find`가 없는지(빠른 경로), `total`이 1초 안팎인지 본다.
  3. 다음 날 아침 키오스크 아래 시각이 04:00 무렵인지 본다(새벽 예약 실행 확인).
- **실패 시 대처**: 함수를 이전 버전으로 되돌리면 표는 쓰이지 않는다(그대로 둬도 무방). 예약 실행만 멈추려면 `select cron.unschedule('kiosk-prepare-daily');`.
