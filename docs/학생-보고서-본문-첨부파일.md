# 학생 보고서 본문·첨부파일

학습기록의 공통 자료와 학습활동의 학생별 결과를 학부모 리포트에서 표시하고, PDF·일반 파일을 열거나 내려받는 기능의 유지보수 안내입니다. 운영자·학부모 사용 안내는 Notion 메뉴얼을 기준으로 합니다.

## 1. 지원 범위와 표시 기준

본문의 설명, 이미지, 동영상과 Notion `pdf`·`file` 블록을 표시합니다. 일반 파일에는 HWP·DOCX·XLSX·PPTX·ZIP 등을 첨부할 수 있지만, 모든 형식을 브라우저에서 미리 보는 기능은 아닙니다. 기기에 별도 앱이 필요할 수 있습니다.

| 구분 | 학습기록 본문 (`sourceBody`) | 학생별 학습활동 본문 (`activityBody`) |
| --- | --- | --- |
| 학습 | 수업 자료 | 학습 결과 |
| 과제 | 출제 내용 | 제출 내용 |
| 평가 | 평가 문항 | 풀이·답안 |

공통 자료와 학생별 자료를 합치거나 바꾸지 않습니다. 본문의 모든 Notion 블록·임베드 형식이 지원된다고 가정하지 말고, PDF와 일반 파일은 해당 블록으로 첨부해 테스트합니다.

## 2. 운영 흐름

1. 공통 수업자료·과제지·평가 문항은 학습기록 본문에 넣습니다.
2. 학생별 결과·제출물·풀이와 답안은 학생 관계를 확인한 학습활동 본문에 넣습니다.
3. 해당 등록의 **학생 페이지 동기화**(`sync-report-cache`)를 실행합니다. 공통 자료를 수정했다면 연결된 등록들의 캐시도 갱신합니다.
4. 리포트의 학습기록 카드를 펼쳐 올바른 영역과 파일을 확인합니다.
5. PDF는 **PDF 열기·인쇄**, 일반 파일은 **파일 열기·다운로드** 버튼으로 엽니다.

본문이나 첨부파일을 추가·수정·삭제하면 캐시를 다시 동기화해야 합니다. Notion 속성 편집 자동화가 본문 변경까지 항상 감지한다고 가정하지 않습니다. 이전 캐시에는 새 파일의 `blockId`가 없을 수 있습니다.

PDF 버튼은 인쇄 명령을 즉시 실행하는 기능이 아닙니다. 열린 브라우저/PDF 뷰어의 인쇄·다운로드 기능을 사용합니다. 모바일은 뷰어 메뉴나 공유 메뉴에서 인쇄하고, 지원되지 않으면 내려받아 컴퓨터에서 인쇄합니다.

## 3. 관련 코드

| 파일 | 역할 |
| --- | --- |
| `supabase/functions/_shared/reportCacheBuilder.ts` | 본문 수집 및 `pdf`·`file` 블록의 캐시 변환 |
| `supabase/functions/_shared/notionClient.ts` | `getBlock(blockId)`로 최신 블록 조회 |
| `supabase/functions/get-report-file/index.ts` | 토큰·캐시 포함 여부 검증 후 최신 파일 URL 반환 |
| `student_report_part1.js` | 본문 정규화·파일 카드·클릭 처리 (`normalizeFeedBody`, `buildFeedFileHtml`, `openReportFile`) |
| `student_report.html` | `.feed-file-*` 첨부파일 카드 스타일 |
| `scripts/check-known-regressions.sh` | PDF·파일 수집, `blockId`, 파일 API 연결 등의 회귀 가드 |

파일 캐시 데이터는 `type`, `blockId`, `url`, `name`, `caption`을 사용합니다. **`blockId`를 제거하지 않습니다.** Notion 업로드 파일의 캐시 URL은 만료될 수 있으므로 영구 다운로드 주소로 취급하지 않습니다.

## 4. 파일 API

`POST https://<학원 Supabase 프로젝트 ref>.supabase.co/functions/v1/get-report-file`

```json
{
  "token": "<학생 보고서 토큰>",
  "blockId": "<해당 보고서 캐시에 포함된 파일 블록 ID>"
}
```

처리 순서:

1. 토큰과 블록 ID를 확인합니다.
2. `selectReportCacheByToken`으로 보고서 캐시를 조회합니다.
3. 요청 블록 ID가 해당 캐시의 `registration_detail` 안에 포함되는지 검사합니다.
4. `getBlock`으로 Notion 블록을 다시 읽습니다.
5. `pdf`·`file` 블록만 허용합니다.
6. Notion 업로드 파일은 최신 `file.url`, 외부 파일은 `external.url`을 반환합니다.

성공 응답:

```json
{
  "url": "<파일 URL>",
  "name": "<파일명 또는 기본 이름>",
  "type": "pdf"
}
```

`type`은 `pdf` 또는 `file`입니다. 응답에 `Cache-Control: no-store`를 사용합니다.

| 상태 | 의미 |
| --- | --- |
| `400` | 토큰/블록 ID 누락 또는 지원하지 않는 블록 |
| `403` | 요청 블록이 해당 보고서 캐시에 없음 |
| `404` | 유효하지 않은 보고서 토큰 또는 파일 URL 없음 |
| `405` | POST가 아닌 요청 (CORS OPTIONS 제외) |
| `500` | Notion 조회 등 처리 실패 |

Notion 업로드 파일 URL 갱신은 클릭 시점에 이뤄집니다. 외부 파일은 원본 서비스의 접근 권한·만료·삭제 정책을 따르므로 갱신 가능한 Notion 업로드 URL과 동일하게 보장하지 않습니다.

## 5. 보안·공유 범위

- 파일 API는 Notion 버튼/자동화가 아니라 리포트 웹앱에서 호출합니다. [버튼·웹훅 매핑](버튼-웹훅-매핑.md)의 웹앱 호출 목록을 참고하세요.
- 파일 API 요청의 토큰은 POST body로 전달합니다. 파일 URL에 보고서 토큰을 덧붙이지 않습니다.
- 브라우저에 `ADMIN_SECRET`, Notion 토큰, service-role 키를 넣지 않습니다. 전용 새 Secret을 추가하는 기능이 아니라 기존 서버 측 Notion 연결·보고서 캐시를 사용합니다.
- 토큰 확인, 캐시 내 블록 포함 검사, `pdf`·`file` 타입 검사를 생략하지 않습니다. 임의의 Notion 블록 ID를 열어주는 API로 변경하지 않습니다.
- 공통 학습기록은 연결된 여러 학생에게 표시될 수 있습니다. 다른 학생의 개인정보·제출물·내부 메모를 넣지 않습니다.
- 개인 리포트 링크를 가진 사람은 해당 자료를 다운로드할 수 있습니다. 링크는 해당 학생 보호자에게만 전달합니다.
- 이미 발급된 파일 URL이나 이미 다운로드한 사본까지 링크 비활성화로 즉시 회수된다고 안내하지 않습니다. 캐시 갱신 전에는 삭제·이동된 자료의 캐시 정보가 남을 수 있으므로 민감 자료는 처음부터 첨부하지 않습니다.

## 6. 배포·검증 체크리스트

기능 도입 기준 커밋: `4dbef936ebfa26fc4054e11987795b8ff3f66ccb`. 현재 동작은 최신 코드와 실제 배포 환경을 기준으로 확인합니다. 아래는 테스트할 항목이며, 모든 항목이 이미 검증됐다는 뜻은 아닙니다.

- [ ] 학습기록과 학습활동 각각에 설명·이미지·동영상·PDF·일반 파일이 올바르게 표시됨
- [ ] 학습·과제·평가의 공통/개별 영역 구분이 유지됨
- [ ] 여러 파일의 순서, 파일명, 설명이 표시됨
- [ ] 본문 추가·수정·삭제 후 동기화하면 변경이 반영됨
- [ ] PDF가 열리고 뷰어에서 다운로드·인쇄 가능
- [ ] 일반 파일이 열리거나 다운로드되며 미지원 형식은 별도 앱으로 확인 가능
- [ ] 업로드 파일 URL 유효시간 경과 후 클릭해도 최신 URL 발급으로 열림
- [ ] 유효하지 않은 토큰은 `404`
- [ ] 다른 보고서 캐시에만 포함된 파일 블록은 `403`
- [ ] 해당 캐시에 포함된 지원하지 않는 블록은 `400`
- [ ] 모바일·데스크톱·시크릿 모드·팝업 차단 환경과 파일 오류 안내 확인
- [ ] 브라우저 코드에 관리자 키·Notion 토큰·service-role 키가 없음
- [ ] 기존 이미지·동영상 렌더링에 회귀 없음
- [ ] `scripts/check-known-regressions.sh` 통과

새 고객 환경에서는 [새 학원 이식 체크리스트](새-학원-이식-체크리스트.md)와 함께 확인합니다.

## 7. 문제 해결

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 파일 카드가 없음 | PDF/파일 블록 첨부 여부, 학생 관계, 해당 등록 캐시 동기화 |
| 파일 API가 `403` | 요청 `blockId`가 현재 토큰의 캐시에 포함돼 있는지, 오래된 캐시인지 |
| 파일 API가 `404` | 보고서 토큰 유효성, 파일 URL 존재 여부 |
| 파일 열기 실패 | 팝업 차단, 파일 지원 앱, 외부 파일 권한, Notion 파일 삭제·접근 권한 |
| 새 학원에서만 실패 | `get-report-file` 배포, 프런트 Supabase 주소, 기존 서버 Secrets·Notion 공유 설정 |

오류 보고 시 실제 토큰·서명 파일 URL·연동 키를 공개 문서나 이슈에 붙이지 않습니다. 오류 상태, 발생 시간, 개인정보를 제거한 재현 절차를 전달합니다.
