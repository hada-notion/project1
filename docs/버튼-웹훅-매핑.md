# Notion 버튼/자동화 → Supabase Edge Function 매핑표

이 문서는 Notion DB의 버튼·체크박스·자동화가 어떤 Supabase Edge Function 웹훅을 호출하는지
정리한 표입니다. **새 학원(고객)에 이 시스템을 이식하면서 Notion 자동화를 다시 연결할 때** 참고하세요.

이 표는 실제 `supabase/functions/*/index.ts` 코드 상단 주석을 근거로 작성했습니다
(추측이 아닌 코드 확인). 다만 Notion 쪽 자동화 이름/조건은 학원마다 약간 다를 수 있으니,
새로 연결한 뒤에는 반드시 테스트해보세요.

## 공통 규칙

- 버튼·자동화·상태 속성 이름은 [이름 규칙](이름-규칙.md)을 따른다. 자동화는 `[웹훅]`·`[생성]`·`[편집]`으로 시작한다.

- 대부분의 함수는 `x-admin-key` 헤더로 인증합니다. Notion 버튼의 "웹훅 보내기" 액션이 커스텀 헤더를
  못 보내는 경우가 있어, 많은 함수가 요청 바디의 `adminKey` 필드도 함께 확인합니다
  (`resolveAdminKeyFromRequest`). 자동화를 새로 만들 때 헤더가 안 먹히면 바디에 `adminKey` 필드를
  고정값으로 추가하세요.
- 엔드포인트 주소는 모두 `https://<이 학원의 Supabase 프로젝트 ref>.supabase.co/functions/v1/<함수명>` 형태입니다.
- pageId가 필요한 함수는 보통 자동화의 "웹훅 보내기" 본문 편집기에서 현재 페이지 ID를 넣어야 합니다.

## Notion 자동화 원칙과 확인된 동작

- **Notion으로 할 수 있는 자동화는 Notion으로 끝낸다.** Notion 자체 자동화(속성 편집, 다른 DB 페이지 추가·편집)는 API 한도에 잡히지 않는다.
- **일괄 작업은 개별 작업 여러 번으로 나눈다.** 일괄 버튼은 대상 페이지들의 상태만 `⚪ 대기`로 바꾸고, 각 페이지 자동화가 개별 웹훅을 보낸다. 서버는 웹훅 본문에 실려 온 값(계획·정보 수식)을 쓰고 다시 조회하지 않는다. 개별 웹훅은 `sync_queue`에 쌓여 워커가 차례로 처리하므로 Notion 호출 속도를 넘지 않는다.

원본에서 시험해 확인한 Notion 동작(2026-10-17 기준):

- API로 만든 페이지에도 "페이지 추가됨" 자동화가 돈다(커넥터로 만든 수업·출석·학습기록 제목이 이름 자동화로 바뀜, v2.6.31 시험).
- 버튼 편집과 API 편집은 자동화를 부른다. **자동화가 바꾼 편집은 다른 자동화를 부르지 않는다**(v2.6.17·v2.6.18). 그래서 자동화가 만든 페이지의 제목은 그 자동화가 직접 넣는다(v2.6.30 성적 이름).
- 버튼·자동화의 "다른 DB 페이지 편집"이 변수(수식으로 고른 페이지 목록)로 여러 페이지를 바꾸고, 바뀐 페이지마다 그 DB 자동화가 돈다(v2.6.24·v2.6.27·v2.6.28·v2.6.30).
- 자동화 "속성 편집·페이지 추가"에서 관계 값을 수식으로 정할 수 있다(v2.6.28 발송함, v2.6.30 시험정보).
- 웹훅 본문에 수식 값을 실을 수 있다(`학습활동 계획`·`학습기록 계획`·`담기 계획`·`출석 조정 정보`). 롤업 값은 미확인.
- 반대쪽 속성으로 "이 페이지 포함" 필터를 하려면 관계가 양방향이어야 한다(v2.6.21 수업 진도교재 탭).
- 관계 속성 트리거에는 "비어 있지 않음" 조건을 고를 수 없다 → 그 조건으로 거른 **보기에 자동화를 건다**(v2.6.30 학생 `응시 등록`).
- 상태 값을 ⚪ 대기로 바꿔 자동화를 부르는 방식은, 자동화가 끝에 ✅ 완료로 바꾸지 않으면 다음에 같은 값으로 바꿔도 돌지 않는다(v2.6.28).
- Notion API(커넥터)로는 다른 DB를 거치는 수식·롤업 속성을 만들 수 없다("Type error") → 그런 수식은 운영자가 화면에서 넣는다.
- 페이지 읽기와 DB 조회 모두 관계를 25개까지만 주고 `has_more`로 표시한다(v2.6.32에서 고쳐 쓰는 곳은 끝까지 읽음).
- (미확인) 자동화 필터에서 트리거 페이지의 클래스를 쓸 수 있는지
- (미확인) 웹훅 본문의 관계 목록도 25개에서 잘리는지(25명 넘는 클래스로)
- 진도교재 `등록`과 등록 `진도교재`는 하나의 양방향 관계다(2026-10-19 원본 스캔).

## 인증 구분 (v2.5.12 보안 모드)

`ADMIN_SECURITY_ENABLED=true`인 운영에서는 같은 `x-admin-key`(또는 body `adminKey`) 자리에 들어온 값을 종류별로 나눠 호출 범위를 제한합니다. 보안 모드가 꺼진 운영은 기존처럼 `ADMIN_SECRET` 하나로 모든 함수를 인증합니다. 켜는 방법은 [v2.6.5 지침](updates/v2.6.5.md) 항목 1 참고.

| 구분 | 키가 있는 곳 | 호출할 수 있는 함수 |
| --- | --- | --- |
| 웹훅 키 | 첫 설정 때 Edge Function Secrets `WEBHOOK_SECRET`(없으면 `ADMIN_SECRET`)으로 정해지고, 교체 후에는 관리자 설정에서 만든 키. Notion 버튼·자동화 헤더/본문에 입력 | 이 문서 §1~§16의 Notion 웹훅 함수와 `sync-attendance`, `sync-school-calendar`. 코드의 `SECURITY_WEBHOOK_ROUTES` |
| 관리자 세션 | 관리자 설정·법정 서류·학교 검색(12시간, 같은 탭에서 공유)과 수업 관리(12시간, 그 기기)에 관리자 비밀번호로 로그인한 브라우저 | 관리 화면이 실제로 부르는 `list-students`, `kiosk-checkin`, `get-legal-document-data`, `school-api`, `class-room`만(v2.5.51에서 Notion 전용 함수는 뺌). 코드의 `SECURITY_BROWSER_ROUTES`. `admin-security`는 로그인 자체라 별도 |
| 키오스크 세션 | 출결 키오스크에서 관리자 비밀번호로 로그인한 브라우저(관리자 비밀번호를 바꿀 때까지 유지, v2.5.82) | `kiosk-checkin`, `list-students?kiosk=1`만 |
| 내부 키 | 서버 DB와 Vault `sync_queue_admin_key`. 비밀번호를 바꿀 때 함께 자동 교체, 사람이 입력하지 않음 | 전부. pg_cron과 함수 간 내부 호출(`process-sync-queue`, `status-watchdog`, `sync-failure-audit`, `backfill-assignment-deadlines`, `kiosk-prepare`, 체이닝) |
| 인증 없음 | — | `get-report-fast`, `get-report-detail`, `get-report-file`(보고서 토큰으로 검증), `sync-report-cache` 키 없는 경로(학생 리포트 화면은 그 등록의 보고서 토큰을 함께 보내야 하고, 라이브러리·일정 자동화는 그 페이지만 갱신. 키 없이 등록 페이지를 지정하면 401, v2.7.19), `admin-security`(로그인 자체) |

- 관리자 비밀번호를 바꿔도 웹훅 키는 바뀌지 않으므로 Notion 버튼·자동화 헤더는 고치지 않습니다.
- 웹훅 키는 유출이 의심될 때만 관리자 설정의 "웹훅 키 교체"로 바꿉니다(v2.5.14). 교체 기간에는 이전 키·새 키가 모두 동작하고, 관리자 설정의 웹훅 체크리스트가 DB별로 버튼·자동화를 나열하고, 각 DB의 "웹훅 등록" 보기로 바로 이동하는 링크와 항목별 체크를 제공합니다. 버튼 위치가 더 필요하면 이 문서의 표를 봅니다. **새 웹훅 함수나 버튼을 추가하면 `admin_settings.js`의 `CHECKLIST`(DB별 버튼·자동화 목록)에도 넣어야 합니다**(테스트가 서버 허용 목록과 대조). 교체 후에는 서버 DB가 웹훅 키의 기준이며 Secrets의 `ADMIN_SECRET`은 고치지 않아도 됩니다.
- 초기 비밀번호 `0000` 상태에서는 관리자·키오스크 세션이 어떤 업무 함수도 호출하지 못합니다. 웹훅과 내부 호출은 그대로 동작합니다.
- 함수 이름은 요청 주소 맨 앞(`/functions/v1/<함수명>`)으로 판정합니다. 하위 경로(`sync-registration-textbook/create-class` 등)는 상위 함수 이름으로 봅니다.
- **새 웹훅 함수를 추가하면** `supabase/functions/_shared/adminSecurity.ts`의 `SECURITY_WEBHOOK_ROUTES`에도 넣어야 합니다. 빠뜨리면 보안 모드 운영에서 그 버튼만 401이 납니다.
- 수동 실행하는 출석 동기화 워크플로(`sync-attendance-incremental.yml`, `sync-attendance-reconcile.yml`)의 GitHub Secret `ADMIN_SECRET`은 웹훅 키와 같아야 합니다.

## 기록 기준 (v2.7)

- **학습기록은 수업 기준**: 만들기·날짜·삭제의 기준이 수업이다(수업 [학습기록 생성]). 학습기록의 `출석`·`등록` 관계는 "누구에게 해당하는지"(그룹 진도는 출석 전원, 개별 진도는 그 학생)를 나타낸다.
- **학습활동은 출석 기준**: 학생 한 명·출석 한 건의 결과(과제 제출·점수·메모). 과제 마감도 출석을 가리킨다.
- 두 관계(수업·출석)는 서버가 함께 맞춘다(학습기록 생성·출석 조정·삭제/종료 처리). 손으로 따로 고치지 않는다.

## §9. "삭제" 버튼 공용 — cascade-delete

아래 7개 DB는 같은 구조입니다. **"삭제" 버튼은 "삭제 체크"를 체크만 하고, 웹훅은 "삭제 체크"가 체크됨일 때 실행되는 자동화가 `cascade-delete`로 보냅니다.** 웹훅 키는 이 자동화에 있습니다. (v2.7) 서버는 누른 페이지 하나에서 하위 페이지까지 큐에서 한 번에 처리합니다(하위 삭제 또는 공용·그룹 진도 기록의 관계 해제). 하위 페이지에는 "삭제 체크"를 켜지 않고 상태 표시 없이 휴지통으로 보내므로, 하위마다 자동화 웹훅이 다시 오지 않습니다. 진행 상태는 누른 페이지의 "삭제 상태"로 봅니다.
DB별로 "삭제 상태" select 속성을 각자 독립적으로 관리하므로, 자동화 설정 시 어떤 DB/페이지인지
식별할 수 있는 값(페이지 ID 등)을 웹훅 본문에 포함해야 합니다.

## 17. Notion 자동화가 아닌 것들 (참고)

아래는 Notion 버튼/자동화가 아니라 웹앱(GitHub Pages)이나 예약 실행(cron)이 직접 호출합니다.
Notion 자동화 재연결 작업 범위에서 제외하세요.

- `sync-attendance` — v2.5.13부터 정기 예약 실행은 해제. 필요할 때만 GitHub Actions에서 `Sync Attendance (incremental)`(`mode: "incremental"`) 또는 `Sync Attendance (daily reconcile)`(`mode: "reconcile"`)을 수동 실행. 두 모드 모두 `x-admin-key` 필요하며, 수동 실행 시 GitHub Secret `ADMIN_SECRET`이 서버의 유효 키(보안 모드에서는 고정 웹훅 키)와 같아야 함. `pageId` 개별 웹훅 요청은 지원하지 않습니다. 증분은 영향받은 보고서 캐시도 갱신하고, 전체 정합성 점검은 출석 원자료만 반영합니다.

- `get-report-fast`, `get-report-detail` — 학부모 리포트 웹앱(`student_report.html`)이 호출
- `get-legal-document-data` — 법정 서류 화면(`legal_documents.html`)이 호출(관리자 로그인)
- `school-api` — 학교 검색 화면(`school_search.html`)이 호출(관리자 로그인)
- `admin-security` — 관리자 설정·로그인 공용(`admin_settings.html`, `admin_auth.js`)
- `get-report-file` — 학부모 리포트에서 PDF·일반 파일 버튼을 누를 때 호출. `POST` body: `{ token, blockId }`. 보고서 토큰과 해당 캐시 내 블록 포함 여부를 검증한 뒤 최신 Notion 파일 URL을 반환. Notion 버튼/자동화 연결이나 브라우저의 관리자 키는 필요하지 않음. [본문·첨부파일 개발 문서](학생-보고서-본문-첨부파일.md) 참고
- `kiosk-checkin`, `list-students?kiosk=1` — 출결 키오스크 웹앱(`attendance_kiosk.html`)이 호출. 오늘 출석 준비·체크 방식·알림톡 응답 뒤 발송은 [키오스크 처리 흐름](키오스크-처리-흐름.md) 참고
- `process-sync-queue`(매분), `status-watchdog`(15분), `sync-failure-audit`(30분), `backfill-assignment-deadlines`(10분), `kiosk-prepare`(매일 04:00 KST) — pg_cron/내부 체이닝이 호출
