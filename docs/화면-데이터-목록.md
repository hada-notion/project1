# 화면 → 데이터 목록 (수업 관리)

수업 관리(`class_room.html`) 화면마다 서버 함수 `class-room`의 어떤 동작을 부르고, 그 동작이 Notion에서 무엇을 읽는지 정리한다. 속도 개선(Supabase 복사본)의 범위를 정하고, "화면에 보이지 않는 정보는 서버도 읽지 않는다"는 원칙으로 불필요한 읽기를 찾는 데 쓴다.

- 기준 코드: `class_room.js`(화면), `supabase/functions/_shared/classRoom.ts`(서버)
- 읽기 방식 표기: **질의** = Notion DB 검색(`queryAllPages`, 100개씩 여러 번일 수 있음) / **낱장** = 페이지 하나씩 읽기(`getPages`, 동시 6개, 페이지 수만큼 호출) / **본문** = 페이지 본문 블록 읽기(`readPageBodyBlocks`, 페이지마다 1회 이상)
- 실제 호출 수·시간은 0단계 측정(`class_room.html?timing=1`)으로 채운다.

## 1. 화면 → 동작

| 화면 | 열 때 부르는 동작 | 다시 부르는 때 |
| --- | --- | --- |
| 첫 화면(강사·클래스·통합 시간표) | `teachers`, `classes`, `day` | 강사 바꾸기, 새로고침 |
| 반 상세 열기(모든 탭 공통) | `session` + `class-sessions`(동시), 날짜가 바뀌면 `day` | 같은 반 다른 수업으로 이동할 때마다 |
| 홈 탭 | (`session` 결과) + `books`(교재 진도) | |
| 교재 탭·교재 상세 | `books`, 교재 상세는 `class-records` | |
| 캘린더 탭 | (`class-sessions` 결과), 다른 달로 가면 `class-sessions(around)` | 날짜를 누르면 `session` |
| 캘린더 날짜 [학습 기록] | `class-records`(마감 과제 카드 보강) | |
| 학습기록 탭 | `class-records` | 기록을 만들거나 고치면 다시 |
| 학생 탭 | `roster`, `class-stats` | |
| 기록 화면 | `activities`, `books` | 저장 후 `activities`, `session` |
| 저장·만들기 | `save-attendance`, `save-activities`, `create-records`, `update-record`, `create-activities`, `create-makeup-session`, `delete-makeup-session` | 저장 뒤 보통 `session`을 다시 읽음 |

화면이 부르지 않는 서버 동작: `days`, `student`, `unlink-makeup` — 지금 화면에서 쓰지 않는다(정리 후보).

## 2. 동작 → Notion 읽기

| 동작 | Notion 읽기 | 화면에서 쓰는 것 |
| --- | --- | --- |
| `teachers` | 강사 DB 질의 1 | 이름·역할 |
| `day` | 수업 질의(그날·강사) + 출석 질의(그날 전체) + 클래스 낱장 | 그날 수업 목록, 등원 수, 보강 대기 |
| `classes` | 수업 질의(앞뒤 4주) + 클래스 낱장 | 반 카드(오늘·다음·지난 수업), 주간 시간표 |
| `session` | 수업 낱장 1 + 출석 낱장(학생 수만큼) + 그날 마감 과제 학습활동·학습기록 낱장 + 이 수업 학습기록 낱장 + 학습활동 질의(과제·평가 기록) + **기록마다 본문** + 교재 이름 낱장 + 클래스 낱장 | 학생 출석·등원·하원·메모, 마감 과제 제출, 이 수업 기록 카드 |
| `class-sessions` | 수업 낱장 1 + 같은 반 수업 질의(9주 전~5주 뒤) + 출석 질의 + 학습기록 질의 + 과제 학습활동 질의 | 달력 칸 색(출석·과제 비율), 막대·칩 |
| `class-records` | 수업 낱장 1 + 같은 반 수업 질의 + 학습기록 질의 + 교재 이름 낱장 + 학습활동 질의 + **최근 20개 기록 본문** | 반 학습기록 타임라인 |
| `class-stats` | 수업 낱장 1 + 같은 반 수업 질의 + 출석 질의 + 학습기록 질의 + 학습활동 질의 | 반 요약 3칸, 평가 추이, 학생별 출석률·점수 |
| `roster` | 수업 낱장 1 + 출석 낱장 + 등록 낱장 + 원생 낱장 | 이름·학교·학년·연락처·보고서 링크 |
| `books` | 수업 낱장 1 + 등록 낱장 + 진도교재 낱장 + 정규교재 낱장 | 교재 카드(표지·제목·진도·최근 범위) |
| `activities` | 학습기록 낱장 1 + 학습활동 낱장 + 출석 낱장 | 기록 화면 입력칸, 학습활동 목록 |

## 3. 지금 보이는 낭비 (측정 전 추정)

1. **같은 반 수업 질의를 동작마다 다시 한다.** 반 상세를 열면 `class-sessions`, 이어서 학습기록 탭 `class-records`, 학생 탭 `class-stats`가 각각 같은 "같은 반 앞뒤 수업" 질의와 출석·학습기록·학습활동 질의를 반복한다.
2. **낱장 읽기가 많다.** `session`은 학생 수·기록 수·교재 수만큼 페이지를 하나씩 읽는다(동시 6개). 학생 15명 반이면 출석만 15회.
3. **본문 읽기가 무겁다.** `session`(이 수업 기록 전부)과 `class-records`(최근 20개)가 기록마다 본문 블록을 읽는다. 본문은 카드를 펼칠 때만 보인다.
4. **같은 수업 페이지를 동작마다 다시 읽는다**(수업 낱장 1이 거의 모든 동작에 있음).
5. **화면이 쓰지 않는 서버 동작**(`days`, `student`, `unlink-makeup`)이 남아 있다.

## 4. 복사본 후보 (측정 결과로 순서 결정)

| Notion DB | 복사본에서 꼭 필요한 항목(화면 기준) | 바뀌는 곳 |
| --- | --- | --- |
| 수업 | 수업일시, 클래스, 강사, 보강, 출석 관계, 학습기록 관계 | 수업 생성(generate-classes), 보강 만들기·삭제 |
| 출석 | 수업, 등록, 출석 상태, 등원·하원 스탬프, 메모, 선생님 한마디 | 키오스크, 수업 관리 저장, Notion 직접 수정 |
| 학습기록 | 수업, 구분, 교재·진도교재, 주제, 범위, 내용, 단원, 보강 | 기록 만들기·고치기, Notion 직접 수정 |
| 학습활동 | 학습기록, 출석, 과제상태, 과제 마감일, 정답·전체 문항 | 학습활동 만들기, 제출·점수 저장 |
| 교재(진도교재·정규교재) | 이름, 표지, 쪽수, 진도, 최근 범위 | 교재 배정·진도 기록 |
| 본문 | 기록 본문 블록(펼칠 때만) | 펼칠 때 따로 읽기로 바꾸는 것도 방법 |

- 이미 Supabase에 쌓이는 것: 출석 행(`attendance_records`, 등원·하원 포함 — 학부모 리포트 캐시용). 수업 관리 출석 읽기에 바로 쓸 수 있는지 확인할 것.
