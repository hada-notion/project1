# 보고서 최신화 구조

이 문서는 현재 운영 코드 기준의 **설명서**다. 변경 이력은 `docs/archive/2026-09-report-sync-history.md`에서 관리한다.

## 1. 기준 데이터와 결과물

- Notion 원본: 출석, 학습기록, 학습활동, 보고서, 등록
- Supabase 원자료: `attendance_records`
- Supabase 완성 캐시: `report_cache`
- 학부모 화면: `student_report.html`이 토큰으로 `report_cache`를 조회한다.

보고서가 최신이라는 뜻은 Notion 원본을 읽어 `attendance_records`와 `report_cache`를 다시 반영한 뒤 학부모 링크에서 같은 값이 보인다는 뜻이다.

## 2. 현재 실제 최신화 경로

### 등록 페이지의 수동 동기화

`sync-report-cache`가 등록 페이지에서 실행되면 다음 순서로 처리한다.

1. 학생 리포트 토큰을 보장한다.
2. 해당 등록의 출석을 `attendance_records`에 전체 반영한다.
3. 출석·학습기록·학습활동·보고서를 읽어 `report_cache`를 다시 만든다.
4. Notion 등록 페이지 버튼으로 실행한 경우, 같은 그룹 학습기록 또는 학습활동을 공유하는 다른 등록도 찾아 **한 명씩 순차적으로** 캐시를 갱신한다.
5. 웹앱의 새로고침은 선택한 등록의 완료 응답을 기다린 뒤 화면을 다시 읽는다.

공유 원본을 쓰는 학생들의 캐시 누락을 막기 위해 현재 경로는 선택적 dirty 갱신보다 **완전 재조립과 공유 학생 전파**를 우선한다.

### 보고서 발송 직전

일일·주간·월간 보고서 발송 함수는 전송 직전에 같은 공용 최신화 경로를 실행한다. 최신화가 실패하면 오래된 캐시로 발송하지 않고 전송을 중단해야 한다.

### 예약 작업

- 매시간 15분: 출석 증분 동기화
- 매일 01:00 KST: 출석 전체 정합성 점검과 삭제분 반영
- 매일 01:30 KST: 당일 발송 보고서 동기화 감사

예약 작업은 안전망이다. 수동 동기화와 발송 직전 최신화가 최종 정확성을 보장한다.

## 3. 원본 변경 표시 속성

출석·학습기록·학습활동·보고서 DB에는 다음 세 속성을 유지한다.

| 속성 | 역할 |
| --- | --- |
| `학습정보 수정일` | 보고서에 영향을 주는 원본 편집 시각 |
| `마지막 동기화` | 해당 원본 버전을 성공적으로 반영한 기준 시각 |
| `동기화 필요` | 두 시각을 비교해 미반영 후보를 표시하는 수식 |

`mark-report-source-dirty` 웹훅은 편집된 페이지의 `학습정보 수정일`만 현재 시각으로 기록한다. 자동화 트리거에서 `학습정보 수정일`, `마지막 동기화`, `동기화 필요` 자체는 제외해 재귀 호출을 막아야 한다.

이 세 속성과 `report_source_sync_state` 테이블, `_shared/reportDirtySync.ts`는 원본 후보와 지문을 추적하는 기반이므로 삭제하지 않는다.

단, 현재 `refreshStudentReport`의 활성 경로는 공유 학습 원본 누락을 막기 위해 dirty 후보만 골라 처리하지 않고 전체 출석 반영과 완성 캐시 재조립을 수행한다. 따라서 `동기화 필요=false`만으로 학부모 화면 최신화를 판정하지 말고 `report_cache` 갱신과 실제 링크 표시까지 확인한다.

## 4. 의미 있는 변경과 내부 변경

지문 추적에서 보고서 내용과 무관한 내부 변경은 제외한다.

- 출석의 등원·하원 스탬프
- 출석의 담당강사 관계

학습활동 제목은 보고서 표시에 영향을 줄 수 있으므로 지문 대상에 포함한다.

## 5. 운영 확인 순서

1. Notion 원본 값과 등록 관계를 확인한다.
2. 수동 동기화 또는 발송 직전 최신화가 오류 없이 끝났는지 확인한다.
3. `attendance_records`에서 해당 등록의 출석이 최신인지 확인한다.
4. `report_cache`의 갱신 시각과 데이터 내용을 확인한다.
5. 학부모 토큰 링크에서 실제 표시를 확인한다.
6. 그룹 공통 학습기록을 수정했다면 같은 원본을 공유하는 다른 학생 링크도 확인한다.

## 6. 변경 시 주의사항

- `mark-report-source-dirty`와 세 동기화 속성을 `sync-attendance` 실시간 웹훅과 혼동하지 않는다.
- 실시간 `sync-attendance` Notion 웹훅은 없어도 예약 작업과 발송 직전 최신화가 동작하지만, 원본 변경 표시 웹훅은 별도의 역할을 가진다.
- 선택적 dirty 갱신을 다시 활성화할 때는 공유 학습기록·학습활동의 모든 등록으로 fan-out하는 로직을 먼저 결합해야 한다.
- 202 응답은 접수일 뿐 완료가 아니다. 최종 캐시와 화면을 확인한다.
- 세 속성이나 웹훅을 제거하기 전에 코드 import, Notion 자동화, Supabase 배포본을 함께 확인한다.
