# 학교 검색·학사일정 연결

## 동작
- 학교 DB의 **학교 검색** 수식 링크에서 `school_search.html?pageId=<학교 페이지 ID>`를 엽니다.
- 관리자 키 확인 → Notion 대상 학교 페이지 선택 → 학교명/주소 검색 → 학교 선택.
- Edge Function이 학교 DB 소속과 나이스 원본을 검증하고 교육청 코드/학교 코드/주소/홈페이지/학교 구분만 저장합니다. 기존 이름과 학생 관계는 그대로 둡니다.
- 연결 시 동기화 체크는 꺼진 상태입니다. 테스트와 운영 스케줄 활성화 이후 운영자가 체크합니다.
- 수집 시 행사 종류 필터를 사용하지 않습니다. **전체 학사일정**은 모두 표시하고 **운영 학사일정**은 숨김 체크·공휴일·토요휴업일을 제외합니다. 뷰 필터는 운영자가 변경할 수 있습니다.
- 이번 달부터 3개월을 학교별·월별로 수집하며 한 번에 6개 원본 행을 처리합니다. 실패한 청크는 재개합니다.

## 서버 설정
기존 `SB_URL`, `SB_SERVICE_ROLE_KEY`, `NOTION_TOKEN`, `ADMIN_SECRET`, `DATA_SOURCE_SCHEDULE_EVENT_ID`를 재사용합니다. 학교/학년 데이터소스는 일정 데이터소스의 관계 속성에서 조회하므로 따로 하드코딩하지 않습니다.

추가 Secret: **NEIS_API_KEY**. [나이스 인증키 신청](https://open.neis.go.kr/portal/myPage/actKeyPage.do?tabIdx=1)에서 발급받아 Supabase → Edge Functions → Secrets에 저장합니다. 채팅/노션/HTML/저장소에 기록하지 않습니다. 인증키 없는 5건 샘플 응답은 운영 동기화에 사용하지 않습니다.

HTML의 공개 Supabase URL은 새 학원 이식 시 교체합니다. 키는 HTML/URL/브라우저 저장소에 포함하지 않으며 사용자 입력을 메모리에서만 사용합니다. 페이지 ID는 접근 권한이 아닙니다. 모든 서버 요청은 기존 관리자 인증을 검증합니다.

## 배포 및 시험
1. main 반영 후 기존 GitHub Actions가 신규 테이블 마이그레이션과 함수 배포를 수행합니다. GitHub Pages 배포도 확인합니다.
2. Secrets 설정 후 `school-api` action `meta`와 `search`를 관리자 인증으로 테스트합니다.
3. 실제 운영 학교 페이지에서 주소를 확인하여 연결합니다. 예제 학교 페이지를 다른 학교로 덮어쓰지 않습니다.
4. 테스트 학교만 ‘학사일정 동기화’를 체크한 뒤 `sync-school-schedules`에 `{ "action": "enqueue" }`를 POST, 다음으로 `{ "action": "process" }`를 반복 POST합니다. 모든 요청은 `x-admin-key` 헤더로 인증합니다.
5. `neis_school_jobs`의 done/failed와 snapshot/row_cursor/last_error를 확인합니다. HTTP 200 한 번을 전체 완료로 보지 않습니다.
6. 재실행 시 중복이 없는지, ‘숨김’과 ‘메모’를 수동 수정한 후 재실행해 그대로 보존되는지 확인합니다.
7. 검증 후 아래 SQL로 자동 실행을 켭니다. 활성화 전에 Vault의 프로젝트 URL과 관리자 키가 맞는지 확인합니다.

## 자동 실행 활성화 (수동 SQL)
`neis_project_url`은 현재 Supabase 프로젝트의 공개 URL로 Vault에 설정합니다. 기존 `sync_queue_admin_key` Vault 값을 인증에 사용합니다. 비밀값을 출력하지 마세요.

```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;
-- 공개 URL만 저장. 새 학원은 자신의 URL을 사용.
select vault.create_secret('https://twczhsxybkcvjkdfdxvs.supabase.co', 'neis_project_url');
-- 매일 02:00 KST = 전날 17:00 UTC. 조회 대상 작업을 적재.
select cron.schedule('neis-schools-daily-enqueue', '0 17 * * *', $job$
 select net.http_post(
   url := (select decrypted_secret from vault.decrypted_secrets where name='neis_project_url' limit 1) || '/functions/v1/sync-school-schedules',
   headers := jsonb_build_object('Content-Type','application/json','x-admin-key',(select decrypted_secret from vault.decrypted_secrets where name='sync_queue_admin_key' limit 1)),
   body := '{"action":"enqueue"}'::jsonb
 );
$job$);
-- 대기 중인 청크 처리. 대기가 없으면 조회만 하고 종료.
select cron.schedule('neis-schools-process', '* * * * *', $job$
 select net.http_post(
   url := (select decrypted_secret from vault.decrypted_secrets where name='neis_project_url' limit 1) || '/functions/v1/sync-school-schedules',
   headers := jsonb_build_object('Content-Type','application/json','x-admin-key',(select decrypted_secret from vault.decrypted_secrets where name='sync_queue_admin_key' limit 1)),
   body := '{"action":"process"}'::jsonb
 );
$job$);
```

## 소유권·안전 정책
- 자동 수정: 행사명/날짜/학교/학년/대상 학년/수업공제일명/원본 행사내용/NEIS 동기화키.
- 수정하지 않음: 숨김/메모/태그/진행상태/담당자/사용자가 작성한 본문/수동 일정.
- 나이스의 행사 고유 ID가 공개되지 않아 자연키에 학교·학사일자·행사명·대상 학년·과정이 포함됩니다. **행사명·날짜·대상 학년 변경은 새 일정으로 처리하고 기존 일정은 남깁니다.** 원본에서 빠진 일정은 자동 삭제하지 않습니다. 운영자가 숨김 처리합니다. 원본 행사내용 변경은 같은 키의 일정을 갱신합니다.
- Notion 생성 응답 유실 시 blind retry하지 않습니다. 다음 처리에서 NEIS 동기화키를 재조회해 복구합니다.
- 처리 RPC는 SKIP LOCKED/15분 임대/토큰 조건 갱신을 사용합니다. 실패는 최대 5회 후 failed. 다음 일일 적재 때 다시 시도합니다.
- 원본 JSON과 수정일자는 작업 snapshot에 보존합니다. 장기 보관/오래된 작업 정리는 자동으로 하지 않습니다.
- 학년 관계는 학교 종류와 학년 이름으로 매칭합니다. 불일치 학년은 텍스트 ‘대상 학년’에 남으며, 중복 학년은 오류로 중단합니다.

## 현재 활성화 상태
이 변경은 코드와 Notion 구조 준비입니다. **인증키 설정·호스팅 환경 테스트·Cron 활성화 전에는 자동 수집이 시작되지 않습니다.**
