# Notion 기준 적용 절차

어느 학원, 어느 시점에서 시작하든 **같은 순서로 작업해 원본과 같은 모양**을 만든다. 버전 번호에 따라 순서를 바꾸지 않는다. 버전 지침(`docs/updates/`)은 무엇이 바뀌었는지 알리는 이력이고, 작업 순서의 기준은 이 문서다.

## 1. 기준 두 가지

| 기준 | 위치 | 공개 | 쓰는 사람 |
| --- | --- | --- | --- |
| 전체 명세(속성·수식 원문·버튼·자동화·DB 보기·페이지 레이아웃) | 원본 Notion "Notion 기준 명세" 페이지의 첨부 파일 | 비공개 | 원본 지원 |
| 지문(항목별 해시) | [노션-지문.json](노션-지문.json) | 공개 | 운영 AI·원장님·원본 지원 |

- 원본 Notion 자체가 기준을 구현한 학원이다. 원본을 바꾸면 다시 스캔해 명세와 지문을 함께 새로 만든다.
- 지문으로는 **무엇이 다른지**만 알 수 있다. 내용은 공개 패치 문서나 원본 요청으로 받는다.
- 서버(Supabase 함수·마이그레이션)는 원본 GitHub `main`이 기준이다.

## 2. 고정 순서

모든 작업은 아래 다섯 단계를 이 순서로 한다. 앞 단계를 건너뛰지 않는다.

1. **스캔**: 대상 학원 Notion을 [스캔 도구](#4-스캔과-비교)로 읽는다. 시스템 정보의 버전은 참고만 한다.
2. **비교**: 스캔을 기준과 비교해 차이 목록을 만든다(같음 / 다름 / 없음 / 이름 다름 / 추가).
3. **적용**: 차이가 있는 항목만, 아래 "적용 순서"대로 고친다.
4. **재스캔**: 다시 스캔·비교해 고친 항목이 "같음"인지 확인한다. 버튼·자동화를 고쳤으면 테스트 건으로 한 번씩 눌러 본다.
5. **기록**: 시스템 정보에 `기준 일치: <지문 스캔 시각>`과 남은 차이(보류·학원 고유)를 남긴다.

### 적용 순서 (의존하는 것부터)

| 순서 | 대상 | 누가 |
| --- | --- | --- |
| 1 | 서버: 원본 `main`의 함수·마이그레이션 | 운영 AI(배포 승인 후) |
| 2 | DB와 관계 속성 | 운영 AI(커넥터) |
| 3 | 일반 속성(선택지 포함) | 운영 AI(커넥터) |
| 4 | 상태 속성(`○○ 상태`·시작 시각) | 운영 AI(커넥터) |
| 5 | 수식: 다른 수식이 참조하는 것부터 | 운영 AI(커넥터). 다른 DB를 거치는 수식·롤업은 커넥터로 만들 수 없어 원장님(화면) |
| 6 | 버튼·자동화 | 원장님(화면) |
| 7 | DB 보기 | 운영 AI(커넥터) |
| 8 | 페이지 레이아웃: 헤더 고정 속성·패널 섹션과 표시 방식·첫 탭 내용 | 운영 AI(커넥터 `page_layout`) |
| 9 | 페이지 탭(연결 보기)의 이름·필터·표시 속성 | 원장님(화면) |
| 10 | 매뉴얼 문장 | 운영 AI |

서버를 먼저 맞추는 이유: 원본 서버는 예전 속성 이름도 읽게 되어 있어서, Notion을 고치는 동안 버튼이 멈추지 않는다.

### 차이별 규칙

| 결과 | 할 일 |
| --- | --- |
| 다름·없음 + 공개 패치 문서에 있음 | 패치 문서의 "바꿀 원문"으로 그 항목을 최종 모양으로 맞춘다 |
| 다름·없음 + 공개 패치에 없음 | 비교 도구가 찍은 "원본 요청 문구"를 원본에 보낸다 |
| 이름 다름 | 운영 이름을 원본 이름으로 바꾼다([이름 규칙](../이름-규칙.md)의 예전 이름 표 확인) |
| 추가 | 지우지 않는다. 학원 고유 항목으로 기록한다 |

- 업무 데이터(학생·등록·출석 등 행)는 바꾸지 않는다. 데이터 정리가 필요하면 따로 보고하고 승인받는다.
- 한 단계에서 실패하면 그 자리에서 멈추고, 마지막으로 성공한 단계와 오류를 기록한다.

## 3. 원본 요청 흐름

1. 운영: 비교 결과의 "원본 요청 문구"를 그대로 보낸다(학원 이름, 지문 스캔 시각, 항목, 원본·운영 지문).
2. 원본: `python -I scripts/notion-extract.py <비공개 노션-명세.json> <요청 문구 파일>`로 해당 항목만 뽑아 확인한 뒤 전달한다.
3. 운영: 적용하고 재스캔해 그 항목이 "같음"인지 확인한다.
4. 여러 학원에서 같은 요청이 반복되면 원본은 그 항목을 다음 패치 문서에 넣어 공개한다.

## 4. 스캔과 비교

### 스캔 (브라우저, 읽기 전용)

1. Chrome에서 대상 학원 Notion의 **공개 DB** 페이지를 연다(데스크톱 앱이 열리면 "브라우저에서 계속").
2. `F12` → Console. 붙여 넣기가 막히면 안내대로 `allow pasting`을 입력한다.
3. GitHub의 [`scripts/notion-scan.js`](../../scripts/notion-scan.js) 내용을 전부 붙여 넣고 Enter.
4. `hada-scan.json`이 내려받아진다. Chrome이 "여러 파일 다운로드"를 물으면 허용한다.

스캔 도구는 Notion 화면이 쓰는 읽기 요청만 보낸다. 웹훅 헤더 값은 읽지 않고, 서버 주소는 `<HOST>`로 바꾼다.

### 비교

```bash
python -I scripts/notion-diff.py hada-scan.json
```

기본 기준은 공개 지문이다. 원본 지원은 두 번째 인자로 비공개 `노션-명세.json`을 넣으면 같은 결과를 내고, 내용까지 확인할 수 있다.

### 원본 기준 갱신 (원본 전용)

1. 원본 공개 DB 페이지에서 스캔한다.
2. `python -I scripts/notion-spec.py hada-scan.json .local/스캔/명세` → `노션-명세.json`·`노션-명세.md`·`노션-지문.json`이 생긴다. 전체 명세는 `docs/` 아래에 만들 수 없게 막혀 있다.
3. `노션-지문.json`만 `docs/기준/`에 복사해 커밋한다.
4. `노션-명세.*`는 원본 Notion "Notion 기준 명세" 페이지에 새로 올리고, 이전 파일은 "이전 명세"로 내린다.

## 5. 화면 작업 규칙 (버튼·자동화·레이아웃)

커넥터로 바꿀 수 없는 것(버튼·자동화, 다른 DB를 거치는 수식, 페이지 탭)은 Notion 화면에서 고친다. 원본 지원이 브라우저 도구로 작업할 때도 같다. 헤더·패널은 커넥터 `page_layout`이 더 정확하다(현재 레이아웃을 읽어 고친 뒤 통째로 넣는다).

- **DB마다 한 번에**: 비교 결과로 그 DB의 할 일을 먼저 다 정한 뒤 편집기를 한 번 열어 끝내고 저장한다. 저장 뒤 재스캔으로 확인한다.
- **레이아웃 편집기 열기**: 그 DB의 보기 설정(⚙) → 추가 설정 → "페이지 레이아웃 사용자 지정". 페이지가 열리지 않는 DB에서도 된다. 저장은 오른쪽 위 **[모든 페이지에 적용]**.
- **헤더 순서**: 원하는 순서가 아니면 해당 속성들의 고정을 풀고 원하는 순서대로 다시 고정한다(다시 고정하면 맨 끝에 붙는다). 끌어 옮기는 것보다 정확하다. 목록이 길면 속성 검색창을 쓴다.
- **패널 표시 방식**: 속성 묶음 ⋯ → 속성 오른쪽 눈 아이콘 → 항상 표시 / 비어 있으면 숨김 / 항상 숨김.
  - 버튼은 늘 "비어 있음"으로 취급되므로 "비어 있으면 숨김"이면 보이지 않는다. 버튼은 헤더에 고정하거나 패널에서 항상 표시.
  - 묶음 안의 "Add a property"는 **새 속성을 만든다**. 기존 속성을 넣을 때 누르지 않는다.
- **버튼·자동화 수식 읽기**: 속성 이름 → 속성 편집 → 자동화 편집 → 값 칸을 누르면 수식 편집이 열린다. 확인만 할 때는 Esc와 닫기(X)로 나오고 저장하지 않는다.
- **DB 보기**: 이름·보이는 열·정렬은 커넥터로 바꾼다. 보기 삭제만 화면에서 한다(보기 탭 우클릭 → 보기 삭제 → 보기 제거).
- **지우기 전에 조회**: 이름 없는 페이지처럼 정리 대상으로 보이는 것도 먼저 속성을 조회한다. 이름만 빈 실제 데이터일 수 있다.
- **큰 DB 열기**: 데스크톱 앱 안내 화면이 나오면 "브라우저에서 계속"(영어 화면이면 "continue in your browser")을 누르고, 빈 화면이면 다시 열어 최대 20초 기다린다.
- **확인은 화면이 아니라 데이터로**: 저장 뒤 화면 미리보기는 가로 스크롤로 일부만 보일 수 있다. 결과는 재스캔(또는 커넥터 page-layout)으로 확인한다.
