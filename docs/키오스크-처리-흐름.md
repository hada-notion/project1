# 키오스크 출결 처리 흐름 — v2.5.2

## 평소 사용

키오스크 로그인 시 학생 이름·클래스 표시명·현재 수강 등록 ID·정규화된 학생/보호자 연락처의 최소 목록을 받습니다. 목록은 화면 메모리에만 보관하며 새로고침·로그아웃 때 지웁니다. 기존 관리자 키 저장 방식은 변경하지 않았습니다. 학생 목록이나 연락처를 localStorage에 저장하지 않습니다.

전화번호를 입력하면 목록에서 등록을 찾습니다. 하나면 등록 ID와 전화번호·등원/하원 구분을 보내고, 둘 이상이면 학생/등록 선택 화면을 먼저 표시합니다. 서버는 전달된 ID를 그대로 믿지 않고 등록 DB 소속, 현재 수강 상태, 연결 학생 DB 소속 및 실제 연락처 일치를 다시 검증합니다. 정상 요청에서는 전체 학생 DB 조회가 없습니다.

## 목록 갱신·예외

- 목록은 출결 요청 시 5분 이상 오래됐으면 갱신합니다. 주기적인 타이머/폴링은 없습니다. 로그인과 화면 재접속 때도 목록을 받습니다.
- 번호가 목록에 없으면 최신 목록을 한 번 더 받습니다. 목록 조회 장애나 여전히 누락된 경우 전화번호만 보내는 기존 전체 조회 경로로 보완할 수 있습니다. 인증 실패는 재로그인합니다.
- 서버가 종료·삭제 등록, 연락처 변경 등으로 힌트를 거부하면 출결 변경 없이 409를 반환합니다. 화면은 목록을 갱신하고 새 후보를 다시 선택하도록 합니다. 자동으로 출결 쓰기를 재시도하지 않습니다.
- 캐시 유효기간 내 신규 형제/다중 등록 추가는 다음 갱신까지 선택 목록에 나타나지 않을 수 있습니다. 등록을 바꾼 직후에는 키오스크 화면을 새로고침하세요. 등록 상태·전화번호는 서버에서 매 요청 확인하지만 후보 전체의 실시간 최신성을 보증하는 구조는 아닙니다.

## 유지되는 동작

등원/하원 중복 스템프 방지, 보강 상태 유지, 오늘 출석 기록·생성, 기존 알림톡 수신 대상 및 전송로그 처리를 유지합니다. 알림톡을 백그라운드로 옮기지 않았으므로 발송과 Notion API 지연은 여전히 응답 시간에 영향을 줄 수 있습니다. 로그인/목록 갱신 단계의 전체 학생·수강 등록 조회도 남아 있습니다.

## 관리자 참고

- 최소 목록: 인증된 `GET list-students?kiosk=1` (`candidates`, `generatedAt`). 보고서 토큰·출석 이력은 반환하지 않으며 `Cache-Control: no-store`를 사용합니다.
- 기존 `GET list-students` 응답은 변경하지 않습니다.
- 출결: 기존 `POST kiosk-checkin`, `{ phone, type, registrationId? }`. 관리자 키 인증 유지. Notion 자동화 웹훅/버튼 재연결 및 DB 스키마 변경은 없습니다.
- 상세 적용 지침: [v2.5.2 업데이트](updates/v2.5.2.md).

## 등원·하원 전송내역 — v2.5.3

새 키오스크 알림톡 로그에는 `출결 구분`이 `등원` 또는 `하원`으로 기록됩니다. 출석 DB의 **전송 내역**은 최신 로그 기준으로 `등원 (MM.DD HH:mm)` / `하원 (MM.DD HH:mm)`을 표시합니다. 담당자를 학생/교사로 가짜 지정하지 않으며 사람 발송자의 기록은 그대로 보존합니다. 실패 시에는 `❌ 등원 실패 (시간) - 사유`처럼 실패 사실을 유지합니다. 시각은 기존 발송일시와 날짜 포맷을 그대로 사용합니다.

과거 로그에는 출결 구분이 없으므로 `등하원 (시간)`으로 표시합니다. 등원/하원을 현재 출석 스템프로 추측해 과거 로그에 덮어쓰지 않습니다. 실제 시간대 표시와 새 로그의 출결 구분 저장 여부는 실제 키오스크 화면/정상 발송에서 확인하세요. 상세 지침: [v2.5.3 업데이트](updates/v2.5.3.md).
