## 원칙

1. **Notion으로 할 수 있는 자동화는 Notion으로 끝낸다.** Notion 자체 자동화(속성 편집, 다른 DB 페이지 편집)는 API 한도에 잡히지 않는다.
2. **일괄 작업은 개별 작업 여러 번으로 나눈다.** 일괄 버튼은 대상 페이지들의 상태만 `대기중`으로 바꾸고, 각 페이지 자동화가 개별 웹훅을 보낸다. 서버는 웹훅 본문에 실려 온 값을 쓰고, 다시 조회하지 않는다.

줄이는 방법 표시:

| 표시 | 방법 |
| --- | --- |
| N | Notion 자동화로 옮김(서버 호출 0) |
| P | 웹훅 본문에 속성 값을 실어 보냄(페이지 다시 조회 안 함) |
| S | Supabase 복사본(`cr_*`)에서 읽음 |
| 1W | 양방향 관계는 한쪽에서 한 번만 씀(읽고-고치고-다시쓰기 없앰) |
| B→I | 일괄 버튼을 개별 웹훅 여러 개로 나눔 |

## 공통 비용 (거의 모든 웹훅)

| 단계 | 호출 | 줄이는 방법 |
| --- | --- | --- |
| 잠금 확인용 페이지 조회(`webhookIngest` `getPage`) | 1 | P: 상태·필요한 속성을 본문으로 받으면 0 |
| 상태 `작업중` 쓰기 | 1 | 버튼이 `대기중`을 Notion에서 쓰므로 서버의 `작업중` 쓰기는 생략 가능 |
| 상태 `완료`/`오류` 쓰기 | 1 | 결과 쓰기(관계 연결 등)와 같은 요청에 합침 |

→ 웹훅 하나당 기본 3회가 0~1회로 준다.

## 일괄 버튼 → 개별 웹훅으로 나눌 후보

| 일괄 버튼 | 개별 대상 | Notion에서 바꿀 값 |
| --- | --- | --- |
| 교재 생성 (클래스) | 등록 | 수강 중 등록들의 `교재 상태` = `대기중` |
| 다음주 수업 일괄 생성 (메뉴) | 시간표 | 시간표들의 `상태` = `대기열` |
| 교재비 생성 (클래스) | 등록 | 등록들의 상태 값(새로 정해야 함) |
| 보고서 일괄 전송 (수업) → `send-class-daily-reports` | 출석 | 출석들의 전송 상태 = `대기중` → 출석마다 `send-daily-report` |
| 일괄 전송 (알림톡 발송함) → `send-selected-notifications` | 보고서 | 선택한 보고서들의 상태 = `대기중` → `send-report` |
| 보고서 생성·월 수강료 생성 (클래스) | 등록 | 등록들의 상태 값 |
| 종료 처리 안의 미래 출석 삭제 | 출석 | 출석들의 `삭제 체크` = 체크 → `cascade-delete` |

개별 웹훅이 한꺼번에 들어와도 지금처럼 `sync_queue`에 쌓고 워커 하나가 차례로 처리하면 Notion 호출 속도(초당 약 3회)를 넘지 않는다.

## Notion 자동화로 옮길 후보

- 시간표 설정 전체(위 표)
- 종료 처리의 종료일 채우기·시간표 비우기
- 일괄 버튼들(대상 페이지 상태 바꾸기)
- 링크 비활성화·활성화(`toggle-report-link`): `토큰` 앞에 `disabled:`를 붙이고 떼는 일이라 수식으로 쓸 수 있는지 확인 필요. 링크 재발급(새 난수)은 서버에 남음.

## 발견한 위험 (코드로 확인)

1. **관계 25개 잘림 + 읽고-고치고-다시쓰기.** (v2.6.32: 남은 곳은 잘렸을 때 끝까지 읽고 씀. 조회 결과도 25개에서 잘린다.) 페이지 조회는 관계를 25개까지만 주는데, 그 목록에 하나를 더하거나 빼서 통째로 다시 쓰는 곳이 있다. 25명이 넘으면 나머지 연결이 지워진다.
   - 교재 생성: 그룹 교재 템플릿의 `등록` (`registrationTextbookTarget.ts` `resolveInstanceForTemplate`)
   - 수업 생성: 수업의 `등록` (`registrationSync.ts` `attachSessionsAndAttendance`)
   - 종료 처리: 수업의 `등록` (`disconnectClassSessionsAfterEndDate`), 그룹 교재의 `등록` (`cleanupUnusedBooksOnEnd`)
   - 1W(등록 쪽에서만 쓰기)로 바꾸면 모두 사라진다.
2. **종료 처리가 공유 학습기록을 지울 수 있음(확인 필요).** `archiveAttendanceAfterEndDate`가 종료일 이후 출석에 연결된 학습기록도 보관한다. 학습기록은 반 전체가 함께 쓰는 공유 페이지라, 미리 만들어 둔 반 기록이 있으면 한 학생 종료로 반 전체 기록이 지워질 수 있다. 실제 데이터에서 일어난 적이 있는지는 미확인.
